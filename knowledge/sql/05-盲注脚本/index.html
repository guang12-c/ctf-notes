    SQL 注入 · 盲注脚本说明¶

    两个脚本和这份文档都放在 E:\dsh\sql\ 目录下。 一个用于条件响应型，一个用于条件错误型。

    E:\dsh\sql\
├── blind_sqli.py                条件响应型（看 "Welcome back"）
├── blind_sqli_error.py          条件错误型（看 HTTP 500）
└── blind_sqli_error_逐行讲解.md  脚本逐行说明

    一、两个脚本的区别¶

    blind_sqli.py blind_sqli_error.py
    适用 条件响应（页面内容变化） 条件错误（状态码变化）
    数据库 PostgreSQL / MySQL Oracle
    判断依据 "Welcome back" in r.text r.status_code == 500
    取字符方式 等值爆破（36 个字符） ASCII 二分（7 次）
    请求数 20 × 36 = 720 20 × 7 ≈ 140
    速度 几秒（并发） 几秒（并发 + 二分）

    二分查找更快，但等值爆破更容易理解、更容易改。

    二、blind_sqli_error.py（条件错误型）¶

    核心逻辑¶

    payload = (f"{TRACKING}'and(select case when("
           f"ASCII(SUBSTR((SELECT password FROM users WHERE username='administrator'),{pos},1))>{ascii_val}"
           f") then to_char(1/0) else 'a' end from dual)='a'--")

    问：这个字符的 ASCII 码 > ascii_val 吗？ - 500 → 是 - 200 → 否

    7 次二分锁定一个字符。

    配置(第 30–36 行)¶

    行 变量 说明
    30 BASE_URL lab 地址
    31 SESSION 可选
    32 TRACKING 注入点原始值
    33 PASSWORD_LEN 已确认的长度
    34 THREADS 并发数,被限流就调小
    35 TIMEOUT 超时秒数
    36 VERIFY_SSL 证书校验

    内置保护¶

    机制 作用
    通道自检 启动先验 1=1 必炸、1=2 必不炸,不过就退出
    重试 单条失败重试 3 次
    状态码校验 遇到非 200/500(如 504)→ 明确提示 lab 过期
    位置并行 20 个位置同时二分

    三、blind_sqli.py（条件响应型）¶

    核心逻辑¶

    payload = (f"{TRACKING}' and substring((select password from users "
           f"where username='administrator'),{pos},1)='{ch}'--")

    问：这个字符是不是 ch？ - 页面出现 "Welcome back" → 是

    36 个字符并发试,命中即进入下一位。

    和错误型的三个差异¶

    响应型 错误型
    判断行 62: "Welcome back" in r.text 62: r.status_code == 500
    查询方式 等值 ='a' 大于 >N（二分）
    数据库函数 SUBSTRING SUBSTR + TO_CHAR(1/0) + dual

    四、改造速查（换题型改哪里）¶

    要改什么 改哪里
    注入位置（Cookie→URL/POST/Header） send() 函数里的 requests.get(...)
    SQL 语句（表名/列名/函数） build_payload()
    判断依据（500/Welcome back/延时） probe() 里的 if 判断
    字符范围 find_char() 里的 lo, hi = 32, 126
    并发 / 超时 配置区
    多跑一列 改 PASSWORD_LEN + build_payload() 的列名

    详细的逐行讲解见同目录的 blind_sqli_error_逐行讲解.md。

    五、常见故障¶

    现象 原因 处理
    自检 1=1 不报 500 TrackingId 过期 / 注入语法错 重新抓 Cookie；手工验证 payload
    全是 504 lab 实例过期 重启 lab,更新 URL/TrackingId/长度
    全是 ? 位置失败 减小 THREADS,增大 TIMEOUT
    密码解出但有 ? 某几位失败 重跑,或单独手工测
    结果全错 表名/列名不对 用 length(password)>0 那条验证

    判断 lab 是否过期¶

    https://portswigger.net/    → 200  → 网络正常
https://<lab域名>/          → 504  → 实例被回收

    六、什么时候用脚本，什么时候用 Intruder¶

    场景 推荐
    只想验证注入存在 Burp Repeater 手工
    少量测试（<20 次） Repeater + 复制粘贴
    批量爆破（>100 次） 脚本
    需要复杂判断逻辑 脚本
    Burp 专业版 + Intruder 都可以

    ⚠️ Burp 社区版的 Intruder 有限速,批量任务用脚本反而更快。

    七、脚本运行前的三条检查¶

    □ ① lab 活着吗?(直接访问根路径返回 200)
□ ② TrackingId 是最新的吗?(重启 lab 后会变)
□ ③ 密码长度重测过吗?(每个实例的密码都不同)

    这三条不确认,脚本跑出来的结果毫无意义。
