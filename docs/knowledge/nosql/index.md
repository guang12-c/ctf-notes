# NoSQL 注入

> **一句话：你交给数据库的「值」，被它当成了「条件」。SQL 里要逃出引号，这里连引号都没有 —— 结构本身就是语法。**

## 这条线的核心

```text
入口:  后端把 JSON 字段原样拼进查询文档
       db.find_one({"username": u, "password": p})
       User.findOne({ user: req.body.user, pass: req.body.pass })
  ↓
机制:  字段值是以 $ 开头的对象 → 数据库按「操作符」解释
       {"password": {"$ne": "x"}}   →   password != "x"
  ↓
利用:  {"$ne":"x"}     只要不等于 x 就命中（登录绕过首选）
       {"$exists":true} 字段存在即可
       {"$regex":"^a"} 逐字符猜值（盲注）
       {"$where":"..."} 直接执行 JS（最危险）
```

## 和 SQL 注入的区别

| | SQL 注入 | NoSQL 注入 |
|---|---|---|
| 载体 | 字符串 | JSON 对象（结构） |
| 逃逸动作 | 闭合引号：`'` `"` | **不需要闭合**，`$` 开头就是语法 |
| 改写的东西 | 语句结构 | 查询条件 |
| 等价形式 | `' OR 1=1-- ` | `{"$ne":"x"}` |
| 失败信号 | 多半报语法错 | **静默 401**，什么都没有 |
| 结论怎么来 | 看报错 | 只能拿回显当黑盒，一个个试 |
