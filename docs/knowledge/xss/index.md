# XSS 跨站脚本

> **一句话：你的输入被当成了页面语法的一部分，于是浏览器（或框架）替你执行了它。**

## 核心模型

```text
入口:  反射型 URL 参数 / 存储型 数据库 / DOM 型 location.search
  ↓
拼接:  HTML 标签之间 / JS 字符串 / innerHTML / location.href / form.action / 模板
  ↓
解析:  浏览器按 HTML、JS 的语法解析 —— 数据越界变成了代码
  ↓
执行:  同源下的任意 JS
```

**和 SQL 注入、SSTI 是同一个道理：数据越界变成了代码。**区别只是越界的"语言"不同——SQL 里逃出引号，模板里逃出 `{{ }}`，XSS 里逃出"文本"。

## 最常用的三条

```html
<img src=x onerror=alert(1)>    HTML 标签之间 / innerHTML —— 不用闭合任何东西
';alert(1)//                    JS 单引号字符串里 —— 闭合引号，注释掉尾巴
javascript:alert(1)             location.href / form.action 这种 URL 汇点
```

## 卡住时的三问

```text
① 我的输入落在哪种语法里？
   HTML 标签之间 / 属性里 / JS 字符串里 / innerHTML / URL / 模板表达式
   —— 上下文决定 payload，不是反过来

② 是没执行，还是执行了看不到？
   显示成文字（被转义）/ 标签在但没反应（innerHTML 不跑 script）/
   Console 报 CSP（被策略拦）/ 弹窗内容不对（alert 被改写）
   —— 四种原因，处理方式完全不同

③ 我是不是在跟"浏览器规则"较劲？
   <script> 被过滤不等于没戏：事件属性、伪协议、模板表达式都是弹药
```
