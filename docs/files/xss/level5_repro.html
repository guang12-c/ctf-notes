level5 拆解：为什么"提交表单"能执行代码

当前页面 URL：

① 先看一个普通表单（这就是原题里那个）

<form action="" method="POST" id="autoForm">
    <input type="text" name="test">
    <input type="submit">
</form>

三个东西决定它怎么工作：

  • action —— 提交到哪个地址（空表示"当前页面"）
  • method —— 用什么方法发请求（GET / POST）
  • 提交按钮 —— 用户点头一下，浏览器就带着表单数据去 action

底下这个真表单，test 里随便写点东西：

② 三条路对比：同一个表单，只改 action

路 A：action 是普通地址（当前页 + ?from=form）

现象：整页刷新，地址栏变成 ...?from=form&test=hello。 这就是"表单提交 = 浏览器导航到一个新地址"。表单数据被拼进了 URL，页面重载。

路 B：action 是 javascript:alert(document.domain)

现象：弹窗。没有发出任何请求、页面没有刷新 —— 因为 javascript: 这个 scheme 的语义是"执行后面的代码"，不是"去某个地方取资源"。

路 C：自检版（用一个不弹窗的 payload 探测到底有没有执行）

如果显示"执行成功"，说明表单提交确实把 javascript: 交给 JS 引擎跑了。 如果显示"没执行"，按 F12 看 Console —— 部分浏览器版本会拦 javascript: 表单提交， 这是浏览器差异，不影响原理。

③ 模拟原题：不用你点按钮，页面自己提交

原题靠 autosubmit 参数触发的就是下面这步 —— 代码调用 submit()，绕过按钮：

关键点：autoForm.submit() 是代码调用的提交，不需要任何用户交互。 这正是原题要 autosubmit 参数的原因 —— 否则光有可控的 action，也没人去点那个按钮。

④ 原题代码，逐行注释

if (getQueryVariable('autosubmit') !== false) {     // ① URL 里有 autosubmit 参数才进来
    var autoForm = document.getElementById('autoForm');
    autoForm.action = (getQueryVariable('action') == false)
        ? location.href                              // ② 没传 action → 提交回当前页
        : getQueryVariable('action');                // ③ 传了 action → 用你给的那个字符串！
    autoForm.submit();                               // ④ 立刻提交，不等用户
} else {
    // 没有 autosubmit：什么都不做，就是普通页面，等你手动点提交
}

getQueryVariable 找不到参数时返回 false，所以
getQueryVariable('autosubmit') !== false 的意思是"有这个参数"；
getQueryVariable('action') == false 的意思是"没传 action"。
传 ?autosubmit=1&action=javascript:alert(1)，第 ③ 步拿到的就是一个字符串， 第 ④ 步把它当"提交目标"交给浏览器 —— 于是触发导航，导航目标是 javascript:，执行代码。

⑤ 为什么"正常提交给自己"这条路走不通

如果只传 ?autosubmit=1，action 就落到 location.href（当前页）， 浏览器就会对该页发一个 POST 请求。

实测：

POST /level5  →  404
<pre>Cannot POST /level5</pre>

服务端根本没写处理 POST 的路由。所以正常路径是死路，只剩伪协议这一条。

⑥ 错误的写法，用来理解边界

  • action=/level6 —— 只是普通跳转，不是 XSS（代码没在目标源里执行）
  • action=http://evil.com/?x= —— 这是钓鱼/开放重定向，也不是 XSS
  • 只给 action 不给 autosubmit —— 页面不自动提交，什么都不会发生
  • javascript:alert(1=1) —— 会被 getQueryVariable 按 = 切断（见 level4 那节的坑）
