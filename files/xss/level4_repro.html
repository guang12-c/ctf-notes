③ 亲眼看看 escape() 干了什么

在下面输入框里打字，右边实时显示 escape() 之后的样子：

javascript%3Aalert%281%29

看到没：: 变 %3A、( 变 %28。 如果这串被塞给 location.href，浏览器只会当成「一个叫 javascript%3A... 的网址」，什么事都不会发生。
反过来：<script> 被 escape 成 %3Cscript%3E，塞进 innerHTML 也只是一段文字 —— 所以标签派 payload 在这关必死。

④ 试试失败的写法，理解边界

  • <script>alert(1)</script> —— 没反应（escape 之后是文字；就算不 escape，innerHTML 也不执行 script）
  • alert(1) —— 没反应（没有 javascript: 前缀，浏览器当成相对路径，导航到 /alert(1)）
  • javascript:alert(1=1) —— 没反应！因为 getQueryVariable 用 = 切分参数，值只取到第一个 = 前面（见 ⑤）

⑤ 原题的参数解析函数（它有个坑）

function getQueryVariable(variable) {
    var query = window.location.search.substring(1);   // 去掉开头的 ?
    var vars = query.split("&");                       // 按 & 切成 "k=v"
    for (var i = 0; i < vars.length; i++) {
        var pair = vars[i].split("=");                 // 按 = 切成 [k, v]
        if (pair[0] == variable) { return pair[1]; }   // 只返回第二个元素
    }
    return false;
}

所以 payload 里不能出现 =（会被切掉）和 &（会被当成下一个参数）。 想赋值就绕开，比如 javascript:alert(document.domain) 而不是 javascript:x=1;alert(x)。
